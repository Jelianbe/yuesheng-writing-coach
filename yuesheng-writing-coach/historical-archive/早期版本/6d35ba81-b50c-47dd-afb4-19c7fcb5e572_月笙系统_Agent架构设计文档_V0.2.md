# 「月笙」AI写作诊断系统 —— Agent 架构设计文档 V0.2

> 版本：V0.2（架构层）
> 定位：从"Prompt工程"到"AI系统工程"的范式转换
> 核心命题：如何让AI长期稳定地理解一部小说
> 生成时间：2026-05-28

---

# 一、架构范式转换声明

## 1.1 旧范式（已放弃）

用户输入文本 → LLM单次分析 → 输出诊断报告

**假设**：LLM能一次性读完所有文本，给出准确判断。

**问题**：
- 1000万字不可能一次读完
- 即使能读，注意力稀释导致幻觉率上升
- 成本爆炸、延迟爆炸
- 无法追踪长期变化
- 每次对话都是"失忆状态"

## 1.2 新范式（当前采用）

用户输入文本
    ↓
【原始文本层】保存但不直接读取
    ↓
【结构解析层】提取人物/地点/势力/时间线/事件/关系
    ↓
【写作认知层】总结用户习惯/风格/长期问题/成长轨迹
    ↓
【动态上下文装载】根据当前任务，只加载相关认知片段
    ↓
LLM分析（基于压缩后的认知，而非原始文本）
    ↓
输出诊断报告 + 更新认知层

**核心原则**：
> LLM不是数据库。真正的长期系统 = 模型 + 外部记忆。
> 不是"记得更多"，而是"知道什么重要"。

# 二、四层架构详解

## 第一层：原始文本层（Raw Text Layer）

### 功能
保存用户上传的所有原始内容，但不作为LLM的直接输入。

### 存储内容

| 类型 | 格式 | 说明 |
|------|------|------|
| 全文原文 | Markdown/TXT | 完整小说文本 |
| 分章节 | 按章节拆分 | 便于逐章分析 |
| 分场景 | 按场景标记 | 场景切换点 |
| 对话片段 | 提取的对话 | 独立分析对话质量 |
| 设定文档 | 世界观/人设 | 用户上传的辅助材料 |

### 技术实现
- 对象存储（S3/MinIO）
- 版本控制（每次修改留痕）
- 全文检索（Elasticsearch/OpenSearch）

### 关键原则
原始文本 = 数据源 ≠ 分析源
LLM不直接读取原始文本，只读取上层提炼后的认知结构。

---

## 第二层：结构解析层（Structural Parsing Layer）

### 功能
自动从原始文本中提取结构化信息，形成"小说结构数据库"。

### 提取维度

#### 2.1 世界信息（World Info）

| 字段 | 示例 | 来源 |
|------|------|------|
| 世界观规则 | "灵脉决定魔法等级" | 自动提取+用户补充 |
| 势力关系 | "帝国 vs 联盟，对立300年" | 自动提取 |
| 地理结构 | "七大洲→三大禁地→中央城" | 自动提取 |
| 时间线 | "天元历2024年→大灾变→重建" | 自动提取 |
| 战力体系 | "一品→九品，每品分初/中/后" | 自动提取 |
| 社会制度 | "贵族世袭，平民不可修炼" | 自动提取 |

#### 2.2 人物信息（Character Info）

| 字段 | 示例 | 更新频率 |
|------|------|---------|
| 姓名 | 林默 | 一次性 |
| 性格标签 | 谨慎、隐忍、报复心强 | 每卷更新 |
| 核心目标 | 为父报仇→保护妹妹→改变世界 | 每卷更新 |
| 创伤/阴影 | 童年目睹父亲被杀 | 一次性 |
| 关系网 | 师父（亦敌亦友）、妹妹（软肋）、反派（镜像） | 每章更新 |
| 成长变化 | 从懦弱到果断，从独狼到领袖 | 每卷更新 |
| 口癖/习惯 | "先想想"、摸鼻子、回避眼神 | 一次性 |
| 行为模式 | 遇事先观察，不轻易承诺，承诺必兑现 | 每卷更新 |

#### 2.3 剧情信息（Plot Info）

| 字段 | 示例 | 更新频率 |
|------|------|---------|
| 主线 | 从废柴到拯救世界 | 每卷更新 |
| 支线 | 寻找母亲下落、解开身世之谜 | 每章更新 |
| 冲突链 | 学院竞争→家族危机→国家战争→世界存亡 | 每卷更新 |
| 爽点节点 | 第3章反杀、第15章突破、第30章 reveal | 每章标记 |
| 高潮节点 | 第10卷大决战 | 每卷标记 |
| 情绪曲线 | 压抑→释放→平静→压抑→爆发 | 每章计算 |
| 伏笔清单 | 第2章"那枚戒指"→第20章"戒指真相" | 每章更新 |

#### 2.4 写作信息（Writing Info）

| 字段 | 示例 | 更新频率 |
|------|------|---------|
| 用户常见问题 | 视角越界（第3次）、情绪标签化（第5次） | 每次诊断更新 |
| 高频错误 | "众人心中…"、"他很紧张…" | 每次诊断更新 |
| 擅长方向 | 对话真实度高、冲突设计强 | 每次诊断更新 |
| 风格偏向 | 偏现实流、喜欢心理描写、压抑感强 | 每卷更新 |
| 节奏习惯 | 爽点周期约15章，中盘易疲软 | 每卷计算 |

### 技术实现

提取流程：

原始文本
    ↓
【分块】按章节/场景/对话拆分
    ↓
【Embedding】每块文本向量化
    ↓
【实体识别】提取人物、地点、势力、物品
    ↓
【关系抽取】人物关系、因果关系、时间关系
    ↓
【事件检测】识别冲突、转折、爽点、高潮
    ↓
【结构化存储】写入图数据库

### 存储方案

| 数据类型 | 存储 | 原因 |
|---------|------|------|
| 实体（人物/地点/物品） | 图数据库 | 关系查询 |
| 事件/情节 | 时序数据库 | 时间线查询 |
| 文本块 | 向量数据库 | 语义检索 |
| 结构化信息 | 关系数据库 | 精确查询 |

## 第三层：写作认知层（Writing Cognition Layer）核心

### 功能
这是系统真正的核心资产。不是保存文本，而是保存"AI理解后的结构化认知"。

### 认知类型

#### 3.1 用户习惯认知（User Habits）

示例JSON结构：

user_id: "user_12345"
writing_habits:
  strengths:
    - dimension: "对话真实"
      evidence: ["第3章对话", "第7章对话"]
      confidence: 0.92
      first_observed: "2026-05-20"
      last_confirmed: "2026-05-28"
  weaknesses:
    - dimension: "视角越界"
      pattern: "频繁写'众人心中…'"
      frequency: "每3章出现1次"
      severity: "高"
      first_observed: "2026-05-20"
      last_occurred: "2026-05-28"
      improvement_trend: "下降"
  style_signature:
    primary: "现实流"
    secondary: "心理描写"
    markers: ["大量内心独白", "环境细节丰富", "对话简短"]
  rhythm_pattern:
    climax_interval: "约15章"
    sagging_point: "第20-25章易疲软"
    hook_density: "前3章高，中盘低"

#### 3.2 小说认知（Novel Cognition）

示例JSON结构：

novel_id: "novel_67890"
cognition:
  world_consistency:
    rules: ["灵脉决定等级", "禁地不可飞行"]
    violations:
      - chapter: 15
        violation: "主角在禁地飞行"
        severity: "高"
  character_arc:
    protagonist:
      start: "懦弱、逃避"
      mid: "犹豫、试探"
      current: "果断、有担当"
      target: "领袖、牺牲精神"
      deviation: "第18章突然变得过于果断，缺乏过渡"
  plot_health:
    main_line_progress: 0.65
    subplot_balance: "支线过多，主线推进慢"
    foreshadowing_resolution:
      - setup: "第2章戒指"
        payoff: "第20章"
        status: "已回收"
      - setup: "第5章神秘人"
        payoff: "待回收"
        risk: "读者可能遗忘"
  emotional_curve:
    data:
      - chapter: 1
        intensity: 0.3
        type: "压抑"
      - chapter: 3
        intensity: 0.9
        type: "释放"
    warning: "第10-15章情绪强度过低，存在流失风险"

#### 3.3 长期问题追踪（Long-term Issues）

示例JSON结构：

user_id: "user_12345"
novel_id: "novel_67890"
issue_tracker:
  - issue_id: "issue_001"
    type: "视角越界"
    first_seen: "2026-05-20"
    frequency_history:
      - date: "2026-05-20"
        count: 5
        chapters: [1,2,3]
      - date: "2026-05-25"
        count: 3
        chapters: [8,9]
      - date: "2026-05-28"
        count: 1
        chapter: [15]
    trend: "改善"
    interventions:
      - date: "2026-05-22"
        type: "视角专项训练"
        effect: "有效"
    status: "监控中"

### 技术实现

认知更新流程：

每次诊断
    ↓
提取新问题/新特征
    ↓
与历史认知对比
    ↓
更新/合并/标记趋势
    ↓
写入认知数据库
    ↓
生成认知摘要（供下次诊断使用）

存储：文档数据库（MongoDB）+ 向量数据库（Pinecone/Milvus）

关键原则：
- 认知必须可编辑（因为AI会记错）
- 认知必须带置信度（不是所有提取都可靠）
- 认知必须带时间戳（追踪变化趋势）
- 认知必须可溯源（能追溯到原文出处）

## 第四层：训练与反馈层（Training & Feedback Layer）

### 功能
基于认知层数据，自动生成训练任务，定向强化弱项。

### 核心能力

#### 4.1 自动训练任务生成

输入：用户认知（弱点：视角越界，频率每3章1次）
    ↓
系统生成：
    - 任务类型：视角专项训练
    - 材料推荐：鲁迅《孔乙己》（已推荐过，换《活着》第一人称段落）
    - 练习：限定视角写500字场景
    - 验证：AI检测是否越界
    - 周期：每2天1次，连续3次

#### 4.2 定向阅读推荐

输入：用户认知（擅长对话，不擅长情绪描写）
    ↓
系统推荐：
    - 余华《活着》第一章（情绪拆解）
    - 汪曾祺《端午的鸭蛋》（感官细节）
    - 海明威《杀手》（冰山理论）
    - 排除：已读过的材料

#### 4.3 成长追踪报告

每月生成：
    - 6维度得分趋势图
    - 弱点改善率
    - 新出现的问题预警
    - 下一阶段训练建议

### 技术实现

- 规则引擎（基于认知触发任务）
- 推荐系统（协同过滤+内容匹配）
- 进度追踪（时序数据库）

# 三、动态上下文装载（Dynamic Context Loading）核心技术

## 3.1 问题本质

用户上传1000万字，系统不应该"永远带着1000万字跑"。

## 3.2 解决方案

根据当前任务，动态提取相关认知片段，组装成"最小有效上下文"。

## 3.3 装载策略

### 场景1：诊断当前章节

当前任务：诊断第15章
    ↓
装载内容：
    - 第15章原文（<2000字）
    - 第14章摘要（200字）
    - 第15章涉及的人物认知（每人100字）
    - 第15章涉及的世界规则（相关条目）
    - 用户习惯认知（弱点高亮）
    - 历史诊断摘要（最近3次）
    ↓
总上下文：约3000-5000字

### 场景2：诊断人物一致性

当前任务：第30章主角行为是否OOC
    ↓
装载内容：
    - 第30章相关段落
    - 主角认知档案（性格、目标、创伤、成长变化）
    - 主角在第1/10/20章的关键行为摘要
    - 人物关系网（当前涉及的关系）
    - 历史OOC记录（如有）
    ↓
总上下文：约2000-4000字

### 场景3：诊断全书节奏

当前任务：第3卷节奏分析
    ↓
装载内容：
    - 全书情绪曲线数据（每章强度+类型）
    - 爽点/高潮节点分布
    - 第3卷摘要（每章100字）
    - 用户节奏习惯认知
    - 同类型优秀作品节奏对比（可选）
    ↓
总上下文：约3000-5000字

## 3.4 装载算法伪代码

def load_context(task_type, target_id, user_id, novel_id):
    context = {
        "system_prompt": load_system_prompt(),
        "user_cognition": load_user_cognition(user_id),
        "novel_cognition": load_novel_cognition(novel_id),
        "task_specific": None,
        "history": load_recent_history(user_id, limit=3)
    }

    if task_type == "chapter_diagnosis":
        context["task_specific"] = {
            "target_chapter": load_chapter(target_id),
            "prev_chapter_summary": load_chapter_summary(target_id - 1),
            "relevant_characters": load_character_cognition(target_id),
            "relevant_world_rules": load_world_rules(target_id)
        }

    elif task_type == "character_consistency":
        context["task_specific"] = {
            "target_scenes": load_scenes(target_id),
            "character_arc": load_character_arc(character_id),
            "historical_behaviors": load_key_behaviors(character_id, limit=5),
            "relationship_status": load_relationships(character_id)
        }

    elif task_type == "rhythm_analysis":
        context["task_specific"] = {
            "emotional_curve": load_emotional_curve(novel_id),
            "climax_distribution": load_climaxes(novel_id),
            "volume_summary": load_volume_summary(target_id)
        }

    return assemble_context(context)

## 3.5 关键技术

| 技术 | 用途 | 实现 |
|------|------|------|
| Embedding检索 | 找到与当前任务相关的历史段落 | 向量数据库 |
| 图遍历 | 找到与当前人物/事件相关的所有节点 | 图数据库 |
| 时序查询 | 提取特定时间段的剧情发展 | 时序数据库 |
| 摘要生成 | 将长文本压缩为认知摘要 | LLM摘要 |
| 置信度过滤 | 只使用高置信度的认知数据 | 阈值控制 |

# 四、双记忆系统（Dual Memory System）核心设计

## 4.1 架构图

用户交互层（当前对话/当前章节/当前任务）
                    ↓
         短期记忆（Session Memory）
          - 当前会话上下文
          - 当前章节原文
          - 当前诊断过程
          - 本轮对话历史
          - TTL：会话结束即清除
                    ↓
         长期记忆（Persistent Memory）
          - 用户习惯认知
          - 小说结构认知
          - 长期问题追踪
          - 成长轨迹
          - 可编辑、可审计、可版本化

## 4.2 短期记忆（Short-term Memory）

### 存储内容
- 当前会话的所有对话轮次
- 当前正在分析的章节原文
- 本轮诊断的中间结论
- 用户本轮的反馈/追问

### 技术实现
- 内存缓存（Redis）
- TTL：30分钟无活动自动清除
- 上限：最近10轮对话

### 关键原则
短期记忆 = 临时工作区
不保存、不积累、会话结束即丢弃

## 4.3 长期记忆（Long-term Memory）

### 存储内容

| 类别 | 内容 | 更新频率 | 可编辑 |
|------|------|---------|--------|
| 用户画像 | 经验等级、态度偏好、常用档位 | 每次诊断 | 是 |
| 习惯认知 | 擅长/弱点/风格/节奏 | 每次诊断 | 是 |
| 小说认知 | 世界/人物/剧情/写作信息 | 每章/每卷 | 是 |
| 问题追踪 | 长期问题清单、改善趋势 | 每次诊断 | 是 |
| 成长轨迹 | 6维度得分历史、里程碑 | 每次诊断 | 否（只读） |
| 诊断历史 | 所有诊断报告摘要 | 每次诊断 | 否（只读） |

### 技术实现

长期记忆存储架构：

长期记忆
    ├── 结构化数据（JSON）→ MongoDB
    │      └── 用户画像、习惯认知、问题追踪
    ├── 向量数据（Embedding）→ Pinecone/Milvus
    │      └── 文本块、认知摘要的语义表示
    ├── 图数据（关系）→ Neo4j
    │      └── 人物关系、事件因果、世界关联
    └── 时序数据（趋势）→ InfluxDB/TimescaleDB
           └── 得分变化、情绪曲线、节奏指标

### 关键原则

长期记忆 = 核心资产
必须：可编辑（人工修正AI错误）
必须：可审计（所有修改留痕）
必须：可版本化（能回滚到历史状态）
必须：带置信度（区分AI提取 vs 人工确认）

## 4.4 记忆同步机制

短期记忆 → 长期记忆 的写入规则：

1. 每次诊断结束后，提取新认知
2. 与现有长期记忆对比
3. 冲突处理：
   - 高置信度新认知 → 覆盖旧认知
   - 低置信度新认知 → 标记为"待确认"
   - 与人工编辑冲突 → 以人工为准
4. 写入长期记忆
5. 生成变更日志

# 五、成本控制系统

## 5.1 分层分析策略

| 层级 | 触发条件 | 分析范围 | 成本 | 收费模式 |
|------|---------|---------|------|---------|
| 轻量分析 | 默认 | 当前章节 + 相关认知 | 低 | 免费/基础版 |
| 深度分析 | 用户主动选择 | 全卷 + 人物成长 + 节奏变化 | 中 | 付费/高级版 |
| 全书分析 | 付费/特定节点 | 全书结构 + 长期趋势 + 对比分析 | 高 | 高级版/按次 |

## 5.2 成本控制手段

| 手段 | 说明 |
|------|------|
| 文本压缩 | 原文→摘要→认知，逐层压缩 |
| Embedding缓存 | 已分析过的文本块不再重复Embedding |
| 增量更新 | 只分析修改过的章节，未修改的复用历史结果 |
| 分层模型 | 轻量用轻量模型，深度用强模型 |
| 异步处理 | 非实时分析（如全书节奏分析）放入队列异步执行 |

# 六、数据资产价值

## 6.1 核心资产

系统运行过程中积累的数据，后期价值极高：

| 数据类型 | 价值 |
|---------|------|
| 中文写作问题库 | 什么问题最常见、什么阶段最容易出现 |
| 训练效果数据 | 什么训练对什么弱点最有效 |
| 风格-效果映射 | 什么风格在什么类型中表现最好 |
| 节奏-留存关联 | 什么节奏模式读者留存最高 |
| 弃坑预警模型 | 什么文本特征预示作者即将弃坑 |

## 6.2 应用场景

- 产品优化：基于数据优化诊断算法
- 内容推荐：基于风格匹配推荐编辑/平台
- 行业报告：中文写作行为年度报告
- 模型训练：训练中文写作专用模型

# 七、实施路线图

## Phase 1：MVP（当前）

目标：单章节分析，验证诊断有效性

架构：
用户 → 上传章节 → LLM直接分析 → 输出报告

无需：长期记忆、结构解析、认知层
只需：系统提示词 + LLM

验证目标：
- 6维度评分准确率 ≥ 75%
- 作者满意度 ≥ 80%

## Phase 2：章节关联（验证通过后）

目标：前后文一致性、人物一致性

新增：
- 短期记忆（最近3章）
- 简单结构解析（人物列表、事件列表）
- 轻量认知层（用户弱点记录）

## Phase 3：全书认知（数据积累后）

目标：全书结构分析、长期成长追踪

新增：
- 完整四层架构
- 动态上下文装载
- 双记忆系统
- 训练与反馈层

## Phase 4：智能体（远期）

目标：主动诊断、预测问题、自动训练

新增：
- 主动预警（"第20章可能出现节奏疲软"）
- 自动干预（检测到视角越界趋势，提前推送训练）
- 个性化模型（基于用户数据微调）

# 八、关键设计原则总结

| # | 原则 | 说明 |
|---|------|------|
| 1 | LLM不是数据库 | 所有长期记忆必须外部化 |
| 2 | 不是记得更多，是知道什么重要 | 动态上下文装载 |
| 3 | 认知 > 文本 | 保存结构化认知，而非原始文本 |
| 4 | 可编辑 > 自动 | 长期记忆必须允许人工修正 |
| 5 | 分层 > 全量 | 根据任务选择分析深度，控制成本 |
| 6 | 短期记忆临时，长期记忆持久 | 双记忆系统分离 |
| 7 | 验证 > 扩张 | MVP只做单章节，验证通过后再扩展 |
| 8 | 数据是资产 | 所有诊断数据积累为后期价值 |

---

> 真正难的地方，从来不是"AI会不会分析小说"。
> 而是："如何让AI长期稳定地理解一部小说"。
> 
> 这个难度，已经开始接近真正的智能体系统设计了。
