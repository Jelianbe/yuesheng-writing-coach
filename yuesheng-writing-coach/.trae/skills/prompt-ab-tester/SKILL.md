# Prompt A/B Tester (Prompt 变体对比框架)

## Purpose

当修改 System Prompt 或任何 Agent Prompt 后，需要**量化评估变更效果**，而非凭感觉判断。本 Skill 提供轻量但系统的 A/B 测试流程——不需要 ML pipeline，只需要 Golden Dataset + 人工评分表 + 对比报告。

## When to Invoke

- **修改 `yuesheng-prompt-v*.md` 后** — 验证新版 vs 旧版差异
- **修改 `diagnosis-agent-prompt-*.md` 后** — 验证诊断准确率变化
- **调整态度档位/语气修饰词后** — 验证 Persona 一致性
- **新增症候/动作后** — 验证新内容的识别率

## The 5 Evaluation Dimensions

| # | 维度 | 权重 | 评估方法 | 来源 |
|---|------|:----:|---------|------|
| D1 | **教练定位遵守率** | 30% | V-01/V-02 违规次数 / 总回复数 | coach-output-validator |
| D2 | **诊断准确率** | 25% | Golden Dataset 标注 vs Agent 输出 F1 分 | syndrome-manual.md |
| D3 | **建议可操作性** | 20% | 人工评分（1-5 分）| 教学效果反馈 |
| D4 | **回复自然度** | 15% | 人工评分（1-5 分）| 用户体感 |
| D5 | **Token 效率** | 10% | 有效信息密度 = 有用字数 / 总 token 数 | 成本控制 |

### D1: 教练定位遵守率 (30%)

使用 `coach-output-validator` skill 的 V-01/V-02 规则自动检测。

```
得分 = (无违规回复数 / 总回复数) × 100 × 0.30
```

### D2: 诊断准确率 (25%)

需要准备 **Golden Dataset**（见下方「Test Input Set 设计」）。

```
精确率 = Agent 正确识别的症候数 / Agent 报告的总症候数
召回率 = Agent 正确识别的症候数 / Golden Dataset 标注的实际症候数
F1 = 2 × P × R / (P + R)
D2 得分 = F1 × 100 × 0.25
```

### D3: 建议可操作性 (20%)

人工评分标准：

| 分值 | 标准 |
|:----:|------|
| 5 | 用户可以直接执行，无需额外思考 |
| 4 | 用户需要少量调整即可执行 |
| 3 | 方向正确但需要用户自己细化步骤 |
| 2 | 建议过于抽象或理论化 |
| 1 | 建议与用户问题无关或无法执行 |

### D4: 回复自然度 (15%)

人工评分标准：

| 分值 | 标准 |
|:----:|------|
| 5 | 像真人教练在对话，无机器感 |
| 4 | 自然但有轻微模板痕迹 |
| 3 | 可以接受，但明显是 AI 生成的 |
| 2 | 生硬、堆砌术语、缺乏情感 |
| 1 | 完全不像对话，像在念说明书 |

### D5: Token 效率 (10%)

```
有效信息密度 = （非套话/非模板的字数）/ 总 token 消耗
D5 得分 = min(密度 × 100, 10) × 0.10  // 封顶 10%
```

## Test Input Set Design (Golden Dataset)

### 最小可行集（5 条）

每条输入覆盖不同的教学场景：

| # | 场景 | 输入示例 | 预期行为 |
|---|------|---------|---------|
| T-01 | 世界观展示（说明书症候 P001）| 用户粘贴一段纯世界观设定文字（>500 字），问"你觉得怎么样？" | 识别 P001，不给评价，引导转向角色体验 |
| T-02 | 大纲焦虑（P002）| 用户说"我不知道怎么写大纲，感觉很乱" | 识别 P002，给出结构化引导而非代写大纲 |
| T-03 | 短输入/沉默 | 用户只发"嗯" | 不走完整诊断，简洁回应 + 开放式追问 |
| T-04 | 安全词触发 | 用户在一段对话后说"轻一点" | 立即降档，语气变温和 |
| T-05 | 引用章节 | 用户发送带 `[[chapter:xxx:第三章]]` 的消息 | 正确加载并引用章节内容做分析 |

### 扩展集（可选，10 条）

在最小集基础上增加：

| # | 场景 | 覆盖目标 |
|---|------|---------|
| T-06 | 多症候叠加 | 同时触达 P001 + P003 |
| T-07 | 高基础用户 | 已完成多次训练的用户，回复应更精简 |
| T-08 | 情绪低落 | 用户表达挫败感，应触发反思门控 |
| T-09 | 技法询问 | 问具体技巧（如"如何写好对话"），非诊断场景 |
| T-10 | 辩驳/质疑 | 用户不同意教练的建议 |

## Execution Flow

```
┌─────────────────────────────────────────────┐
│  1. 准备阶段                                  │
│     ├── 确定对比对象: Prompt-V-A vs Prompt-V-B │
│     ├── 准备 Test Input Set (T-01 ~ T-05)     │
│     └── 准备评分表格（打印或电子版）            │
├─────────────────────────────────────────────┤
│  2. 执行阶段                                  │
│     ┌───────────┐    ┌───────────┐            │
│     │ Variant A │    │ Variant B │            │
│     │ T-01→T-05 │    │ T-01→T-05 │            │
│     └─────┬─────┘    └─────┬─────┘            │
│           │                │                  │
│           ▼                ▼                  │
│     ┌─────────────────────────┐              │
│     │ 收集所有输出            │              │
│     └───────────┬─────────────┘              │
├─────────────────────────────────────────────┤
│  3. 评分阶段                                  │
│     ├── D1: 自动跑 coach-output-validator   │
│     ├── D2: 对照 Golden Dataset 手动评分     │
│     ├── D3-D4: 人工打分（1-5）               │
│     └── D5: 统计 Token 消耗                   │
├─────────────────────────────────────────────┤
│  4. 报告阶段                                  │
│     └── 生成对比报告（见下方模板）             │
└─────────────────────────────────────────────┘
```

## Integration with blind-test-plan.md

项目已有 `docs/plans/blind-test-plan.md`。本 Skill 是其**执行层**：

| 层级 | 文件 | 角色 |
|------|------|------|
| 计划层 | `blind-test-plan.md` | 定义盲测策略、参与人员、时间安排 |
| 执行层 | **本 Skill (prompt-ab-tester)** | 提供 5 维评估框架 + 测试输入集 + 报告模板 |
| 数据层 | `coach-output-validator` | D1 维度的自动化检测工具 |

## Notes

- 最小可行集 5 条输入足够发现主要回归问题，扩展到 10 条用于深度分析
- D3/D4 人工评分建议由不同的人独立打分，取平均值减少主观偏差
- 如果总分差异 < 5 分，认为两版本无显著差异，保持旧版
- 每次 Prompt 变更都应保留 A/B 测试报告存档，形成变更基线
