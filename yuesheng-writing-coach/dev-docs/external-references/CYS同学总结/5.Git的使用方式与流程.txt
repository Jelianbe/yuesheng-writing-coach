# Git 的使用方式与流程

> 用 AI 写代码，Git 不是加分项，而是保命项。它是项目的“存档点”和“后悔药”，让你每一步都有记录，随时可退回稳定版本。以下流程专为 AI 辅助编程场景设计，兼顾安全、简洁与可执行。

---

## 一、Git 的核心价值

- **记录每一次重要变更**：AI 一次可能改动多个文件，Git 让你清楚知道它改了什么。
- **随时回退到稳定版本**：效果不理想或项目被改乱时，可以一键恢复。
- **保护你的劳动成果**：避免误删、误改导致不可逆损失。
- **让你敢于尝试**：就像游戏存档，打过 Boss 前先存盘，打输就重来，没有心理负担。

---

## 二、安装与基本配置

### 1. 安装 Git
- **Windows**：下载 [Git for Windows](https://git-scm.com/download/win) 并安装（一路默认即可）。
- **macOS**：终端输入 `git --version`，若未安装会提示安装 Xcode Command Line Tools，点击安装即可。
- **Linux**：使用包管理器，如 `sudo apt install git`（Debian/Ubuntu）。

### 2. 首次配置身份
打开终端（或 IDE 内置终端），设置用户名和邮箱，这些会记录在每次提交中：
```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@example.com"
```

> 建议使用与 GitHub / Gitee 账号一致的邮箱，方便后续关联远程仓库。

## 三、基础概念速览

| 概念 | 说明 |
|------|------|
| 仓库（Repository） | 被 Git 管理的项目文件夹，包含所有版本记录。 |
| 提交（Commit） | 一次存档操作，记录当前所有文件的快照。 |
| 暂存区（Stage） | 提交前的“准备区”，选择哪些修改要放入这次存档。 |
| 分支（Branch） | 一条独立的开发线，可在不影响主线的情况下试验新功能。 |
| 远程仓库（Remote） | 存放在网络上的仓库副本（GitHub / Gitee 等），用于备份和协作。 |

## 四、AI 编程场景下的 Git 工作流程

### 阶段式提交（核心习惯）
**原则**：每完成一个可运行的、边界清晰的小阶段就提交一次。不要让 AI 连续改几十次都不存档。

**典型节奏**：
1. 项目初始化（空架子，能跑） → 提交
2. 目录结构、基础配置完成 → 提交
3. 一个页面/组件初步可用 → 提交
4. 一个接口调通 → 提交
5. 一个完整功能模块（如登录）完成并验证通过 → 提交
6. 每次让 AI 做大改动之前 → 先确保当前状态已提交

### 配合 AI 的完整操作序列
1. **开始一项新任务前**：确认工作区干净（`git status` 无未提交修改）。
2. **任务执行过程中**：AI 改完代码并自验通过后，让它总结本次修改内容。
3. **生成提交**：使用 AI 生成的总结作为提交说明，执行提交。
4. **继续下一阶段**：重复上述步骤。

> 可以将此流程写入 **Agent 宪法**，例如：  
> “每完成一个阶段性功能并验证通过，必须总结修改内容，并执行一次 git commit。提交信息需清晰描述改了什么。”

## 五、常用操作命令

以下命令可在 IDE 终端中执行，或让 AI 代劳。

### 初始化仓库
```bash
cd 你的项目文件夹
git init
```

### 查看状态
```bash
git status          # 查看哪些文件被修改、哪些未跟踪
git diff            # 查看具体改了什么内容
```

### 提交（存档）
```bash
git add .           # 将所有修改加入暂存区（或指定文件 git add 文件名）
git commit -m "描述本次改了什么"   # 提交并附上说明
```
**提交信息规范**（让 AI 按此格式生成）：
- `feat: 添加用户登录功能`
- `fix: 修复首页白屏问题`
- `refactor: 重构请求模块`
- `chore: 更新依赖版本`

### 查看历史
```bash
git log --oneline   # 一行一条记录，方便浏览
```

### 回退操作
```bash
# 回退到上一个提交（保留当前修改在工作区）
git reset --soft HEAD~1

# 彻底回退到上一个提交，丢弃所有修改（谨慎！）
git reset --hard HEAD~1

# 回退单个文件到上次提交状态
git checkout -- 文件名
```

> **AI 项目专用技巧**：如果不确定该用什么命令，直接告诉 AI：  
> “我想回到今天下午 3 点那个能正常运行的版本，帮我执行 git 命令。”

### 忽略文件
在项目根目录创建 `.gitignore` 文件，列出不需要版本管理的文件/夹（如依赖包、构建产物、环境变量文件）。可让 AI 根据技术栈自动生成一份基础版本。

## 六、远程仓库的使用

### 1. 创建远程仓库
- **GitHub**（https://github.com）或 **Gitee/码云**（https://gitee.com）注册账号后新建仓库。
- 仓库名与本地项目名保持一致，默认设为**私有**。
- 不要勾选 “Initialize this repository with a README”（因为本地已有项目）。

### 2. 关联远程并推送
```bash
# 关联远程仓库（二选一，或同时配置两个）
git remote add origin https://github.com/用户名/项目名.git
git remote add gitee https://gitee.com/用户名/项目名.git

# 推送本地代码到远程（首次推送需 -u 指定上游）
git push -u origin main
```

### 3. 日常同步
```bash
git push            # 将本地新提交推送到远程
git pull            # 拉取远程更新（多人协作或换电脑时使用）
```

### 4. 克隆已有仓库到本地
```bash
git clone https://github.com/用户名/项目名.git
```

## 七、隐私与安全：哪些文件不该提交和公开

### 绝对不该提交的
- 包含密钥、密码的配置文件（`.env`、`credentials.json` 等）
- 自动生成的依赖目录（`node_modules/`、`vendor/`）
- 构建产物（`dist/`、`build/`）
- 操作系统或 IDE 的临时文件（`.DS_Store`、`.vscode/` 视情况而定）
- 大型二进制文件（除非使用 Git LFS）

### 开源时格外注意
- **不要公开**：商业计划、内部规划、真实用户案例、Agent 宪法中涉及策略的部分、立项文档里的敏感信息。
- **可以公开**：代码、README、使用说明、贡献指南、开源许可证、非敏感的框架规范。
- **推送前检查**：让 AI 列出本次即将推送到远程的文件清单，人工确认无敏感内容后再推送。
  > 对 AI 说：“我准备推送，请列出所有将要推送到远程仓库的文件，并标注其中是否包含可能敏感的文档。”

### 仓库权限设置
- 个人项目或未准备公开 → **Private（私有）**
- 决定开源 → 先清理敏感信息，再改为 Public

## 八、将 Git 习惯写入 Agent 宪法

将以下规则加入项目宪法，可有效防止 AI 连续改动导致项目崩溃：

```markdown
## 版本管理规则
- 每完成一个可运行的功能阶段，必须执行 git add 和 git commit，提交信息格式为 `<type>: <简述>`。
- 大范围重构或删除文件前，必须确认当前工作区干净且已有最近提交。
- 如果任务导致项目无法正常运行，应主动建议回退到上一个提交，而不是继续修补。
- 推送远程前，必须列出新增/修改文件清单，经用户确认后执行。
```

## 九、常见问题速查

| 问题 | 解决方案 |
|------|----------|
| AI 改乱了但还没提交，怎么恢复？ | `git checkout -- 文件名` 丢弃单个文件修改；或 `git stash` 暂存修改后再做打算。 |
| 提交后觉得不满意，想撤销这次提交？ | `git reset --soft HEAD~1`（保留修改） 或 `git revert HEAD`（生成反向提交，更安全）。 |
| 忘了提交，AI 把文件删了怎么办？ | 试试 `git reflog` 查看所有操作记录，找回丢失的提交。可以请 AI 辅助操作。 |
| 不知道当前状态是否“干净”？ | 执行 `git status`，若显示 “nothing to commit, working tree clean” 即为干净。 |
| 怎么让 AI 帮我写提交信息？ | 在完成一个阶段后，对 AI 说：“总结一下你刚才改了什么，用 git commit 格式写一条提交信息。” |

## 十、总结行动清单

开始正式让 AI 写项目代码前，请先完成：

- [ ] 安装 Git 并配置好用户名和邮箱
- [ ] 在项目根目录执行 `git init`，并创建 `.gitignore`
- [ ] 将“阶段提交”规则写入 Agent 宪法
- [ ] 完成项目初始化后就做第一次提交
- [ ] 在 GitHub 或 Gitee 创建私有远程仓库并关联
- [ ] 首次推送前，让 AI 列出文件清单并确认隐私
- [ ] 此后每次 AI 稳定完成一个小目标，就提交并推送

---

> Git 并不复杂，你不需要精通所有命令。只需记住：**让 AI 大改之前先存档，出问题就回退，阶段成果及时推送备份。** 这套简单的流程，能让你在 AI 编程这条路上少掉坑、不白干。
