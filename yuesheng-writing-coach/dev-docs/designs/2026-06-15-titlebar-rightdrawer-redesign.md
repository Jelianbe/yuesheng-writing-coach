## 2. 整体布局

### 2.1 三分栏 + 视觉 header 层

```
┌─────────────┬──────────────────────────┬──────────────────────────────┐
│ 月笙        │                          │ [标签1][标签2][＋] [⤢][─][□][✕]│ ← 三个 header 区（同背景色，视觉连通）
├─────────────┤                          ├──────────────────────────────┤ ← 深色分割线（全宽，各栏跟随宽度）
│ [对话] [项目]│                          │ [项目/会话标签层]             │
│             │    中间栏                │                              │
│  左侧栏     │    (对话区)              │  右侧栏内容                  │
│  SessionList│                          │  - 有工具 → 展示内容         │
│  /          │    无 header             │  - 无工具 → 工具网格         │
│  WorkTree   │                          │                              │
│  Panel      │                          │                              │
└─────────────┴──────────────────────────┴──────────────────────────────┘
```

**核心规则：**
- 三分栏是**独立窗口模型**（不是叠加覆盖），共同挤占屏幕
- 三个栏各自拥有独立的 header 区
- 三个 header 区共享同一背景色，底部全宽深色分割线，视觉上形成"header 层"效果
- header 区始终存在（不随栏收起/展开消失），只是宽度变化
- 所有栏都有 min/max 宽度限制
- `[─][□][✕]` 为窗口控制键，**窗口级独立渲染**（`position: fixed` + 最高 z-index），不嵌套在任何栏的 DOM 中。视觉上位于右侧栏 header 最右端，与 `[⤢]` 形成连续序列

### 2.2 各栏宽度限制

| 栏 | 默认 | 最小 | 最大 | 可拖拽 | header |
|:---|:---:|:---:|:---:|:------:|:------|
| **左侧栏** | 240px | 180px | 380px | ✅ | `月笙 [▶]`（收起态独立悬浮，展开态在 header 右端） |
| **中间栏** | flex:1 | 400px | 100% | ❌ | 右上浮动 `[＋][⚙]`（对齐位置随右侧栏状态变化） |
| **右侧栏** | 420px | 320px | 900px | ✅ | `[标签...][＋]` 左 / `[⤢][─][□][✕]` 右 |

**收起/展开行为：**
- **左侧栏收起** → 左侧栏完全隐藏（宽度 0），header 消失；`月笙[▶]` 独立悬浮在左上角，[▶] 为展开入口；中间栏自动向左扩展
- **左侧栏展开** → 左侧栏 header 显示 `月笙`（左）和 `[▶]`（右），[▶] 为收起入口
- **右侧栏收起** → 右侧栏内容区隐藏，header 区保留；`[＋][⚙]` 在中间栏右上靠右对齐，`[⤢][─][□][✕]` 在右侧 header；视觉上形成 `[＋][⚙][⤢][─][□][✕]` 序列，**无窄条**
- **右侧栏展开** → `[＋][⚙]` 在中间栏右上与右侧栏左边界对齐（向左偏移）；右侧栏 header 显示 `[标签...][＋]` 左 + `[⤢][─][□][✕]` 右，内容区展开
- `[─][□][✕]` 窗口级独立渲染（`position: fixed`），始终位于窗口右上角，不随任何栏的收起/展开变化
- Header 跟随各栏宽度变化，不独立浮动

### 2.3 各栏 header 内容

| 栏 | header 左 | header 右 | 可见性 |
|:---|:---------|:---------|:-------|
| 左侧栏 | `月笙` | `[▶]` | `月笙` 始终可见（收起态随品牌图标准入，展开态在 header 左端）；`[▶]` 始终可见（收起态在月笙右侧做展开入口，展开态在 header 右端做收起入口） |
| 中间栏 | （空，无 header） | `[＋] [⚙]` | 始终可见。**右侧栏展开时**：与右侧栏左边界对齐（向左偏移）；**右侧栏收起时**：靠右对齐 |
| 右侧栏 | `[标签1] [标签2] [＋]` | `[⤢] [─] [□] [✕]` | header 始终可见。**收起态**：内容区隐藏，header 保留，`[→]` 前无标签；**展开态**：标签出现，内容区展示 |

### 2.4 按钮样式规则

| 按钮 | 位置 | 样式 | 行为 |
|:----|:----|:-----|:-----|
| `[▶]`（左侧栏） | 收起态：月笙右侧独立悬浮；展开态：header 右端 | 品牌色，hover `var(--accent)` | 收起态点击展开左侧栏；展开态点击收起左侧栏。同一 toggle 图标，位置/含义随状态变化 |
| `[＋]`（中间栏） | 中间栏右上（左） | `var(--text-secondary)`，hover `var(--accent)` | 新建对话 |
| `[⚙]` | 中间栏右上（右邻 ＋） | `var(--text-secondary)`，hover `var(--accent)` | 打开设置 |
| `[⤢]` | 右侧栏 header 右端（左邻窗口三键） | `var(--text-secondary)`，hover `var(--accent)` | 右侧栏内容区展开/收起 |
| `─` | 窗口右上角（窗口级独立渲染，视觉上位于右侧栏 header 最右端） | 独立配色，动态变色 | 最小化窗口 |
| `□` | 同上 | 同上 | 最大化/还原 |
| `✕` | 同上 | 同上 | 关闭窗口 |
| 标签 | 右侧栏 header 左端（仅展开态） | 活跃 `var(--accent)`+白，非活跃 `var(--bg-subtle)` | 切换工具视图 |
| `[＋]`（右侧栏） | 标签区末尾（仅展开态） | 同标签样式 | 展开未打开工具列表 |

**窗口三键（─ □ ✕）配色规则：**
- `[─][□][✕]` 独立于右侧栏内容渲染，始终存在
- 右侧栏展开态 → 浅色背景 + 深色图标
- 右侧栏收起态 → 深色背景 + 浅色图标
- 展开和收起之间做过渡动画

### 2.5 Header 高度 & 分割线

- 三个 header 区高度统一：40~48px
- 背景色：`var(--bg-header)`（所有 header 区共用）
- 底部深色分割线：`1px solid var(--border)`，全宽贯穿三个 header 区
- 各栏宽度变化时，分割线跟随各栏宽度

### 2.6 Z-index 层次

```
z-index 自上而下：
┌──────────────────────────────────────────────┐
│ 右上: [─][□][✕]（窗口级，position: fixed）   │  最高层 — 始终固定，不可覆盖
├──────────────────────────────────────────────┤
│ 左上: ⦿月笙[▶]（收起态独立悬浮）            │  第二层 — 始终可见
├──────────────────────────────────────────────┤
│ 右上: [⤢]（右侧栏 header）                   │  第三层 — 始终可点
│ 左上: 月笙（左侧栏 header）＋ [▶]（右端）    │  同层次
├──────────────────────────────────────────────┤
│ 三栏内容区（左侧栏 tab+内容 / 中间栏 /       │  基础层
│ 右侧栏标签层+内容层）                        │
└──────────────────────────────────────────────┘
```

**说明：**
- `[─][□][✕]` 位于最高 z-index 层，窗口级 `position: fixed`，不嵌套在任何栏的 DOM 中。始终位于窗口右上角，不随任何栏的收起/展开隐藏或移动
- `⦿月笙` 品牌图标独立于三分栏体系之外，位于第二 z-index 层
- 收起态时 [▶] 紧邻月笙右侧，作为展开入口；展开态时 [▶] 在 header 右端
- `⦿月笙[▶]` 收起态独立悬浮，展开态融入左侧栏 header（月笙在左端，[▶] 在右端）
- 为后续 Solo（纯写作）/ IDE（全功能）两种工作模式切换预留
- 左侧栏和右侧栏 header 在同一 z-index 层

## 3. 左侧栏（本轮关键改动）

### 3.1 收起态

**原有设计：** 44px 窄条（PanelLeftOpen 汉堡图标 + 分隔线 + [＋] 新建对话按钮）。
**改为：完全隐藏，无窄条。**

```
收起态下内容区展示：
┌──────────────────────────┬────────────────────────┐
│   ⦿月笙[▶]              │           [＋][⚙]       │
├──────────────────────────┴────────────────────────┤
│                      中间栏                       │
│                   （100% 可用宽度）                 │
└───────────────────────────────────────────────────┘
```

**收起态布局规则：**
- 左侧栏整体隐藏（宽度 0），其 header 随之消失
- `⦿月笙[▶]` 独立悬浮在左上角最高 z-index 层
- `[▶]` 在月笙右侧，点击展开左侧栏（展开态时 [▶] 移到 header 右端作为收起入口）
- 中间栏自动向左扩展填充
- 右侧栏展开时 `[＋][⚙]` 与右侧栏左边界对齐（向左偏移）；右侧栏收起时靠右对齐

行为：
- **展开入口**：点击 `[▶]`（收起态位于月笙右侧）→ 左侧栏带动画展开
- 展开动画：`width 280ms cubic-bezier(0.25, 1, 0.5, 1)`
- 展开后 `月笙` 融入左侧栏 header 左端，`[▶]` 移到 header 右端成为收起入口

### 3.2 展开态

```
┌─────────────────────────┐
│ 月笙               [▶]  │  ← header（深色背景 + 底部分割线）
├─────────────────────────┤
│ [对话]    [项目]          │  ← Tab 切换区
├─────────────────────────┤
│                         │
│ 对话 Tab: SessionList   │  ← 内容区
│ 项目 Tab: WorkTreePanel │
│    + 作品/章节树         │
│                         │
└─────────────────────────┘
```

- `月笙` 在 header 左端（收起态独立悬浮时带 [▶]，展开态 header 左端 仅品牌名）
- `[▶]` 在 header 右端，点击收起左侧栏（不留窄条）
- `[对话] [项目]` 两个 Tab 切换下方内容
- 保持现有行为：对话 → 会话列表，项目 → 作品/章节树
- `[▶]` 是同一个 toggle 图标，收起态在月笙右侧（展开入口），展开态在 header 右端（收起入口）

**拖拽手柄：**
- 左侧栏右边缘（与中间栏的分界线）
- hover 时高亮显示拖拽条
- 可拖拽范围：180px ~ 380px（默认 240px）

## 4. 右侧栏

### 4.1 收起态

右侧栏内容区完全隐藏，header 区保留。`[＋][⚙]` 在中间栏右上靠右对齐，`[⤢][─][□][✕]` 在右侧 header。视觉上形成连续序列。**无窄条。**

```
收起态布局：
┌──────────────────────────────────────────────────┐
│     ⦿月笙[▶]              [＋][⚙][⤢][─][□][✕]    │  ← header 区（全宽）
├──────────────────────────────────────────────────┤
│                      中间栏（全宽）                │  ← 右侧内容区隐藏
│                                                   │
└──────────────────────────────────────────────────┘
```

行为：
- **展开入口**：点击 `[⤢]` → 右侧栏内容区展开
- 右侧栏展开后，`[＋][⚙]` 与右侧栏左边界对齐，`[⤢][─][□][✕]` 保持在 header 右端
- `[─][□][✕]` 始终存在，不随收起/展开变化
- 收起态下右侧 header 区不显示标签（仅展开态显示）

### 4.2 展开态 — 三区域

```
┌────────────────────────────────────────────┐
│ [标签1] [标签2] [＋]          [⤢] [─] [□] [✕] │  ← Header 区
│  ← 左对齐（有内部滚动）        固定右对齐 →  │
├────────────────────────────────────────────┤
│ [tab1] [tab2]                             │  ← 标签层（打开的会话/功能 tab）
├────────────────────────────────────────────┤
│                                            │
│  - 已有工具内容：正常展示                  │  ← 内容层
│  - 首次打开新工具：展示工具图标网格         │
│    （图标入口替代当前图标条 navBar）        │
│                                            │
└────────────────────────────────────────────┘
```

**Header 区布局规则：**
- 标签区（左半）：`[标签1] [标签2] [＋]` — 左对齐，仅展开态显示
- 操作区（右半）：`[⤢] [─] [□] [✕]` — 右对齐，固定右上角
- 标签溢出时：标签区内部 `overflow-x: auto`，4 按键不参与滚动
- `[＋]`（标签区末尾）：点击展开「未打开工具」下拉菜单

**标签层规则：**
- 类似于 VSCode 的打开 tabs
- 用户可在多个会话/功能间切换
- 支持关闭单个标签（× 按钮 hover 显示）

**内容层规则：**
- 有工具内容 → 正常展示
- 首次打开新工具（无内容） → 展示工具图标网格

### 4.3 拖拽缩放

- 缩放 handle 放在**右侧栏左边缘**（中间栏与右侧栏的分界线）
- 约 4px 不可见区域，hover 时显示拖拽条
- 沿用现有 mousedown/mousemove/mouseup 方案
- 缩放范围：320px ~ 900px（默认 420px）

## 5. 交互行为

### 5.1 展开/收起动画

| 栏 | 方向 | 动画 | 参数 |
|:---|:----|:-----|:----|
| 左侧栏 | 展开/收起 | `width` | `280ms cubic-bezier(0.25, 1, 0.5, 1)` |
| 右侧栏 | 展开/收起 | `width`（内容区） | `200ms ease-out` |

- Header 区不参与动画（直接跟随宽度变化）
- 中间栏宽度自适应跟随
- `[▶]` 在收起态与展开态之间的位置过渡做动画
- 窗口三键（─ □ ✕）在展开/收起切换时做颜色过渡动画

### 5.2 窗口控制 IPC

```typescript
// renderer → main: 通过 ipcRenderer.send 调用
// 通道格式遵循 domain:action 规范
ipcRenderer.send('window:minimize');
ipcRenderer.send('window:maximize');
ipcRenderer.send('window:close');
```

- `frame: false` 下需要自己处理窗口拖拽
- 通过窗口级 `[─][□][✕]` 组件按钮触发 IPC
- `[─][□][✕]` 组件不依赖任何栏的 DOM，在 `AppShell` 层或 `WindowControls` 独立组件中注册

## 6. 样式规则

### 6.1 Header 区

- 三个 header 区高度：40~48px（统一）
- 背景色：`var(--bg-header)` 或深色主题色（所有 header 区共用）
- 底部深色分割线：`1px solid var(--border)`，全宽贯穿

### 6.2 窗口三键（─ □ ✕）

- 窗口级独立渲染（`position: fixed; top: 0; right: 0` + 最高 z-index），不嵌套在任何栏的 DOM 中
- 视觉上位于右侧栏 header 最右端（右侧栏需预留 padding-right 避免重叠）
- 独立配色方案，不继承各栏背景色
- 展开态：浅色背景 + 深色图标
- 收起态：深色背景 + 浅色图标
- 过渡动画：`color 150ms ease, background 150ms ease`
- 通过 Zustand store（`useUiLayoutStore`）监听右侧栏状态实现颜色切换

### 6.3 ⤢ 键

- 颜色：`var(--text-secondary)`，与 `[＋] [⚙]` 统一
- hover：`var(--accent)`
- 过渡：`color 120ms ease`
- 始终位于右侧栏 header 最右端，左邻窗口三键 `[─][□][✕]`

### 6.4 右侧栏标签样式

- 活跃标签：底色 `var(--accent)` + 白色文字
- 非活跃标签：底色 `var(--bg-subtle)` + `var(--text-secondary)`
- 标签关闭按钮（×）：默认隐藏或半透明，hover 标签时显示

### 6.5 [＋] [⚙]（中间栏）

- 颜色：`var(--text-secondary)`
- hover：`var(--accent)`
- 过渡：`color 120ms ease`

### 6.6 [▶]（左侧栏 toggle）

- 收起态（月笙右侧）：品牌色，hover `var(--accent)`
- 展开态（header 右端）：`var(--text-tertiary)`，hover `var(--accent)`
- 过渡：`color 120ms ease, transform 120ms ease`

## 9. 后续设计任务（已敲定方向，暂不实现）

月笙 [▶]

### 9.2 训练工房

**来源：** Issue #6 — "当前训练工房内容依然简陋，后续将训练作为独立窗口覆盖中间对话栏"

**背景：** 当前训练工房只有基础页面框架，内容空洞。需要作为独立模块建设。

**方向：**
- 从左侧栏田字格「训练」格进入 → 中间栏切换为训练界面
- 三层递进结构：
  1. **技法分类网格**（2×3）：展示写作技法大类（人物塑造、情节构建、对话描写、环境渲染、修辞运用、风格模仿）
  2. **技法列表**（点击分类后）：展示该分类下具体技法条目，标注掌握进度（待学/进行中/已掌握）
  3. **教学对话**（点击技法后）：进入 AI 针对特定技法的教学对话
- 右侧栏可弹出配套训练素材或练习模板
- 训练数据来源：`resources/config/training-library.json`（29 条）
- 需要 DB schema 支持训练进度持久化存储

### 9.3 创作工具重构

**来源：** Issue #7 — "创作工具窗口内容需要重构，当前实际功能已被覆盖"

**背景：** 现有的创作工具面板功能已被诊断引擎等新功能取代，存在价值不足。

**方向：**
- 重新定义创作工具的定位 — 专注「写作辅助」而非「功能聚合」
- 潜在模块：
  - **字词统计**（实时统计当前作品字数/章字数，目标设定）
  - **写作目标**（每日字数目标，进度条）
  - **写作时间线**（记录每次写作会话时长/字数，趋势图）
  - **随手记**（轻量笔记面板，与当前章节关联）
- 需要和训练工房共用右侧栏工具框架

### 9.4 模板填充系统（AI 驱动）

**来源：** Issue #5 — "模板内容涉及存在缺陷，更多是发送对话但无实际内容引用"

**背景：** 当前模板系统只是把模板文本发送到对话中，没有结构化协作能力。

**方向：**
- 用户在对话中表达需求（如"帮我构筑世界观"、"设计一个 OC"）
- AI 识别意图 → 右侧栏弹出对应结构化模板（世界观模板/角色模板/AI 模板/场景模板）
- AI 与用户协作填写模板字段：
  - AI 根据上下文生成预填内容（用户可接受或修改）
  - 用户手动编辑字段
  - 右侧栏实时预览填写结果
- 完成后将结构化数据插入作品/章节
- 涉及：右侧栏新模板模块、AI 结构化数据写入能力、模板管理机制

### 9.5 MessageInput 重构

**来源：** 布局设计过程中的用户体验优化方向

**方向：**
- 输入框占满整个底部区域（当前 MessageInput 在视觉占比上偏小）
- 模板 pill 缩小移至左下角
- 发送按钮移至右下角，Enter 键联动发送
- 提升输入空间占比，减少不必要的视觉干扰

### 9.6 排版样式设置 + 排版联动

**来源：** Issue #10 + #11 — "撤销排版无作用"、"需增加排版格式设置按键与排版联动"

**方向：**
- SettingsPopover 新增「排版样式」选项

- 「撤销排版」应真正恢复到排版前的文本状态（当前未实现该功能）
