# 月笙写作教练项目原则

## 核心定位
1. **教练不代笔** - 不替用户写、不给答案、帮用户看清问题
2. **诊断基于规则** - 诊断引擎使用规则+信号权重识别病症，不依赖 AI 生成诊断结果
3. **用户主权优先** - 用户指令拥有最高优先级（R-009）

## 技术选型
4. **Electron + TypeScript + React** - 桌面应用主技术栈
5. **Zustand 状态管理** - 轻量状态管理，配合 electron-store 做配置持久化
6. **SQLite 本地存储** - better-sqlite3 用于会话、诊断、用户数据存储
7. **DPV4 模型** - 用户自备 API Key，不内置模型服务

## 架构设计
8. **诊断引擎在主进程** - 避免渲染进程卡顿，保证响应性
9. **IPC 通道命名规范** - 使用 `domain:action` 格式（如 `chat:send`、`diagnosis:analyze`）
10. **配置外置** - 所有信号权重、阈值必须外置到 JSON 配置文件，禁止硬编码（R-014）

## 代码质量
11. **类型安全** - 禁止使用 `any`，所有 API 和数据流必须有明确类型定义
12. **测试覆盖** - 诊断引擎 80%、IPC 处理器 90%、Store 70%、UI 组件 60%
13. **原子化提交** - 每次提交只解决一个问题，便于回滚和审查（R-001）
14. **逻辑解释** - 复杂算法、业务规则必须有清晰注释（R-005）

## 开发流程
15. **规范驱动开发** - 先写规范文档，再写代码（Spec-Driven Development）
16. **假设驱动** - 算法/功能改动前提出假设并设计验证方案（R-012）
17. **DoD 准出标准** - 每个阶段开始前定义完成标准，至少 3 条可验证标准（R-004）
18. **回退机制** - 每次改动前确保有明确的回退路径（R-006）

## 文档管理
19. **文档同步** - 代码变更必须同步更新文档（R-008）
20. **版本控制** - 所有文档遵循 `<类型代码>_<主题>_V<主版本>.<次版本>.md` 命名（R-017）
21. **记忆强化** - 关键决策、重要状态变更必须持久化记录（R-011）

## 安全与隐私
22. **API Key 安全** - 用户 API Key 存储在 electron-store，提醒用户风险
23. **诊断报告权限** - 诊断报告仅系统内部可见，用户端不可访问
24. **数据本地化** - 所有用户数据本地存储，不上传云端

## 用户体验
25. **流式输出** - AI 回复使用流式输出，提升响应感知速度
26. **诊断面板** - 会话结束后自动触发诊断，在侧边栏展示结果
27. **训练任务推荐** - 根据诊断结果推荐个性化训练任务
