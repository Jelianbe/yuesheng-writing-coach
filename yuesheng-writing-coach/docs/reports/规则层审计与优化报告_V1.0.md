## 四、优化方案

### 4.1 保留不变（8条）

| 规则 | 理由 |
|------|------|
| R-003 里程碑节点管理 | 与 R-004 配合良好 |
| R-004 准出标准DoD | 必要的过程检查 |
| R-005 逻辑解释 | 有实际指导意义 |
| R-009 用户主权 | 最高优先级保障 |
| R-015 AI协作规范 | 当前高频使用 |
| R-016 Git提交规范 | 标准行业实践 |
| R-017 文档管理规范 | 文档体系需要 |

### 4.2 合并精简（合并2条为1条）

**R-001（原子化） + R-010（最小化范围） → R-001 变更最小化原则**

合并后保留核心4个检查点：
1. 每次变更只解决一个问题
2. 只修改必要的文件
3. 不引入不必要的复杂度
4. 变更前后测试通过

### 4.3 简化（3条）

| 规则 | 优化方式 |
|------|---------|
| R-006 回退机制规范 | 从 116 行 → ~40 行：仅保留 L0 快照标准 + P0 回退条件 |
| R-007 双向绑定 | 从 64 行 → ~40 行：保留核心原则，移除尚未实现的训练任务场景 |
| R-012 假设驱动开发 | 从 78 行 → ~40 行：保留 5 字段核心模板，移除决策矩阵和冗长示例 |
| R-011 记忆强化 | 从 58 行 → ~30 行：收敛为关键决策日志方式，移除4个目录要求 |

### 4.4 标注为"当前阶段暂不启用"（3条）

| 规则 | 说明 |
|------|------|
| R-002 依赖锁定机制 | 在团队扩充至 3 人以上时启用 |
| R-013 测试覆盖率要求 | 配备基础设施（lint、typecheck、testing-library）后启用 |
| R-014 配置外置规范 | 扫描脚本就绪、config 目录创建后启用 |

### 4.5 修复引用问题（R-013 / R-014）

在 `package.json` 的 scripts 中添加空桩脚本，确保 `npm run typecheck` 和 `npm run lint` 可执行。
