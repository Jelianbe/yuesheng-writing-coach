## 二、核心矛盾与化解

### 2.1 用户提出的核心矛盾

第 1 轮选择中,用户同时选择了两个看似冲突的约束:

- **教学半透明**(约束 7):用户不应被术语打扰
- **进度是核心价值**(约束 8):进度反馈必须显眼到用户能感知

这两个约束在**单层界面**里无法同时满足 —— 半透明要求藏,核心价值要求露。

### 2.2 化解:分层架构

**渐进展开**(约束 9)+ **用户显式声明**(约束 10)的组合,恰好化解了这个矛盾:

| 层级 | 教学显隐 | 进度反馈形态 |
|:---|:---|:---|
| **新手层** | 完全半透明,用户只感受对话 | 隐藏(用户还在写第一个字,没有进度可言) |
| **进阶层** | 半透明(对话仍是主舞台) | 显式可见(用户主动想看自己走了多远) |

**同一个产品,不同层级,两个约束各自得到满足。** 这就是为什么单层 spec 和单层样板都让用户"勉强满意但不满足" —— 它们都试图用一个界面同时满足两个矛盾约束。

## 三、产品定义(一句话版)

> **月笙是一个分层的写作教学软件。用户在 Onboarding 时显式声明自己的学习阶段,界面随之展开。新手层只有对话和教练引导,让用户安心写下第一个字;进阶层解锁技法库、训练、诊断详情、进度档案,支持主动学习。所有层级共享同一个对话内核和教学状态机,差异只在"界面向用户暴露多少教学基础设施"。**

---

## 四、分层架构详解

### 4.1 两层划分(初步设计)

> **设计原则**:层级数量要克制。两层是下限(否则无法服务多阶段),三层可能过重。
> 初步设计为两层,后续可根据实际使用反馈增加中间层。

#### Layer 0:新手层(暂命名"起步")

**目标用户**:
- 第一次写作的人
- 写过一点但很不自信,需要从基础引导的人
- 符合用户教学哲学:"先让用户写下第一个字"

**界面对用户暴露的内容**:

| 区域 | 暴露内容 | 说明 |
|:---|:---|:---|
| 左栏 | 会话列表(只有对话,无项目树) | 新手不需要管理项目结构 |
| 中间栏 | 对话区 + 输入区 + 三岔路口(空状态) | **唯一的主舞台** |
| 中间栏 header | 项目名 + 教学状态 badge(简化版:"学习中"/"梳理中") | 不显示 0/N 数字,不显示阶段术语 |
| 右栏 | **默认收起或极简** | 新手用不到工具集合 |
| 态度灯 | 暴露 | 用户可调教练态度 |
| 设置 | API Key + 态度偏好 | 基础配置 |

**刻意隐藏的内容**(新手不需要):
- ❌ 技法目录(看不懂,会被吓到)
- ❌ 训练入口(还没到主动学习阶段)
- ❌ 诊断详情/症候列表(术语太多)
- ❌ 能力画像/成长曲线(还没有数据)
- ❌ 教学笔记树(还没产出物可沉淀)
- ❌ 0/N 进度数字(还没有进度可言)

**教学如何发生**:
- 完全在对话中,教练半透明引导
- 用户粘贴作品 → 教练在回复中自然诊断(不暴露症候术语)
- 教练在对话中布置小练习(不叫"训练",叫"我们试试改这一段")
- 用户改完 → 教练反馈 → 自然进入下一个引导

**升级到进阶层的触发**:
- 用户在设置里手动切换
- 或教练在对话中,判断用户已经成熟后,**温和建议**:"你现在已经掌握了基础,要不要解锁更系统的训练库?" → 用户同意 → 切换

---

#### Layer 1:进阶层(暂命名"研习")

**目标用户**:
- 有一定经验,想系统提升的写作者
- 主动想学特定技法的用户
- 成熟写作者,精准求教

**界面对用户暴露的内容**:

| 区域 | 暴露内容 | 说明 |
|:---|:---|:---|
| 左栏 | 会话列表 + 项目树(含章节) | 支持多项目管理 |
| 中间栏 | 对话区 + 输入区 + 引用区 | 对话仍是主舞台,但支持文本片段引用 |
| 中间栏 header | 项目名 + **教学状态 badge(完整版,含 0/N)** | 进度可见,满足"核心价值" |
| 右栏 | **工具集合**(技法目录/训练/教学笔记/进度档案/学习日志/作品) | V6.2 样板的核心价值区 |
| 态度灯 | 暴露 + 锁定 | 同新手层 |
| 设置 | API Key + 态度偏好 + **学习模式切换** | 这里是层级切换入口 |

**教学如何发生**:
- 对话仍是主入口(长会话为主)
- **额外支持主动学习**:用户可主动从技法目录选技法 → 建训练会话
- 教练在对话中也会更直接地引用症候术语(因为用户已经能理解)
- 进度/诊断/成长曲线对用户可见

**这一层基本对应 V6.2 样板的现状**,但需要修正:
- 中间栏 header 要加 0/N 进度(样板目前缺失)
- 训练入口要做成 spec §6.3 的主动作(样板目前是被动筛选)
- 教学笔记树要补齐(样板目前是死按钮)

---

### 4.2 两层共享的内核

不管在哪个层级,以下东西**不变**:

| 共享内核 | 说明 |
|:---|:---|
| 对话引擎 | 同一个 chat:send + 流式回复 |
| 教学状态机 | 同一个 TeachingState + 状态流转 |
| 诊断能力 | 教练都在后台诊断,差异只在"诊断结果是否对用户可见" |
| 态度档位 | 同一套 doubao/yuesheng/direct(待 G-05 决策统一) |
| 项目容器 | 同一个 project → session 结构 |
| 后端 IPC | 同一套合约,差异只在"前端调用哪些" |

**关键设计**:层级切换**不改后端行为**,只改前端 UI 暴露面。教练(AI)的教学深度由教学状态机驱动,**不直接由 UI 层级驱动**。这意味着一个新手层用户如果作品质量很高,教练依然会给他高质量教学;只是界面不暴露术语和工具。

---

### 4.3 层级切换机制

**主入口**:设置面板的"学习模式"切换(用户显式声明)。

**切换的副作用**:
- 从新手层 → 进阶层:界面展开,右栏工具出现,header 进度出现。**对话历史和项目数据完全保留**。
- 从进阶层 → 新手层:界面收缩,右栏工具隐藏。**数据不丢**,只是不显示。

**Onboarding 时的初始选择**:

用户第一次配置完 API Key 后,出现一个**轻量引导**(不是弹窗,是中间栏内容):

```
┌─────────────────────────────────────────────────┐
│ 欢迎使用月笙。在开始之前,告诉我你的情况:        │
│                                                 │
│  🌱 我刚起步,想从零开始                          │
│     —— 教练会陪你写下第一个字                    │
│                                                 │
│  📝 我有一些经验,想系统提升                      │
│     —— 解锁技法库、训练和完整教学工具            │
│                                                 │
│  ✍️ 我写了很多,想精准求教                        │
│     —— 同上,教练会直接用专业术语和你对话        │
└─────────────────────────────────────────────────┘
```

- 选 🌱 → 新手层
- 选 📝 或 ✍️ → 进阶层

**技术对接**:
- `session:isNewUser`(后端已存在)判断是否首次 → 触发引导
- 用户选择存到 config(需扩展 config 合约,加 `learningLayer: 'starter' | 'advanced'`)
- `OnboardingAnalyzeRequest.baseline.experience`(后端已存在)可承载这个选择

## 五、这个架构如何解决之前的所有问题

| 之前的问题 | 本架构如何解决 |
|:---|:---|
| 新手被完整教学操作台吓到 | 新手层只暴露对话,工具全部隐藏 |
| 进阶者找不到训练入口 | 进阶层有独立的训练主动作入口(spec §6.3) |
| 进度数字打扰长会话 | 新手层无进度;进阶层进度在 header 但用户已主动选择看到 |
| 教学半透明 vs 进度核心价值的矛盾 | 新手层半透明,进阶层显式,各得其所 |
| 教学术语对新手不友好 | 新手层教练回复不暴露术语(由 prompt 控制) |
| V6.2 样板"勉强满意" | 样板本质是"进阶层的实现",缺的是新手层 + 层级切换 |

## 六、与现有资产的关系

### 6.1 V6.2 样板的定位

**V6.2 样板 = 进阶层的视觉基线。**

- 样板的视觉皮肤(配色/token/微交互)✅ 全部保留
- 样板的三栏布局 ✅ 保留
- 样板的右栏工具集合 ✅ 作为进阶层右栏的基础
- 样板需要补的:中间栏 header 的 0/N 进度、训练主动作入口、教学笔记树

### 6.2 后端的关系

**后端几乎不需要为分层架构做改动**:
- IPC 合约全部沿用
- 教学状态机不变
- 唯一需要新增:`config` 里加 `learningLayer` 字段(小改动)

### 6.3 spec 的关系

spec §4 的教学理念(诊断/教学/精通门控/反馈回路)**全部保留**,只是从"单层"改为"分层呈现"。

spec 需要修订的:
- §4.2 进度条位置:从"中间栏 header 常驻"改为"仅进阶层可见"
- §6.1 左栏结构:增加层级差异说明
- §4.8 右栏定位:明确"新手层默认收起"

## 七、需要用户进一步确认的开放问题

这个架构已经比较完整,但有几个细节我无法替你决定,需要你拍板:

### Q1:新手层是否完全不要右栏?

- 选项 A:新手层**完全没有右栏**(两栏布局:左栏会话 + 中间栏对话)
- 选项 B:新手层右栏**默认收起,但保留一个入口**(比如设置/作品),用户主动展开可用

### Q2:教练建议升级层级时,是"建议"还是"自动切换"?

- 选项 A:教练只**建议**,切换必须用户手动操作
- 选项 B:教练建议 + 用户同意后**自动切换**
- 选项 C:教练判断成熟后**直接切换**(不推荐,违反"用户显式声明"原则)

### Q3:层级是否可以更细?(未来扩展)

当前是两层。未来是否考虑三层(新手/进阶/专业)?还是永远保持两层?
