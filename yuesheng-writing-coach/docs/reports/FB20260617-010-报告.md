## 7. 经验教训

### 7.1 命名反模式识别
- **症状**: 多个文件使用相同数字前缀
- **风险**: 数字排序失效,产生隐式依赖
- **预防**: 决策时优先使用"现状规范"或"显式新编号"而非"沿用已占用编号"

### 7.2 自定义迁移系统的脆弱性
- **优势**: 按 name 字符串去重,允许编号重复
- **劣势**: 编号去重是"宽容"而非"严格",不能阻止命名反模式
- **改进建议**: 未来可加 `migrations-loader.ts` 数字去重检测,但属于范围外

### 7.3 git mv 的可追溯性
- 优势: `git log --follow` 可查完整历史
- 优势: PR review 中显示为 rename 而非 delete+add
- 注意: 必须在 git 中操作,文件系统 mv 会丢失 git 跟踪
