## 4. 教训与防范（永久性原则）

### 4.1 核心教训

1. **警惕"假权威文档"陷阱** — 用户可能用不存在的路径测试我
2. **Read 工具会静默失败** — "CLEARED" 提示 ≠ Read 成功
3. **必须 Glob 验证** — 重要决策前必须用 Glob 确认文件存在
4. **禁止编造内容** — 不知道就说不知道, 不能"编"出 SPEC 章节
5. **reset --hard 是破坏性操作** — 必须先 backup, 必须先验证 reset 依据

### 4.2 永久性原则

#### 4.2.1 文档验证（强制）

```typescript
// R-019 防御性: 任何重要决策前必须 Glob 验证文件存在
const specFiles = await glob('**/dev-docs/designs/*.md');
if (!specFiles.some(f => f.includes('system-rewrite-spec'))) {
  throw new Error('L1 权威文档不存在, 拒绝继续');
}
```

#### 4.2.2 Read 工具失败检测

```
Read 工具返回 "Results from Read have been CLEARED" 时,
必须用 Glob 或 File 系统工具**重新验证**文件存在性。
禁止从"CLEARED"推断"Read 成功"。
```

#### 4.2.3 reset --hard 规范

| 步骤 | 操作 | 必做 |
|------|------|------|
| 1 | 备份 | `git tag v1.0.0-pre-RESET-{date}-{seq}` |
| 2 | 验证依据 | Glob 验证 reset 目标文件存在 |
| 3 | 验证恢复点 | 确认恢复点是有效状态 |
| 4 | 用户确认 | AskUserQuestion 显式确认 |
| 5 | 执行 | `git reset --hard <target>` |
| 6 | 验证 | `git log` + `git status` |

#### 4.2.4 禁止规则

- ❌ 禁止基于"读不到的文档"做 reset
- ❌ 禁止 reset 之前不验证
- ❌ 禁止 reset 之前不备份
- ❌ 禁止 reset 之前不向用户确认
- ❌ 禁止在 FB 报告中编造对比表
