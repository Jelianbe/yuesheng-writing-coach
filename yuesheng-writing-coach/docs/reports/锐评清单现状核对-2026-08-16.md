## 三、2026-08-16 现状的增量发现（旧锐评未覆盖）

1. **健康评分 0/100 与 7-15 一字不差**：30 条规则里 21 条失败的状态在 31 天里没有任何改善。四闸门禁（tsc/eslint/jest/doc-sync）全绿 + 健康体检 0 分并存，说明**门禁没有覆盖架构维度**——这是治理体系的设计缺口，不是偶发。
2. **分层违规翻倍（24 → 60 处）**：7 月锐评点名"components 直连 services/db"，现在组件层直接摸 DAO/Store 的更多了（ChapterSection→basic-dao、FileSection→file-dao、SaveToFileSheet→file-dao、ProgressReport→toast-store 等）。AGENTS.md 的"单一 Owner/目录责任表"约束在生产代码上形同虚设。
3. **39/45 skill 未被 skill-dispatcher 引用**：skill 资产层（智力资产所在）与运行时引用层脱节。这与 N-006"保留文件"决策不冲突，但至少应有一份"哪些 skill 已挂载、哪些是储备"的映射表，否则未来无人能分清死代码与储备资产。
4. **3 个新服务缺测试**：`evaluation-service.ts`、`training-input-builder.ts`、`phase-mapper-resolver.ts` 是 TRAINING-V3 之后新接入闭环的服务，健康脚本显示 `evaluation-service.ts` 无测试文件，但 `training-input-builder` 有 `design-002-e2e.test.ts`（测试命名与文件命名不一致导致健康脚本误判"缺测试"——**检测器与命名规范也需要对齐**）。
5. **依赖漏洞 16 个高危**：升级 Expo 57 引入了新的高危链（@expo/cli、metro、react-native 本体等），`npm audit` 从未清零过。
6. **权限面偏大**：`READ/WRITE_EXTERNAL_STORAGE`（API 33+ 已废弃）、`SYSTEM_ALERT_WINDOW`（弹窗权限，写作 App 无明确用途）。
7. **lint 边界规则待迁移**：eslint-plugin-boundaries 20 条规则用 v5 legacy selector 语法，v6 已发迁移指南，不迁移会在未来升级时静默失效——**分层约束目前实际只靠健康脚本，不靠 lint 门禁**。

## 四、最需要整改的 Top 清单（按 ROI，对 Flutter 新项目同样适用）

### 🔴 必须在 Flutter 新项目里避免的（教训级）

1. **"假完成"文化**：T-034 暗色模式、T-035 Alert 替换、门禁全绿 vs 健康 0 分——同一套"勾选式完成任务"模式反复出现。新项目验收标准必须是**运行时证据**（截图/实机操作），不是"commit 记录 + 自述完成"。
2. **治理文档与代码现实脱节**：宪法写了"分层禁止"，实际违规 60 处；写了"防假完成"，实际 Phase 全 ✅。新项目要么把分层约束做成**机器强制**（lint 规则/CI 检查），要么删掉写不动的宪法条文。
3. **在 P0 没跑通前不做 P2/P3 架构**：FSRS/Kappa/状态机全家桶的前车之鉴。新项目先做"写 → 评估 → 反馈 → 改"最小闭环，再加教学引擎。
4. **测试覆盖用机器保证**：DAO/Store/Hook 全空测试的教训——新项目把"覆盖率阈值"设进 CI，不允许"没测试也提交"。

### 🟡 RN 版遗留问题（若还值得处理）

1. 暗色模式：要么在 Flutter 版做对，要么在 RN 版修 Bridgeless Context 问题（RN 0.86 有 `unstable_batchedUpdates`/`createContext` 的已知坑，需查官方 issue）。
2. `bookshelf.tsx` 搜索按钮占位 + 49 处 Alert.alert：低风险收尾项。
3. 依赖高危漏洞：`npm audit fix` 后重跑四闸。
4. Android 权限瘦身：去掉 READ/WRITE_EXTERNAL_STORAGE（用 SAF/文件选择器替代）、评估 SYSTEM_ALERT_WINDOW 是否必需。
