## 3. 发现的问题 + 修复

| 编号 | 问题 | 严重度 | 修复 |
|------|------|--------|------|
| **P-1** | `project:delete` handler 返回 `{deleted: true}` 与 `ProjectDeleteResponse = void` 契约不一致 | ⚠️ 中 | `return { deleted: true }` → `return;`（void 语义）|
| **P-2** | project.handler.ts L116-117 注释仍说"外键尚未建立(RWR-P0-5 处理)"，但 RWR-P0-5 已完成 | ℹ️ 低 | 注释更新为"023_data_migration.sql 已建立, ON DELETE SET NULL 自动处理" |

### 3.1 修复详情

**P-1 修复对比**：

```ts
// 修复前 (L128)
return { deleted: true };
// → 客户端期望 void, 实际收到 { deleted: true }, TypeScript 编译通过但运行时类型错配

// 修复后 (L128)
return;  // void
// → 客户端期望 void, 实际收到 undefined, 完全一致
// → R-007 双向绑定: void 比 {deleted: true} 更精简
```

**P-2 修复对比**：

```ts
// 修复前 (L116-117)
// 注: sessions/manuscripts 的 project_id 外键尚未建立(RWR-P0-5 处理),
//    故暂不级联删除关联数据

// 修复后 (L116-118)
// 注: sessions/manuscripts 的 project_id 外键已在 023_data_migration.sql
//    建立, ON DELETE SET NULL 自动处理关联数据(无需级联删除)
// 响应: void(删除成功即返回, 失败抛 PROJECT_NOT_FOUND)
```
