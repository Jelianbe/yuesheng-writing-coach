### 1.1 NovelCrafter

NovelCrafter 是当前最成熟的 AI 写作工作台之一，其 Prompt 工程体系的核心价值在于**高度结构化的变量注入系统**和**可编程的 Persona 系统**。

#### Prompt 结构 / 模板语法

| 维度 | 分析 |
|:----|:------|
| **整体骨架** | 三层结构：系统指令（Persona定义 + 写作规则）→ 变量注入（{expression} 模板占位符展开）→ 用户输入（分场景的自由文本） |
| **变量语法** | `{expression}` 格式：`{character_name}`、`{character_traits}`、`{setting_desc}`、`{style_guide}`。2025年5月更新后支持更复杂的表达式 |
| **三种核心变量类型** | **角色变量**（性格/动机/背景）、**世界观变量**（地理/规则/氛围）、**风格变量**（句式/词汇/节奏）——三分法是其模板语言的核心设计 |
| **用户输入处理** | 半结构化：提供表单式输入（场景描述/角色选择）但不强制，支持自由文本 |

#### Prompt 工程技术特征

| 特征 | 描述 |
|:----|:------|
| **约束机制** | 字数控制（`max_words: 500` 格式），风格锁定（`style: literary`），格式限定（`format: prose_only`）|
| **上下文管理** | Codex 知识库系统：角色/世界观/故事线的结构化知识库，通过上下文注入机制将条目注入到 Prompt |
| **角色/世界观定义** | Persona 系统：高度结构化的角色设定，含行为模式约束、对话风格、核心动机。Codex 中的每个条目可独立编辑和版本控制 |
| **反馈/迭代机制** | 支持用户在输出上做修改指示，但不内建"教学反馈"概念 |

*置信度：高（基于公开文档和社区讨论推断）*

#### 可借鉴 Prompt 模式

```
PE-001 | Persona 结构化模板
来源：NovelCrafter
核心结构：角色=【性格标签3-5个】+【核心动机1句】+【说话风格1句】+【行为约束2-3条】
引导策略：AI 在每次输出前自动加载 Persona，依据角色设定校准回复风格
可借鉴点：月笙的 Agent 角色（教学态度/档位切换）可以使用类似的 Persona 结构化管理
对应症候：通用（所有症候的诊断反馈风格一致性）
月笙最小版本：在系统 Prompt 中使用 Persona 字段替代"态度档位"的硬编码，使教学风格可配置

PE-002 | Codex 结构化知识注入
来源：NovelCrafter
核心结构：知识条目 = {trigger_condition} + {content_block} + {injection_priority}
引导策略：当满足 trigger_condition 时，自动将 content_block 注入 Prompt 的指定位置
可借鉴点：月笙的诊断结果和教学历史可以通过类似机制注入到回复 Prompt 中
对应症候：通用（上下文一致性的基础架构）
月笙最小版本：将"最近3条诊断结果"格式化为结构化条目，按优先级注入回复 Prompt 的上下文

PE-003 | 角色-世界-风格三分变量系统
来源：NovelCrafter
核心结构：变量分为3个独立 namespace：character.* / world.* / style.*，每个 namespace 有预定义字段
引导策略：用户在写作时只需选择变量名，无需重复填写完整信息
可借鉴点：月笙的学员信息（{student_info}）可以拆分为3个子 namespace——profile.* / diagnosis.* / progress.*
对应症候：通用（信息组织的架构性原则）
月笙最小版本：将系统 Prompt 中的 {student_info} 展开为 {/* TODO: 用真实数据替换 */}
```

#### 与月笙对比

| 维度 | NovelCrafter | 月笙 | 评价 |
|:----|:-------------|:----|:-----|
| **变量系统** | `{expression}` 模板语法，3 个 namespace | `{student_info}`/`{diagnosis}` 等字符串替换 | 月笙可以借鉴 namespace 设计 |
| **知识注入** | Codex 自动触发注入 | 手动注入（诊断结果 + 教学历史拼接） | 月笙缺自动触发机制 |
| **Persona** | 结构化角色模板 | 态度档位硬编码在 Prompt 中 | 月笙可以外配 Persona 模板 |
| **教学概念** | 无 | 症候诊断 + 训练推荐 | 根本差异：月笙是教学系统 |

### 1.2 ChatGPT 写作 GPTs

ChatGPT GPTs Store 中有大量写作类 GPTs（"写作教练""小说家""Story Architect"等），代表了当前 AI 写作 Prompt 的主流实践模式。

#### Prompt 结构 / 模板语法

| 维度 | 分析 |
|:----|:------|
| **整体骨架** | 开场身份声明 → 引导问题链 → 用户输入处理 → 约束条件清单 → 输出格式模板 |
| **变量系统** | 无内置模板变量，依赖自然语言描述（"你的故事设定是[用户输入]"） |
| **用户输入处理** | 标准化：开场用 2-4 个选择题或填空题框定输入范围 |
| **引导策略** | 固定模式：先问"你想写什么类型的作品？"再问"你需要什么帮助？" |
| **常见问题链** | "类型/题材→当前问题→期望输出→字数要求→风格偏好"的五步引导 |

*置信度：中-高（基于 GPTs Store 公开信息和用户评测分析）*

#### Prompt 工程技术特征

| 特征 | 描述 |
|:----|:------|
| **约束技巧** | 字数控制（"字数控制在500字以内"）、格式限定（"只输出正文，不加说明"）、风格锁定（"保持第一人称现在时"）|
| **上下文管理** | 依赖单轮对话窗口，无专用持久化机制。复杂项目需要用户手动维护前情提要 |
| **角色/世界观定义** | 无专用的知识库系统，依赖对话中的重复描述。信息衰减严重 |
| **反馈机制** | 用户自然语言指示修改，无非结构化约束 |

#### 可借鉴 Prompt 模式

```
PE-004 | 开场五步引导链
来源：ChatGPT 写作 GPTs（通用模式）
核心结构：类型→问题→期望→字数→风格，五步框定用户输入空间
引导策略：在接收用户创作内容前，先用问题链让用户明确需求，避免"我要写小说"这样模糊的输入
可借鉴点：月笙在用户首次提交文本前可以引导用户说明"写作目的/期望帮助/当前阶段"
对应症候：通用（减少无效输入的预处理机制）
月笙最小版本：在 TrainingWorkshop 的"开始训练"按钮前增加 2 个选择题（"你想练什么？""你卡在哪里？"）

PE-005 | 约束三明治技术
来源：ChatGPT 写作 GPTs（"Story Architect"等 GPTs）
核心结构：约束条件放在输出格式模板的上方和下方——上方约束（字数/风格/视角）+ 输出格式 + 下方约束（不可违反的规则）
引导策略：上下双重约束比单次约束有效。用户更容易在"先说规则→给模板→再重申禁忌"的节奏中记住约束
可借鉴点：月笙的 Prompt 中诊断指令和训练指令之间的"约束隔离"区域
对应症候：通用（Prompt 结构优化）
月笙最小版本：在诊断 Prompt 中，将"禁忌"条款拆分为两部分——诊断规则前的"总体约束"和诊断规则后的"输出验证"

PE-006 | 渐进式提需求策略
来源：ChatGPT 写作 GPTs（"Writing Coach" GPT）
核心结构：不要求一次说清所有需求，而是让用户分步骤给出——第一步: 粘贴文本, 第二步: 选择需求类型(评价/诊断/训练), 第三步: 指定关注点
引导策略：渐进式减少了用户的初始参与门槛，从"我要你给我诊断"的压力降到"先让我看看你的文本"
可借鉴点：月笙的"从零构建引导流程"（T-019）已经部分实现了渐进式，但可以在训练阶段更细化
对应症候：通用（降低用户心理门槛）
月笙最小版本：在训练 Workshop 的"开始训练"流程中增加"先指定关注点（POV/节奏/角色）"的中间步骤
```

#### 与月笙对比

| 维度 | ChatGPT GPTs | 月笙 | 评价 |
|:----|:-------------|:----|:-----|
| **引导策略** | 五步问题链 | T-019 入门引导 | 月笙已有，可以吸收五步链的"类型→问题→期望"结构 |
| **约束管理** | 三明治技术（上下双重约束） | 禁忌条款集中在 Prompt 尾部 | 月笙可以改进约束位置 |
| **上下文持久化** | 依赖单轮窗口 | SQLite 持久化 | 月笙更强 |
| **渐进式需求** | 分3步收集 | 已有 T-019 | 可细化到训练阶段 |

### 1.3 Claude Projects

Claude Projects 的 Project Instructions + Knowledge 文件体系提供了一种**分层指令管理 + 外挂知识库**的 Prompt 工程模式。

#### Prompt 结构 / 模板语法

| 维度 | 分析 |
|:----|:------|
| **整体骨架** | 三层 Prompt 架构：Layer 1（核心写作哲学/不可妥协原则）→ Layer 2（交互规则/约束）→ Layer 3（上下文激活指令/文件调用约定） |
| **变量系统** | 无模板变量，通过 Knowledge 文件中的结构内容填充。文件引用由自然语言描述触发 |
| **用户输入处理** | 格式预设：Project Instructions 中定义输入格式（如"我发送大纲+指令，你输出正文"） |
| **引导策略** | 初始化验证：用户在开始前要求 Claude 输出"理解摘要"确认，避免误解 |

*置信度：高（基于公开文档和社区最佳实践）*

#### Prompt 工程技术特征

| 特征 | 描述 |
|:----|:------|
| **分层设计** | Project Instructions 的"原则层→规则层→激活层"三层架构，优先级递减但不可跳过 |
| **文件组织** | Knowledge 文件按角色/世界观/情节分类组织。关键文件：核心人物卡（必选）、世界观设定（必选）、大纲（需要更新）、风格锚点（可选）|
| **记忆胶囊机制** | 每3-5次交互后，手动封装"前情提要"（角色状态/未解决伏笔/下一次触发条件）。Claude 无自动记忆 |
| **一致性审核循环** | 定期执行专项检查（角色漂移/设定矛盾/时间线/伏笔遗忘/用词统一）|

#### 可借鉴 Prompt 模式

```
PE-007 | 三层 Prompt 架构
来源：Claude Projects
核心结构：
  Layer 1（哲学层）：「你的定位是教练。不替学生写句子。」
  Layer 2（规则层）：「诊断结果先在内部判断，不输出症候编号。」
  Layer 3（激活层）：「每次回复前，先检查最近3条诊断结果。」
引导策略：优先级递减但不可跳过的高层原则，确保核心要求不会在长对话中被淡化
可借鉴点：月笙的 V3.4 Prompt 已经有铁三角+参考抽屉的结构雏形，可以更明确地分为 3 层
对应症候：通用
月笙最小版本：在 V3.4 Prompt 头部增加明确的"三层架构"分隔标记，使层次更分明

PE-008 | Knowledge 文件引用策略
来源：Claude Projects
核心结构：文件体系 = 核心人物卡(必) + 世界观设定(必) + 场景设定卡(条件触发) + 风格锚点文件(可选)
引导策略：每次涉及关键内容时，主动引用对应知识文件（"请参考世界观文件中的东大陆设定"）
可借鉴点：月笙的技法库(technique-library.json)和策略模版(coaching-templates.json)可以参照此策略实现"条件触发引用"
对应症候：通用（知识库的组织和引用方式）
月笙最小版本：在训练 Prompt 中增加"引用指令"，根据诊断结果自动引用对应的技法条目

PE-009 | 记忆胶囊机制
来源：Claude Projects
核心结构：每 3-5 次交互后封装：当前角色状态 + 未解决伏笔 + 最近一次场景变更 + 关键对话记录 + 下一次触发条件
引导策略：用户主动维护，但格式标准化。比完全依赖 AI 的上下文管理更可靠
可借鉴点：月笙的 SQLite 持久化可以自动生成类似"诊断历史摘要"的片段注入到对话上下文
对应症候：通用（长对话一致性的保障机制）
月笙最小版本：在训练服务中自动生成"最近3次诊断摘要 + 当前进度"的格式化文本，每次 AI 回复前注入
```

#### 与月笙对比

| 维度 | Claude Projects | 月笙 | 评价 |
|:----|:---------------|:----|:-----|
| **分层 Prompt** | 显式三层（哲学/规则/激活） | 隐式（铁三角+策略+参考抽屉） | 月笙可以引入显式分层 |
| **知识库** | Knowledge 文件（手动上传） | technique-library.json（内建） | 月笙的结构化更强 |
| **记忆机制** | 手动记忆胶囊 | SQLite 持久化（自动） | 月笙更强 |
| **一致性审核** | 手动触发审核指令 | 诊断引擎自动执行 | 月笙更强 |

### 1.4 NovelAI

NovelAI 的 Storyteller 模式和 Lorebook 系统是小说生成领域的经典 Prompt 设计。

#### Prompt 结构 / 模板语法

| 维度 | 分析 |
|:----|:------|
| **整体骨架** | Memory（持久记忆）→ Lorebook（条件激活知识库）→ Author's Note（当前指令）→ Context（最近输出）。四层信息逐级融合到生成上下文 |
| **变量系统** | 无传统模板变量。Lorebook 条目使用 {trigger} 标记自动激活 |
| **用户输入处理** | 自由输入 + 强制元数据标签（格式：`[Character: xxx]`、`[Setting: xxx]`） |
| **引导策略** | 无引导——NovelAI 定位为"写作工具"不是"教练"，不引导用户只响应输入 |

*置信度：中-高（基于公开文档和社区分析）*

#### Prompt 工程技术特征

| 特征 | 描述 |
|:----|:------|
| **Lorebook 条目** | 每条有触发关键词(trigger)、内容文本(content)、优先级(priority)。当输出中出现 trigger 匹配词时，对应条目自动注入上下文 |
| **Memory 机制** | 固定长度的"持久记忆"区，放在所有信息的最前方。内容由用户手动维护，不会被生成内容冲掉 |
| **Author's Note** | 放在生成窗口底部的当前指令。比 Memory 优先级高，格式灵活（"增加紧张感"）
| **风格控制** | 通过前置指令（"Style: Literary"等）+ 负面提示词（排除不想看到的词汇）|

#### 可借鉴 Prompt 模式

```
PE-010 | Lorebook 触发式信息注入
来源：NovelAI
核心结构：信息条目 = {trigger_words} + {content} + {priority}。输出中出现 trigger 时自动激活对应条目
引导策略：AI 不需要在每次回复中都加载全部知识，只在相关时注入。减少上下文噪声
可借鉴点：月笙诊断引擎中的"症候信号→对应训练推荐"可以采用类似的触发-注入模式
对应症候：通用（上下文管理的效率优化）
月笙最小版本：将 technique-library.json 中的每个技法条目加上 trigger 字段（关联症候ID），当诊断出对应症候时自动引用

PE-011 | 四层上下文堆叠
来源：NovelAI
核心结构：Memory(持久) + Lorebook(条件) + Author's Note(当前) + Context(最近输出)，四层按优先级从高到低融合
引导策略：持久信息（Memory）不受生成内容影响；当前指令（Author's Note）覆盖持久信息；最近输出作为生成基础
可借鉴点：月笙的回复 Prompt 可以类似地分为"教学原则(持久)→诊断摘要(条件)→当前动作指令(当前)→对话历史(最近)"
对应症候：通用
月笙最小版本：在 Prompt Builder 中将注入内容明确分为 3 个 zone（Zone1: 不变的教学原则 / Zone2: 本次诊断结果 / Zone3: 最近2次对话）
```

#### 与月笙对比

| 维度 | NovelAI | 月笙 | 评价 |
|:----|:--------|:----|:-----|
| **知识注入** | Lorebook 触发式 | 无条件全量注入 | 月笙可借鉴触发式减少上下文噪声 |
| **上下文分层** | 4 层显式堆叠 | 隐式混合 | 月笙可以引入显式分层 |
| **风格控制** | 前置指令+负面提示词 | 态度档位+Prompt 原则 | 月笙可加"负面提示词"机制 |
| **教学概念** | 无 | 症候诊断+训练推荐 | 根本差异 |

### 1.5 NovelFlix

PE-012 | 场景密度自动检测算法
来源：NovelFlix

### 2.1 Scrivener（6 个机制，3 个可借鉴设计）

| 机制 | 描述 |
|:----|:------|
