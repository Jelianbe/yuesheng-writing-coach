## 一、背景与问题定义

### 1.1 放弃的方案：流派纯度检测

**放弃原因**：
- **边界模糊** — 凡人流和爽文大量重叠，很多作品本身就是"凡人流爽文"
- **流派爆炸** — 起点活跃流派标签上百个（苟道流、稳健流、签到流、模拟器流、长生流…），不可能穷举
- **动态演化** — 今天的"凡人流"定义和十年前《凡人修仙传》时期已经不同

### 1.2 采纳的方案：意图-执行一致性检测

**核心问题**：不是"作者写了爽文"，而是"作者声称的目标与他实际的操作之间存在矛盾"。

**核心转变**：

| 维度 | 旧思路（流派纯度） | 新思路（意图-执行一致性） |
|------|-----------------|----------------------|
| 检测对象 | "这是什么流派" | "作者想达到什么效果" |
| 对比标准 | 是否符合某某流规则 | 操作是否服务于目标 |
| 诊断输出 | "爽文80%/凡人流20%" | "你的目标是A，但操作X、Y、Z在削弱A" |
| 体系扩展性 | 差（流派无限增长） | 好（意图稳定，操作变化） |

### 1.3 与现有体系的兼容性

意图-执行一致性**不是新增症候 P008**，而是跨所有已有症候的元检测维度：

| 现有症候 | 新增维度：意图-执行一致性检测 |
|---------|---------------------------|
| P001 世界观膨胀 | 意图是"主角清晰"，但操作是"设定堆砌" |
| P002 角色工具人化 | 意图是"角色鲜活"，但操作是"功能化使用" |
| P003 情绪标签化 | 意图是"读者共情"，但操作是"概括代替描写" |
| P004 信息硬塞 | 意图是"读者理解"，但操作是"旁白灌输" |
| P005 视角漂移 | 意图是"沉浸感"，但操作是"全知视角" |
| P006 节奏停滞 | 意图是"吸引读者"，但操作是"无冲突开篇" |
| P007 阅读结构单一 | 意图是"提升笔力"，但操作是"只读同类" |

## 二、三阶段诊断流程

意图提取不能一步到位。根据作者意图的清晰度，分为三个阶段：

```
作者意图状态
     │
     ├── 未成形（灵光一现/边写边找感觉）→ Phase 0 意图孵化
     ├── 存在但模糊/不自知               → Phase 1 意图浮现
     └── 明确但执行不一致                 → Phase 2 一致性检测
```

### Phase 0：意图孵化

**适用场景**：作者意图未成形——"灵光一现"型作者，或边写边找感觉。

**触发信号**（检测到任意一项即进入 Phase 0）：

| 信号 | 检测方式 | 示例 |
|------|---------|------|
| 风格摇摆 | 前3章风格关键词不一致 | 悬疑开头→爽文战斗→抒情独白 |
| 信息密度异常 | 第一章同时出现 ≥3 个设定元素 | 穿越+金手指+秘境+老爷爷+家族 |
| 作者说"试试" | 关键词匹配 | "先写着看看""试试这个路子" |
| 诊断置信度低 | ≥3 个症候同时命中且置信度均 < 0.5 | P001+P004+P006，各 0.3 |

**孵化提问（3 组递进问题）**：

第 1 组 — 对比锚定（缩小范围）：
> "你的开篇给我两种感觉——一种是凡人流的厚重感（慢节奏、生态位、挣扎），一种是爽文的冲击力（快节奏、金手指、反杀）。如果非要二选一，你更倾向哪个方向？"

不接受"都要"或"中和"——逼出偏好。

第 2 组 — 排除法（确认边界）：
> "你更怕读者觉得无聊，还是更怕读者觉得套路？"

揭示作者的内在风险偏好，比问"想写什么"更可靠。

第 3 组 — 效果具象化（可操作化）：
> "假设第一章写完了，一个读者合上手机说：'好看，因为_____。'你希望那个下划线里填什么？"

**退出条件**：作者给出了一个**可检验的意图陈述**。

| 不合格（太模糊） | 合格（可检验） |
|----------------|--------------|
| "我想写好" | "我想让读者觉得主角随时可能死" |
| "我想写凡人流" | "我想写一个没有金手指、全靠算计活下来的主角" |
| "要有代入感" | "读者能感受到主角每天为下一颗丹药发愁" |

### Phase 1：意图浮现

**适用场景**：意图存在但模糊/作者不自知。

**核心方法**：镜像反馈法——不做判断，只做呈现。

**提问模板**：

1. **宽口径提问**（获取表层意图）：
   > "你希望读者读完第一章后，对主角产生什么感觉？"
   > "选一句你觉得最能代表你想要的效果的句子。"

2. **镜像反馈**（呈现矛盾，让作者自己发现）：
   > "你说想让读者有代入感。我注意到主角开局是筑基中期——你觉得一个筑基期的修士，读者代入的难度和凡人相比如何？"

   关键：**把球踢回给作者**，不替他下结论。

3. **意图修正**（等待作者自我调整）：
   > 作者："嗯…其实我既想要凡人流的受众，又想要爽文的快感。"

   此时意图才真正可用——经过了自我审视。

**意图置信度评估**：

| 信号 | 置信度 | 说明 |
|------|--------|------|
| 作者明确陈述意图 | 1.0 | "我想写凡人废柴" |
| 从关键词匹配推断 | 0.7 | 正则在对话中匹配到目标关键词 |
| 从文本反推 | 0.3-0.5 | 仅从文本分析，无作者确认 |
| 防御性回应 | 0.1 | "费力气写的"——无有效意图 |

**意图提取实现（对应 extractIntent）**：

```typescript
interface AuthorIntent {
  /** 用户声称的流派/类型 */
  statedGenre?: string;

  /** 用户想要的效果 */
  statedEffect?: string;

  /** 用户描述的主角类型 */
  statedProtagonistType?: string;

  /** 提取来源：第几轮对话 */
  extractedFromRound: number;

  /** 提取置信度 0.0-1.0 */
  confidence: number;

  /** 原始文本引用 */
  sourceText: string;

  /** 来源阶段：0=孵化, 1=浮现 */
  sourcePhase: 0 | 1;
}
```

### Phase 2：一致性检测

**适用场景**：意图已明确，对比执行操作是否匹配。

#### 2.1 执行模式提取

```typescript
interface ExecutionPattern {
  /** 主角起点修为/地位 */
  protagonistStartingLevel: string;

  /** 危机类型 */
  crisisType: string;

  /** 叙事模式 */
  narrativePattern: string;

  /** 金手指类型 */
  advantageType?: string;

  /** 日常/经济/阶层描写密度 0-1 */
  dailyLifeDensity: number;

  /** 与意图的匹配度（规则引擎计算） */
  intentConsistencyScore: number;

  /** 检测到的矛盾点 */
  mismatches: ConsistencyGap[];
}
```

#### 2.2 规则引擎（V1 硬编码）

```typescript
interface ConsistencyRule {
  id: string;                    // 规则ID
  intentPattern: RegExp;         // 意图匹配正则
  executionPattern: RegExp;      // 执行匹配正则
  gapTemplate: string;           // 矛盾描述模板
  severity: number;              // 严重程度 1-5
  relatedSyndrome?: string;      // 关联病症（可选）
}
```

**V1 规则库**（6 条）：

**类型一：意图-执行对比规则（C001-C005）**

这类规则需要意图输入，检测"作者说的目标"与"文本的实际操作"是否一致。

| ID | 意图模式 | 执行模式 | 矛盾模板 | 严重度 | 关联 |
|----|---------|---------|---------|--------|------|
| C001 | 凡人/废柴/底层/挣扎 | 筑基/金丹/元婴/起点高 | "凡人/废柴流通常炼气期起步，{execution}起点过高，削弱'底层挣扎感'" | 3 | P001 |
| C002 | 凡人/废柴/底层 | 神魂强/天赋强/天生/被动优势 | "被动天赋无代价，与'凡人靠努力逆袭'的核心冲突" | 2 | P002 |
| C003 | 凡人/废柴/底层 | 下副本/打怪/升级/秘境 | "下副本升级是爽文套路，凡人流的爽点来自'苟'和'算计'而非直接战斗" | 2 | P006 |
| C004 | 代入感/真实/沉浸/底层 | 缺乏日常/无经济/无阶层 | "缺乏日常/经济/阶层描写，读者无法建立代入感" | 1 | P004 |
| C005 | 谨慎/稳健/苟/算计 | 主动挑战/硬刚/越级/冲动 | "主角行为过于激进，与'谨慎稳健'的设定矛盾" | 3 | P002 |

**类型二：文本内部一致性规则（C006）**

这类规则**不需要意图输入**，仅靠文本内部对比即可检测——它管的是"一段话自己的用词风格是否自洽"。

#### C006：用词风格内部自洽性

**原理**：不依赖外部性格提取，只检测"文本内部的用词风格是否有断裂"——如果连续几句都在用强势动词，突然冒出一句被动句式，这大概率是刻意雕琢的结果，而非角色塑造。

**V1 动词词库**（硬编码，可扩展）：

| 类别 | 示例词 | 权重 |
|------|--------|------|
| **强势动词** | 撕、扯、砍、砸、摔、踢、踹、捏、掐、拧、拽、捅、刺、劈、斩、割、削、抽、扇、拍、按、压、推、拉、拖、抓、握、夺、抢、撕碎、撕裂、丢弃、抛弃、碾压、践踏、摧毁、击碎 | +1 |
| **弱势动词** | 被、受、遭、挨、让、任、由、被冲洗、被磨砺、被折磨、被遗忘、被抛弃、感觉、觉得、好像、仿佛、似乎 | -1 |
| **中性动词** | 是、有、在、说、走、看、听、想、知道、觉得（指认知非感受） | 0 |

**检测逻辑**：

```
对每个段落：
  1. 按句拆解
  2. 对每句计算动词指数：
     动词指数 = (强势动词数 - 弱势动词数) / (强势动词数 + 弱势动词数 + 中性动词数)
     → 结果范围 -1 到 1
     → > 0.3 标记为"强势句"
     → < -0.3 标记为"弱势句"
     → 介于之间标记为"中性句"
  
  3. 风格断裂检测：
     连续 ≥3 句强势句后出现弱势句 → 标记"强势→弱势断裂"
     连续 ≥3 句弱势句后出现强势句 → 标记"弱势→强势断裂"
     段落内反复横跳（强弱强强弱） → 标记"风格摇摆"
  
  4. 排除规则（不触发标记的特殊情况）：
     - 对话段落（角色切换正常）
     - 时间对比（"当年" vs "现在"）  
     - POV 切换
     - 情绪拐点（如愤怒爆发前蓄力）
     
  5. 严重度判定：
     断裂 1 处 → severity: 1
     断裂 2 处 → severity: 2
     断裂 ≥3 处 或 风格摇摆 → severity: 3
```

**输出格式**（与 C001-C005 统一为 ConsistencyGap 接口）：

```typescript
{
  intent: "文本内部用词风格自洽性",
  execution: `第${sentenceIdx}句"${text}"使用了弱势动词"${verb}"，但前3句均为强势风格`,
  gap: `动词风格断裂：前文连续使用强势动词（${listPrevVerbs}），但这里用"${verb}"转为被动——` +
       `如果这是角色弧光的铺垫（先弱后强），保留；如果是无意识用词降级，建议统一为主动动词`,
  severity: 1-3,
  relatedSyndrome: "STYLE-001",  // 关联表达能力
}
```

**与 C001-C005 的区别**：

| 维度 | C001-C005 | C006 |
|------|-----------|------|
| 检测对象 | 意图 vs 执行 | 文本自身用词风格 |
| 是否需要意图输入 | ✅ 需要 | ❌ 不需要 |
| 检测时机 | Phase 2（意图明确后） | Phase 0/1/2 均可独立运行 |
| 误判风险 | 中（依赖意图提取的置信度） | 低（纯文本内部对比） |
| 输出定位 | "你的目标被操作削弱" | "这段的用词风格和前文不一致" |

**示例：《红湾玫瑰》开篇检测**

```
输入段落（原版）：
"从红湾烂泥爬到南区销冠，我一共用了十一年。
18岁时那张稚嫩的脸，在时间的冲洗下，早就变得面目全非。
犹记当年穿着一身洗得发白的短袖..."
                    ↓
逐句分析：
句1："爬" → 强势动词（主角主动动作） → 强势句
句2："被冲洗" → 弱势动词（被动承受）  → 弱势句  ← 断裂！
句3："穿着" → 中性动词                → 中性句

输出：
⚠️ C006 触发 | severity: 1
  "开篇第1句用'爬'（强势，主动），第2句突然转为'被冲洗'（弱势，被动）。
   如果这是刻意对比（强势主角 vs 被动过往），保留；
   如果不是，建议统一为主动动词：'早已被我撕了下来，丢弃了'。"
```

#### 2.3 评分算法

```
一致性评分 = max(0, 1 - totalPenalty × 0.2)
  其中 totalPenalty = 所有匹配规则的 severity 之和
```

评分区间：

| 分数 | 含义 | 输出策略 |
|------|------|---------|
| 0.8-1.0 | 意图与执行基本一致 | 正常诊断，不做特殊处理 |
| 0.4-0.7 | 存在明显矛盾 | 输出一致性警告，指出矛盾点 |
| 0.0-0.3 | 严重不一致 | 中断当前诊断，优先进行意图校准 |

#### 2.4 矛盾点输出

```typescript
interface ConsistencyGap {
  intent: string;              // 意图描述
  execution: string;           // 实际操作
  gap: string;                 // 矛盾说明
  severity: number;            // 严重程度 1-5
  relatedSyndrome?: string;    // 关联病症
}

interface ConsistencyRecord {
  timestamp: number;           // 诊断时间
  score: number;               // 该轮一致性评分
  gaps: ConsistencyGap[];      // 矛盾点列表
  diagnosisId: string;         // 关联诊断ID
}
```

## 四、教学动作

### 4.1 新增动作：A012 意图校准

**定义**：当检测到意图-执行不一致时，通过对话引导作者发现矛盾，而非直接下判断。

**执行步骤**：
1. 呈现作者自己的意图陈述（引用原文）
2. 呈现文本中的执行操作（引用具体段落）
3. 指出矛盾："你说想要A，但这里在削弱A"
4. 提问校准："你确认这是你想要的效果吗？"

**禁止**：
- 不说"你写错了"
- 不说"这是流派错误"
- 不代替作者做决定

### 4.2 新增训练任务：T015 意图-执行校准

```
### T015：意图-执行校准

**适用病症**：意图-执行不一致（跨病症）

**任务内容**：
写下你希望你读者读完第一章后的三个感受。
然后逐段检查：你的文字是在强化这些感受，还是在削弱它们？
发现矛盾的地方，标记出来。

**禁止**：
- 使用"我觉得""我认为"等模糊表述
- 只描述情节不描述效果

**字数**：300字（意图陈述）+ 逐段标注

**评估标准**：
- ✅ 能明确说出三个目标感受
- ✅ 能指出至少一处"意图与操作矛盾"
- ✅ 矛盾分析具体（不是"写得不好"，而是"这里想写A但做了B"）
- ❌ 无法指出矛盾 → 需要进一步引导

**示例（合格）**：
> 目标感受：
> 1. 主角很弱，随时可能死
> 2. 世界很危险，资源稀缺
> 3. 主角必须靠脑子活下来
>
> 矛盾检查：
> - 第一段："筑基中期" → 削弱感受1（筑基中期在散修里不算弱）
> - 第二段："神魂强大" → 削弱感受2（天生优势，不是努力得来）
> - 第三段：直接下副本 → 削弱感受3（没有展示"靠脑子"的过程）
```

## 五、常见教学陷阱

### 5.1 逻辑自洽陷阱

**表现**：作者用"逻辑成立"为不合理操作辩护。

**检测信号**：
- "动机逻辑成立吧？"
- "逻辑说得过去"
- "理论上没问题"

**应对规则**：
```
IF 用户说("逻辑说得过去" OR "动机成立" OR "理论上没问题")
   AND 之前有诊断建议被否定
THEN 触发：意图-执行一致性检查
     输出："逻辑自洽是底线，不是目标。你的逻辑服务于什么效果？"
```

### 5.2 作者阶段识别

作者在面对诊断时可能经历 4 个阶段，系统需要识别并调整策略：

| 阶段 | 表现 | 置信度 | 应对策略 |
|------|------|--------|---------|
| 防御 | "费力气写的""随手搓的" | 0.1 | 不追诊断，先建立信任 |
| 接受 | "起点太高了""有道理" | 0.5 | 引导具体修改方向 |
| 修补 | "加入炼丹消耗大设定" | 0.7 | 检验修补方案是否触及根因 |
| 归因 | "意图-执行不匹配" | 1.0 | 确认认知，给出训练任务 |

```markdown
### 5.4 意图-执行一致性检查（新增）

当用户明确表达了写作意图（如"我想写凡人/废柴/底层"），对比当前文本的操作是否匹配该意图。

**三阶段流程**：
1. **意图未成形**（风格摇摆/信息密度异常）→ 进入孵化模式，用对比锚定法引导
2. **意图模糊**（说了但说不清）→ 用镜像反馈法让作者自己发现矛盾
3. **意图明确但执行不一致** → 逐项对比操作，输出矛盾点

**常见矛盾模式**：
- 意图"凡人/废柴" + 操作"高修为开局" → 起点过高，削弱挣扎感
- 意图"凡人/废柴" + 操作"被动天赋无代价" → 与"努力逆袭"核心冲突
- 意图"谨慎/稳健" + 操作"主动挑战/硬刚" → 人设与行为矛盾

**输出方式**：
不说"你写错了"，说"你想写A，但这里的操作在削弱A——你确认这是你想要的效果吗？"
```
