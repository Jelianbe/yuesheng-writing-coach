## 二、任务 A：教学记录分层总结

### 2.1 分层标准

基于 Agent Prompt V3.1 中的学员分层定义：

| 层级 | 标识 | 特征 | 典型表现 |
|------|------|------|---------|
| **新手** | beginner | 刚接触网文写作，对基础技法缺乏认知 | 设定倾倒、情绪标签、形容词依赖 |
| **进阶** | intermediate | 有一定写作经验，能识别问题但不知道如何修正 | 角色工具化、节奏失衡、视角漂移 |
| **高阶** | advanced | 技法熟练但遇到瓶颈，需要精细化提升 | 世界观说明书症、对话空洞、人物空心 |

### 2.2 总结维度

每层产出需覆盖以下 4 个维度：

#### 2.2.1 诊断维度

| 维度 | 内容 | 数据来源 |
|------|------|---------|
| 高频症候组合 | 该层用户最常出现的 2-3 个症候及其共现关系 | 教学案例中的诊断结果 |
| 置信度特征 | AI 诊断该层用户时的平均置信度（新手通常置信度高，高阶可能置信度低但更复杂） | 诊断记录的 confidence 字段 |
| 误诊模式 | AI 在该层用户上容易犯的误诊类型（如果有数据） | 案例复盘 |

#### 2.2.2 技法维度

| 维度 | 内容 | 数据来源 |
|------|------|---------|
| 有效动作 TOP3 | 对该层用户最有效的 3 个教学动作（A001-A011） | 教学案例中的动作使用记录 |
| 无效动作 | 对该层用户效果不佳的动作（用户不理解/抵触） | 教学案例中的降级记录 |
| 动作组合 | 最有效的动作组合序列（如 A001→A003→A009） | 教学案例中的动作流转 |
| 降级触发频率 | 该层用户触发方法降级的频率和常见原因 | 教学案例中的降级记录 |

#### 2.2.3 节奏维度

| 维度 | 内容 | 数据来源 |
|------|------|---------|
| 平均教学轮次 | 从诊断到用户理解的平均对话轮次 | 教学案例的对话轮数 |
| 理解标志 | 如何判断该层用户"学会了"（行为信号） | 教学案例中的确认节点 |
| 注意力分散点 | 该层用户在什么节点容易失去兴趣/跑题 | 教学案例中的过渡邀请触发点 |

#### 2.2.4 成果维度

| 维度 | 内容 | 数据来源 |
|------|------|---------|
| 典型成长路径 | 该层用户的能力评分变化曲线（诊断前后的能力变化） | 教学案例中的能力变化 |
| 成功案例模板 | 一个完整的"从状态 A 到状态 B"的案例 | 教学案例 |
| 常见卡点 | 该层用户最常卡住的环节 | 教学案例 |

### 2.3 输出文档结构

每层输出一份独立文档，命名格式：`teaching-summary-{level}-V1.md`

```markdown
# 教学记录分层总结 — {beginner/intermediate/advanced}

## 一、层级特征概述
- 典型用户画像
- 与教学系统的交互模式
- 常见心态和期望

## 二、诊断特征
- 高频症候 TOP5（含出现频率）
- 症候共现模式
- 置信度特征
- 误诊模式（如有）

## 三、有效技法
- TOP3 有效教学动作（含使用场景和效果）
- 最佳动作组合序列
- 无效/需谨慎的动作
- 降级策略建议

## 四、教学节奏
- 平均教学轮次
- 理解标志
- 注意力分散点
- 最佳干预时机

## 五、成长路径
- 典型能力评分变化
- 成功案例模板
- 常见卡点与突破方法

## 六、系统优化建议
- 对该层用户的 Prompt 调整建议
- 对该层用户的训练任务优化建议
- 对该层用户的 UI/交互优化建议

## 七、原始案例索引
- 引用的教学案例列表
- 对应章节/轮次
```

### 2.4 执行步骤

```
Step 1: 读取所有可用教学案例
  → case-ayuan-rebirth-ch1.md（已有）
  → 用户提供的其他案例（如有）

Step 2: 按用户水平对案例分类
  → 分析每个案例中的用户表现、诊断结果、教学动作响应
  → 归类到 beginner / intermediate / advanced

Step 3: 对每层提取 4 个维度的数据
  → 诊断维度、技法维度、节奏维度、成果维度

Step 4: 生成 3 份分层总结文档
  → teaching-summary-beginner-V1.md
  → teaching-summary-intermediate-V1.md
  → teaching-summary-advanced-V1.md

Step 5: 交叉验证
  → 检查分类是否合理（有没有用户表现出跨层特征）
  → 检查数据是否支撑结论
```

## 三、任务 B：网文技法蒸馏

### 3.1 拆书分析框架

每部作品/每位作者产出一份拆书报告：

```markdown
# 拆书分析报告 — {作品名/作者名}

## 一、基本信息
- 书名/作者/平台/字数/连载状态
- 核心标签（玄幻/都市/仙侠等）
- 数据表现（均订/月票/收藏等，如有）

## 二、节奏分析

### 2.1 开篇钩子
- 前 3000 字的核心钩子是什么
- 使用的手法（悬念/冲突/信息差/情绪共鸣等）
- 与传统文学开篇的对比

### 2.2 章节断点
- 每章结尾的悬念设计模式
- 断点的类型（ cliffhanger / 信息揭示 / 情绪高点 / 行动中断）
- 断点密度（平均每章几次小悬念）

### 2.3 节奏曲线
- 紧张 vs 放松的交替模式（几章紧/几章松）
- 高潮间隔（多久一个大高潮）
- 节奏变化的信号（读者能感知到的节奏转折）

### 2.4 信息密度
- 设定/对话/动作/心理描写的比例估算
- 设定融入叙事的方式（直接讲解 vs 自然展现）
- 信息释放节奏（一次性释放 vs 渐进释放）

## 三、技法分析

### 3.1 视角控制
- 主要视角类型（第一人称/第三人称限知/全知）
- 视角切换的规则和频率
- 视角切换的效果（是否造成混乱）

### 3.2 对话设计
- 对话的功能（推进剧情/塑造人物/传递设定/制造冲突）
- 潜台词使用频率
- 角色声音区分度（不看标签能否分辨是谁说话）

### 3.3 场景构建
- 环境描写的功能化使用（氛围营造 vs 纯粹描写）
- 场景转换的方式（硬切/过渡/蒙太奇）
- 场景节奏（大场景 vs 小场景的比例）

### 3.4 人物塑造
- 核心人物的出场方式
- 人物动机的展现方式（直接说明 vs 行为暗示）
- 人物成长弧线的设计

### 3.5 世界观呈现
- 世界观信息的释放节奏
- 设定与剧情的融合度
- "冰山理论"的运用（水面上的 vs 水面下的）

## 四、网文 vs 传统文学对比

### 4.1 适配传统的技法
- 哪些技法来自传统文学但在网文中做了调整
- 调整的方向和原因

### 4.2 网文独有的技法
- 传统文学中没有或不常用的技法
- 这些技法为什么适合网文环境

### 4.3 不适用的传统规则
- 哪些"写作教科书"的规则在网文中不适用
- 替代方案是什么

## 五、可蒸馏技法清单

| 技法编号 | 技法名称 | 来源章节 | 适用症候 | 训练方法 | 难度 | 网文 vs 传统 |
|---------|---------|---------|---------|---------|------|-------------|
| TQ-001 | 示例技法 | 第X章 | P001 | 具体训练方式 | beginner | 网文独有 |
| TQ-002 | ... | ... | ... | ... | ... | ... |

## 六、与传统文学的对照

| 传统技法 | 网文适配版 | 差异点 | 适用场景 |
|---------|-----------|--------|---------|
| 示例：Show don't tell | 网文版展示不告知 | ... | ... |
```

### 3.2 对比分析维度（起点 vs 番茄）

| 维度 | 起点中文网风格 | 番茄小说风格 | 对教学系统的启示 |
|------|--------------|-------------|----------------|
| 开篇速度 | 允许 1-3 万字铺垫 | 前 3000 字必须有冲突 | 新手教学需区分平台 |
| 设定密度 | 可详细展开 | 轻量、融入剧情 | 新手不宜学起点重度设定 |
| 对话风格 | 可文雅、带古风 | 口语化、直接 | 训练方式需区分 |
| 章节长度 | 3000-5000 字 | 1500-2500 字 | 训练任务长度需适配 |
| 悬念设计 | 长线悬念（跨章节） | 章章有悬念 | 训练节奏需区分 |
| 读者预期 | 期待深度和逻辑 | 期待爽感和节奏 | 教学侧重点不同 |
| 世界观构建 | 系统化、详细 | 碎片化、够用就好 | 新手应先学番茄式 |

### 3.3 技法蒸馏入库流程

```
拆书分析完成
    ↓
提取可蒸馏技法（TQ-001, TQ-002, ...）
    ↓
技法映射到现有体系
    ├── 对应哪个症候？（P001-P010）
    ├── 对应哪个训练任务？（T001-T021，或新增）
    ├── 对应哪个教学动作？（A001-A011，或新增）
    └── 适合哪个水平的用户？（beginner/intermediate/advanced）
    ↓
输出技法蒸馏清单
    ├── 新增训练任务（如需）
    ├── 新增诊断规则（如需）
    ├── 更新 SPEC_Ability_Map（训练映射表）
    └── 更新教学案例库（作为参考案例）
```

### 3.4 技法编号规范

| 编号 | 含义 | 示例 |
|------|------|------|
| TQ-001 ~ TQ-099 | 网文特有技法（Technique for Web Novel） | TQ-001: 三章定生死 |
| TC-001 ~ TC-099 | 传统技法网文适配版（Traditional adapted） | TC-001: 网文版展示不告知 |
| TN-001 ~ TN-099 | 传统技法不适用（Not applicable） | TN-001: 详细环境描写 |

### 3.5 输出文档结构

```
docs/research/
├── technique-distillation/
│   ├── TQ-index-V1.md              # 技法蒸馏索引
│   ├── case-{book-name}-V1.md      # 拆书分析报告（每本书一份）
│   └── platform-comparison-V1.md   # 起点 vs 番茄对比分析
```

### 3.6 执行步骤

```
Step 1: 用户提供拆书目标（1-3 部作品）
  → 推荐清单：
     起点：《诡秘之主》《大奉打更人》《夜的命名术》
     番茄：《十日终焉》《我不是戏神》《我在精神病院学斩神》

Step 2: 逐部作品进行拆书分析
  → 按 3.1 拆书分析框架执行
  → 重点分析节奏、技法、与传统文学的差异

Step 3: 平台对比分析
  → 起点 vs 番茄的 7 个维度对比
  → 输出对比报告

Step 4: 技法蒸馏清单
  → 提取所有可蒸馏技法（TQ/TC 编号）
  → 映射到现有教学体系（症候/训练/动作/用户水平）

Step 5: 输出索引文档
  → TQ-index-V1.md（技法索引，方便后续检索）
  → 更新 SPEC_Ability_Map 中的训练映射
```

