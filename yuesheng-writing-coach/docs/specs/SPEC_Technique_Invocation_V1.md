## 一、定位

技法调用层是连接"诊断输出"和"教学对话"的中间层。它定义了一个根因如何匹配合适的技法、如何进行动态过滤、以及如何在对话中被引用。

## 二、调用链

```
诊断 Agent 输出结构化根因
    ↓
技法调用层
  ├── 1. 根因 → 技法池匹配（3-5条候选）
  ├── 2. 动态过滤（用户水平/对话阶段/上下文）
  └── 3. 选 1 条最贴合的输出
    ↓
教学 Agent 引用技法进行对话
```

## 四、动态过滤规则

### 4.1 按用户水平过滤

| 用户水平 | beginner 技法 | intermediate 技法 |
|---------|--------------|-----------------|
| 新手 | ✅ 全部可用 | ❌ 跳过 |
| 进阶 | ✅ 全部可用 | ✅ 全部可用 |
| 高基础 | ✅ 全部可用（可选介绍） | ✅ 全部可用 |

### 4.2 按对话阶段过滤

| 对话阶段 | 技法引用方式 |
|---------|------------|
| 第一轮诊断后 | 只提 1 条，不说技法名，给方向 |
| 用户确认问题后 | 可提来源作品："大奉打更人用了类似的绝境开局" |
| 用户尝试修改时 | 可给具体框架："试试图三段的走法" |
| 用户完成修改后 | 引用技法做对比评价 |

### 4.3 按上下文过滤

- 如果用户刚说了"我不看诡秘之主" → 跳过诡秘之主来源的技法
- 如果用户说"我写的是凡人流" → 优先凡人修仙传来源的技法
- 如果用户说"我写的是番茄/飞卢" → 优先番茄来源的技法
- 如果用户说"别给我看原文案例" → 只给框架不给案例

## 五、技法引用规范（对话层）

| 引用方式 | 示例 | 适用时机 |
|---------|------|---------|
| 方向级 | "试试让读者通过角色的动作自己发现设定" | 第一轮 |
| 来源级 | "诡秘之主用了类似的手法" | 用户确认后 |
| 框架级 | "可以试试三段式：紧张→好奇→温情" | 用户尝试修改时 |
| 案例级 | "诡秘之主第一章用手枪放在书桌上…" | 用户主动要求看案例 |

## 七、维护规则

1. 新增技法时：在 technique-library 中添加，然后更新本 spec 的映射表
2. 删除技法时：标注"已弃用"而非直接删除（防止历史诊断引用失效）
3. 技法难度调整：当 85% 以上的 beginer 用户能自主完成时，可升级为 intermediate
4. 映射表验证：每完成一次真实的诊断→教学对话，检查组配是否合理
