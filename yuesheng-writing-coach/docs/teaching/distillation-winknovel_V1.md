## 一、蒸馏概览

### 1.1 核心判断

WinkNovel 本质上是一个**大模型前端编排器**，它的核心竞争力不是提示词写得好，而是把模糊的创作需求变成了**可量化、可重复、可修改的标准化流程**。

对月笙的价值：**不是复用它的提示词，而是提取它"结构化创作思维"背后可教给用户的技法。**

## 二、阶段 1：解构

### 2.1 源工具信息

- **工具名称**：WinkNovel 世界观构建体系与提示词工程
- **工具类型**：AI 写作辅助（结构化问卷 + 多 Agent 协作 + 分层提示词注入）
- **核心功能**：通过结构化问卷采集世界观设定，分发指令给多 Agent 生成统一风格的小说内容
- **目标用户**：网络小说作者（尤其是长篇连载作者）
- **信息来源**：官方文档 / 功能逆向 / 同类工具分析

### 2.2 功能模块清单

| 模块编号 | 模块名称 | 功能描述 | 输入 | 输出 | 实现方式 |
|---------|---------|---------|------|------|---------|
| M-01 | 世界观基底问卷 | 通过 100+ 问题采集世界设定 | 作者对世界的想法 | 结构化键值对+标签的世界观数据 | 问卷交互 → 自动格式化存储 |
| M-02 | 实体卡生成系统 | 基于世界观基底生成人物/地点/物品卡片 | 基础信息（名称/类型/一句话） | 标准化实体卡（含唯一 ID） | 世界观 Agent 自动生成 |
| M-03 | 一致性校验引擎 | 检查生成内容是否违反世界观规则 | 生成内容 + 世界观规则 | 校验通过/不通过标记 | 校验 Agent 规则匹配 |
| M-04 | 全局基础提示词 | 定义 AI 身份和写作风格，所有生成共用 | 小说类型 | 固定身份+风格指令 | prompt 文件硬编码，拼接动态字段 |
| M-05 | 大纲 Agent | 生成三卷小说大纲 | 核心设定+人物+矛盾 | 每卷每章的标题和核心剧情 | 独立 Agent 专用提示词 |
| M-06 | 正文生成 Agent | 按章节生成正文 | 章节设定+人物+地点+上文 | 完整章节正文 | 动态注入上下文生成 |
| M-07 | 润色 Agent | 润色生成的内容 | 原始内容 | 润色后内容 | 独立 Agent 专用提示词 |
| M-08 | 动态上下文注入 | 自动检索相关上下文，排除无关信息 | 当前章节信息 | 精炼的上下文数据 | 自动检索+拼接 |

### 2.3 核心工作机制（数据流/信息流）

```
作者创作意图
    ↓
[阶段 1：结构化问卷采集]  ← 100+ 问题，默认值降低门槛
    ↓ (键值对+标签 存库)
[阶段 2：实体卡生成]  ← 世界观 Agent 自动生成人物/地点/物品卡（唯一 ID 管理）
    ↓ (实体卡片)
[阶段 3：内容生成]  ← 分层指令下发到各 Agent
    ├── 大纲 Agent → 三卷结构大纲
    ├── 正文生成 Agent → 逐章正文（含动态上下文注入：前 3 章 + 关键检索）
    └── 润色 Agent → 最终润色
    ↓
[阶段 4：一致性校验]  ← 校验 Agent 检查是否违反核心规则，不通过则打回
    ↓
最终小说内容
```

### 2.4 关键架构模式

1. **数据与提示词分离** — 世界观数据从提示词中抽离到数据库，通过 `{}` 变量动态注入
2. **多 Agent 分工** — 不同 Agent 负责不同任务，各有独立提示词
3. **有限上下文窗口** — 只保留前 3 章完整内容 + 前 10 章摘要 + 当前相关实体卡
4. **规则优先级系统** — 核心规则赋予最高权重，次要规则可弹性处理
5. **唯一 ID 关联** — 所有实体都有唯一 ID，章节生成时自动关联相关实体

### 3.2 B 层：教学可用

| 编号 | 来源模块 | 原始内容 | 改造方向 | 改造后内容 | 对应症候 |
|------|---------|---------|---------|-----------|---------|
| B-01 | M-01 世界观问卷（100+问题） | 填空式问题给 AI 采集数据 | 改为"自检清单"——用户写完后对照检查 | 世界观自检清单：你的设定中是否回答了"世界运行法则是什么？有什么不能打破的禁忌？"等问题 | P008 P009 |
| B-02 | M-03 一致性校验引擎 | AI 自动检查内容是否违反规则 | 改为"用户自查表"——校验自己的章节是否违反核心规则 | 章节一致性自查表：把规则列在左边，逐条核对自己当前章节 | P009 P005 |
| B-03 | M-08 动态上下文注入 | 自动检索相关上下文、排除无关信息 | 改为"叙事线索管理法"——教用户管理当前活跃的线索 | 写章节前先列出：本章活跃的线索/人物/地点，删掉不相关的内容 | P005（视角漂移）P007 |
| B-04 | 多 Agent 分工模式 | 大纲 Agent→正文 Agent→润色 Agent 流水线 | 改为"分阶段审稿法"——写完后分三次审稿 | 第一次审结构（大纲对不对）、第二次审描写（画面感够不够）、第三次审语言（通不通顺） | P007 P004 |
| B-05 | M-02 物品卡框架 | AI 自动生成标准化物品卡 | 改为"重要物品登记表"——用户自己记录关键物品 | 重要物品表：名称、外观、来历、功能、在剧情中的作用、当前持有者 | P009 P003 |
| B-06 | P-02 要求 4 伏笔与回收 | "合理安排伏笔和回收，确保剧情逻辑自洽" | 从 AI 要求改为用户写作技能 | 伏笔管理三问：这个伏笔准备什么时候收？用什么方式收？收的时候能产生什么效果？ | P007 P005 |
