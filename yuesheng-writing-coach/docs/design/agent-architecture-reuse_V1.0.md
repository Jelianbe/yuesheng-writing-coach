## 二、Phase 1：LangGraph 状态机 → 创作流程引擎

### 2.1 当前问题

现有教学状态机是**线性推进**的：
```
P0_INIT → P1_WORLD → P2_PRACTICE_LOOP → P4_REVIEW
```

但真实创作是**跳步、回退、卡壳**的：
- 用户在 Phase 4 突然开始堆世界观 → 需要回退到 Phase 1
- 用户聊到一半离开 → 回来要能继续
- 用户突然表达情感诉求（"我想纪念一个人"） → 需要切换到 B 类流

### 2.2 复用方案：图结构状态机

```
[诊断节点] --(A类)--> [循循善诱流]
          --(B类)--> [强拆灵堂流]
          --(C类)--> [缺口补完流]

[世界观节点] --(用户飘了)--> [五感降维器] --(落地)--> [主角锚定节点]
[主角锚定] --(信息不足)--> [追问子图] --(答完)--> [刑侦笔录节点]
[刑侦笔录] --(交不出作业)--> [硬门槛施压环] --(通过)--> [验收节点]
```

### 2.3 核心能力映射

| LangGraph 能力 | 月笙场景 | 技术实现 |
|---------------|---------|---------|
| **图节点（Node）** | 教学阶段（诊断/世界观/主角/笔录/验收） | TypeScript 函数 + 状态枚举 |
| **条件边（Conditional Edge）** | 学员类型 A/B/C → 不同教学流 | 意图识别 + 规则路由 |
| **状态持久化** | 断点续传、跨会话保持 | SQLite teaching_state 表 |
| **循环节点（Cycle）** | 硬门槛施压环（反复练习直到通过） | while 循环 + 最大迭代限制 |
| **子图（Subgraph）** | 追问子图（针对信息不足的深入追问） | 嵌套状态机 |

### 2.4 当前教学状态机的差距

| 已有 | 缺失 |
|------|------|
| 线性阶段推进 | **条件边路由**（根据用户类型/状态自动跳转） |
| 用户确认手动推进 | **自动触发**（检测到信号自动切换流程） |
| 单会话状态 | **跨会话持久化**（断点续传） |
| 固定动作推荐 | **动态子图**（根据具体问题生成追问链） |

### 2.5 实施步骤

1. 将现有 `TeachingPhase` 和 `TeachingSubphase` 改为图节点定义
2. 增加条件边函数：`getNextNode(currentNode, userState) => nextNode`
3. 扩展 `teaching_state` 表，增加 `current_node`、`node_history` 字段
4. 实现断点续传：每次状态变更时保存完整图状态
5. 增加最大迭代限制（防止循环死锁）

## 三、Phase 2：RAG 混合检索 → 角色原型库

### 3.1 当前问题

现有 Agent 是"凭空教写作"，LLM 容易泛泛而谈。没有历史案例参考，每次教学都是从零开始。

### 3.2 复用方案：RAG 架构

```
文档解析 → 切片 → 向量化 → 混合检索（向量 + BM25） → 重排序 → Few-shot 注入
```

### 3.3 检索场景映射

| 用户输入 | 向量检索（语义） | BM25（关键词） | 最终输出 |
|---------|----------------|---------------|---------|
| "理科生卷入超自然" | 匹配"社恐主角+异常事件"案例 | 匹配"高中生、阴差、尸变"标签 | 这维来特案例 |
| "想写龙族" | 匹配"非人类主角+人类社会"模板 | 匹配"龙族、觉醒、伴生" | 龙族案例 |
| "不想她被遗忘" | 匹配"纪念型叙事"方案 | 匹配"亡妻、白月光" | 触发 B 类流 |

### 3.4 重排序规则

根据用户类型（A/B/C）调整排序权重：

| 用户类型 | 重排序策略 |
|---------|-----------|
| A 类（循循善诱） | 优先推送结构化案例模板 |
| B 类（强拆灵堂） | 将"纪念型模板"压后，优先"感官降维模板" |
| C 类（缺口补完） | 优先推送"断点续写"类案例 |

### 3.5 技术选型

| 组件 | 方案 | 说明 |
|------|------|------|
| 向量库 | SQLite + sqlite-vss | 轻量级，与现有数据库统一 |
| 向量化 | 用户自备 API Key 调用 Embedding | 与聊天共用模型 |
| BM25 | 内存索引（flexsearch） | 关键词检索 |
| 重排序 | 规则引擎 + 用户类型权重 | 不需要额外模型 |

### 3.6 实施步骤

1. 收集已有教学案例（这维来特、亡妻哥、夜兰、锦泠等）
2. 切片入库：每个案例拆分为 问题描述 → 教学过程 → 产出结果
3. 建立向量索引
4. 实现混合检索 + 重排序
5. 集成到 System Prompt 中作为 few-shot

## 四、Phase 3：三层记忆系统 → 用户创作画像

### 4.1 复用方案

| 层级 | 京东用法 | 月笙用法 | 存储 |
|------|---------|---------|------|
| **短期记忆** | 多轮对话上下文 | 当前 session：正在确认主角家庭背景，已答"父母健在" | Zustand |
| **长期记忆** | 用户画像、历史行为 | 用户标签：`{type:"A类", 偏好:"玄幻", 卡点:"世界观膨胀", 耐受度:"高"}` | SQLite |
| **垂类知识** | 电商规则、佣金政策 | 创作方法论库：降维引导法、刑侦笔录20问、五感降维词典 | JSON 文件 |

### 4.2 用户画像数据结构

```typescript
interface UserProfile {
  userId: string;
  userType: 'A' | 'B' | 'C'; // 学员类型
  preferences: {
    genre: string[]; // 偏好题材
    style: string[]; // 偏好风格
  };
  painPoints: {
    syndromeId: string;
    severity: string;
    firstDetected: string;
    status: 'active' | 'improving' | 'resolved';
  }[];
  tolerance: 'low' | 'medium' | 'high'; // 对高强度教学的耐受度
  triggerCount: number; // B 类用户触发次数
  firewallLevel: 'normal' | 'elevated' | 'max'; // 情感防火墙等级
  sessionHistory: {
    sessionId: string;
    date: string;
    phase: string;
    outcome: 'completed' | 'abandoned';
  }[];
}
```

### 4.3 快捷回复体系（创作急救包）

| 类型 | 月笙场景 | 触发条件 |
|------|---------|---------|
| **历史续写** | 用户写了 200 字卡住了 | 检测连续 2 轮无进展 |
| **预设问题** | "我没灵感" → 触发 A 类流 Step 1 | 关键词匹配 |
| **预设问题** | "我想纪念一个人" → 触发 B 类流 | 情感信号检测 |
| **预设问题** | "我的设定是不是太宏大" → 设定瘦身器 | 关键词匹配 |
| **路径规划** | 按业务目标设计交互流程 | 终点：角色档案卡 + 初幕场景 |

### 4.4 实施步骤

1. 扩展 `teaching_state` 表，增加 `user_profile` JSON 字段
2. 实现用户画像 CRUD
3. 每次会话开始时自动加载画像
4. 实现快捷回复预设（10 个高频卡壳场景）
5. 实现路径规划（从诊断到验收的完整流程图）

## 五、Phase 4：人机协同 → 高价值 IP 审核

### 5.1 复用方案

```
Agent 完成角色档案 → 人工审核节点 → 通过则进视觉管线
                                 → 不通过则结果反哺（修正 RAG 模板库）
```

### 5.2 触发条件

| 条件 | 说明 |
|------|------|
| 高价值角色 | 付费/企业定制 |
| 复杂情感线 | 检测到强烈情感表达（亡妻哥类型） |
| 人工标记 | Agent 自我判断需要人工介入 |

### 5.3 反哺机制

人工修改结果 → 存储为修正案例 → 更新 RAG 模板库 → Agent 学习新逻辑

## 六、整合架构图

```
┌─────────────────────────────────────────┐
│           用户入口（Electron 桌面应用）     │
└─────────────┬───────────────────────────┘
              ▼
┌─────────────────────────────────────────┐
│  【意图识别】LLM 判断 A/B/C 类 + 加载画像  │
│  （SQLite：用户画像、历史卡点、防火墙等级） │
└─────────────┬───────────────────────────┘
              ▼
┌─────────────────────────────────────────┐
│  【状态机引擎】创作流程引擎（Phase 1）      │
│  Node 0: 诊断 → Node 1: 载体 → Node 2: 题材│
│  Node 3: 世界观速描（限时3轮，超则切）     │
│  Node 4: 主角锚定（必须答完5问）            │
│  Node 5: 刑侦笔录（who/what/where/why）   │
│  Node 6: 硬门槛作业（300字文本锁）          │
│  Node 7: 验收 → 通过则生成角色档案卡        │
└─────────────┬───────────────────────────┘
              ▼
┌─────────────────────────────────────────┐
│  【RAG 知识库】角色原型与创作模板（Phase 2）│
│  混合检索（向量语义 + BM25关键词）→ 重排序  │
│  输入：用户描述 → 输出：最适引导模板        │
└─────────────┬───────────────────────────┘
              ▼
┌─────────────────────────────────────────┐
│  【工具调用层】ReAct 范式：推理→行动        │
│  • 设定瘦身器：检测世界观冗余度            │
│  • 情感防火墙：检测 PTSD 信号              │
│  • 五感降维器：概念→感官（自动替换）        │
│  • 缺口补完器：C 类用户断点续写            │
└─────────────┬───────────────────────────┘
              ▼
┌─────────────────────────────────────────┐
│  【结果生成】角色档案卡 + 初幕场景文本      │
│  档案卡：姓名/年龄/核心矛盾/视觉关键词      │
│  场景文本：300字，动作+对话+感官           │
└─────────────┬───────────────────────────┘
              ▼
┌─────────────────────────────────────────┐
│  【视觉管线】THA4 / EasyVtuber 立绘生成    │
│  输入：角色档案卡 → 输出：角色立绘          │
└─────────────────────────────────────────┘
```

## 七、分阶段实施计划

| Phase | 内容 | 预估时间 | 核心价值 |
|-------|------|---------|---------|
| **Phase 1** | LangGraph 状态机（图结构+条件边+断点续传） | 1 周 | 解决"聊到一半失忆" |
| **Phase 2** | RAG 模板库（案例入库+混合检索+重排序） | 1 周 | Agent 不再凭空教学 |
| **Phase 3** | 记忆系统+快捷回复（用户画像+创作急救包） | 1 周 | 用户第二次来无需重新诊断 |
| **Phase 4** | 人机协同（高价值 IP 审核+反哺） | 按需 | 企业级质量保障 |
