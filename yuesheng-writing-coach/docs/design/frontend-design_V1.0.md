## 1. 设计原则与定位

### 1.1 产品定位

月笙是**AI写作教练**，核心定位：
- **不替用户写** - 只给示范，不替完成
- **不替用户决定** - 给选择，不给答案
- **帮用户看清问题** - 让用户自己解决

### 1.2 设计哲学

| 原则 | 说明 | 设计体现 |
|------|------|----------|
| **教练感** | 不是聊天工具，是教学环境 | 诊断面板优先展示，强调"看清楚问题" |
| **沉浸感** | 适合长时间写作和阅读 | 深色主题、舒适的排版、低干扰界面 |
| **清晰度** | 诊断结果必须一目了然 | 结构化展示病症、严重度、建议动作 |
| **克制感** | 不堆砌功能，不做多余的事 | 界面简洁，功能按需展开 |

### 1.3 用户画像

| 维度 | 描述 |
|------|------|
| **目标用户** | 网文/小说创作者（新手到有一定基础的作者） |
| **使用场景** | 长时间写作、反复修改、学习写作技巧 |
| **核心需求** | 看清自己写作的问题，获得改进方向 |
| **环境偏好** | 安静、专注、低干扰的写作环境 |
| **技术能力** | 基础电脑操作能力，非技术人员 |

## 2. 整体布局架构

### 2.1 三栏布局

应用采用**三栏式布局**，这是信息密度高、操作效率好的经典布局模式：

```
┌─────────────────────────────────────────────────────────────────┐
│ 标题栏 (Window Title Bar)                                        │
│ [应用菜单] 月笙写作教练                          [态度档位] [设置]│
├────────┬──────────────────────────────────────┬─────────────────┤
│        │                                      │                 │
│ 侧边栏  │           主内容区域                  │   右侧面板       │
│        │                                      │                 │
│ 250px  │           自适应宽度                   │   320px         │
│        │                                      │   (可折叠)       │
│ ·会话  │   · 聊天界面                          │  · 诊断书        │
│ ·训练  │   · 训练任务                          │  · 动作建议      │
│ ·参考  │   · 设置面板                          │  · 置信度        │
│        │                                      │                 │
├────────┴──────────────────────────────────────┴─────────────────┤
│ 底部状态栏                                                       │
│ [连接状态] [当前会话] [消息计数]                   [版本信息]     │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 窗口配置

根据 PRD 定义的窗口配置：

| 参数 | 值 | 说明 |
|------|-----|------|
| 默认宽度 | 1200px | 适合三栏布局的舒适宽度 |
| 默认高度 | 800px | 保证聊天区域有足够垂直空间 |
| 最小宽度 | 900px | 确保侧边栏+主内容区的基本可读性 |
| 最小高度 | 600px | 保证输入框和消息列表的基本显示 |
| 背景色 | `#0f0f23` | 深色主题基调色 |

### 2.3 布局区域职责

| 区域 | 职责 | 包含内容 |
|------|------|----------|
| **标题栏** | 应用标识、全局控制 | 应用名称、态度档位切换、设置入口 |
| **侧边栏** | 导航、会话管理 | 会话列表、训练任务入口、参考文件入口 |
| **主内容区** | 核心工作区 | 根据当前页面显示聊天/任务/设置 |
| **右侧面板** | 辅助信息 | 诊断书、动作建议、分析结果 |
| **状态栏** | 状态反馈 | API 连接状态、当前会话信息 |

## 6. 交互流程设计

### 6.1 首次启动流程

```
应用启动
    ↓
检查 API 配置
    ↓
未配置 → 显示 API 配置页面
    ↓
用户填写配置
    ↓
点击"测试连接"
    ↓
成功 → 进入主聊天界面
失败 → 显示错误，保持配置页面
```

### 6.2 对话交互流程

```
用户在输入框输入消息
    ↓
点击发送 (或 Ctrl+Enter)
    ↓
消息添加到消息列表
    ↓
显示"AI 正在输入..."
    ↓
调用 chat:send IPC
    ↓
接收流式数据 (chat:stream:data)
    ↓
实时更新 AI 回复（打字机效果）
    ↓
流结束 (chat:stream:end)
    ↓
触发诊断分析
    ↓
更新诊断面板
    ↓
保存会话到 SQLite
```

### 6.3 诊断面板更新流程

```
AI 回复完成
    ↓
主进程调用 diagnosisEngine.analyzeMessage()
    ↓
生成 DiagnosisEntry
    ↓
通过 IPC 发送 diagnosis:update
    ↓
diagStore 更新状态
    ↓
DiagnosisPanel 重新渲染
    ↓
显示识别到的病症
    ↓
显示建议教学动作
    ↓
更新置信度条
```

### 6.4 态度档位切换流程

```
用户点击态度档位按钮
    ↓
AttitudeSwitch 组件更新本地状态
    ↓
调用 configStore.setAttitudeLevel()
    ↓
通过 IPC 保存到主进程
    ↓
主进程更新 electron-store
    ↓
返回确认
    ↓
UI 显示切换成功提示
    ↓
后续对话使用新的态度档位
```

### 6.5 会话管理流程

```
用户点击"新会话"
    ↓
调用 session:create IPC
    ↓
主进程创建新会话，返回 sessionId
    ↓
chatStore 更新 currentSession
    ↓
侧边栏显示新会话
    ↓
主内容区清空消息列表
    ↓
用户开始新对话
```

### 6.6 训练任务交互流程

```
用户点击侧边栏"训练任务"
    ↓
导航到 /tasks 页面
    ↓
调用 tasks:list IPC
    ↓
加载任务列表
    ↓
显示任务卡片
    ↓
用户点击"查看详情"
    ↓
展开任务详情模态框
    ↓
显示任务描述、要求、禁忌词
    ↓
用户点击"标记完成"
    ↓
调用 tasks:progress IPC
    ↓
更新任务状态为 completed
    ↓
刷新任务列表
```

## 7. 响应式设计

### 7.1 断点定义

虽然桌面应用窗口大小相对固定，但需要考虑用户调整窗口大小时的响应式行为：

| 断点 | 宽度范围 | 布局调整 |
|------|----------|----------|
| **宽屏** | ≥ 1200px | 完整三栏布局 |
| **中屏** | 1000px - 1199px | 三栏布局，右侧面板缩小到 280px |
| **窄屏** | 900px - 999px | 右侧面板折叠，显示为抽屉式 |
| **最小** | < 900px | 不允许（最小宽度限制） |

### 7.2 响应式行为

| 场景 | 行为 |
|------|------|
| 窗口宽度 < 1100px | 右侧面板自动折叠为可展开抽屉 |
| 窗口宽度 < 1000px | 侧边栏可折叠，默认折叠状态 |
| 窗口高度 < 700px | 输入框高度减小，消息列表滚动 |
| 窗口高度 < 600px | 不允许（最小高度限制） |

### 7.3 组件响应式

| 组件 | 响应式行为 |
|------|------------|
| 侧边栏 | 可折叠为 60px 图标栏 |
| 右侧面板 | 可折叠为抽屉式，从右侧滑入 |
| 消息列表 | 自动调整消息气泡最大宽度 |
| 输入框 | 高度自适应，但不超过 200px |
| 任务卡片 | 宽度自适应，保持最小宽度 |

## 9. 设计准出标准 (DoD)

根据 R-004 规则，本设计方案的开发阶段准出标准如下：

### 9.1 M1 阶段 DoD（核心聊天界面）

1. **用户能够看到三栏布局（侧边栏、主内容区、右侧面板）**
   - 验证：应用启动后显示三栏布局，各区域有明确的视觉边界
   - 测量：目视检查，布局符合设计稿

2. **聊天界面能够正常显示消息列表（用户消息和 AI 消息）**
   - 验证：发送消息后，消息正确显示在消息列表中，用户消息和 AI 消息有不同的视觉样式
   - 测量：发送至少 3 条消息，验证显示正确

3. **AI 回复支持流式输出（打字机效果）**
   - 验证：AI 回复逐字显示，有光标闪烁效果
   - 测量：观察输出过程，确认流畅无卡顿

### 9.2 M2 阶段 DoD（诊断功能）

1. **诊断面板能够显示识别到的病症和严重度**
   - 验证：每轮对话后，诊断面板更新显示识别到的病症
   - 测量：输入已知病症文本，验证诊断结果正确

2. **诊断面板能够显示建议教学动作**
   - 验证：诊断面板显示与病症对应的建议动作
   - 测量：触发至少 2 种不同病症，验证动作建议正确

3. **置信度条正确显示诊断置信度**
   - 验证：置信度条的进度与诊断置信度匹配
   - 测量：对比诊断数据与 UI 显示

### 9.3 M3 阶段 DoD（数据持久化）

1. **会话能够跨应用重启保持**
   - 验证：关闭应用后重新打开，之前的会话和消息仍然存在
   - 测量：创建会话、发送消息、重启应用、验证数据

2. **API 配置能够持久化保存**
   - 验证：配置 API 后重启应用，配置仍然有效
   - 测量：配置 API、重启应用、测试连接

3. **态度档位切换能够持久化**
   - 验证：切换态度档位后重启应用，档位保持
   - 测量：切换档位、重启应用、验证档位

### 9.4 M4 阶段 DoD（训练任务）

1. **训练任务页面能够显示任务列表**
   - 验证：导航到训练任务页面，显示 T001-T014 任务卡片
   - 测量：检查任务数量和基本信息

2. **任务状态能够更新（待开始 → 进行中 → 已完成）**
   - 验证：点击"标记完成"后，任务状态正确更新
   - 测量：操作至少 2 个任务，验证状态变化

3. **任务进度能够持久化保存**
   - 验证：更新任务进度后重启应用，进度保持
   - 测量：更新进度、重启应用、验证进度

### 9.5 M5 阶段 DoD（参考文件）

1. **参考文件页面能够列出所有参考文件**
   - 验证：显示动作库、病症手册、训练任务库等文件
   - 测量：检查文件列表完整性

2. **能够查看参考文件内容**
   - 验证：点击文件后显示文件内容，支持 Markdown 渲染
   - 测量：打开至少 3 个不同文件，验证内容正确

3. **参考文件搜索功能正常工作**
   - 验证：输入关键词后能够过滤文件列表
   - 测量：使用不同关键词搜索，验证结果正确
