---

## 一、蒸馏流程

每次蒸馏必须按以下四个阶段执行，不可跳过：

```
阶段 1：解构 → 拆解源工具的结构和功能
阶段 2：分类 → 按"直接可用 / 教学可用 / 改造后可用"三层分类
阶段 3：转化 → 将每个可用内容转化为教学零件
阶段 4：对接 → 将教学零件对接到月笙现有体系
```

## 三、阶段 2：分类模板

### 3.1 三层分类标准

对每个功能模块和提示词，必须按以下三层分类：

#### A 层：直接可用（技法类）

**定义**：源工具中的技法、框架、结构可以直接作为教学内容使用，无需改造。

**判断标准**：
- [ ] 这个技法是否教用户"怎么写"而不是帮用户"写出来"？
- [ ] 这个技法是否具有普适性（不依赖特定工具）？
- [ ] 这个技法是否能对应到月笙已有的某个症候？

**记录模板**：
```markdown
### A 层：直接可用

| 编号 | 来源模块 | 技法名称 | 技法描述 | 对应症候 | 对应训练 |
|------|---------|---------|---------|---------|---------|
| A-01 | | | | | |
```

#### B 层：教学可用（稍作改造）

**定义**：源工具的内容需要调整提问方式或呈现形式，但可以转化为教学材料。

**判断标准**：
- [ ] 这个内容是否能从"填空题"改为"思考题"？
- [ ] 这个内容是否能从"AI 代劳"改为"用户自学"？
- [ ] 这个内容是否能从"生成结果"改为"理解原理"？

**记录模板**：
```markdown
### B 层：教学可用

| 编号 | 来源模块 | 原始内容 | 改造方向 | 改造后内容 | 对应症候 |
|------|---------|---------|---------|-----------|---------|
| B-01 | | | | | |
```

#### C 层：改造后可用（核心价值提取）

**定义**：源工具的核心思路有价值，但需要大幅改造才能用于教学。

**判断标准**：
- [ ] 这个思路的底层逻辑是什么？
- [ ] 这个底层逻辑如何转化为教学行为？
- [ ] 转化后的教学行为是否提高用户成长速度？

**记录模板**：
```markdown
### C 层：改造后可用

| 编号 | 来源模块 | 核心价值 | 改造方式 | 教学转化 | 对应症候 |
|------|---------|---------|---------|---------|---------|
| C-01 | | | | | |
```

### 3.2 排除清单

**定义**：与月笙"教用户写"的核心目标冲突的内容，必须明确排除。

**排除标准**：
- [ ] 是否帮用户代写内容？（如正文生成、润色、填充）
- [ ] 是否让用户依赖工具而非提升自身能力？
- [ ] 是否与月笙已有的诊断逻辑冲突？

**记录模板**：
```markdown
### 排除清单

| 编号 | 来源模块 | 排除原因 | 替代方案（如有） |
|------|---------|---------|----------------|
| X-01 | | | |
```

## 六、蒸馏质量检查清单

每次蒸馏完成后必须执行以下检查：

### 6.1 第一性原理校准

- [ ] 每个教学零件是否解决了具体的用户问题？
- [ ] 如果删除这个零件，用户是否仍能完成"发现→理解→训练→成长"？
- [ ] 这个零件是帮助教学，还是帮助系统理解小说？
- [ ] 这个零件是否明确提高新人作者的成长速度？
- [ ] 这个零件是否能转化为诊断/训练/评估能力？

### 6.2 去代写检查

- [ ] 教学零件中是否包含任何"AI 帮你写"的内容？
- [ ] 教学零件是否会让用户产生对工具的依赖？
- [ ] 教学零件的输出是否是"用户能力提升"而非"内容产出"？

### 6.3 降级检查

- [ ] 讲解是否避免了学术术语？
- [ ] 案例是否使用网络文学而非经典文学？
- [ ] 练习是否在 10-15 分钟内可完成？
- [ ] 评估标准是否具体可验证？
