
## 二、当前问题

### P1：主内容区不堪重负

ChatView 和 TrainingWorkshop 共享同一个 flex:1 的区域，通过 centerMode 二选一。用户想要"边聊边对照训练"时做不到——两者是互斥的。

```
对话中 → 发现训练推荐 → 点进训练 → ChatView 被替换成 TrainingWorkshop
       → 训练完 → 点返回 → 重新看到 ChatView
       → 想再对比训练结果 → 又要切进去
       → ❌ 反复切换，体验断裂
```

### P2：无法承接更多功能

已完成待补的新手功能（创作地图、成就墙、脚手架工具）和已有的进阶任务（F-05 看点可视化、F-06 伏笔追踪等）都需要**独立的内容空间**。当前架构只能"替换聊天区"，不能"并行展示"。

### P3：RightPanel 信息过密

右侧 340px 面板同时承载：诊断症候（分层反馈）、能力画像、成长趋势折线图、训练历史。加上未来要加的 SF 系列报告（情绪曲线、POV分布），空间明显不够。

### P4：无 New Feature 扩展点

新增一个功能需要：
1. 在 App.tsx 加条件渲染分支
2. 在 training.store 或加新 store 控制显隐
3. 在 AppSidebar 加入口按钮
4. 在 RightPanel 找一个角落塞数据

每加一个功能就牵动所有组件，耦合度高。

## 五、UI 演进方向

### 方向 A：Tab 标签栏（推荐）

```
┌───────────────────────────────────────────────┐
│  AppHeader                                     │
├──────────┬──────────────────────┬──────────────┤
│ Sidebar  │  [对话] [训练] [成就] [地图] [工具] │              │
│ (保留)   │  ┌───────────────────────────────┐  │  RightPanel  │
│          │  │  当前 Tab 全宽展示            │  │  (保留)      │
│          │  │  Tab 1: ChatView（现有）      │  │              │
│          │  │  Tab 2: TrainingWorkshop（扩）│  │              │
│          │  │  Tab 3: 成就墙（N-01 新建）   │  │              │
│          │  │  Tab 4: 创作地图（N-03 新建） │  │              │
│          │  │  Tab 5: 脚手架（N-02 新建）   │  │              │
│          │  └───────────────────────────────┘  │              │
└──────────┴──────────────────────┴──────────────┘
```

**核心变更**：
- AppShell 骨架不动，Sidebar 和 RightPanel 保留
- Main Content 从 `centerMode` 二选一 → TabBar + 多 Tab 路由
- 每个 Tab 一个独立视图组件，通过 URL-like 状态切换
- Tab 之间状态隔离（各自保持 scroll position、输入内容）
- TabBar 固定在顶部（~48px），不占内容高度

**优点**：
- 改造成本最低（不涉及 AppShell 重构，只改 Main Content 内部）
- 横向扩展性强——加功能=加 Tab
- 学 Greate Scrivener、VS Code 的成熟模式，用户心理模型清晰
- Tab 之间可以独立收放 RightPanel

**缺点**：
- Tab 多了会拥挤（5+ 个可能需要 dropdown 或滚动）
- 无法并排看两个 Tab（比如边聊天边看成就不行）

**改造工作量**：约 3-5 天
- TabBar 组件 + TabContext：1d
- App.tsx 视图路由改造：1d
- 现有组件适配（ChatView / TrainingWorkshop 保持 props 接口不变）：1d
- 新建 Tab 壳组件 + 迁移 store：1-2d

---

### 方向 B：独立窗口（Electron 多窗口）

```
主窗口（三栏结构不变）                   辅助窗口（弹窗）
┌───────────────────────┐               ┌──────────────────────┐
│  Sidebar │ Chat │ Diag│               │  创作地图（全屏）     │
│          │      │     │  点击"创作地图" │                      │
│          │      │     │  ──────────►  │  进度条里程碑         │
│          │      │     │               │  成就徽章网格         │
│  (保留现有结构不变)   │               │                       │
└───────────────────────┘               └──────────────────────┘
```

**核心变更**：
- 主窗口保持现有三栏结构，只负责对话+基础诊断
- 进阶功能（创作地图、成就、脚手架、看点可视化）打开独立 BrowserWindow
- 通过 IPC 在主窗口和辅助窗口之间同步数据

**优点**：
- 界面干净，新手不会被高级功能吓到
- 辅助窗口可全屏，沉浸感强
- 功能模块物理隔离，互不干扰

**缺点**：
- Electron 多窗口状态同步复杂（跨窗口 store 同步）
- 窗口管理（位置、大小、关闭）增加大量模板代码
- 用户可能搞不清"为什么这个功能在另一个窗口"
- 维护成本高（需要对 Electron BrowserWindow 做专门管理）

**改造工作量**：约 7-10 天
- 窗口管理器 service：2d
- IPC 跨窗口状态同步：2d
- 各功能窗口组件：1-2d/个
- 窗口布局记忆 + 系统托盘等：2d

---

### 方向 C：侧栏 Tab 扩展（最小改动）

```
┌───────────────────────────────────────────────┐
│  Header                                        │
├──────────┬──────────────────────┬──────────────┤
│ Sidebar  │  Main Content        │  RightPanel  │
│ (280px)  │  (chat/training)     │  (诊断)      │
│          │                      │              │
│ 会话列表  │  不变                │  新增：      │
│ 功能入口  │                      │  ┌────────┐  │
│ ──────── │                      │  │成就微件│  │
│ [成就]   │                      │  │地图微件│  │
│ [地图]   │                      │  │工具入口│  │
│ [工具]   │                      │  └────────┘  │
└──────────┴──────────────────────┴──────────────┘
```

**核心变更**：
- 不改变主内容区结构，ChatView / TrainingWorkshop 不变
- 新功能（成就、地图）作为 RightPanel 的子面板/微件
- 或者 Sidebar 新增功能入口，点击后弹出 Modal 覆盖

**优点**：改动最小（1-2 天）
**缺点**：RightPanel 只有 340px，塞更多微件只会更挤。治标不治本。

**改造工作量**：约 1-2 天
- RightPanel 新增 tab 切换：0.5d
- 各微件组件：0.5d/个

## 六、推荐策略

**短期（当前 Phase）→ 方向 C**：先把 N-04(训练目标追踪) 和 N-05(故事进度条) 塞进 RightPanel 或 TrainingWorkshop 内部，最小代价验证新手功能价值。

**中期（下一 Phase）→ 方向 A**：确认新手功能有价值后，做 Tab 标签栏重构，统一承接全部新功能。Sidebar 加"创作"、"成就"入口按钮，RightPanel 保留诊断专用。

**长期（视需求）→ 方向 B**：如果用户量增长、功能复杂度持续上升，考虑辅助窗口做"创作实验室"（看点可视化、伏笔追踪等老手工具）。

## 七、讨论要点

以下问题需外围 AI 区域讨论确定：

1. **方向 A vs 方向 B vs 方向 C**：选哪个作为主方向？
2. **Tab 标签的粒度**：每个功能独立 Tab，还是分组（如"创作"Tab 里包含地图+成就）？
3. **RightPanel 的未来角色**：继续承载诊断+微件，还是纯诊断专用？
4. **Sidebar 扩展**：是否需要在 Sidebar 增加"功能导航"（如现在只有会话列表）？
5. **Tab 数量上限**：当 Tab > 7 个时如何处理？（滚动 vs 折叠 vs 分组）
6. **多窗口的门槛**：何时触发从方向 A 切换到方向 B？
