## 一、设计哲学

### 1.1 设计方向

**"专注的工坊"**

月笙不是写作工具，是写作教练。设计语言要传达：**安静、专注、有安全感**——让作者放下防御，沉浸在教学对话中。

设计关键词：
- **安静**：低视觉噪音，浅色为主，白底 + 柔和阴影
- **专注**：内容区最大化，去掉不必要的装饰元素
- **温度**：柔和曲线（corner radius 12px+）、暖灰色文字、微动效

### 1.2 与品牌的一致性

| 品牌属性 | 设计表达 |
|---------|---------|
| 教练（非工具） | 对话式布局优先于面板式布局 |
| 感性（非机器） | 圆角、暖色调、微交互动效 |
| 专业（非焦虑） | 干净排版、克制的色彩、充足留白 |

## 二、色彩系统

### 2.1 主色板

```css
/* CSS Variables */
:root {
  /* 基础色 */
  --color-bg: #FAFAF8;           /* 主背景：米白暖底 */
  --color-surface: #FFFFFF;       /* 卡片/面板背景：纯白 */
  --color-surface-secondary: #F3F2EF;  /* 次级表面：暖灰 */
  --color-border: #E8E6E1;        /* 边框：柔和暖灰 */
  --color-border-light: #F0EFEC;  /* 轻边框 */

  /* 文字色 */
  --color-text-primary: #2C2C2C;    /* 主文字：深灰（非纯黑，更柔和） */
  --color-text-secondary: #6B6B6B;  /* 次级文字 */
  --color-text-tertiary: #9C9C9C;   /* 辅助文字 */
  --color-text-inverse: #FFFFFF;    /* 反色文字 */

  /* 品牌色 */
  --color-accent: #C0776E;        /* 主品牌色：暖陶土色（月笙的感性） */
  --color-accent-light: #F0D5D0;  /* 品牌色浅色 */
  --color-accent-dark: #A05A52;   /* 品牌色深色 */

  /* 语义色 */
  --color-success: #7AB87A;        /* 成功/已验证：柔绿 */
  --color-warning: #D4A84B;        /* 警告/待验证：暖黄 */
  --color-error: #C4736B;          /* 错误：柔红 */
  --color-info: #7A9EC0;           /* 信息：柔蓝 */

  /* 功能色 */
  --color-highlight: #FDF6E9;     /* 高亮背景：用于诊断标记 */
  --color-overlay: rgba(44, 44, 44, 0.4);  /* 遮罩层 */
}
```

### 2.2 色彩使用原则

| 用途 | 使用色 | 说明 |
|------|--------|------|
| 页面背景 | `--color-bg` #FAFAF8 | 暖底降低视觉疲劳 |
| 卡片背景 | `--color-surface` #FFF | 白底干净，信息清晰 |
| 可交互元素 | `--color-accent` #C0776E | 唯一动作指引色 |
| 链接/hover | `--color-accent-dark` #A05A52 | 品牌色加深 |
| 禁用态 | `--color-border` #E8E6E1 | 灰色弱化 |
| 成功/正确 | `--color-success` #7AB87A | 不抢品牌色 |
| 错误/问题 | `--color-error` #C4736B | 柔和不刺眼 |

## 三、排版系统

### 3.1 字体选型

```css
/* 主字体 */
--font-sans: 'DM Sans', 'Noto Sans SC', system-ui, sans-serif;
/* 等宽 - 用于代码/示范 */
--font-mono: 'JetBrains Mono', 'Noto Sans Mono', monospace;
```

**选型理由**：
- **DM Sans**：几何现代感，与暖色搭配不生硬，字重递进明显
- **Noto Sans SC**：中文字体兼容，与 DM Sans 风格协调
- **JetBrains Mono**：等宽用于写作示范片段，视觉上区分"教的内容"和"教的对话"

### 3.2 字号层级

```css
--text-xs: 0.75rem;    /* 12px — 辅助信息 */
--text-sm: 0.875rem;   /* 14px — 次级文字 */
--text-base: 1rem;     /* 16px — 正文 */
--text-lg: 1.125rem;   /* 18px — 重要正文 */
--text-xl: 1.375rem;   /* 22px — 小标题 */
--text-2xl: 1.75rem;   /* 28px — 中标题 */
--text-3xl: 2.25rem;   /* 36px — 大标题 */
--text-4xl: 3rem;      /* 48px — 展示标题 */
```

### 3.3 行高

```css
--leading-tight: 1.25;    /* 标题/紧凑 */
--leading-normal: 1.5;    /* 正文 */
--leading-relaxed: 1.75;  /* 长文阅读 */
```

**正文（Chat 消息）使用 `--leading-relaxed`**，这是故意设计的——当用户读自己的作品反馈时，宽松行高降低心理防御。

## 四、间距与布局

### 4.1 间距系统

```css
--space-1: 0.25rem;   /* 4px */
--space-2: 0.5rem;    /* 8px */
--space-3: 0.75rem;   /* 12px */
--space-4: 1rem;      /* 16px — 基础间距 */
--space-5: 1.5rem;    /* 24px */
--space-6: 2rem;      /* 32px */
--space-8: 3rem;      /* 48px */
--space-10: 4rem;     /* 64px */
--space-12: 5rem;     /* 80px */
```

### 4.2 圆角系统

```css
--radius-sm: 8px;       /* 小元素（Badge/标签） */
--radius-md: 12px;      /* 卡片/面板 */
--radius-lg: 16px;      /* 大卡片/模态框 */
--radius-xl: 20px;      /* 侧边栏/容器 */
--radius-full: 9999px;  /* 圆形/药丸 */
```

**核心设计原则**：所有可交互元素都有 `--radius-md` 以上的圆角。「柔和曲线」体现为 **无直角**——即使是按钮也是圆角而非直角矩形。

### 4.3 阴影

```css
--shadow-sm: 0 1px 2px rgba(44, 44, 44, 0.05);
--shadow-md: 0 4px 12px rgba(44, 44, 44, 0.08);
--shadow-lg: 0 8px 24px rgba(44, 44, 44, 0.10);
--shadow-xl: 0 16px 48px rgba(44, 44, 44, 0.12);
```

阴影使用暖灰黑色（而非冷黑），保持色调一致。

### 5.2 内容组件

#### MessageBubble（聊天消息）

| 类型 | 对齐 | 背景 | 圆角 |
|------|------|------|------|
| 用户 | 右 | `--color-accent` | `--radius-lg`（右下角 `--radius-sm`）|
| 月笙 | 左 | `--surface-secondary` | `--radius-lg`（左下角 `--radius-sm`）|
| 系统 | 居中 | 无 | 居中文字 |

**消息头**：用户头像用 ini 首字母圆形，月笙用笔形图标。
**时间戳**：微弱灰色，hover 显示完整时间。
**代码块**：`--font-mono`，浅灰底 `--surface-secondary`。

#### DiagnosisCard（M-5 简化诊断卡片）

诊断卡片是 Chat 流中的一个嵌入组件，**不是独立页面**：

```
┌─── Diagnosis Card ─────────────────────┐
│  📋 分析摘要                           │
│  "意图'底层挣扎'与执行'筑基中期'矛盾"   │
│                                        │
│  ┌── Highlight ──────────────────────┐ │
│  │ "筑基中期。普通散修资质..."       │ │
│  └──────────────────────────────────┘ │
│                                        │
│  定位根因 →                          │
│  尝试修改 →                          │
└────────────────────────────────────────┘
```

| 元素 | 说明 |
|------|------|
| 摘要 | 带品牌色左边框（`--color-accent`） |
| Highlight | 原文段落，带柔和黄底 `--color-highlight` |
| 操作按钮 | "定位根因"（展开详细诊断）和"尝试修改"（M-2） |
| 定位根因展开 | 展开显示 rootCause + 技法推荐（不提编号，提来源作品） |

**关键设计**：诊断卡片默认折叠，只显示摘要。点击"定位根因"展开详情。不展示 Evidence、置信度分数等内部概念。

#### EditPanel（M-2 修改原文入口）

诊断卡片中点击"尝试修改"后展开的内联编辑区：

```
┌─── 修改这段 ──────────────────────────┐
│                                        │
│  ┌── 原文 ──────────────────────────┐ │
│  │ (不可编辑的灰色原文)              │ │
│  └──────────────────────────────────┘ │
│                                        │
│  ┌── 你的修改 ─────────────────────┐ │
│  │ (可编辑区域，placeholder 引导)   │ │
│  └──────────────────────────────────┘ │
│                                        │
│  [取消]           [提交评估 →]        │
└────────────────────────────────────────┘
```

| 元素 | 说明 |
|------|------|
| 原文区 | 灰色底 `--surface-secondary`，只读 |
| 编辑区 | 白色底，聚焦时 `--color-accent` 外发光 |
| 提交 | 调用 `diagnosis:submitRewrite` IPC |
| 取消 | 收起面板 |

#### EvaluationCard（M-3 AI 修改评估）

提交修改后，月笙返回评估结果，作为新消息展示：

```
┌─── 修改评估 ─────────────────────────┐
│  ✅ 这个改法有效                      │
│                                        │
│  你的修改用"摸符箓"替代了"资源稀缺"    │
│  的旁白说明——这个小场景让读者自己       │
│  感受到主角的处境。                    │
│                                        │
│  建议再试一步：如果在这个动作之后       │
│  加一个环境细节（比如阴冷的风吹过他     │
│  后颈），氛围会更完整。                │
│                                        │
│  ───                                  │
│  对比之前：                           │
│  ❌ "筑基中期。普通散修资质..."        │
│  ✅ "他摸了摸腰间仅剩的两张匿气符"     │
└────────────────────────────────────────┘
```

| 元素 | 说明 |
|------|------|
| 状态标签 | ✅ 有效 / ⚠️ 部分有效 / ❌ 需要调整 |
| 评语 | 月笙风格：先肯定再给建议 |
| 对比视图 | 旧写法 vs 新写法的并置对比 |
| 下一步 | 可选：继续修改 / 进入训练 |

#### GrowthCard（M-4 一句话成长记录）

### 5.3 通用组件

#### Button

| 变体 | 背景 | 圆角 | 适用场景 |
|------|------|------|---------|
| primary | `--color-accent` | `--radius-md` | 主要操作 |
| secondary | `--surface-secondary` | `--radius-md` | 次要操作 |
| ghost | 无（hover 时显示背景） | `--radius-md` | 文字操作 |
| danger | `--color-error` | `--radius-md` | 危险操作 |

所有按钮 hover 时有 `translateY(-1px)` + `--shadow-sm` 的微动效。点击时有 `scale(0.97)` 反馈。

#### Badge

| 变体 | 背景色 | 用途 |
|------|--------|------|
| accent | `--color-accent-light` | 内部标签（技法/症候） |
| success | `--color-success` 浅色版 | 已验证 |
| warning | `--color-warning` 浅色版 | 待验证 |
| error | `--color-error` 浅色版 | 有问题 |

#### Input / Textarea

- 聚焦时 `--color-accent` 外发光（`box-shadow`）
- 圆角 `--radius-md`
- placeholder 使用 `--color-text-tertiary`

## 六、交互模式

### 6.1 微交互动效

| 场景 | 动效 | 时长 |
|------|------|------|
| 页面加载 | 内容区淡入 + 上移 8px | 400ms |
| 切换功能区 | Sidebar 内容交叉淡出/淡入 | 200ms |
| 编辑面板展开 | 高度动画 + 淡入 | 300ms |
| 评估卡片出现 | 左侧品牌色边框滑动至右侧 | 500ms |
| 按钮 hover | 上移 1px + 阴影 | 150ms |
| 按钮点击 | scale 0.97 | 100ms |
| 消息出现 | 淡入 + 轻微上移 | 300ms |
| 诊断卡片展开 | 高度动画 + 内容淡入 | 250ms |

**所有动效使用 `cubic-bezier(0.4, 0, 0.2, 1)`**，保持一致的缓动曲线。

### 6.2 诊断→修改→评估 流程

这是 MVP 的核心交互流，应确保每个转场自然：

```
用户上传文本
    ↓ (自动)
Diagnosis Card 出现在月笙消息中（默认折叠）
    ↓ (用户点击"定位根因")
展开诊断详情
    ↓ (用户点击"尝试修改")
EditPanel 内联展开在 Chat 流中
    ↓ (用户修改后提交)
EvaluationCard 作为新消息显示
    ↓ (自动)
GrowthCard 显示进步摘要
```

### 6.3 空状态

| 场景 | 显示内容 |
|------|---------|
| 无会话 | 居中：笔形图标 + "写点什么，我们聊聊" |
| 会话无消息 | 底部：发送第一条消息的引导 |
| 无诊断记录 | "还没有诊断记录，上传文本开始分析" |
| 无可比历史 | "这是你的第一次诊断" |

## 八、可访问性

| 标准 | 实现方式 |
|------|---------|
| 色彩对比 | 所有文字与背景对比度 ≥ 4.5:1 |
| 焦点可见 | 聚焦元素有 `outline: 2px solid --color-accent` |
| 语义标签 | 按钮使用 `aria-label`，可交互区域有 `role` 属性 |
| 动效减敏 | 通过 `prefers-reduced-motion` 禁用动效 |
| 字体缩放 | 所有尺寸使用 rem，支持浏览器字体缩放 |
