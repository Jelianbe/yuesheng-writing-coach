## 零、为什么三管齐下

月笙的核心教学链路是：

```
用户作品 → 发现问题 → 解释原因 → 制定训练 → 执行训练 → 验证进步 → 形成能力
```

三条蒸馏路径分别回答这个链路中的三个核心问题：

| 蒸馏路径 | 回答的问题 | 产出 | 对接位置 |
|---------|-----------|------|---------|
| **小说技法蒸馏** | 教什么？ | 可执行的写作技法 | technique-library.json → 训练推荐 |
| **AI工具Prompt蒸馏** | 怎么反馈？ | 反馈模式 + 教学策略素材 | diagnosis-agent-prompt → 诊断反馈 |
| **教育学理论蒸馏** | 为什么这样教？ | 教学方式决策规则 | TeachingStrategyRouter → 教学方式选择 |

三者关系：

```
小说技法蒸馏（教什么）
    ↓ 提供训练内容
AI工具Prompt蒸馏（怎么反馈）
    ↓ 提供反馈模式
教育学理论蒸馏（为什么这样教）
    ↓ 提供决策依据
    → TeachingStrategyRouter（Phase 3）
```

### 2.4 蒸馏流程（简化版，2阶段）

原5步流程简化为2阶段，因为"三遍阅读法"和"交叉对比"在实际执行中合并更高效：

```
阶段 1：定向提取
  1. 按症候选择作品和章节
  2. 阅读目标章节，标记与该症候相关的写法
  3. 对每个标记执行必要性过滤 + 可教性过滤（同 DISTILLATION_GUIDE_V1.md 第3步）
  4. 通过过滤的技法进入结构化

阶段 2：结构化入库
  1. 按技法模板结构化（编号、名称、难度、适用症候、来源、说明、训练方法）
  2. 写入 technique-library.json（机器可读）
  3. 写入 docs/teaching/technique-library/ 对应分类文档（人可读）
  4. 更新 index_V1.md 索引
```

### 3.3 蒸馏策略调整

原4阶段流程（解构→分类→转化→对接）保留，但做以下调整：

#### 调整1：症候映射更新

原模板中的症候定义已过时，需替换为当前体系：

```
旧定义（distillation-template_V1.md）：
  P002: 能力通货膨胀
  P003: 角色悬浮
  P006: 情绪失重
  P007: 节奏平淡

  P002: 角色工具人化
  P003: 情绪标签化

  P007: 阅读结构单一
  P010: OC平面化
```

#### 调整2：蒸馏重点聚焦

不是所有 AI 写作工具都值得蒸馏。聚焦以下维度：

| 维度 | 关注点 | 排除点 |
|------|--------|--------|
| 反馈模式 | 怎么给用户反馈？直接/提问/打分/重写建议 | 纯生成类功能 |
| 用户控制 | 用户能控制什么？控制粒度如何？ | 一键生成类 |
| 教学假设 | 工具隐含了什么教学理念？ | 无教学意图的工具 |
| 结构化输出 | 输出是否有结构？结构是否可转化为教学？ | 纯文本输出 |

#### 调整3：新增"月笙已有技法"边界检查

蒸馏前先确认月笙技法库已有什么，避免重复提取：

```
蒸馏前检查：
  □ 该技法是否已在 technique-library.json 中？
  □ 如果已有，新蒸馏的版本是否有增量价值？
  □ 如果没有，是否对应月笙的某个症候？
```

## 四、路径三：教育学理论蒸馏（T-028，Phase 3）

### 4.1 现状

| 维度 | 数据 |
|------|------|
| 概念文档 | teaching-strategy-router_V1.0.md（决策树概念） |
| 笔记 | teaching-strategy-notes.md（缺口分析） |
| 执行记录 | 无 |

### 4.2 目标

回答核心问题：**"当用户犯X错误时，Y教学方式为什么比Z更有效？"**

为 TeachingStrategyRouter 提供理论依据和决策规则。

### 4.3 蒸馏策略：按问题定向查找

**不是通读教育学，而是按问题找理论。** 每个问题找到 2-3 个相关理论，提取核心原则，转化为可执行规则。

#### 定向蒸馏问题清单

| 编号 | 核心问题 | 目标理论 | 预期产出 |
|------|---------|---------|---------|
| Q1 | 初学者 vs 进阶者，教学方式应如何不同？ | Vygotsky 最近发展区 / Bruner 脚手架理论 | userLevel → teachingMode 映射规则 |
| Q2 | 什么时候"先给案例再模仿"，什么时候"先反思再练习"？ | Schön 反思性实践 / Bandura 社会学习理论 | syndromeType → feedbackMode 决策规则 |
| Q3 | 如何让用户"愿意做训练"而非跳过？ | 自我决定理论（Deci & Ryan）/ 游戏化学习 | motivationStrategy 选择规则 |
| Q4 | 同一错误反复出现时，教学策略如何调整？ | 刻意练习理论（Ericsson）/ 元认知策略 | repetitionCount → escalationMode 规则 |
| Q5 | 多个症候同时存在时，教学优先级如何决定？ | 认知负荷理论（Sweller）/ 教学设计理论 | syndromePriority 排序规则 |

### 4.4 蒸馏流程（2阶段）

```
阶段 1：理论定向提取
  1. 按问题清单逐项查找相关理论
  2. 每个理论提取：
     - 理论名称 + 核心原则（≤100字）
     - 月笙应用场景（对应哪个症候/哪个教学阶段）
     - 教学方式建议（具体的，不是抽象的）
  3. 产出格式：theoryFragments 数组

阶段 2：规则转化
  1. 将理论转化为可执行的决策规则
  2. 格式：condition → recommendedMode + rationale
  3. 示例：
     {
       condition: { userLevel: "beginner", syndromeSeverity: "L2" },
       recommendedMode: "案例驱动",
       rationale: "Vygotsky ZPD: 初学者需要脚手架支撑",
       source: "Q1-Vygotsky"
     }
```

### 4.5 产出文档

```
docs/research/education-theory-distillation_V1.0.md  # 研究报告
resources/config/education-theory-fragments.json     # 机器可读的决策规则（Phase 3 使用）
```

### 4.6 DoD

1. 5 个定向问题各有 ≥2 个理论支撑
2. 每个理论都有月笙应用场景和教学方式建议
3. 产出 ≥10 条可执行的决策规则（condition → recommendedMode）
4. 决策规则格式与 TeachingStrategyRouter 概念文档对齐
