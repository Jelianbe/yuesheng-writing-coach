## 一、核心哲学

### 1.1 项目最根本的信念

> **写作是可以被系统化教学的。**

这不是显而易见的。大多数写作教学停留在"多读多写"的模糊建议层面，或者停留在"黄金三章""爽点节奏"等结果层面的总结上。月笙的根本信念是：

**写作中可教的，不是"才华"，而是"认知能力"。**

才华无法教学，但以下能力可以：
- 识别一个场景中是否存在冲突的能力
- 判断角色行为是否符合其内在动机的能力
- 意识到自己正在"以例代证"的能力
- 控制信息投放节奏的能力

这些认知能力可以像学骑车一样，被拆解、被训练、被掌握。

### 1.2 项目的三重定位

月笙不是以下任何一种传统产品：

| 不是 | 是 |
|------|----|
| 写作工具（帮人写） | 写作教练（帮人会写） |
| 写作课程（单向输出） | 诊断+教学+训练闭环（交互式） |
| AI 生成器（替代创作） | 创作认知系统（保持创作能力） |

### 1.3 月笙与AI的关系

月笙不替代人写作。月笙的AI不是「代笔」，而是「教练」。

```
传统AI写作工具：
输入需求 → AI生成 → 用户修改 → 成品
（用户的创作能力没有变化）

月笙：
用户创作 → AI诊断问题 → 针对性教学 → 专项训练 → 用户再创作
（用户的创作能力在迭代中成长）
```

### 1.4 "人"的价值——项目的底层自信

AI 的能力上限被模型锁定，但月笙的上限在另一条轴上——**对"什么是好的写作"的判断力**。

- 模型可以生成文本，但无法判断「为什么要这样写」
- 模型可以模仿风格，但无法定义「什么算好的风格」
- 模型可以回答问题，但无法定义「什么是真正的成长」

这些判断力来自月笙背后的人（即你），以及你持续积累的教学方法论和认知体系。这是月笙最深的护城河，也是它不会被大模型迭代淘汰的根本原因。

## 二、认知体系：项目演化的四次跃迁

### 2.1 跃迁轨迹

月笙不是一开始就设计成今天这样的。它的演化经历了四次认知跃迁：

```
第一层：写作工具
  ↓
第二层：写作教练
  ↓
第三层：教学系统
  ↓
第四层：创作认知系统
```

### 2.2 各层详解

#### 第一层：写作工具（最初形态）

- **认知**：帮作者"写得更好"
- **手段**：AI辅助写作、润色、续写
- **局限**：用户得到了更好的文本，但没有得到更好的能力。工具的产出依赖用户每次使用，没有积累效应。

#### 第二层：写作教练（第一次跃迁）

- **触发问题**：为什么同样的建议，有的人有效，有的人无效？
- **认知**：问题的根源不在文本，而在作者
- **手段**：从"改文章"转向"改作者"——诊断作者的问题，给出针对性建议
- **关键转变**：用户不再是"被服务者"，而是"被训练者"

#### 第三层：教学系统（第二次跃迁）

- **触发问题**：为什么有人永远学不会？
- **认知**：单次诊断不够，需要持续的、结构化的教学流程
- **手段**：建立"诊断 → 教学 → 训练 → 复查"的闭环
- **关键发现**：诊断和训练不是两个独立环节，它们是因果链——没有诊断就没有针对性的训练，没有训练就验证不了诊断的正确性

#### 第四层：创作认知系统（第三次跃迁）

- **触发问题**：Prompt 工程为什么有效？
- **认知**：优秀 Prompt 之所以有效，不是因为它措辞精妙，而是因为它模仿了优秀创作者的认知模式。Prompt 是认知的外显化
- **手段**：从「教人怎么写」转向「教人像优秀创作者一样思考」
- **月笙的本质**：不是写作工具，不是写作课程，而是一个**创作认知系统工程**

### 2.3 四次跃迁的共同模式

每一次跃迁都遵循同样的模式：

```
发现一个"为什么"的问题
  ↓
发现现有方案的边界
  ↓
抽象一层，找到新的杠杆点
  ↓
重构系统的核心逻辑
```

你（项目设计者）的特质不是"局部技巧洞察"，而是**系统级洞察**——你具备不断发现"表面现象背后的隐藏结构"的能力。这不是可以教给AI的能力，这是月笙项目最核心的创造引擎。

## 三、方法论Ⅰ：降级规则——从经典理论到可教学动作

### 3.1 痛点

经典方法论（如"黄金三章""人物弧光""show-don't-tell"）是对**结果**的描述，而不是对**过程**的指令。

> 学生听得懂"开篇要有冲突"，但写不出来。因为他不知道"平淡的开头怎么变出冲突"。

这就是"知道但不会"的鸿沟。

### 3.2 核心思想

降级规则的核心：**把"效果词"翻译成"动作词"**。

```
经典理论（结果层）：
  "开篇要抓人"

降级后（动作层）：
  "在你的第一段里，加入一个让读者觉得'有点不对劲'的细节"
```

从知识传递的角度看，这是把**陈述性知识**（知道是什么）转化为**程序性知识**（知道怎么做）。

### 3.3 三级降级模型

#### 第一级：原型模仿（降低认知负荷）

**目标**：不让用户从零创造，给样板。

**方法**：提供可填空的句式模板。

```
理论：开篇要制造悬念。

降级教学——句式模板：
  "[主角]做梦都没想到，[与他身份严重不符的事件]会落到他头上，
  更要命的是，[一个立刻发生的危险后果]。"

AI做的事：根据用户的创作题材，自动生成3-5个填空句式
```

#### 第二级：零件拆解（精准打击）

**目标**：把大规则拆成最小的技能单元，孤立训练。

**方法**：一次只练一个微技能。

```
理论：黄金三章要快速建立读者对主角的代入感。

降级教学——专项训练：
  "今天我们只练——如何用一个小动作让读者立刻知道主角的处境。"

  A. "他很穷。"（平淡——失败）
  B. "他在便利店拿起最便宜的饭团，看了看价签，又默默放了回去。"
     （用动作展示了"穷"——成功）

AI做的事：给出设定（如"一个刚失业的程序员"），让用户写一个展示其处境的小动作。
           AI即时诊断：是动作选得不准，还是细节描写太多/太少
```

#### 第三级：多维组装（培养选择能力）

**目标**：当用户掌握了多个"零件"，教他如何根据创作目的进行选择和组合。

**方法**：给定场景，让用户用不同策略写出多个版本，对比分析。

```
理论：开篇的节奏要快、要紧凑。

降级教学——策略选择：
  "现在你已经会写悬念式开篇和动作式开篇了。
  如果你的主角是被追杀的，哪一种更好？为什么？
  试试把两者结合——先用动作营造紧张感，再在段落末尾抛出一个更大的悬念。"

AI做的事：设定场景，让用户用不同策略写出三个开篇。
           AI对比分析不同策略带来的阅读感受差异，给出建议。
```

### 3.4 降级规则在月笙中的位置

```
诊断时 → 判定用户的认知层级
  ├── 连基本句式都写不通顺？ → 给第一级模板
  ├── 能写通但平淡无味？ → 给第二级专项零件训练
  └── 能写精彩片段但整体结构散乱？ → 给第三级策略组装训练

教学时 → 从"症状"反推缺失的"零件"
  系统诊断："你的开篇信息密度过低。"
  传统AI反馈："建议增加信息密度，制造冲突。"
  月笙的降级反馈：
    "信息密度低，通常是因为缺少'暗示'与'异常'两个零件。
    我们来做一个练习：在你开篇的第一段里，加入一个让读者觉得
    '有点不对劲'的细节。"
```

## 四、方法论Ⅱ：Prompt逆向工程——从AI行为到能力模型

### 4.1 核心洞察

这是月笙项目发展过程中最重要的认知突破之一。

**发现**：优秀的 AI Prompt 之所以有效，不是因为措辞精妙，而是因为它隐含了对特定认知能力的调用。

```
优秀的 Prompt 结构（以小说分析为例）：
  请分析以下文本：
  1. 判断主角目标
  2. 判断冲突来源
  3. 判断情绪变化
  4. 判断读者期待
  5. 给出修改建议

这个 Prompt 背后隐含的能力模型：
  优秀作者会天然关注：
    目标 → 冲突 → 变化 → 期待

这不是 Prompt，这是一个"写作认知"的外显化。
```

### 4.2 "AI能力考古学"——从Prompt中提炼教学内容

#### 核心理念

> **不要收集 Prompt，收集 Prompt 背后的能力。**
>
> Prompt 属于模型时代，能力属于认知时代。
> 月笙最终要沉淀的不是 Prompt 模板，而是
>   写作能力 → 病症表现 → 训练方法的映射体系。

#### 提取流程

```
收集优秀 Prompt
  ↓
拆解 Prompt 要求的行为模式
  ↓
提取底层的认知能力
  ↓
转译成写作教学中的能力定义
  ↓
转译成可训练的具体动作
```

#### 示例

| Prompt来源 | Prompt要求的行为 | 提取的能力 | 对应月笙病症 | 对应训练 |
|-----------|----------------|-----------|------------|---------|
| Claude小说分析Prompt | 识别人物动机、识别人物矛盾、识别行为逻辑 | **角色逻辑链** | P002 角色工具人症 | 给角色行为补充动机 |
| ChatGPT长篇规划Prompt | 建立大纲、建立章节目标、建立信息回收点 | **结构控制** | P001 世界观膨胀 | 限制信息投放 |
| 润色类Prompt | 感官细节检查、情绪一致性检查、语言节奏检查 | **表达意识** | P003 情绪标签化 | 感官描写专项训练 |

### 4.3 更广泛的矿脉——不只是写作类Prompt

灵感来自Cursor（代码Agent）的启发：

```
Cursor 的工作模式：
  先扫描 → 再定位 → 再修改 → 最后验证

这是软件工程的闭环。
而写作其实一样：
  观察 → 诊断 → 训练 → 复测

这与月笙的核心流程完全一致。
```

这意味着**非写作领域的优质Prompt同样有价值**——只要它背后的认知结构可以被迁移到创作领域。

### 4.4 "能力提取库"的设计构想

```
月笙能力提取库（概念设计）

案例：Claude 长篇小说分析 Prompt
  原始能力：
    ├── 人物动机识别
    ├── 冲突识别
    └── 情绪轨迹识别
  对应病症：P002, P003
  对应训练：T012, T015
  价值评估：高

案例：ChatGPT 世界观校验 Prompt
  原始能力：
    ├── 规则一致性检查
    ├── 伏笔回收检查
    └── 逻辑矛盾发现
  对应病症：P001, P007
  对应训练：T003, T008
  价值评估：高
```

### 4.5 一条重要原则

> **不要收集 Prompt，收集 Prompt 背后的能力。**

因为 Prompt 会过时。GPT-5 有效的 Prompt，GPT-7 可能就失效了。但 Prompt 背后指向的**认知能力**——比如"识别人物动机""识别冲突来源"——是稳定的。

## 五、方法论Ⅲ：教学诊断体系——从经验判断到数据驱动的自适应教学

### 5.1 诊断表——单次"体检报告"

#### 是什么

诊断表是用户每次提交作品后，AI生成的**结构化问题清单**。它不是模糊的"写得不错/写得不好"，而是分门别类的精准诊断。

#### 应该包含什么

```
诊断表（概念结构）

问题定位：开篇段落，第3-5句
问题归类：【情节】信息密度不足
           【人物】行为逻辑缺失
           【描写】陷入"以例代证"
严重等级：核心 / 重要 / 建议
关联知识点：直接链接到降级规则库或零件练习
改进建议：具体可操作的动作指令
```

#### 三层价值

1. **消除黑箱感**——用户不再只得到一个分数或模糊建议，而是拿到一份清晰的"创作体检报告"，知道问题在哪、有多严重、该去哪补课

2. **动态诊断，看见进步**——用户可以看到上次的"核心"问题变成了"建议"，甚至消失了——这种可视化的进步是最好的激励

3. **数据沉淀**——每一次诊断都是对用户能力模型的更新输入

### 5.2 长期能力表单——持续"成长档案"

#### 是什么

长期表单是月笙在后台为每个用户维护的**个性化能力数据库**。它让教学从"单次教练"升级为"长期私教"。

#### 存储内容

```
用户能力模型（概念结构）

技能掌握度：
  ├── 对话写作：80分
  ├── 悬念设置：45分
  ├── 场景节奏：60分
  └── 感官描写：70分

常见弱点标签（自动标记）：
  ├── 习惯性以例代证
  ├── 主角驱动力薄弱
  └── 场景开头易拖沓

训练历史：
  ├── 完成了哪些专项练习
  ├── 分别用了多少时间
  └── 进步曲线如何
```

#### 核心价值

1. **自适应训练的数据引擎**——系统知道用户的"悬念设置"只有45分，就不会急着让他推进剧情，而是精准推送"悬念的三种制造方法"微课 + 练习

2. **诊断不再从零开始**——系统知道这个用户有"以例代证"的标签，下次诊断时会重点审查论证段落，比通用诊断精准得多

3. **用户毕业/模式切换的依据**——当能力表上的各项数值普遍达到阈值，系统可以优雅地提示用户进入更高级的创作实验室模式

### 5.3 诊断表 + 长期表单 = 教学大脑

```
诊断表                   长期表单
  │                        │
  ▼                        ▼
单次体检报告             持续成长档案
  │                        │
  ▼                        ▼
让用户看见问题           让教学有据可依
  │                        │
  └────────┬───────────────┘
           ▼
    自适应教学引擎
           │
           ▼
    根据用户当前能力状态，
    动态推荐教学内容、训练强度和学习节奏
```

### 5.4 后端数据流的完整闭环

```
用户创作 → AI诊断 → 生成诊断表
                         ↓
                   更新长期能力表单
                    （更新技能评分、记录弱点标签）
                         ↓
                   教学引擎读取能力表单
                    （判断用户当前最弱的3项能力）
                         ↓
                   从降级规则库中匹配训练内容
                    （针对弱项选取训练任务）
                         ↓
                   完成训练 → 再次创作 → 再次诊断
                    （对比两次诊断表，评估进步）
                         ↓
                   更新长期能力表单
                    （调整技能评分，标记强弱点变化）
```

## 六、工程架构：创作工程学

### 6.1 核心理念

> **月笙教的不是"怎么写好句子"，而是"如何像工程师一样系统性地生产一部作品"。**

"创作工程学"是月笙区别于所有写作课和写作工具的核心定位。

### 6.2 三层架构

#### 第一层：组件库——创作维度的"零件化"

- **内容**：将所有写作知识拆解成最小的、可教学的"零件"
  - "角色设计"下包含：核心欲望、致命缺陷、人物弧光、行为逻辑……
  - "场景设计"下包含：冲突构建、信息控制、节奏调节……
- **AI的角色**：根据用户创作类型和当前阶段，动态推荐最适合的"零件"

#### 第二层：工作流引擎——创作过程的"脚手架"

- **内容**：将创作流程转化为交互式引导程序
  - 从概念到大纲（三幕结构引导）
  - 从大纲到章节（单元剧结构引导）
  - 从章节到段落（场景微循环引导）
- **AI的角色**：在每一步诊断用户的输出质量，即时给出教学建议

#### 第三层：适应性教练——实现"千人千面"

- **内容**：基于用户的长期能力表单和创作记录，智能匹配训练
- **AI的角色**：真正的一对一私教——发现用户薄弱环节，自动调取对应零件课程、经典案例和练习，形成专属强化训练营

### 6.3 从WinkNovel借鉴的架构思想

来自对WinkNovel（AI写作IDE）的架构拆解：

| WinkNovel设计 | 月笙可转化的 | 价值 |
|-------------|-----------|------|
| 结构化问卷采集（100+问题拆解世界观） | 结构化诊断表（化模糊判断为可量化清单） | 消除"黑箱感"，让用户知道自己具体哪里有问题 |
| 多Agent分工（大纲Agent/正文Agent/润色Agent） | 多"思维模型"教学（帮用户建立大脑中的内部Agent） | 训练用户在不同创作阶段调用不同的认知模式 |
| 数据与提示词分离（人物卡/地点卡以结构化数据存储） | 用户能力模型与教学内容分离（长期表单独立于训练库） | 用户数据不丢失，诊断随能力更新而精准 |
| 一致性校验Agent | AI诊断功能——检查逻辑自洽性 | 精准诊断：不仅看语法，还能发现"第三章怕水的主角在第五章跳湖救人"这类前后矛盾 |

### 6.4 关于"工程学"教学的一个关键判断

你讨论中那位AI的观察非常精准：

> 市面上有写作工具（如WinkNovel），有写作课程，但没有一个产品，是用一套"创作工程学"的教学体系，手把手地把你训练成一个能独立运转这套工程系统的人。

月笙的产品生态位就在这个空白处——它连接"想写"和"能写"之间的桥梁。

## 七、用户分层与产品策略

### 7.1 用户分层模型

| 维度 | 新手 | 中段作者 | 老手 |
|------|------|---------|------|
| 核心需求 | 信心和方向 | 突破瓶颈 | 效率和市场 |
| 最大痛点 | "我能不能写出来？" | "为什么卡在这里？" | "怎么更快更好？" |
| 月笙定位 | 主服务对象 | 可承接 | 留一扇窗 |
| 交互方式 | 游戏化、任务驱动 | 诊断+专项训练 | 创作实验室模式 |

### 7.2 策略

**产品初期旗帜鲜明地为新手服务。**

不要试图用一款产品通吃所有阶段。硬要加入"拆书赚钱"等老手功能，反而会让新手感到恐惧和偏离焦点，让产品变得臃肿。

### 7.3 新手"没耐心"的解药——游戏化创作体验

把宏大的"写小说"变成即时的"玩闯关"：

**1. 把终极目标拆解成极小的"成就颗粒"**
- 不要："今天我们来学习如何建立读者的代入感。"
- 而要："恭喜你获得新任务【凝视深渊】：让你的主角在开篇做一件他极其不情愿做的小事。奖励：解锁'冲突制造者'徽章。"
- 每个任务就是一次零件库里的专项训练，完成感本身就是即时正反馈

**2. 提供"可玩性"极强的脚手架**
- "世界观生成器"——点选几个选项，AI瞬间生成一个充满矛盾和张力的世界观基底
- "开篇生成器"——提供三种完全不同的开篇策略，让用户"选择"而非"创造"

**3. 进度可见化和里程碑激励**
- 清晰的"创作地图"：角色初设100% → 场景一草稿100% → 核心冲突确立80%
- 完成里程碑时的仪式感反馈

### 7.4 老手的出口——"创作实验室"模式

不把老手功能堆在同一界面里，而是**场景切换**：

- **节拍分析器**：上传稿件，AI用经典叙事理论分析节奏问题
- **风格模仿器**：喂几段某作家的文字，AI分析其用词句式特点，辅助风格化练习
- **点子碰撞板**：陪用户头脑风暴的AI伙伴

这样既保护了新手期纯粹的学习环境，也为"毕业用户"提供了留下的理由。

## 八、月笙的核心资产：能力图谱

### 8.1 月笙真正的核心竞争力是什么

答案不是代码，不是Prompt库，甚至不是训练库——而是：

> **《月笙能力图谱》**

这是一个将"写作能力 → 病症表现 → 训练方法 → 案例验证"四者串联起来的映射体系。

### 8.2 能力图谱的结构

```
能力图谱（概念结构）

观察能力
  ├── 场景观察（能识别场景中的戏剧冲突点）
  ├── 人物观察（能识别人物的行为模式）
  └── 情绪观察（能识别文本中的情绪变化）

角色能力
  ├── 动机构建（能赋予角色清晰的内在驱动力）
  ├── 行为逻辑（能确保角色行为前后一致）
  └── 关系塑造（能设计有张力的人物关系）

结构能力
  ├── 节奏控制（能安排信息的投放速度）
  ├── 信息投放（能控制读者的信息获取量）
  └── 冲突设计（能制造有效的戏剧冲突）

表达能力
  ├── 感官描写（能用五感细节创造沉浸感）
  ├── 情绪传递（能让读者感受到角色情绪）
  └── 细节选择（能选取最具表现力的细节）
```

### 8.3 图谱的演化机制

```
能力图谱
  ↓
每种能力对应一组"病症表现"（当该能力不足时出现什么问题）
  ↓
每种病症对应一组"训练方法"（针对性地锻炼该能力）
  ↓
每种训练方法对应一组"案例验证"（如何判断训练是否有效）

最终形成：
  能力图谱 → 病症图谱 → 训练图谱 → 案例图谱
  四图一体，构成月笙的知识系统
```

### 8.4 图谱的持续进化

能力图谱的构建方式不同于传统教学体系：

- **传统方式**：一个人从零总结，过程缓慢且依赖个人经验
- **月笙方式**：从全世界AI团队沉淀的Prompt工程中持续"挖矿"
  - 每条Prompt背后隐含的能力模型 → 月笙图谱的一个节点
  - 每个节点的有效性 → 通过实际教学反馈验证
  - 验证有效的节点 → 沉淀为图谱的正式成员

这种方式让月笙的认知体系可以持续获得外界养分，而不完全依赖一个人从零总结。

## 九、研发路线与实验原则

### 9.1 一条重要的实验原则

来自对话中的关键建议（已被你采纳）：

> **不要立刻引发架构重构。新增一个实验模块，先验证小规模链路是否成立。**

```
正确方式：
  发现新结构 → 兴奋但克制 → 设实验模块
  → 选3-5个样本验证 → 看看是否成立
  → 成立 → 升级为正式体系
  → 不成立 → 沉淀为"失败考古"，也有价值

避免方式：
  发现新结构 → 兴奋 → 项目暂停 → 开始重构
```

### 9.2 当前阶段的核心任务

基于截止到 V1.0 的设计哲学，优先级的判断：

| 优先级 | 任务 | 依据 |
|--------|------|------|
| P0 | 完善能力图谱的基础映射 | 这是月笙的核心资产 |
| P1 | 验证"Prompt→能力→训练"链路 | 这是持续获取养分的路径 |
| P2 | 补全降级规则库的前50条 | 保证教学内容的可操作性 |
| P3 | 连接诊断表与长期能力表单的数据链路 | 实现自适应教学的数据基础 |
| P4 | 游戏化交互设计 | 提升新手留存 |

### 9.3 "失败考古"的价值

对话中提到一个很好的建议——**不要只看成功项目，失败项目同样有价值**：

```
失败项目考古（概念）

案例：XX AI写作工具
  失败原因：长篇一致性崩坏
  对月笙的警示：需要建立严格的世界观一致性校验机制
  对应月笙能力：P001（世界观膨胀）的深度扩展

案例：XX 写作教学产品
  失败原因：用户留存低，训练链路失效
  对月笙的警示：没有数据反馈的训练是无效的
  对应月笙方案：诊断表 + 长期表单的双表联动
```

这些失败案例直接映射到月笙的系统风险库，是低成本避坑的重要途径。

### 9.4 迭代节奏

```
发现隐藏结构 → 兴奋但克制
  ↓
设实验模块，小规模验证（3-5个样本）
  ↓
验证通过 → 沉淀为正式体系
  ↓
验证不通过 → 记录为"失败考古"，也有价值
  ↓
继续寻找下一个结构
```

这个节奏的核心是：**允许发现，但不允许每次发现都触发重构。**
