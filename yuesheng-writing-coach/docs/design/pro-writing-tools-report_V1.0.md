### Scrivener

Scrivener（Literature & Latte）是长篇写作的行业标杆工具，核心设计哲学是 **"先写，再结构，最后排版"**。

#### 核心结构管理机制

| 机制 | 描述 |
|:----|:------|
| **Corkboard（软木板）** | 卡片化的大纲视图。每章/场景是一张索引卡，显示标题+摘要+标签颜色+写作状态。支持拖拽重排、多列布局、按标签/状态过滤。层级嵌套（项目级/Part级/Chapter级各层独立） |
| **Outliner（大纲视图）** | 表格化的树状大纲。可自定义列（标题/摘要/字数/进度/标签/状态/时间/关键词/角色等）。支持批量编辑、排序、分组、拖拽改变层级 |
| **Scene Cards（场景卡片）** | 最小写作单元（Leaf Node）。每个场景有独立的元数据面板（POV视角/时间段/地点/情绪基调），支持多版本快照(Snapshots) |
| **Compilation（编译系统）** | 内容与样式完全分离。每个层级类型（Part/Chapter/Scene）可映射不同输出排版格式。一键导出 DOCX/PDF/EPUB/MOBI/Markdown 等。Scratch Pad 自动排除草稿 |
| **Goal Tracking（目标追踪）** | 三级目标体系：项目总字数→每个文档字数目标→每次会话字数/时间目标。实时进度条+统计面板+日历热力图 |
| **Collections（集合）** | 虚拟文件夹，按条件（标签+状态+关键词）自动筛选文档，不改变原层级 |
| **Binder（文件树）** | 左侧树状浏览器，管理所有文档、材料、笔记、模板 |
| **Inspector（右侧面板）** | 当前文档元数据面板：摘要、标签、状态、快照、注释、脚注、关键词 |

#### 可借鉴设计

| 设计概念 | 解决用户的什么痛点 | 月笙最小版本 |
|---------|-------------------|-------------|
| **G1-01 场景卡片元数据面板** | 用户写了一段文本但忘了"当时为什么这么写"——场景的视角/情绪/时间标记帮助回溯创作意图 | 在现有训练面板中为每个用户提交的文本段增加轻量级标签：POV(第一人称/第三人称)、基调(紧张/平淡/悬念)。用户手动标记，AI分析时参考 |
| **G1-02 目标追踪三级体系** | 用户写到一半不知道写作进度，容易失去动力或拖延 | 在训练面板底部增加迷你进度条：本次训练目标字数 → 用户写完后自动统计字数并显示完成率。与T-024训练评分联动 |
| **G1-03 大纲-卡片双视图切换** | 诊断反馈只有文字列表，缺少视觉化的结构概览 | 在诊断面板中增加"卡片模式"切换按钮：现有症候列表(表格模式) ↔ 症候卡片(卡片模式，每张显示症候名+严重度+一句话+颜色标签)。MVP不做拖拽排序 |

#### 与已有功能关联

- **G1-01（场景元数据）** ↔ F-02（AI味四维自查）：元数据中的"情绪基调"标签可作为AI味检测的参考维度
- **G1-02（目标追踪）** ↔ T-024（训练效果评分）：目标追踪的完成率数据可作为评分上下文
- **G1-03（双视图切换）** ↔ F-04（分层反馈）：卡片模式天然支持分层——critical卡片用红色边框，info用灰色

### Final Draft

Final Draft 是行业标准的剧本创作软件，其结构管理工具形成了"创意层→结构层→数据层→文本层"的多层级体系。

#### 核心结构管理机制

| 机制 | 描述 |
|:----|:------|
| **Scene List（场景列表）** | 剧本骨架视图。每行一个场景，显示编号/页码/地点/时间/篇幅/角色出场。支持按任意字段排序，场景颜色标记（红色=动作戏/蓝色=情感戏），拖拽重排 |
| **Beat Board（节拍板）** | 故事节奏卡片墙。创建叙事节拍（如"主角震撼时刻""中点转折"），卡片之间建立因果连线，节拍可转换为剧本场景。支持Snider节拍表/Save the Cat框架 |
| **Outline View（大纲视图）** | 场景序列的线性结构化视图。介于Beat Board（创意层）和剧本正文（对白层）之间。展示动作描述而非对白，支持折叠展开 |
| **结构分析报告** | 自动生成多维度报告：场景分布统计(各幕比例)/角色出场报告(每个角色的出场次数/总对白行数)/地点统计/对白-动作比例/角色互动热图/场景长度异常检测 |

#### 可借鉴设计

| 设计概念 | 解决用户的什么痛点 | 月笙最小版本 |
|---------|-------------------|-------------|
| **G2-01 节拍板-叙事节奏诊断** | 用户判断不了自己的故事节奏哪里"不对"。Save the Cat节拍表映射为自动诊断标准 | 在诊断结果中增加"节奏健康度"：根据用户提交文本自动检测5个标准节拍是否存在(激励事件/中点转折/高潮/结局)。有→绿标，无→黄标提示"这一步缺失，可能弱化读者期待" |
| **G2-02 场景分布报告** | 诊断反馈说"你的节奏有问题"但用户不知道具体哪里。量化数据让诊断可视化 | 在诊断面板中增加"字数分段分析"：将用户文本按500字分段，显示每段的情绪强度(基于关键词匹配)迷你折线图。与F-05(看点密度可视化)互补 |
| **G2-03 场景颜色标记系统** | 长对话或反馈中平铺展示的信息太多，没有视觉层级 | 在诊断症候列表左侧增加颜色条：红色→critical、黄色→warning、灰色→info。用户快速扫颜色就知道严重分布。与F-04(分层反馈)互补 |

#### 与已有功能关联

- **G2-01（节拍板诊断）** ↔ F-07（迷你维度反馈）：节拍诊断可作为F-07的一个新增维度(维度8：节拍完整性)
- **G2-02（场景分布报告）** ↔ F-05（看点密度可视化）：两者都是量化数据补充定性诊断，可以合并实现
- **G2-03（颜色标记）** ↔ F-04（分层反馈）：颜色标记是分层反馈的前端实现方式之一

### Manuskript

Manuskript（开源写作软件）的核心优势在于**可视化叙事线索管理**和**角色驱动的结构设计**。

#### 核心结构管理机制

| 机制 | 描述 |
|:----|:------|
| **情节网（Plot Web）** | 可视化网状图展示情节点之间的关联。多线叙事管理（主线/副线/感情线），每条线索独立编辑，同时显示交叉点。拖拽建立"起因→发展→结果"因果链 |
| **三幕结构模板** | 内置经典三幕结构（开端→对抗→结局），自动划分故事阶段。关键节点标注（激励事件/中点转折/高潮），各幕长度占比检查 |
| **角色卡系统** | 结构化角色档案（基本信息/背景/动机/冲突），角色关系图（盟友/对立/爱情/家族），角色弧光追踪（从故事开始到结束的成长轨迹对应章节和情节），视角管理 |
| **世界观构建向导** | 分模块引导（地理/历史/文化/魔法系统），层级化组织（宏观→微观），设定与情节联动 |

#### 可借鉴设计

| 设计概念 | 解决用户的什么痛点 | 月笙最小版本 |
|---------|-------------------|-------------|
| **G3-01 角色一致性追踪** | P009(角色动机缺失)和P010(OC平面化)的诊断缺乏"纵向对比"——只看当前文本不看角色在故事中的演变 | 在用户提交文本时，AI自动记录该角色的"前一次行为描述"。当前行为与前一次矛盾时标黄提示。MVP不做全篇追踪只做本次会话内的对比 |
| **G3-02 情节网-叙事线健康度** | 多线叙事时用户自己都不知道哪条线断了（P006节奏停滞的深层原因可能是一条线被遗忘太久） | 在训练面板中增加"叙事线管理器"：用户手动标注当前文本属于哪条叙事线（主线/副线A/副线B）。超过3次提交没有某条线的更新时，系统提示"你的XX线已经沉默很久了" |
| **G3-03 三幕结构健康检查** | 用户写长篇时不知道"我写到哪了"——故事的整体结构是否合理 | 训练侧栏底部增加"故事进度条"：用户标记文本的"故事阶段"（开端/发展/高潮/结局）。系统根据字数占比显示"你的开端占了60%，通常开端应占25%。你的开篇可能太长了。" |

#### 与已有功能关联

- **G3-01（角色一致性）** ↔ F-03（角色行为推导模板）：F-03推导行为预期，G3-01追踪实际行为是否一致。两者形成"预期→追踪→反馈"的完整链路
- **G3-02（叙事线管理器）** ↔ P006诊断：叙事线沉默可直接触发P006诊断的升级信号
- **G3-03（三幕健康检查）** ↔ F-01（写作前七问引导）：F-01管"写之前"的规划，G3-03管"写之后"的结构校验

### yWriter

yWriter（免费小说写作软件）的核心哲学是：**"写不下一本小说，但可以写下一章；写不下一章，但可以写下一个场景"**。

#### 核心结构管理机制

| 机制 | 描述 |
|:----|:------|
| **章节/场景管理器** | 项目→章节→场景三层树形结构。每个场景独立文件，含元数据面板(视点角色/冲突类型/情绪基调/时间/时长/地点)。支持合并拆分、POV绑定 |
| **项目笔记** | 结构化的笔记系统：角色卡(姓名/年龄/外貌/动机)、地点卡(视觉/声音/氛围)、物品卡(关键物品及其重要性)、研究笔记 |
| **目标追踪** | 每日字数目标、项目总字数目标、场景字数统计、会话计时器、POV字数统计。以数据驱动写作进度 |
| **报告系统** | 场景列表/POV报告/冲突报告/时间线报告/情绪弧线报告/角色出场报告/场景位置报告 |
| **故事板（Storyboard）** | 卡片墙展示所有场景，拖拽排序+颜色标记（橙=动作/蓝=情感/绿=过渡） |

#### 可借鉴设计

| 设计概念 | 解决用户的什么痛点 | 月笙最小版本 |
|---------|-------------------|-------------|
| **G4-01 情绪弧线报告** | 用户不知道自己的故事节奏起伏是否合理——连续紧张场景后需要缓冲 | 在诊断面板中增加"情绪曲线"迷你图：将用户文本按段拆解，每段标记情绪倾向(通过情感词典匹配)。连续≥5段"紧张"↔"紧张"之间无"平淡"过渡段时，提示"需要缓冲" |
| **G4-02 POV分布报告** | P005(视角漂移)的诊断只判断"是否漂移"，不展示"视角用了多少次" | 在诊断报告P005项下增加"视角分布"微件：统计每个视角的使用频率。如果用户在1小时内切换了6次视角，提示"视角切换过于频繁" |
| **G4-03 场景级目标追踪** | 现有系统只有"会话级"的目标（用户写了多少字），没有"写作单元级"的目标 | 在训练Workshop中增加"本次训练目标"输入框：用户输入目标字数→写完后自动统计并显示完成率+用时。与T-024评分联动："你写这段用了30分钟，但评分只有4分。也许需要更多思考而不是更快的输出。" |

#### 与已有功能关联

- **G4-01（情绪弧线）** ↔ F-05（看点密度可视化）：G4-01管"情绪强度"，F-05管"看点密度"。情绪弧线+密度曲线=完整的节奏诊断可视化
- **G4-02（POV分布）** ↔ P005诊断：P005诊断升级(gate)依据是"视角是否漂移"，G4-02提供"漂移程度"的量化数据
- **G4-03（场景级目标）** ↔ T-024（训练评分）：目标完成率可作为评分的权重因子

## 综合结论

### 最适合月笙引入的 3 个设计概念

按**可行度（MVP难度）** × **用户价值** × **与现有系统互补性** 排序：

| 排名 | 设计概念 | 来源 | 理由 |
|:----:|---------|:----:|:-----|
| **1** | **G2-01 节拍板-叙事节奏诊断** | Final Draft | 可行度最高（✅ 纯规则检测，无需AI调用，可在诊断Prompt中追加）。直接增强现有症候诊断能力（P006/P007的量化补充）。用户感知最明显（"你的故事缺了中点转折"比"你的节奏有问题"具体得多）。MVP：5个标准节拍的自动检测，在诊断结果中附加标签 |
| **2** | **G1-01 场景卡片元数据面板** | Scrivener | 与现有F-02/F-03/F-05有直接互补。用户手动标记POV/基调/叙事线，AI诊断时利用这些元数据提高准确率。MVP：在训练Workshop的文本输入区域增加3个下拉选择（POV/基调/叙事线） |
| **3** | **G4-01 情绪弧线迷你报告 + G3-03 故事进度条** | yWriter + Manuskript | 两者可以合并为一个"结构健康度"面板，都不需要AI调用（纯规则计算），用户感知度高。用户写了5000字后看到"你的开端占60%应占25%"时，会比"你的结构需要改进"更愿意去改 |

### 与 T-030 已有评估的互补关系

| T-030 设计 | 本报告的互补设计 | 互补方式 |
|-----------|----------------|---------|
| **F-01 写作前七问引导** | G3-03 故事进度条 | 互补：F-01管"写之前"的规划，G3-03管"写之后"的结构校验 |
| **F-02 AI味四维自查** | G1-01 场景元数据 | 互补：元数据中的"情绪基调"可作为AI味检测的参考维度 |
| **F-03 角色行为推导** | G3-01 角色一致性追踪 | 互补：F-03推导行为预期，G3-01追踪实际行为是否一致 |
| **F-04 分层反馈** | G2-03 颜色标记 + G1-03 卡片模式 | 互补：分层反馈决定"内容逻辑"，颜色标记和卡片模式决定"视觉呈现" |
| **F-05 看点密度可视化** | G4-01 情绪弧线报告 | 互补：密度曲线+情绪曲线=节奏诊断的完整可视化 |
| **F-06 伏笔生命周期追踪** | G3-02 叙事线管理器 | 关联：伏笔追踪和叙事线管理共享"线级追踪"的数据结构 |
| **F-07 迷你维度反馈** | G2-01 节拍诊断 | 互补：节拍诊断可以作为F-07的新维度 |
| **F-08 叙事漏洞审计**（已拒绝） | — | 不互补，F-08已因功能重叠被拒绝 |

### 实施建议

1. **立即可行**：G2-01（节拍诊断）— 纯规则检测，在现有诊断Prompt中追加5个节拍检查指令即可
2. **次优先**：G1-01（场景元数据面板）— 前端改动小（3个下拉选择），后端无变化。但与F-03/F-05有联动依赖，适合与F-03一起做
3. **待规划**：G4-01+G3-03（结构健康度面板）— 前端可视化工作量大，适合做独立迭代
