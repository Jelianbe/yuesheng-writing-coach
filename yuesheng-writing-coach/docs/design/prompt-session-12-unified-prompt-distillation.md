# 会话12：统一 Prompt 工程蒸馏 + 结构功能提取

## ⚠️ 项目背景（必读）

月笙写作教练（Electron + React + TypeScript + SQLite），基于多 Agent 架构的 AI 写作教练系统，面向网文作者群体。核心定位：**教练而非代写**。

**蒸馏总目标**：一个会话同时完成两件事——

1. **Prompt 工程深度蒸馏（核心）**：从 NovelCrafter、ChatGPT 写作 GPTs、Claude Projects、NovelAI 中提取高价值的 Prompt 工程模式  
2. **结构功能提炼（附带）**：从 Scrivener、Final Draft、Manuskript、yWriter 中提取功能设计概念

两条线的产出统一用 **PE（Prompt Engineering）** 和 **SF（Structure Function）** 编号体系标识。

## 第二部分：分析维度

### PE 维度（Prompt 工程 — 核心）

对每个 Prompt 工程对象，提取：

#### 1. Prompt 结构 / 模板语法
- Prompt 的整体骨架是什么？（主题->语气->示例的框架？还是自由写作？）
- 有没有变量系统？变量如何定义（`{character_name}`、`[context]` 等）？
- 用户输入的处理模式——是自由输入还是结构化表单？
- 引导策略——开场用什么问题链引导用户？

#### 2. Prompt 工程技术特征
- 约束机制：字数控制、格式限定、风格锁定的具体写法
- 上下文管理：长文中如何保持一致性？（摘要？分段压缩？关键信息提炼？）
- 角色/世界观定义：如何让 AI 记住角色特征和世界规则？
- 反馈/迭代机制：是否允许用户对输出做修改指示？

#### 3. 可借鉴 Prompt 模式
每条模式格式：
```
PE-NNN | [模式名称]
来源：NovelCrafter
核心结构：[一句话描述 Prompt 的核心结构]
引导策略：[它怎么把用户引导到高质量输出的]
可借鉴点：[月笙可以怎么用]
对应症候：[P001-P010 中哪个症候可以用这个模式]
月笙最小版本：[如果引入这个模式，最轻量的实现方式]
```

#### 4. 与月笙对比
- 哪些是月笙已有的设计？有哪些不同？
- 哪些月笙没有但值得引入？
- 哪些月笙有但做得更好的？

### SF 维度（结构功能 — 附带）

对每个结构功能对象，提取：

#### 1. 核心结构管理机制
- 用户如何组织长篇内容？
- 有哪些视图或工具帮助作者"看到"结构？
- 如何追踪多个叙事线的状态？

#### 2. 可借鉴设计概念
```
SF-NNN | [设计名称]
来源：Scrivener
痛点：[解决用户的什么问题]
月笙最小版本：[最轻量的实现方式]
与已有功能关联：[对应月笙哪个模块]
互补设计：[与 F-XX/PE-XX 的互补关系]
```
