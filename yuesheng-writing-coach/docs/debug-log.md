# 月笙写作教练 — Bug 调试日志

> 按照 R-023 Bug 调试记录规范，调试耗时超过 15 分钟时必须记录完整四要素。
>
> 时间阈值：<5min 不强制 / 5-15min 建议一行摘要 / **>15min 必须完整记录** / >60min 同时写入 Lessons Learned

---

## 记录模板

### 完整记录（>15 分钟）

```markdown
## [YYYY-MM-DD] [简短标题]

**耗时**: XX 分钟
**严重度**: P0(阻塞) / P1(功能受损) / P2(体验问题)

### 现象
- 触发条件：[什么操作触发的]
- 错误表现：[报错信息 / 异常行为]
- 影响范围：[哪些功能受影响]
- 复现率：[必现 / 偶现 / 难复现]

### 定位
- 排查路径：[从哪里开始查 → 查了什么 → 排除了什么]
- 关键线索：[哪个日志/报错/行为暴露了方向]
- 陷入的误区：[错误假设，防止重蹈覆辙]

### 根因
- 直接原因：[代码层面的 bug 是什么]
- 根本原因：[设计缺陷？遗漏？误解？]
- 引入时机：[何时引入的]

### 修复
- 修改内容：[改了什么]
- 涉及文件：[文件列表]
- 验证方式：[怎么确认修好了]
- 防再发措施：[防止同类问题]
```

### 快速记录（5-15 分钟）

```
[YYYY-MM-DD] [标题] (XXmin) — [现象] → [原因] → [修复方式]
```
