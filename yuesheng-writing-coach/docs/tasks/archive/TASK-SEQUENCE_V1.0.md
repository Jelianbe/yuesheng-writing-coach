**目标**：诊断后直接在当前页面展示修改建议并提供内联编辑

| 子任务 | 工时 | 操作 |
|--------|------|------|
| M-2.1 诊断页面改造 | 3h | 诊断结果下方增加"尝试修改这段"按钮，点击展开内联编辑区 |

**DoD**：
- [ ] 每条诊断结果旁都有"尝试修改"入口
- [ ] 点击后展开可编辑的原文区域

- [ ] TypeScript 编译零错误

### M-3：AI 修改评估

**来源**：V2 审计 — "改好了没有"环节缺失  
**目标**：用户提交修改后，AI 评估并反馈

| 子任务 | 工时 | 操作 |
|--------|------|------|
| M-3.1 评估 API 调用 | 2h | 在 `api-proxy.ts` 新增评估调用（对比原文和修改，输出评估） |
| M-3.2 评估反馈展示 | 1.5h | 评估结果显示"改前 vs 改后"对比 + 一句话评价 |

**输出格式**：
```
评估结果：
- ✅ P001 设定倾倒：从 5 处减少到 2 处，改善明显
- ⚠️ P002 人物空心：改善不明显，可再尝试练练 T001
- 一句话：你的环境描写进步了，但对话潜台词还需要加强
```

**DoD**：
- [ ] 提交修改后 3 秒内返回评估
- [ ] 评估内容可读（不是系统语言）
- [ ] 评估结果存入数据库

**工时**：3.5h

## 六、不需要有的功能

| 功能 | 理由 |
|------|------|
| Evidence 前端概念 | 用户不需要"证据"这个词，改为"诊断依据" |
| 数字评分展示 | 精确分数对新人有副作用，改为文字分级 |
| NovelProfile | 系统内部缓存优化，不是教学功能 |
| Pattern Detector 独立服务 | 一个 if 语句解决 |
| 统计基准线配置 | 新手不需要知道行业基准 |
| Agent 架构正式化 | 保持 Service 层即可 |
| 三标签面板 | 改为单视图 |
| 诊断前聚焦方向选择 | 新手不知道自己的问题在哪 |
| Level 2-3 证据展示 | 系统内部用，不给用户看 |
