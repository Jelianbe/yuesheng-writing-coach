# 月笙文档验证

## 触发场景
- 创建新文档时
- 更新现有文档时
- 归档历史文档时
- 文档定期审查时

## 验证范围

### 1. 文档分类检查

| 检查项 | 规则 |
|--------|------|
| 存储位置 | 文档是否存放在正确的目录？ |
| 命名规范 | 是否遵循 `<类型代码>_<主题>_V<主版本>.<次版本>.md` 格式？ |
| 类型代码 | PRD/ARCH/SPEC/PLAN/RULE/RPT/DECISION/PROMPT/CASE |

### 2. 版本控制检查

| 检查项 | 规则 |
|--------|------|
| 版本号 | 是否有明确的版本号？ |
| 变更记录 | 是否有变更记录表格？ |
| 版本规则 | 重大更新主版本+1，小幅更新次版本+1 |

### 3. 文档结构检查

| 文档类型 | 必需章节 |
|---------|---------|
| PRD | 概述、目标、范围、技术选型、模块设计 |
| 架构文档 | 概述、架构图、组件说明、数据流 |
| 技术规范 | 概述、规范条目、示例、注意事项 |
| 报告 | 概述、核心内容、结论与建议、附录 |

### 4. 链接有效性检查

- 内部链接是否有效？
- 外部链接是否需要更新？
- 跨文档引用是否一致？

## 验证输出格式

```markdown
## 文档验证报告

### 文档信息
- 文件：`path/to/file.md`
- 类型：PRD/ARCH/...
- 版本：V1.0

### 验证结果
- 通过：X 项
- 警告：Y 项
- 失败：Z 项

### 失败项（必须修复）
| 问题 | 说明 | 修复建议 |

### 警告项（建议修复）
| 问题 | 说明 | 修复建议 |
```

## 注意事项
- 新文档必须通过验证后才能发布
- 旧文档更新时需要重新验证
- 验证失败项必须记录并跟踪修复
