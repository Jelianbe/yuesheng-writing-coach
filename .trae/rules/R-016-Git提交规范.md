# R-016: Git提交规范

## 规则内容
所有 Git 提交信息必须遵循约定的格式，以确保提交历史清晰、可读性强，便于追踪变更和自动化处理。

## 提交信息格式
```
<type>(<scope>): <subject>

<body>

<footer>
```

### Type（类型）
- **feat**: 新功能
- **fix**: Bug修复
- **docs**: 文档更新
- **style**: 代码格式调整（不影响逻辑）
- **refactor**: 代码重构（既不修复bug也不添加功能）
- **perf**: 性能优化
- **test**: 测试相关
- **chore**: 构建过程或辅助工具变动

### Scope（范围）
描述改动影响的范围，如模块名、组件名等：
- api
- ui
- db
- auth
- etc.

### Subject（主题）
- 使用祈使句，如"change"而不是"changed"
- 首字母小写
- 不超过50个字符
- 不以句号结尾

### Body（正文）
- 解释"为什么"和"如何"变更
- 每行不超过72个字符
- 解释动机，对比之前的行为

### Footer（页脚）
- 关联 Issue: `Closes #123`
- 破坏性变更: `BREAKING CHANGE:`

## 示例
```
# 好的提交信息
feat(auth): 添加用户登录功能

实现用户邮箱密码登录，包括表单验证和错误处理。

Closes #45

# 不好的提交信息
update code
fixed stuff
```

## 检查清单
```
提交前检查：
□ 类型是否正确？
□ 主题是否简洁清晰？
□ 是否遵循祈使句？
□ 是否包含足够的上下文？
□ 是否关联了相关Issue？
```

## 自动化检查
- 使用 husky + commitlint 进行提交前检查
- CI/CD 流程验证提交格式
- 自动生成 CHANGELOG

## 与其他规则的协作

| 规则 | 关系 | 协作方式 |
|------|------|----------|
| R-018 变更溯源规范 | 依赖 | R-016 的提交信息必须引用 R-018 的溯源链条中的依据文档 |
| R-017 文档与报告管理 | 互补 | R-016 的规范化提交信息为 R-017 的 CHANGELOG 自动生成提供数据源 |

## 优先级
中优先级 - 保障代码历史的可读性
