# R-029: 安全与隐私（Flutter）

## 原则

**一次泄露就是永久伤害。** API Key、Token、密码这类凭证一旦进入代码仓库
历史，即使后续删除也不安全（git history 保留）。必须在源头阻断。

> 本项目为**纯本地架构**（无后端中转），密钥由用户自行配置、
> 存于设备平台安全存储。这降低了服务端泄露面，但**设备端泄露面仍在**。

## 绝对禁止

| 禁止项 | 原因 | 正确做法 |
|:--|:--|:--|
| 代码中硬编码 API Key | 提交即泄露 | 经 `LlmConfigStorage` 读写（底层 `flutter_secure_storage`） |
| Prompt 中写入真实 Key | Prompt 可能被日志/调试输出暴露 | 运行时注入，不写进 Skill 常量 |
| `.env` 提交到 Git | 同上 | `.env` 加入 `.gitignore` |
| 将密钥打印到日志 | 日志可能被收集上传 | 禁止打完整 Key；必要时只打前 4 位或掩码 |
| 把密钥写进 `error_logs` | 错误体可能带回显 Key | **经 `ErrorHandler.captureError` 落库（自动脱敏）** |
| 把密钥写进测试 fixture | 测试文件同样进仓库 | 用占位符，测试替身注入内存 fake |

## 项目已有的安全机制（务必沿用，不要绕过）

### 1. 安全存储：`LlmConfigStorage`

`lib/services/llm_config_storage.dart` 封装 `flutter_secure_storage`
（Android Keystore / iOS Keychain），提供 `getLlmConfig` /
`saveLlmConfig` / `clearLlmConfig`。

```dart
// ❌ 错误：硬编码
const apiKey = 'sk-abc123xyz456...';

// ✅ 正确：经安全存储读取
final config = await ref.read(llmConfigStorageProvider).getLlmConfig();
final apiKey = config?.apiKey ?? '';
```

测试替身：`session_providers.dart` 已提供接缝，
生产用 `flutter_secure_storage`，测试 override 注入内存 fake。

### 2. 错误脱敏：ErrorHandler（A12 安全红线）

`lib/services/error_handler.dart` 的 `captureError` 会在落库/上报前
统一脱敏，防止形如 `Authorization: Bearer <key>` 的回显内容经
`error_logs` 或 UI 泄漏。

**所有入口（FlutterError / PlatformDispatcher / 直接调用）已收口于此，
单点防护。** 新增错误上报路径时，必须走 `ErrorHandler`，
不要自行 `debugPrint` 后直接落库。

> ⚠️ 例外：`error_log_repository.dart` 是日志写入方本身，
> 其内部不得调用 `captureError`（会递归），改用 `debugPrint`。

## .gitignore 必须排除

```
# 敏感配置
.env
.env.local
.env.*.local

# 凭证文件
*.pem
*.key
credentials.json

# OS 生成的敏感文件
.DS_Store
Thumbs.db
```

## Prompt 安全特殊要求

本项目 Prompt 以 Dart 常量形式存在于 `skill_registry.dart` 与各
`skills_*.dart`。这些文件**受 git 追踪**，因此：

- Skill 常量中**绝不能**包含真实凭证
- 需要动态值时用占位符，运行时替换
- 导出/分享诊断档案（`archive_export_service`）前，确认内容不含凭据

## 泄露应急处理

如果发现密钥已被提交到 Git 历史：

1. **立即轮换**该密钥（在服务提供商后台生成新的）
2. 从代码中移除硬编码值
3. 使用 `git filter-branch` 或 BFG Repo Cleaner 清除历史（视敏感程度）
4. 记录事件到 `yuesheng-flutter/docs/` 下的决策记录
5. 审查是否有其他地方使用了相同模式

## 检查清单

```
每次涉及配置/凭证时：
□ 是否有任何硬编码的 Key / Token / 密码？
□ 密钥是否经 LlmConfigStorage（flutter_secure_storage）读写？
□ .env 及变体是否在 .gitignore 中？
□ Skill / Prompt 常量中是否使用占位符而非真实值？
□ 日志与错误上报是否经 ErrorHandler（自动脱敏）？
□ debugPrint 中是否会输出敏感信息？
□ 测试 fixture 是否泄漏了真实凭据？
```

## 与其他规则的协作

| 规则 | 关系 | 协作方式 |
|:--|:--|:--|
| R-025 Prompt治理 | 依赖 | Prompt 安全审查是 R-025 治理流程中的必要环节 |
| R-026 Prompt工程规范 | 互补 | R-026 的 Constraints 段必须包含 R-029 的安全声明 |

最高优先级 — 安全底线，零容忍
