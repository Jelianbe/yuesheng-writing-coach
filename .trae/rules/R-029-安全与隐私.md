# R-029: 安全与隐私

## 原则

**一次泄露就是永久伤害。** API Key、Token、密码这类凭证一旦进入代码仓库历史，即使后续删除也不安全（git history 保留）。必须在源头阻断。

## 绝对禁止

| 禁止项 | 原因 | 正确做法 |
|--------|------|---------|
| 代码中硬编码 API Key | 提交即泄露 | 环境变量 `process.env.API_KEY` |
| Prompt 中写入真实 Key | Prompt 可能被日志/调试输出暴露 | 占位符 `{{API_KEY}}` 运行时注入 |
| `.env` 提交到 Git | 同上 | `.env` 加入 `.gitignore` |
| 将密钥打印到 console.log | 日志可能被收集 | 使用 debug 级别日志，生产环境关闭 |
| 在前端代码中嵌入密钥 | 前端代码可被逆向 | 密钥只存在于 main process（Electron） |

## 占位符注入模式

### 配置文件中使用占位符

```typescript
// ❌ 错误：硬编码
const API_KEY = 'sk-abc123xyz456...';

// ✅ 正确：占位符 + 运行时注入
const API_KEY = process.env.DEEPSEEK_API_KEY ?? '';

// Prompt 模板中的占位符
const promptTemplate = `
  你是一个写作教练。
  API Endpoint: {{API_ENDPOINT}}
  // 实际值在发送前替换
`;
```

### Electron 中的安全加载

```typescript
// main process 中加载（安全：不可被浏览器 DevTools 看到）
import { config } from 'dotenv';
config();

// 通过 IPC 暴露给 renderer（不传递原始 key）
ipcMain.handle('config:getEndpoint', () => {
  return { endpoint: process.env.API_ENDPOINT };  // 只传 endpoint，不传 key
});

// renderer 中调用
const { endpoint } = await ipcRenderer.invoke('config:getEndpoint');
// key 始终留在 main process
```

## .gitignore 必须排除

```
# 敏感配置
.env
.env.local
.env.*.local

# 凭证文件
*.pem
*.key
credentials.json

# OS 生成的敏感文件
.DS_Store
Thumbs.db
```

## Prompt 安全特殊要求

Prompt 文件可能被：
- 复制到外部工具中进行调试
- 包含在错误日志中
- 通过分享功能发送出去

因此 **Prompt 模板中绝不能包含真实的凭证信息**：

```markdown
<!-- ❌ 错误 -->
请调用 API：https://api.example.com/v1/chat?api_key=sk-real-key-here

<!-- ✅ 正确 -->
请调用 API：{{API_ENDPOINT}}
认证凭据由运行时注入，不在 Prompt 中体现。
```

## 泄露应急处理

如果发现密钥已被提交到 Git 历史：

1. **立即轮换**该密钥（在服务提供商后台生成新的）
2. 从代码中移除硬编码值
3. 使用 `git filter-branch` 或 BFG Repo Cleaner 清除历史（可选，取决于敏感程度）
4. 记录事件到 decision-log.md
5. 审查是否有其他地方使用了相同模式

## 检查清单

```
每次涉及配置/凭证时：
□ 是否有任何硬编码的 Key / Token / 密码？
□ .env 及变体是否在 .gitignore 中？
□ Prompt 模板中是否使用占位符而非真实值？
□ 密钥是否只在 main process 中使用？
□ console.log 中是否会输出敏感信息？
```
