# R-005: 全流程文档化 - 逻辑解释

## 规则内容
所有复杂逻辑、算法实现和业务规则必须在代码中包含清晰的解释性注释。这不仅是为了他人理解，也是为了未来的自己能够理解当时的设计意图。

## 解释标准
1. **为什么** - 解释为什么选择这种实现方式
2. **怎么做** - 说明实现的关键步骤
3. **注意事项** - 列出需要特别注意的点
4. **关联关系** - 说明与其他模块的关联

## 注释规范
```typescript
// ❌ 不好的注释
// 循环遍历数组
for (let i = 0; i < arr.length; i++) {
  // 处理每个元素
  process(arr[i]);
}

// ✅ 好的注释
/**
 * 诊断信号匹配
 * 
 * 为什么：需要快速定位用户文本中的病症信号
 * 怎么做：使用正则表达式匹配预定义的信号模式
 * 注意：权重计算在信号匹配后进行，避免重复计算
 * 关联：与 diagnosis-engine.ts 中的评分逻辑配合
 */
function matchSignals(text: string): SignalMatch[] {
  // 实现...
}
```

## 必须解释的场景
- 算法实现（排序、搜索、优化算法）
- 状态机逻辑
- 复杂的条件判断
- 异步流程控制
- 性能优化代码
- 业务规则实现

## 触发场景
- 诊断引擎开发
- 学员类型识别算法
- 教学动作触发逻辑
- 个性化推荐算法

## 优先级
常规优先级 - 提升代码可读性
