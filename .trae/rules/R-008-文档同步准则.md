# R-008: 文档同步准则

## 规则内容
所有代码变更必须伴随相应的文档更新。文档是项目的重要组成部分，必须与代码保持同步，以确保团队协作和知识传承。

## 同步要求
1. **代码变更** → 更新相关技术文档
2. **API 变更** → 更新 API 文档和示例
3. **功能更新** → 更新用户文档和 README
4. **架构调整** → 更新架构文档和设计图
5. **配置修改** → 更新配置说明

## 检查清单
```
代码变更时检查：
□ 相关代码注释是否更新？
□ API 文档是否与实际一致？
□ README 是否反映当前状态？
□ 技术文档是否更新？
□ 示例代码是否仍有效？
```

## 文档类型
| 文档类型 | 更新时机 | 负责人 |
|----------|----------|--------|
| 代码注释 | 每次代码变更 | 开发者 |
| API 文档 | API 变更时 | 开发者 |
| README | 项目结构变更 | 项目负责人 |
| 技术文档 | 架构调整 | 架构师 |
| 用户文档 | 功能更新 | 产品团队 |

## 与其他规则的协作

| 规则 | 关系 | 协作方式 |
|------|------|----------|
| R-018 变更溯源规范 | 依赖 | 代码变更后文档同步是 R-018 溯源链完整性的必要保障 |
| R-017 文档与报告管理 | 依赖 | 文档更新的具体流程、版本控制和审核遵循 R-017 的规范 |

## 优先级
中优先级 - 保障项目可维护性和团队协作
