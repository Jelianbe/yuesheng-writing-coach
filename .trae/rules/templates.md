# TRAE 规则模板

## YAML 头部信息
```yaml
---
name: "规则名称"
description: "规则描述，简要说明规则用途和适用场景"
alwaysApply: true/false  # 是否总是应用（L1=true, L2/L3=false）
priority: "highest/very-high/high/medium/low"  # 优先级
trigger:  # 触发场景
  - "触发条件1"
  - "触发条件2"
checkLogic:  # 检查逻辑
  - "检查项1"
  - "检查项2"
enforcement: "违规处理方式"
---
```

## 规则结构
1. **规则编号** - R-XXX-规则名称（三位数字编号）
2. **规则内容** - 核心规则描述
3. **触发场景** - 何时应用此规则
4. **检查清单** - 如何验证是否遵循规则
5. **执行机制** - 违反规则的处理方式
6. **优先级** - 规则的重要程度

## 分层说明
- **L1 (alwaysApply: true)** - 核心规则，始终生效
- **L2 (alwaysApply: false)** - 关键节点规则，特定时刻检查
- **L3 (alwaysApply: false)** - 智能触发规则，条件满足时激活

## 规则编写要点
1. **明确性** - 规则表述清晰，无歧义
2. **可执行性** - 规则可以被检查和验证
3. **实用性** - 解决实际问题，不是纸上谈兵
4. **可衡量性** - 有明确的检查标准
5. **适度性** - 规则不应过度限制创新
