# 月笙写作教练项目开发规则汇总

> ⚠️ **重要边界声明：界面改造范围**
>
> 1. **当前阶段目标：改造现有界面，而非新建界面**。所有改动必须在现有组件内部完成，不新建独立的"训练面板"或"IDE 界面"，不改动主界面的整体布局框架（`centerMode` 切换机制）。
> 2. **界面设计的前置条件**：主界面改造方案尚未完成 UI/UX 设计。在获得设计决策前，**禁止**实现任何新的界面布局或拆分逻辑。未设计、不实现。
> 3. **所有变更必须可追溯**（遵循 R-021 B6 溯源边界），且范围最小化（遵循 R-010 最小化范围原则）。

## 🎯 场景触发矩阵

| 开发场景 | 触发规则 |
|---------|---------|
| **启动新任务** | R-004（DoD定义） |
| **编写代码** | R-005（逻辑解释）、R-010（最小化范围）、R-014（配置外置）、R-019（代码规范+DRY）、R-021（AI行为边界） |
| **AI 修改代码** | R-021（行为边界五条）、R-010（最小化范围）、R-006（回退备份）、R-027（质量门禁四道） |
| **复杂/多文件操作** | R-022（过程可见三要素）、R-006（L1 备份） |
| **提交代码 / review→done** | R-010（原子化）、R-013（测试）、R-016（提交规范）、R-027（门禁四道） |
| **阶段完成** | R-003（里程碑）、R-011（记忆强化+阶段回顾） |
| **算法优化/架构变更** | R-012（假设驱动）、R-005（逻辑解释）、R-022（过程可见） |
| **模块导入/组件引用** | R-020（循环依赖检查） |
| **Bug 调试 (>15min)** | R-023（调试记录四要素） |
| **编写/修改 Prompt** | R-025（Prompt 治理版本管理）、R-026（工程规范四段式）、R-029（安全：无硬编码 Key） |
| **IPC handler / API 调用** | R-028（防御性编码边界校验）、R-019（IPC 格式）、R-029（安全） |
| **涉及密钥/配置** | **R-029（安全与隐私 — L1 alwaysApply 零容忍）** |
| **收到反馈/Bug** | **R-030（反馈处理工作流 — 9 步流程）** |
| **用户要求停止** | R-009（用户主权） |
| **数据变更** | R-007（双向绑定） |
| **文档更新** | R-017（文档规范含同步要求） |
| **代码改动前** | R-006（回退机制）、R-021（B6 溯源边界） |
| **需要 sub-agent** | R-015（AI协作规范） |
| **AI 工具首次接入** | R-024（AGENTS.md 入口文件检查） |
