# R-028: 防御性编码（Flutter）

> 2026-08-29 由 Electron/TS 版适配。原版以 IPC handler 为边界样板，
> 本项目无 IPC 层，边界对应物为 Repository / LLM Client / 平台通道 / 表单。

## 原则

**防御性编码有两个极端错误：**

1. **完全不防御** — 用户输入直接进 LLM，Repository 参数不校验 → 脏数据 + 崩溃
2. **过度防御** — 每个函数都包 try/catch，每个参数都做 null check → 掩盖真实 bug

正确做法：**只在边界防御，内部信任已控制的数据。**

## 边界 vs 内部

### 必须防御的边界（Boundary）

| 边界位置 | 校验要求 | 示例 |
|---------|---------|------|
| **Repository 入参** | 校验 id 非空、范围、必填字段 | `if (manuscriptId.isEmpty) return [];` |
| **LLM / 外部 API 响应** | 检查状态码 + 响应体结构，解析失败要降级 | `jsonDecode` 包 try/catch |
| **DB 中存放的 JSON 字段** | 解析失败按默认值降级，**且必须留痕** | 见「降级必须可观测」 |
| **用户输入（表单）** | 提交前校验格式、长度、非法字符 | `TextFormField.validator` |
| **配置 / 密钥读取** | 启动时校验存在性与格式 | LLM Key 缺失给明确提示 |
| **drift 查询结果** | 可能为空时用 `getSingleOrNull` | `await query.getSingleOrNull()` |

### 不应防御的内部（Internal）

| 内部位置 | 为什么不防御 |
|---------|------------|
| Riverpod Provider 之间调用 | 数据形状由 Dart 类型系统保证 |
| Widget 构造参数 | 非空类型由编译器保证（避免 `!` 断言，见 R-019） |
| 纯函数之间调用 | 调用方负责传正确参数；有单测覆盖 |

## try/catch 使用规则

### ✅ 正确使用（有特定错误要处理）

```dart
// 1. 已知可能失败的特定操作
try {
  final response = await client.post(uri, body: payload);
  if (response.statusCode != 200) {
    throw LlmException('HTTP ${response.statusCode}');
  }
} catch (e, st) {
  // 有具体处理：记录 + 用户可见反馈 + 向上抛
  debugPrint('[LlmClient] 请求失败: $e');
  ErrorHandler.instance.captureError(
    level: 'error',
    category: 'api',
    message: 'LLM 请求失败',
    context: {'error': '$e'},
    stack: '$st',
  );
  rethrow;
}

// 2. 需要清理的 finally
final sub = stream.listen(onData);
try {
  await sub.asFuture();
} finally {
  await sub.cancel();
}
```

### ❌ 错误使用（禁止）

```dart
// 1. 空 catch — 吞掉所有错误，bug 被静默隐藏
try {
  doSomething();
} catch (_) {}          // ← 这里什么都没有！

// 2. 无意义的 fallback
final value = maybeNull ?? 'default';   // "不可能发生"的情况
// 如果真的不该为 null，让它崩掉，这样你能发现 bug

// 3. 包裹整个函数体
Future<void> handler() async {
  try {
    // 100 行代码全包在里面
    // 任何 bug 都被吞掉，永远不知道哪里出错
  } catch (e) {
    debugPrint('$e');    // 只有一行，没有上下文
  }
}
```

## 降级必须可观测（2026-08-29 补充）

数据解析失败走默认值是**合理降级**，但**静默降级不合理**。

全仓曾存在 17 处空 catch 用于 JSON 解析降级，导致 DB 字段损坏时，
用户侧表现为「学习记录凭空消失」「文笔画像没了」，而日志中无任何痕迹，
事后无法追溯是写入截断、旧版本格式还是迁移残留。现已全部改为可观测降级。

统一守卫见 `lib/services/decode_guard.dart`：

```dart
} catch (e, st) {
  // 降级行为保留（返回默认值），仅补可观测性
  logDecodeFailure(field: 'student_model.teachingHistory', error: e, stack: st);
}
```

⚠️ **例外**：`error_log_repository.dart` 是日志写入方本身，
其内部**不得**调用 `captureError`（会形成「记日志失败 → 再记日志」递归），
该文件内改用 `debugPrint`。

## 正确的错误传播策略

```
边界层（Repository / LLM Client / 平台通道）
  → 捕获 + 记录 + 转换为可理解的失败态 + 视情况 rethrow

业务层（Service / Notifier）
  → 不捕获（让自然冒泡），或仅做 context 补充后 rethrow

表现层（Widget）
  → 异步失败用 SnackBar / 内联错误态展示
  → 渲染错误由 ErrorHandler.installErrorHandlers() 兜底
```

## Repository 方法模板

```dart
Future<List<DiagnosisRow>> getBySession(String sessionId) async {
  // 1. 入参校验（边界防御）
  if (sessionId.isEmpty) return const [];

  try {
    // 2. 数据访问（内部不额外防御）
    return await (_db.select(_db.diagnoses)
          ..where((t) => t.sessionId.equals(sessionId)))
        .get();

  } catch (e, st) {
    // 3. 记录 + 向上抛，由表现层统一展示
    debugPrint('[DiagnosisRepo] 查询失败: $e');
    ErrorHandler.instance.captureError(
      level: 'error',
      category: 'database',
      message: '诊断记录查询失败',
      context: {'sessionId': sessionId, 'error': '$e'},
      stack: '$st',
    );
    rethrow;
  }
}
```

## 检查清单

```
code review 时检查：
□ try/catch 是否有具体的错误处理逻辑？（不能是空 catch）
□ catch 块是否至少留下痕迹（ErrorHandler / debugPrint）？
□ 确需静默降级的，是否用了 decode_guard 而非裸 catch？
□ 参数校验是否只在 Repository / LLM / 表单等边界层？
□ 内部函数调用是否无 try/catch 包裹？
□ 是否用了无意义的 fallback 值？
```
