# R-015: AI协作规范

## 规则内容

定义 AI 在编码过程中何时使用 sub-agent（Task 工具）、何时直接操作文件的决策标准，确保开发效率和资源使用的最优化。

## 触发场景

在以下场景需要评估工具使用策略：
- AI 需要决定是否启动 sub-agent 时
- 处理大型/多文件任务时
- 涉及多层架构修改时
- 需要搜索/调查型任务时

## 决策矩阵

| 场景 | 推荐方式 | 理由 |
|------|---------|------|
| 修改单个文件（≤ 200 行变动） | 直接操作（SearchReplace/Write） | 效率优先，上下文连贯 |
| 跨 2-3 个文件修改 | 直接操作 | 保持上下文连贯 |
| 跨模块/跨前后端修改 | ✅ **启动 sub-agent** | 各层独立，可并行执行 |
| 搜索/调查型任务（非编码） | ✅ **启动 search sub-agent** | 自动化多轮查询，减少主线程阻塞 |
| 复杂重构+多步验证 | ✅ **启动 sub-agent** | 任务拆解+独立验证 |
| 纯文本分析/文档任务 | 直接操作 | 无需额外开销 |
| 耗时超过 3 分钟的连续操作 | ✅ **启动 sub-agent** | 避免主线程阻塞，提升用户体验 |
| 代码审查/规则检查 | ✅ **启动 rule-guardian agent** | 专项审查，提高质量 |
| Python 代码开发 | ✅ **启动 python-expert agent** | 专业领域知识 |
| TypeScript 代码开发 | ✅ **启动 typescript-expert agent** | 严格类型检查 |
| UI/UX 设计任务 | ✅ **启动 uiux-designer agent** | 专业设计指导 |

## TRAE Agent 类型选择指南

### 搜索类
- **search**: 高跨模块查询、概念理解、文档检索
- 适用：查找代码在哪里、理解架构、搜索相关文档

### 开发专家类
- **general_purpose_task**: 复杂多步骤编码任务
- **typescript-expert**: 严格类型安全、企业级 TypeScript
- **python-expert**: Python 最佳实践、异步编程、测试
- **react-frontend-developer**: React 组件、Hooks、状态管理
- **backend-architect**: 后端架构设计、API 设计、数据库设计

### 审查优化类
- **rule-guardian**: 项目规则合规检查
- **config-security-reviewer**: 配置安全和生产可靠性
- **performance-optimization-engineer**: 性能分析和优化
- **architecture-review-expert**: 架构评审和技术选型

### 测试文档类
- **test-automation-expert**: 测试架构和 CI/CD 配置
- **api-documentation-engineer**: API 文档和开发者指南
- **documentation-architect**: 文档体系设计

### 专项类
- **bug-detective**: 疑难问题诊断和根因分析
- **incident-response-expert**: 生产事故应急响应
- **data-scientist**: 数据分析和机器学习

## 禁止事项

- ❌ 使用 sub-agent 执行纯文本编辑（如格式化、换行符调整）
- ❌ 启动 sub-agent 后等待其完成却不检查结果
- ❌ 对不需要 sub-agent 的任务无故启动（浪费资源）
- ❌ sub-agent 执行期间修改其正在处理的文件
- ❌ 启动多个 sub-agent 处理相互依赖的任务

## sub-agent 输出要求

sub-agent 完成工作后必须返回：
1. 改动文件清单（含路径）
2. 核心决策说明（30 字以内）
3. 验证结果（测试通过/失败/待验证）
4. 遗留问题或后续建议（如有）

## 并行执行策略

当多个独立任务可并行时：
1. 使用单个消息中的多个 tool calls 启动多个 sub-agent
2. 确保各 sub-agent 处理的文件/模块无重叠
3. 等待所有 sub-agent 完成后统一验证

## 上下文管理

启动 sub-agent 时的上下文要求：
1. 包含完整的任务描述和背景信息
2. 明确期望的输出格式和内容
3. 提供相关文件路径和代码片段
4. 说明与其他模块的依赖关系（如有）

## 月笙项目特定场景

### 诊断引擎开发
- 信号权重调整 → 直接操作（涉及配置文件）
- 诊断算法重构 → 启动 python-expert 或 typescript-expert
- 规则膨胀检查 → 启动 rule-guardian

### Prompt 工程
- Prompt 迭代 → 直接操作（文本编辑）
- Prompt 效果盲测 → 启动 test-automation-expert

### 前端组件开发
- React 组件开发 → 启动 react-frontend-developer
- 状态管理重构 → 直接操作（Zustand 轻量）
- UI/UX 优化 → 启动 uiux-designer

## 检查清单

```
sub-agent 启动前检查：
□ 当前场景是否适合启动 sub-agent？
□ sub-agent 的输入上下文是否完整？
□ 是否选择了正确的 sub-agent 类型？
□ 是否有并行执行的机会？

sub-agent 完成后检查：
□ sub-agent 返回的结果是否有验证？
□ 改动文件清单是否完整？
□ 是否存在需要跟进的遗留问题？
□ 是否存在资源浪费？
```

## 优先级

中优先级 - 效率优化而非强制约束
