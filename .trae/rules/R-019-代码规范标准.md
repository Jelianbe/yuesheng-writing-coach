## DRY 原则（Don't Repeat Yourself）

相同的数据结构**只能定义一次**，统一集中在 `shared/types.ts`。

```
❌ 错误：在 3 个文件中分别定义相同的 interface
// diagnosis-parser.ts
interface DiagnosisResult { syndromes: Syndrome[]; confidence: number; }
// teaching-state-machine.ts
interface DiagnosisResult { syndromes: Syndrome[]; confidence: number; }
// chat.store.ts
interface DiagnosisResult { syndromes: Syndrome[]; confidence: number; }

✅ 正确：统一在 types.ts 定义，其他文件 import
// shared/types.ts
export interface DiagnosisResult { ... }
// 其他文件
import type { DiagnosisResult } from '../shared/types';
```

### 常量集中管理

跨文件使用的常量必须提取到统一位置：

| 常量类型 | 推荐位置 | 示例 |
|---------|---------|------|
| IPC 通道名 | `shared/ipc-channels.ts` | `export const IPC = { CHAT_SEND: 'chat:send', ... }` |
| UI 尺寸常量 | `shared/layout-constants.ts` | `export const SIDEBAR_WIDTH = 240` |
| 业务枚举 | `shared/types.ts` 或独立 enum 文件 | `enum SyndromeId { P001, P002, ... }` |
| 魔法数字 | 使用处附近的具名 const | `const MAX_RETRIES = 3` |

### 禁止的重复模式

| 模式 | 为什么禁止 | 替代方案 |
|------|-----------|---------|
| 同一 interface 在多文件定义 | 改一处漏一处 | 统一到 types.ts |
| 相同的 utility 函数复制粘贴 | bug 修复需改 N 处 | 提取到 shared/utils/ |
| 相同的 error class 多处定义 | 类型不统一 | 统一到 shared/errors/ |
| 硬编码字符串（路由/通道名/事件名） | 重构时搜不全 | 集中到 constants 文件 |

## 内联样式迁移路线图

### 当前状态
项目存在约 **1260 行内联样式**（`style={{}}` 形式），零 CSS 类名。这是审查报告标记的最大代码债务之一。

### 迁移原则

1. **新代码禁止内联样式** — 所有新组件必须使用 CSS Modules / CSS 变量 / Tailwind 类名
2. **修改旧组件时顺手迁移** — 如果改动涉及某个组件的样式，将该组件的内联样式一并迁移
3. **不单独开任务批量迁移** — 遵循 R-010 最小化范围，每次只迁当前改动的组件

### hover 效果规范

```css
/* ✅ 正确：CSS 伪类 */
.button:hover { background-color: var(--color-primary-dark); }

/* ❌ 错误：JS 事件驱动 */
onMouseEnter={() => setHover(true)}
style={{ backgroundColor: isHover ? '#xxx' : '#yyy' }}
```
