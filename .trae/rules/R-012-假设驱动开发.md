# R-012: 假设驱动开发

## 原则
任何可能显著影响系统行为的改动，必须先提出假设，验证后采纳或回退。

## 假设模板（精简版）
```
改动内容: （一句话说清改了什么）
预期效果: （改动后应该达到什么效果）
验证方式: （如何验证这个假设）
回退条件: （满足什么条件时回退）
实验结果: （接受/拒绝 + 原因）
```

## 决策规则
| 情况 | 决策 |
|------|------|
| 目标达成，基线不降 | ✅ 接受 |
| 目标未达成 | ⚠️ 拒绝或回退，记录教训 |

## 检查清单
```
改动前检查：
□ 是否有明确的目标？
□ 是否有验证方案？
□ 是否设定了回退条件？

改动后检查：
□ 是否验证了效果？
□ 实验结果是否记录？
□ 是否接受了假设或回退了改动？
```

## 优先级
高优先级 - 保障改动的有效性
