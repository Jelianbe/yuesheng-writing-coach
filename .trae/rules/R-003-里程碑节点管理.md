# R-003: 里程碑节点管理

## 规则内容
在项目或阶段结束时，必须设置里程碑。只有达成既定目标才能开启下一阶段。这是为了确保每个阶段的质量和完整性。

## 里程碑检查清单
```
阶段结束检查：
□ 核心任务是否都已审核？
□ 是否生成了阶段小结？
□ 是否达成预定目标？
□ 是否满足下一阶段准入条件？
```

## 里程碑标准
每个里程碑必须包含：
1. **完成状态** - 明确哪些任务已完成
2. **质量评估** - 功能是否按预期工作
3. **文档交付** - 相关文档是否完成
4. **经验总结** - 遇到的问题和解决方案

## 里程碑示例
### MVP 里程碑
- [ ] API 配置界面完成
- [ ] 聊天界面基础功能完成
- [ ] 诊断引擎集成完成
- [ ] 基础测试通过
- [ ] 用户反馈收集

### 增强阶段里程碑
- [ ] 训练任务系统完成
- [ ] 学员类型识别完成
- [ ] 实时反馈系统完成
- [ ] 性能测试通过

## 里程碑审批流程
```
里程碑达成 → 提交检查清单 → 团队审核 → 签字确认 → 开启下一阶段
```

## 触发场景
- 项目阶段结束
- 版本发布前
- 重要功能完成
- 项目节点检查

## 与其他规则的协作

| 规则 | 关系 | 协作方式 |
|------|------|----------|
| R-004 准出标准DoD | 被依赖 | R-003 的里程碑达成判定依赖 R-004 定义的 DoD 标准作为验收依据 |
| R-011 记忆强化 | 互补 | 里程碑达成后通过 R-011 的阶段回顾模板记录关键决策和遗留问题 |

## 优先级
中优先级 - 保障项目进度和质量
