# R-004: 准出标准（DoD）

## 规则内容
每个阶段开始前都必须定义完成标准。没有标准，不得开发。每个阶段的 DoD 必须包含至少 3 条可验证标准，DoD 未定义或不完整时阻止阶段启动。

## 触发场景
在任何开发阶段开始前必须检查：
- 项目启动时
- 阶段性任务开始时
- 新功能模块开发时

## DoD 质量标准
每个标准必须满足 SMART 原则：
- **S**pecific（具体的）
- **M**easurable（可测量的）
- **A**chievable（可实现的）
- **R**elevant（相关的）
- **T**ime-bound（有时限的）

## DoD 示例（第一阶段）
1. 用户能够成功配置 API 密钥并连接到服务
2. 聊天界面能够正常发送和接收消息
3. 诊断面板能够显示识别到的问题和建议

## 强制检查
```
阶段开始前检查：
□ DoD 是否存在？
□ DoD 是否包含至少 3 条标准？
□ 每条标准是否可验证？
□ 是否有明确的验收条件？

如果任何一项为"否"：
→ 阻止阶段启动
→ 提示完善 DoD
```

## 与其他规则的协作

| 规则 | 关系 | 协作方式 |
|------|------|----------|
| R-003 里程碑节点管理 | 被依赖 | R-003 的里程碑达成判定依赖 R-004 定义的 DoD 标准 |
| R-011 记忆强化 | 互补 | 阶段完成后通过 R-011 进行阶段回顾，验证 DoD 是否真正达成 |
| R-017 文档与报告管理 | 依赖 | DoD 文档的创建、版本控制和审核流程遵循 R-017 规范 |

## 优先级
中优先级 - 保障交付质量
