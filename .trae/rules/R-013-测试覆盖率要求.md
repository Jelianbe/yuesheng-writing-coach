# R-013: 测试覆盖率要求（Flutter）

## 原则

所有代码改动必须通过已有基线测试，新增功能至少覆盖一条测试用例。

## 每次改动必须执行

```bash
# 1. 格式（只带本次改动的具体文件；禁止对整个目录跑，避免波及范围外）
dart format --set-exit-if-changed -o none <改动文件>

# 2. 静态分析（全 lib——import 变化可能影响其他文件）
flutter analyze lib --no-pub

# 3. 循环依赖（R-020）
python scripts/check_circular.py

# 4. 全量测试（排除需真实 API Key 的 live / external 标签）
flutter test --exclude-tags live,external --no-pub
```

四道全绿方可声称完成。完整定义见 R-027。

## 新增功能建议执行

- ✅ 至少 1 个单元测试覆盖核心逻辑
- ✅ 测试数据不依赖线上环境（不依赖真实 API Key）
- ✅ Mock 外部依赖（LLM 调用走测试替身，如 `_FakeChatService`）
- ✅ 纯函数优先（解析器 / 校验器 / 检测器无副作用，最易覆盖）

## 覆盖度目标

| 层级 | 目标 | 说明 |
|:--|:--:|:--|
| 纯函数 / 解析器 / 校验器 | **高** | 无副作用，最易覆盖，应优先保证 |
| Repository（数据访问） | 中高 | 用内存数据库或 mock |
| Service（业务编排） | 中 | 依赖较多，用测试替身 |
| Widget（UI） | 中 | `pumpWidget` + `pumpAndSettle` |
| 需真实 API 的链路 | 豁免 | 打 `live` / `external` 标签，不进常规门禁 |

## 注意事项

- **测试替身与 override 契约**：Dart 扩展方法**非 virtual**。若把类内实例方法
  迁到 `extension`，测试替身的 `@override` 会被静默绕过（曾导致 9 例
  `pumpAndSettle` 超时）。详见 R-019 关于 part/extension 伪拆分的说明。
- **测试环境**：Windows 下 `flutter test` 需保证系统 TEMP 所在盘有足够空间
  （编译产物数百 MB）。磁盘告满会使 `test_compiler` 报
  `errno = 112 磁盘空间不足`，此时把 TEMP 指向空间充足的盘再跑即可。
