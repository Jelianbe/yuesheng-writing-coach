# 月笙 · 教学机制审查包

> 用途：供外部 AI 审查**机制运转层**（闭环 / 状态 / 交互 / 误判链），非内容质量审查。
> 生成日期：2026-08-11
> 内容资产（症候库/技法/动作/态度/N系/训练库）已单独审查修复过，见 `docs/教学诊断训练资产清单.md`。
> 所有行号引用均为代码真源位置（`lib/` 相对路径），描述与代码一致，可交叉核对。

## 〇、审查目标与范围

**审查对象**：教学机制如何被编排、如何流转、会不会断——而不是内容本身好不好。

**四层范围**（本次审查聚焦）：
1. **闭环层**：诊断 → 沉淀 → 训练 → 评估 → 迁移五环节是否首尾相接、无断点/死链路/悬空调用
2. **状态层**：teaching_state FSM 四态 + TeachingPhase P0-P4 迁移条件是否自洽、有无死锁/悬空态/状态残留
3. **交互/对话层**：协议块、三层校验、意图分类、颗粒度、表达密度注入、引用管理、大纲确认、训练 V2 L2/L3
4. **误判链**：误诊断、态度升降档误判、症候误报、规则观察误触发、防骚扰 gate

**设计总原则**（审查时请以此为准绳，勿用行业惯例否定我们的设计取舍）：
- 内容做**锚点与边界**（校验方法/few-shot 锚点/判断原则/示范参考/自查锚点），**不给 AI 大段照念话术**，放开 AI 自身知识库自主组织教学。
- **代码引擎 vs LLM 分工边界**：所有确定性计算（严重度趋势/达标率/FSM/阶段迁移校验）在 Dart 代码侧完成并注入上下文；所有教学话术流程（自评三选一、改前改后对比、降级阶梯、挂起卡点）是注入 LLM 的 skill 指令，代码层不硬编码。

## 六、审查方向与问题清单（给外部 AI）

### 方向 1：闭环完备性（价值最高）
- 五环节（诊断→沉淀→训练→评估→迁移）是否存在断点/死链路/悬空调用？
- 两条诊断路径（单次 ≤4000 / 分块 >4000）是否真的一致，有无分支遗漏？
- 失败路径是否全部静默安全（无块/解析失败/非章节引用），有无吞错导致静默丢数据？
- teacher_suggestion / editor / reviewer 独立分支与主链路是否存在状态不同步？

### 方向 2：状态机一致性
- FSM 三个写回入口（评估面板/训练前/训练后）是否可能产生竞态或回退？
- mastered→resolved 双入口（evaluation_service / diagnosis_service）是否有重复执行或漏执行风险？
- 阶段迁移 P0-P4：M4-A 自动迁移（remaining.isEmpty + passRate≥0.7）与 AI 建议路径是否会互相覆盖？子阶段重置是否完整？
- 有无悬空态：teaching_state 为 NULL、active_problem 无 diagnosis 对应、resolved 后被重新激活？

### 方向 3：自由度 vs 约束平衡（核心关注）
- 25 步注入是否出现"约束叠约束把 AI 锁死"或"锚点被绕过"的极端？
- 临场输出约束（最高优先级）放在历史之前，是否真的能被 LLM 遵循？会不会被后续更具体的内容覆盖？
- 意图分类 / 颗粒度 / 态度档位三层指令是否有冲突优先级问题（如 concise 与详细诊断需求矛盾）？
- L2/L3 加载是否会出现 token 膨胀突破预算（maxBudget / warningRatio）？

### 方向 4：误判链
- 态度升降档触发条件是否可能误判（把学员正常反馈当挫败、把 AI 自身问题当学员进步）？
- 症候互斥与触发信号是否覆盖了所有常见混淆场景？有无新的边界重叠？
- 规则观察检测器命中即注入，是否存在误命中导致 AI 被带偏？
- chat_gates 心流窗口是否可能过度抑制教学建议（该提醒时不提醒）？

### 方向 5：协议健壮性
- 六个协议块的解析失败路径是否全覆盖？流式拦截跨 chunk 边界是否正确？
- 无 validator 的协议块（YS_ENTITY / YS_FACT）是否校验不足？
- 协议块嵌套（如 FACT 在 DIAGNOSIS 内）或顺序错乱会怎样？

### 方向 6：规模可维护性
- 症候扩容（P023+）与淘汰机制的缺口在哪？L2/L3 加载膨胀对 token 与检索质量的影响？
- 内容一致性维护成本（症候/技法/动作/训练四库映射）是否已有防漂移机制？

## 九、设计原则与决策史（防误判须知）

1. **AI 自由度原则**：内容只给锚点和边界，不给大段话术；评估重点应是"约束是否适度"，而非"锚点是否足够详尽"。
2. **代码引擎 vs LLM 分工**：确定性计算在代码，话术在 LLM——"某规则在代码里没有实现"不一定是缺陷，可能是刻意交给 LLM。
3. **双路径**：诊断式（P 系，有文本）与生成式（N 系 N0-N4，零基础）并行，不可互相否定。
4. **RN 已废弃**：yuesheng-android 不再维护，真源为 yuesheng-flutter；如发现"两处不一致"，以 Flutter 为准。
5. **症候数量不限制**：不设上限，用优先级排序（教学原则：学员问题不能人为截断）。
6. **保守迭代史**：大量"看似冗余"的防御（静默跳过、NO_OP 合并、双重校验）来自真实断点事故，删改需谨慎。
