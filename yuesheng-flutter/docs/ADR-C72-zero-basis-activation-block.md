## 1. 问题（N-1）

两条规则真实打架，且各有文本依据：

- §3.9 不附加清单：「从零构建引导模式（7.3，用户还没有可诊断的内容）」→ 不附加；
  §7.3：「从零构建模式下，诊断引擎不启动」。
- `suggested_beginner_level` 字段说明（同文件 §3.9）：「首次检测到零基础学员……时填
  N0_ENGAGE **激活零基础路径**」——该字段只能经诊断块输出。

模型只能随机选边：盲测实测同一输入行为分裂（`R0-C21_r1` 无块 / `r2` 有块）。
在 ADR-C71 之前，这条不稳定通道是零基础路径的**唯一**跨会话激活方式；
C71 之后它降级为兜底通道（旧会话、极端边界），但冲突本身仍在产生非确定行为。

## 2. 裁决（方案 A：补第三行撞车裁决，把 r2 行为扶正为唯一正解）

**首次识别零基础学员（尚无任何文本）→ 仍附「最小激活块」**：

- `syndromes` 必为空、不写任何症候相关字段、`confidence` 如实标低；
- 只填 `suggested_beginner_level`（首次检测 → `N0_ENGAGE`）；
- 语义澄清：这**不属于启动诊断引擎**——没有症候可处理，块在这里只是系统激活信号的信封；
- 自然语言部分照常受 N0 铁律约束：不诊断、不评判、不给技法提示。

**否决项**：
- 改激活通道（块外字段 / 新协议）——动 schema 与解析链，远大于收益；
- 删「不附加」中的从零构建条目——会让纯闲聊/从零构建中期也漏块，扩大行为面；
- 代码侧代填——越权教学状态机（A.12.27 N38 已有先例裁决：不代填）。
