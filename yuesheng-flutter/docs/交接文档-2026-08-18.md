## 0. 一句话定位

## 5. 工作流程铁律（必须遵守）

1. **批次制 + 四闸门禁**：每批改动须过 ① `dart analyze lib` 0 错误 ② 全量 `flutter test` 全绿（当前基线 **1773 项**）③ 守护一致性测试（four_libraries_consistency 等）④ 相关专项测试。每批独立 commit。
2. **改知识库数据必须逐字迁移或走一致性测试**：四库之间有双向逐字一致校验，绝不能"顺手调整"数据。
3. **先完整规划再动手**，批量文件操作用脚本（带边界断言），不手工剪切。舰长明确批评过执行效率问题，认可顾问/分析角色。
4. **破坏性操作（尤其删除）先报告确认**，先隔离再处理。
5. **教练哲学不可违反**：App 不替用户写、不替用户决定。诊断面板"尝试修改"类功能曾被判违反哲学，勿再犯。
6. 汉字路径/中文文件名常见，脚本注意编码（Python 用 `io.open` + utf-8）。

## 6. 环境坑（踩过的坑，直接绕行）

- **沙箱拦截 flutter**：AI 沙箱会话里 `flutter test` / `flutter --version` 可能被静默拦截（零输出 exit 1；flutter.bat / cmd 包装 / dart 直连 flutter_tools.snapshot 三路全失败时即中招）。**解法**：让舰长在自己终端（项目根 `D:\ai-teacher\yuesheng-flutter`）跑测试；或沙箱内改用 `/d/flutter/bin/cache/dart-sdk/bin/dart.exe analyze` 做静态门禁（这个能跑通）。
- **flutter test 必须前台跑**：后台跑会假死。
- **文件锁**：sandbox safe-file 策略会拦截对已存在文件的覆写（EPERM）。等锁释放或换工具再试；参考资料库已落地 `reconcileIndex()` 自愈机制。
- **flutter.bat.lock** 残留时先删：`rm -f /d/flutter/bin/cache/flutter.bat.lock`。
