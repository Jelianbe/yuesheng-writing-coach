【六、开工前必读的坑（AGENTS.md 全文都要读，以下最高频）】
- **同步死循环让用例级 Timeout 失效（2026-09-04 批次 H 实证）**：flutter test
  的 timeout: Timeout(...) 靠 Timer 调度，同步死循环阻塞 event loop 后**永不
  触发**——表现为测试零输出、进程被外部 SIGTERM。判别：跑一个不相关测试做
  对照（对照正常 = 你的变异把代码改死循环了）。唯一兜底是**进程级超时**
  （_verify_batch_h_coverage.py 的 240s + taskkill /F /T /PID，超时计为拦截）。
  批次 I 修死循环的变异验证必须带这套。
- V4.21：**单点评据只证明「那一条」被锚定**，不证明整个函数真覆盖。每个分支
  各准备一个判据级变异，全拦截才叫真覆盖。
- V4.18（最坑，会浪费你一小时）：跑 flutter test 前**必须清空会话代理**，
  否则所有测试集体报 "Unable to connect to flutter_tester process:
  WebSocketException: Invalid WebSocket upgrade request"——包括上一轮刚跑全绿的。
  跑法（设空值而非 env -u，本会话实测有效）：
    env HTTP_PROXY= HTTPS_PROXY= http_proxy= https_proxy= \
        NO_PROXY=localhost,127.0.0.1 flutter test <文件>
  scripts/gate.sh 已内联清代理（门禁 2 直接可跑），但你单独跑命令仍需注意。
  此故障格外阴险：加载失败的输出行**同样带 [E]**，会让变异验证的「拦截成功」
  判据假绿。故验证脚本必须先做基线健康校验（不绿就 abort）。
- **gate.sh 门禁 0 只扫 lib，test 文件是格式盲区（批次 G/H 两次实证）**：
  新增/改动的测试文件收尾时手动补查：
    dart format --set-exit-if-changed -o none test/<改动文件>
  报 exit 1 时按 V4.5 先写入（dart format <file>）再复验，然后**重跑受影响
  测试**（format 会改文件，后续 Edit 前也要重新 Read，否则报
  "File has been modified since read"）。

  progressive_diagnosis）在 dart run 下报 dart:ui unavailable。批次 H 曾试图
