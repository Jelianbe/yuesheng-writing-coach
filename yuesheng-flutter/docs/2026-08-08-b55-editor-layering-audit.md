# B55 编辑反馈分层 — 审计与落地（Sudowrite 研究借鉴点 B）

**日期**：2026-08-08
**类型**：审计 + 轻量落地（1 处 UI 文案）
**背景**：Sudowrite 工作流分 **Developmental Edits（整体结构反馈）** 与 **Line Edits（逐行建议）** 两层。立项审计月笙是否具备/需要该分层。

---

## 1. 审计对象

| 层 | Sudowrite 对应 | 月笙对应 | 证据 |
|----|--------------|---------|------|
| 整体层（叙事结构） | Developmental Edits | **Editor 观察**（`agent_skills.dart` kEditorObservationSkillContent） | 9 个观察维度：角色主动性/立体度/节奏控制/冲突动态/转折处理/主题表达/情节机制/世界一致性/对话动态 |
| 表达层（逐行/语言） | Line Edits | **症候诊断**（P003 情绪标签化 / P008 语言堆砌等表达层症候） | skill 明确"不报告表达层技术问题，那些由诊断系统处理"——边界清晰 |

## 2. 关键发现：分层已内化

1. **职责边界显式**：Editor skill 明文"不报告表达层技术问题（情绪标签/句式单一/描写堆砌）"，与症候诊断正交——两层天然分离
2. **数据链路完整**：Editor 观察 → Teacher 决策（encourage/guide/train/defer）→ 学员教学反馈；编辑观察持久化 `editor_observation` 表（`chat_service.dart` R1，总是写入）
3. **呈现分层**：学员可见的"表达层"= 诊断卡/症候；"整体层"= 成长页 ObservationAuditCard（`growth_page.dart:349`，叙事层观察记录）
4. **架构合理性**：Editor 是 Teacher 的内部输入层（非学员直接反馈），避免向学员泄露三层 Agent 架构——与 Sudowrite"两个编辑工具"的形态不同，但教学目标一致

## 3. 落地：分层认知显式化

分层在架构与数据层已完备，缺的是**学员端的分层认知引导**。最自然落点：能力图谱（六维天然分属两层——情节/人物/主题=整体层，语言=表达层）。

- `ability_chart.dart` description 由"基于诊断与解决情况评估的六大写作能力"改为
  **"从整体（情节/人物/结构）与表达（语言/细节）两个层面评估的六大写作能力"**

不做的事（审计结论明确）：
- ❌ 不在消息流新增"叙事层卡片"（Editor 是内部输入层，向学员暴露会泄露内部架构）
- ❌ 不重构六维分组（情感/逻辑为跨层维度，强行分组失真）

## 4. 结论

Sudowrite 的编辑反馈分层在月笙**已通过"Editor（叙事层）+ 症候（表达层）"双 Agent 架构内化**，无需新增分层功能。本批仅做学员端分层认知的显式化（能力图谱文案），并以本文档记录审计证据。
