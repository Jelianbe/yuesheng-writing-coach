## 1. 为什么要立这份 ADR

`ADR-C151` 定的是「实验怎么读数才可算」。本 ADR 定的是**读数从哪来、存哪、存什么形状**。
不立的后果已经发生过了，两次：

| 缺口 | 已经发生的形态 |
|:--|:--|
| `evidence` 全链路不落库 | 历史诊断**无法复算 AER**，「离线回放」物理不可行（原料不存在，不是成本问题） |
| `p0_verify` 三件套只被测试引用 | 40 项测试全绿、全 `lib/` **零调用** —— 代码就绪 = 零生效 |

> ★ 第一条的性质值得单独说：它不是「存得不够」，是**存不下**。三处独立核实全部确认无 `evidence` 列/字段：
> `active_problem`（`tables.dart:236–287`）只有 `evidence_confidence` 这个**计算结果**；
> `sessions.diagnosis_summary`（`diagnosis_repository.dart:851–877`）只有聚合值；
> `messages.content` 的协议 JSON 块已被 `diagnosis_parser.dart:223` 的 `_stripDisplayBlocks` **剥掉**。
> ⇒ `evidence` 只在 `ParsedDiagnosis` 内存对象里活一瞬。**每多跑一次长文诊断，就永久少一个样本。**

### 1.1 为什么锚定率不是一个「顺手加的指标」

`lib/services/evidence_confidence.dart` 判「引文具体度」的依据是：

```dart
final specific = evidence.first.trim().length >= kEvidenceSpecificMinChars; // 6
strength = specific ? 0.55 : 0.35;
```

**只看第一条、只看长度、不接触原文。** 与阈值链对照（全部可复算）：

| 情形 | `strength` | vs `kWeakEvidenceConfidence = 0.4` | 结局 |
|:--|--:|:--|:--|
| 1 条引文，≥6 字 | `0.55` | 过线 | 进教学焦点 |
| 1 条引文，<6 字 | `0.35` | 被 gate | 挡住 |
| ≥2 条（哪怕全编造） | `0.65 + 0.05×(n−2)`，封顶 `0.8` | 稳过 | 进教学焦点 |

而 `listActiveProblems`（`diagnosis_repository.dart:487`）按 `evidenceConfidence >= 0.4 | status='confirmed'` 放行。

⇒ **编一条 6 字以上的假引文，收益是「让一条错误症候进入学员的教学焦点」** —— 这是**正收益**，不是中性偏差。
在该函数里，编造与真实**完全同价**：它手上没有原文，判不了。

⇒ 所以 `AER` 的职责不是「报告里多一个数」，而是 **`evidence_confidence` 唯一可能的反证通道** ——
因为只有锚定这一层手上有原文。二者**并置**才有信息量：

| `strength` | `AER` | 读法 | 处置 |
|:--|:--|:--|:--|
| 高 | 低 | 证据写得具体，但原文里没有 ⇒ 编造或改写 | **该拦** |
| 高 | 高 | 真引用 | 可信 |
| 低 | 高 | 引文真在原文，但太短 | **判据该改，不该拦** |

三者的处置完全不同，压成一个分数就永远分不开。**这是本 ADR 存在的第一理由。**

## 2. 影子模式：接线必须零行为变更

`anchor.dart` 是纯函数（零 IO / 零 LLM / 不改输入）。接线层 `anchor_probe.dart` 的三条纪律**写进类型**，不靠调用方记：

| # | 纪律 | 实现 | 不这么做会怎样 |
|:--|:--|:--|:--|
| 1 | **只观测** | 只记 `AnchorProbeLog`（环形 50）+ `pilot_metric_event` 明细；**不删条、不降级、不改诊断内容** | 探针一旦能改判定，就再也无法区分「误报来自判据」还是「误报来自探针」 |
| 2 | **未测 ≠ 0 命中** | `skippedReason` 区分「未测」与「0 命中」；`AER` 为 `null` 时打印 `n/a`，不打印 `0.000`；未测也落库（只写 `skip` 字段，**不写任何比率**） | 打印 `0.000` 会让「没测」被读成「全错」；只落已测则「一直没拿到原文」永远不可见 |
| 3 | **分母口径只有一个** | 一律走 `aggregateEvidence`，本层不得自算比率 | 第二处分母算法 = 第二个真源 |

补充一条同样写进类型的口径纪律：**空白 `evidence` 单列 `emptyEvidenceCount` 且不进分母**。
否则 `too_short_rate` 被抬到 `0.15` 以上 ⇒ 整份 `AER` 返回 `null`（`anchor.dart` 的既定行为），
一份本来测得的报告会被读成「测不了」。

### 2.1 接线点：整章锚定，不是逐块锚定

接在长链 `commitDiagnosisFromContent`，**在 `commit` 之前**（`commit` 会改写 `active_problem`，
可能 gate 掉弱证据条目；在它之后跑就看不到被 gate 掉那批 —— 而那正是最需要看的）。

用**整章原文**锚定而非逐块：合并后的诊断条目已不带块索引，逐块要动 merge 契约（改动深一层）。
整章锚定对跨块引文更宽松，也更接近真实 —— 引文本来就该在原文某处。

失败**静默且不上 `error_logs`**（探针自身故障混进产品错误率，两个指标就搅在一起，之后谁也说不清错误率升的是哪一类）。

## 3. 落库：落**明细**，不落比率

### 3.1 落点选择（三次否决记录）

| 候选 | 判定 | 理由 |
|:--|:--:|:--|
| `error_logs` | ❌ 否决 | 语义是「出错了」，`AER` 不是错误 ⇒ 污染错误率口径 |
| 只留内存环形 50 | ❌ 否决 | release 不输出 `debugPrint` ⇒ 生产包**永久**看不到 |
| 新建专用表 | ❌ 否决 | v48 刚动 schema，为一个实验指标不值 |
| **`pilot_metric_event`** | ✅ 采纳 | 既有追加式事件表，零 migration、零 schema 变更，已有 `recordEvent`/`listByType`/`countByType` |

### 3.2 `payload` 形状（版本 `kAnchorPayloadVersion = 1`）

```json
{"v":1,"src":55,"syn":3,"emp":1,"n":3,"items":[
  {"s":"P001","k":"ok_exact","o":1,"l":12,"h":"他握紧了青玉牌，指节发白"},
  {"s":"P002","k":"fail",    "o":0,"l":13,"h":"他曾把青玉牌摔在地上，碎了"},
  {"s":"P002","k":"ok_exact","o":1,"l":10,"h":"那块牌子是母亲留下的"}]}
```

| 字段 | 含义 | 为什么这样切 |
|:--|:--|:--|
| `v` | payload 版本 | 口径一改要能分辨历史行，**不许靠猜** |
| `src` / `syn` / `emp` | 原文字符数 / 症候数 / 空白 evidence 条数 | 空白单列，不混进分母（§2） |
| `n` / `items` | 明细条数 / 逐条裁决 | **按 `bySyndrome` 展开而非扁平 `items`** —— 扁平列表丢了「哪条症候」，而「谁在编造」正是要回答的问题 |
| `items[].k` | `AnchorStatus.code`：`ok_exact`/`ok_ws`/`ok_width`/`ok_joined`/`ambiguous`/`too_short`/`fail`/`fail_joined` | 存原始状态码，**不存**折叠后的「成功/失败」二元值 ⇒ 口径变了还能重算 |
| `items[].o` / `l` | 原文出现次数 / 引文真实长度 | `l` 独立存 ⇒ `h` 截断不丢信息 |
| `items[].h` | 引文 head，**截断到 `kAnchorHeadChars = 24`**（截断补 `…`） | 够定位，不必把整段学员正文复制进观测日志 |
| `skip` | 未测原因（如 `no_source_text`） | **与比率字段互斥**：未测时 `payload` 里一个比率数字都没有 |

> ★ **不落 `AER` 本身**。比率是明细的函数；存比率而丢原料，口径一改历史就再也算不出来。
> 这是 `ADR-C151 §1` 那条「四者失效时都不报错」的同一族 —— 比率存进去时读起来完全正常，
> 只是正常地不可复算。

## 4. 防「试点表退役」断层：三处留痕

`pilot_metrics_repository.dart` 头注自述「试点专用表，正式设计批评估后决定去留；本批不承诺长期保留」。
而 `AER` 要做**跨批次纵向比较**（`ADR-C151` 的注入面 / 窗口语义 / `I10` 三条待裁全靠它）。
若将来有人按注释退役本表，`AER` 历史会一起没。故在三处写明**例外条款**：

1. **文件头注**「去留」一节：`anchor_probe` 不受此约束，退役前须先归档；
2. **`PilotEventTypes.anchorProbe` 常量注释**：退役本表前**必须**先把该类型的行归档进实验报告；
3. **本 ADR §5**。

> ★ 与「表被 sync ≠ 表在维护」同族，但在**新维度**上：那张表的维护者读到的注释恰好说「可以删」。
> 三处留痕不是冗余 —— 只有注释在的地方，才有人在删之前看见。

## 5. 与 ADR-0005 的边界（这一节是本 ADR 存在的第二理由）

`ADR-0005 §3` 对 V3 埋点的口径是「**静默 · 不持久化**」，其 §6 未收尾第 5 项写明
「埋点持久化（进程内累计重启即清零；持久化涉 PHI/隐私）—— **待单独裁定**」。

本 ADR 的落库**正是那次「单独裁定」**，范围与边界：

| 边界项 | 裁定 |
|:--|:--|
| 是否持久化 | ✅ 是（本地 `pilot_metric_event`，追加式） |
| 是否出网 | ❌ **否**。实测：无云同步实现（全 `lib/` 零 `cloud_sync`/`firebase`/`supabase` 命中）；`recordEvent` 只走 `guardRepoWrite('pilot_metrics', ...)` 写本地库 |
| 存了什么 | 明细裁决 + **引文 head 24 字**（学员正文片段） |
| 全文是否入库 | ❌ 否。`evidence` 仍不落库（§1），这是本 ADR 明确**不**改变的事实 |
| 是否有 UI / 弹窗 | ❌ 否。纯旁路 |
| 能否据此反推学员写了什么 | **能读到 24 字片段** ⇒ 这是本裁定唯一实质让步，也是它必须被单独写下来的原因 |
| 保留期 | 随表；**退役前须归档**（§4） |

> ⚠️ **若将来给 `pilot_metric_event` 加云同步或导出功能，本 ADR 立即失效** ——
> 「不出网」这条是本裁定的全部隐私依据。改动前须重新裁定，不得以「表已有例外条款」推论仍然允许。

## 6. 本轮不做（明确留口）

| 项 | 为什么不做 |
|:--|:--|
| **短链未接** | 原文在 `SendMessageOptions.chapterFullText`，**可获得**；但接线点在 `_sendMessageCore`（大函数，R-019 敏感）。⇒ 当前读数只覆盖「>4000 字真实小说」这一段 |
| **`evidence_confidence` 的长度代理未改** | 改判据须先有 `AER` 的真实分布作依据，否则又是「拿印象改尺子」。ADR-C151 的 `calibration` 列要求标 `工作阈值·未标定` —— 这一列正是为这种时候准备的 |
| **不删条、不降级** | 即便 `AER` 很低，本轮也不让探针影响任何判定。要不要让它**改变条目状态**，是另一份 ADR 的事（`ADR-C151 §6` 已登记：将来接线时 `fail` 必须能改变条目状态，否则接了也没用） |
| **不建 `gold/**/*.jsonl`** | `G8④` 代码已就绪但跑不出读数，缺的是数据不是实现（ADR-C151 §8 已登记） |
