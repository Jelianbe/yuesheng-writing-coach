## 2. 优先级分级（P0 → P4）

排序逻辑：**核心链路价值 × 测试锚定（能否安全拆） × 拆解成本**。
有直接测试锚定的优先（可判据级变异验证，拆得安全）；零覆盖的必须**先补测再拆**
（V4.20 教训：虚覆盖不能裸重构——函数被调用于是覆盖率好看，但分支从未被断言锚定）。

### P0 —— 核心链路最大头（价值最大，难度最大，单独一批）
- **`_sendMessageCore`（311）**：产品心脏路径，全项目最大超限。零直接测试，
  需先补判据级测试，再拆 6-7 层（参考批次十二 234 行拆 5 层的节奏）。

### P1 —— 核心校验/解析 + 直接测试锚定（安全优先）
- **`validateDiagnosisSchema`（101）**：有直接测试，拆得稳。
- **`_validateDiagnosis`（145）**：诊断解析核心，有间接锚定，拆前确认判据覆盖。

### P2 —— 画像/评估（直接测试或可快速补测）
- **`buildStudentContext`（117）**：直接测试最充分（5 处引用），最安全的一批。
- **`_buildSyndromeDetail`（98）**：零覆盖，需先补测。

### P3 —— 校验器族（零直接覆盖，先补测再拆）
- **`validateEditorSchema`（145）+ `_parseObservation`（142）**：`editor_validator.dart` 两个。
- **`_parseTrainingTask`（141）+ `validateTeacherSchema`（112）**：`teacher_validator.dart` 两个。
- 这 4 个同属"schema 校验 + 字段解析"模式，拆法高度相似，可同批处理。

### P4 —— LLM 客户端（live 测试，风险高，最后）
- **`streamChat`（154）**：流式状态机，live 测试被排除，变异验证只能靠 mock 补测，
  风险最高，放最后单独谨慎处理。

## 5. 每批标准流程（范式固化，批次一~十二验证）

1. **扫描**：`python tool/check_r019.py --json <tmp>` → 确认目标函数与新增超限。
2. **拆前**：Read 确认拆点 → 有测试的确认判据覆盖；零覆盖的**先补判据级测试**。
3. **拆分**：写一次性 Python 脚本（`io.open(newline='')`，按实际 eol；锚点 assert 防部分写盘）。
4. **format + analyze**：`dart format` 写入 → `flutter analyze lib --no-pub` 全绿。
5. **抽测**：`flutter test <锚定文件> --no-pub`。
6. **变异验证**：判据级变异（`tool/_r019_mutation_bNN.py`，shell=True、'All tests passed!' 判据、
   try/finally 恢复、INJECT-FAILED 锚点校验、基线健康校验）。漏网先补测再收。
7. **全量门禁**：六道（format / analyze / 全量测试 / 循环依赖 / 密钥 / R-019 止血）。
8. **baseline 重生成**：`python tool/check_r019.py --json tool/r019_baseline.json`（**绝不带 --baseline**）
   → `python tool/_verify_r019_baseline.py` 验证仍能拦（V4.14 硬约束）。
9. **清理**：删一次性拆分脚本（保留 mutation 脚本）。
10. **台账 + commit**：`docs/待办执行清单.md` 追加（53→56 起）、git commit。

## 6. 关键风险与依赖

- **零直接测试的 6 个函数**（_sendMessageCore / validateEditorSchema / _parseObservation /
  _parseTrainingTask / validateTeacherSchema / _buildSyndromeDetail）：拆前必须先补判据级测试，
  否则变异验证无从谈起（V4.20/V4.21 虚覆盖教训）。
- **`streamChat`**：live 测试被排除，变异验证需 mock SSE 流补测；流式解析状态机拆错易引入
  行为漂移，最后谨慎处理。
- **拆过头风险**：无护栏防"拆得丑"（间接层地狱）。每批 review 时留意 helper 是否内聚。
- **baseline 陷阱**：重生成绝不能带 `--baseline`（V4.14）；清偿后必须验证仍能拦。
- **CRLF 陷阱**：`dart format` 写入会把文件重置 LF（V4.17）；测试文件工作区 CRLF，
  补测写入用 Python 归一化（V4.4）。
