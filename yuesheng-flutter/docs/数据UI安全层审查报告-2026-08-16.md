## 一、数据层（drift，schemaVersion=25，20 张表）

### 🔴 致命（1 个）

**`outline_impression.status='expired'` 与迁移 CHECK 三方脱节（历史 RN bug 同型复发）**
- `outline_repository.dart:230/249` 的 `cleanupPendingImpressions` 写 `status='expired'`；
- 迁移 v18 的 CHECK 只允许 `('pending','active','rejected','superseded')`（`database.dart:530-531`）；
- 而 `tables.dart:656-658` 又**没声明 CHECK**。
- 结果（SQLite 实测复现）：**新装库**（drift createAll 生成、无 CHECK）写入成功；**升级库**（v18 起带 CHECK）写入必抛 `CHECK constraint failed`。
- 该调用在 `outline_service.dart:134` → 被 `chat_service_diagnosis.dart:597-599` 整条吞掉 → **升级用户一旦出现超 7 天的 pending 印象，大纲记忆功能静默报废**。
- **与 RN 版 `session_reference.ref_type` CHECK 漏 'file' 是同一类 bug，且多了一层"新装/升级双 schema 分叉"。**

### 🟠 严重（3 个）
1. `session_repository.dart:398-420` **`deleteOrphanSessions` 漏删 student_model** → `student_model.session_id` 是 NOT NULL + FK SET NULL，删父会话时触发 `NOT NULL constraint failed`（实测复现）→ "清除缓存"功能必然失败。
2. `database.dart:667` **v24 重建 chapters 时 DROP TABLE 隐式清空全部 `sessions.chapter_id`**（FK SET NULL）→ 升级后会话冗余缓存丢失，`getOrCreateSessionForChapter` 会重复建会话。
3. `editor_observation_repository.dart:54` **UPSERT 冲突目标错位** → drift `insertOnConflictUpdate` 只认主键（随机 uuid），`UNIQUE(session_id,message_id)` 冲突不被吸收 → 重复写入抛 UNIQUE violation 且被静默吞掉 → 丢观察数据。

### 🟡 一般（5 个）
多步写未包事务（建会话三连写）、resolve/remove/confirm 非原子、`deleteVolume` 只删 draft 章节（与注释不符）、outline 两表 drift 定义无 CHECK 但迁移有（双 schema 温床）、章节物理删除不清理孤儿 KV。

### ✅ 健康部分（实测确认）
WAL + foreign_keys=ON 在 beforeOpen 开启；迁移链 v2→v25 连续无跳号、所有 ALTER 带默认值、v11/v21 重建表 INSERT-SELECT 保数据；CHECK↔Dart 枚举**全部一一对齐**；v21 file 修复是"三方一致"正面范例；commitDiagnosis/deleteSession 等核心路径事务规范。

## 二、UI/体验层

### 🔴 致命（1 个）
**跨会话流式状态泄漏**：`chat_store.dart:79-172` ChatStore 全局单例且 `isStreaming/streamingContent` 不带 sessionId；流式中切换/新建会话不清流式状态 → **旧会话流式气泡渲染到新会话**，`onComplete` 闭包还可能把旧会话消息整表覆写当前会话。

### 🟠 严重（8 个）
1. 流式自动滚动劫持（每 token 无条件滚到底，用户上翻被拽回）
2. 每 token 全页 rebuild + O(n²) 字符串拼接
3. 消息加载竞态（fire-and-forget last-write-wins 乱序）
4. 书架动作失败污染整页错误态（一次创建失败吞掉已加载列表）
5. 作品详情章节 Tab 无错误态、文件 Tab 无 loading/error
6. 设置页静默失败（配置读失败误显"尚未配置"）
7. 自动诊断失败静默（无 SnackBar 无日志）
8. 输入区按钮 <44dp 触控目标

### 🟡 一般（9 个）
500ms 定时器未取消（dispose 后 ref 崩溃风险）、7 处无日志静默 catch、暗夜主题色值硬编码（违反 app_theme"唯一常量来源"）、IntrinsicHeight 布局开销、4 处非懒加载列表、色条卡片/删除弹窗/格式化函数多处重复、自定义 checkbox 无 Semantics。

### 🔵 观察（4 个）
路由字面量混用、版本/邮箱硬编码、以及正向实践（气泡 Semantics、RepaintBoundary、三态覆盖、prefers-reduced-motion 尊重）。

## 四、跨层核心发现（最重要）

**宪法 §八 A7「类型/建表/DAO 三方脱节」被标为"✅ 已布防（批次7 v21 file 修复）"，但数据层审计实测发现：同一类 bug 在 `outline_impression.status='expired'` 上又复发了一次——而且更隐蔽（新装/升级双 schema 分叉，测试全 mock 测不出）。**

**结论：A7 这条教训没有被真正吸收，只修了 file 那一处。宪法 §八 A7 的布防状态应从"✅ 已布防"修正为"⚠️ 部分布防"。** 这正是"防假完成"的又一次印证——批次 7 修好了 file，但"三方脱节"这类结构性风险需要机器级防护（迁移 SQL 的 CHECK 与 drift 表定义由同一真源生成），否则每加一个 status 值都可能再踩一次。
