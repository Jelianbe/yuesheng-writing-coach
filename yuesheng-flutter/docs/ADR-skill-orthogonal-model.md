# ADR：Skill 三正交维度模型（知识 × 动作 × 态度）

- 状态：**提案**（待舰长确认后生效）
- 日期：2026-08-28
- 关联：R-019（代码规范）、R-021（AI 行为边界）、R-010（最小化范围）
- 影响模块：`lib/services/skill_registry.dart`、`skill_layers.dart`、`skill_dispatcher.dart`、`syndrome_knowledge_base.dart`、`technique_knowledge_base.dart`
- 真源参考：`yuesheng-android/src/assets/skills/skill-layers.ts`、`architecture-design-provenance-2026-08-26.md` §7（P1-1 待回填）

## 1. 上下文与问题

### 1.1 舰长的早期设想

产品早期设想是「态度 skill 拼接内容 skill，形成指令姿势」——即**人格层与知识层分离**：

```
态度（怎么说话）  +  内容（教什么）  →  一份完整指令
```

换态度不动内容，换内容不动态度。这是 prompt 工程的标准正交组合模型。

### 1.2 现状：态度已独立，内容层「不纯」

用代码核验（2026-08-28）：

- **态度层已分离** ✅：`attitude-doubao/yuesheng/sensei` 是纯姿势——角色定位、教学行为约束（提问上限、反馈结构、示范与否）、表达密度。零教学内容。
- **内容层是「知识 + 场景姿势」的混合块** ❌：以 `plot-design` 为例——

| 段落 | 本质 |
|:--|:--|
| 「故事结构 = 因果链。B 必然因 A 发生」 | 知识（死的） |
| 「教练的工作是帮用户找到第一圈引擎」 | 教学动作（活的） |
| 「引擎启动三问（必问）」 | 教学动作（活的） |
| 「❌ 红线：不要问结局」 | 教学动作边界（活的） |
| 「话术：『好了，我们现在有……』」 | 话术示例（半活的） |

### 1.3 混合块带来的三个具体毛病

1. **规则打架**：态度层说「每轮最多 3 个问题」，内容层说「引擎启动三问必问」。学员答不上来时，砍问题还是换追问？两层无消解机制，AI 自行猜测。
2. **重复注入**：态度层已有反馈结构，内容层又自带引导话术——都在教「怎么引导」，token 浪费且互相稀释。
3. **僵化**：切档位只变语气，但「新手扶着走 vs 老手直接指出」的教学动作差异没有独立维度承载，动作不随学员成熟度变化。

### 1.4 数量膨胀的机制（40 份的构成）

`skillRegistry` 实测 40 份，去重后约 28 个本体：

- **L1 常驻 9 + 态度 3**：骨架（`skill_layers.dart` L24-35）
- **L2 五组 26 条注册**：按教学场景横向展开——每新增一类场景（beginner/diagnosis/training/advanced/outline）就横切一组，场景枚举一开数量失控
- **虚拟索引 2**：`syndrome-diagnosis-index` / `technique-library-index`
- 三笔虚胖：
  1. **V1/V2 双轨**：`useTrainingV2Pilot = true`，注册表仍有 3 个 V1 残留（training-loop / training-evaluation / text-surgery）
  2. **跨组重复挂载**：10 个本体被挂 26 次（reader-awareness 挂 4 组、coaching-actions 挂 4 组），同一份 4000 tokens 知识多场景各注入一遍
  3. **大块未索引化**：teaching-strategy 4400 / narrative-design 4200 / advanced-phases 4200 / outline-diagnosis 4200 / coaching-rhythm 3500 / genre-guide 3500 / plot-design 3400

而「索引化」模式**已经在代码里验证过**：`syndrome-diagnosis-index`（L2 索引 1800 tokens + L3 手册按需检索）、`technique-library-index`（L2 索引 900 tokens + L3 完整技法库）。这条路走了一半，剩下的大块没跟上。

## 2. 决策

### 2.1 目标模型：三个正交维度

```
知识（数据）    ×    教学动作（行为）    ×    态度（参数）
教什么                怎么教                 做多猛
因果链理论             三问启动引擎            豆包  = 扶着走
红线标准              断裂诊断法              sensei = 直接指出
```

| 维度 | 载体 | 可变性 |
|:--|:--|:--|
| 知识 | 知识库数据文件（现有 `*_knowledge_base.dart` 体系扩展） | 改内容只改数据，不碰代码、不过门禁 |
| 教学动作 | 行为指令卡（skill 本体瘦身后的核心） | 决定 AI 做什么，随场景选择 |
| 态度 | 参数（提问数量、示范与否、直接程度） | 作用于动作的调节量，随档位切换 |

### 2.2 关键设计决策

**教学动作是独立维度，不并入态度层。**
理由：新手 vs 老手的差异不只语气，还有教学节奏本身（扶着走 vs 直接指出）。动作需要同时受「学员成熟度」和「场景」两个因素影响，塞进态度层会重新焊死两个维度。

**态度层参数化**：`attitude-*` 从「独立 skill 文本」演化为「参数集」，注入时作用于动作指令（如「提问上限 = 3」直接调节动作卡里的提问指令）。

### 2.3 判断标准（逐句切分工具）

> 「删掉这句话，AI 还知道教什么吗？」
> - **知道** → 这是动作/话术，抽走或参数化
> - **不知道** → 这是知识，进数据

### 2.4 长期治理规则

1. **准入规则**：新 Skill 必须证明「无法由已有 Skill 组合实现」，否则并入现有组。写入 `skill_registry.dart` 头注释。
2. **索引优先**：新增知识先走知识库（L3），skill 只挂索引 + 路由。
3. **态度档位扩展**：加第四档态度 = 加一个参数文件，不新增 skill。

## 3. 后果

### 3.1 收益

- 改话术/知识点不再依赖代码操作（舰长可自助改数据）
- 加档位、换场景、换教材互不牵连
- 注入 token 总量下降（跨组去重 + 大块索引化，预计 L2 注入降 30%+）
- 注册表从 40 份收敛到 ~25 个本体

### 3.2 成本（诚实声明）

- **分层后总 token 不会更少，甚至略增**（索引 + 组装层开销）。换的是**可组合性与可维护性**。
- 25 个内容本体逐个拆分「知识/动作」是**大工程**，每个都要语义等价确认，必须立项，不能顺手做。
- 涉及教学核心模块，按项目纪律需走 GStack Think→Plan→Build→Review→Test→Ship，全链路门禁。

### 3.3 风险与缓解

| 风险 | 等级 | 缓解 |
|:--|:--|:--|
| 拆分后语义漂移（动作抽取破坏教学行为） | 高 | 每本体拆分前后做语义等价断言；分阶段交付，Phase 4 逐个确认 |
| 索引化后 L3 检索命中率不足 | 中 | 复用 syndrome/technique 已验证的检索链路；补命中率测试 |
| 跨组去重改变组内上下文语义 | 中 | 共享本体只存一份 content，各组挂「语境指针+适配指令」；等价测试 |
| 组装层复杂度上升 | 中 | 组装逻辑收敛到 dispatcher 单点，先写契约测试 |

## 4. 备选方案

### 4.1 不重构，维持现状
- 优点：零风险
- 缺点：死板感持续，舰长改话术永远依赖技术操作，规则打架问题无解
- 结论：否决（正是本次要解决的问题）

### 4.2 只压缩数量，不做维度拆分（删 V1 + 去重）
- 优点：快速见效，Phase 1-2 即可
- 缺点：只治「虚胖」，不治「死板」——混合块结构原样保留
- 结论：作为本 ADR 的 Phase 1-2 先行落地，但必须继续到 Phase 4 才算完成

### 4.3 教学动作并入态度层（二维模型）
- 优点：实现简单（只拆知识/姿势两层）
- 缺点：动作差异（新手 vs 老手）与语气差异捆绑，切档位会连带改变教学节奏，无法按学员成熟度独立调节
- 结论：否决，理由见 §2.2
