## 1. 生成正式 keystore（本机执行，约 1 分钟）

```bash
# keytool 随 JDK 17 安装（项目要求 Java 17）。Windows 常见位置：
# "C:\Program Files\Android\Android Studio\jbr\bin\keytool"
keytool -genkey -v -keystore D:/keys/yuesheng-upload.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias yuesheng
```

- 会提示输入两个密码（keystore 密码与 key 密码，可设为同一个）——**不要用 AI
  会话生成或转达密码，自己想、自己存**。
- **keystore 目录建议放仓库之外**（如 `D:/keys/`）。`android/.gitignore` 已覆盖
  `key.properties`、`**/*.keystore`、`**/*.jks`，双保险。
- ⚠️ **丢失 keystore = 永远无法再给同一包名发更新**（用户只能卸载重装）。
  生成后立刻把 `yuesheng-upload.jks` + 两个密码备份到你信任的地方（密码管理器 /
  离线介质各一份）。这是本清单里唯一不可挽回的一步。

## 2. 填写 key.properties（不上库）

新建 `yuesheng-flutter/android/key.properties`（模板如下，值换成你的真实信息）：

```properties
storeFile=D:/keys/yuesheng-upload.jks
keyAlias=yuesheng
keyPassword=<你的 key 密码>
storePassword=<你的 keystore 密码>
```

- `storeFile` 建议用绝对路径（正斜杠）；若写相对路径，是相对 `android/app/` 目录。
- 填完执行 `git status` 确认它**没有**出现在待提交列表里（被 ignore 即正常）。

## 3. 正式出包

```bash
cd yuesheng-flutter
# versionCode 真源 = pubspec.yaml 的 `+N`（当前 0.5.3+4017 ⇒ 4017），必须大于线上已发最大值、不得回退
# ⚠️ 不要手写 --build-number 覆盖 pubspec —— 2026-10-11 那次正是这么做的（pubspec 写 2016、实发 4016），
#    且未留痕，导致 `+N` 与线上真实值长期不一致。让 pubspec 做唯一真源。
flutter build apk --release --target-platform android-arm64
```

- 若 `key.properties` 缺失或不完整，构建会**直接报错**（fail-fast，防止误发
  debug 签名包）——这是设计行为，补齐文件重跑即可。
- 产物：`build/app/outputs/flutter-apk/app-release.apk`。

### 4.5 部署后必跑：下载链路自检（★ 2026-11-13 事故后新增）

> **事故原形**：落地页下载按钮写的是相对路径 `downloads/xxx.apk`，**不带 `sharecode`**，
> 而站点由 `?sharecode=` 门禁放行 —— 相对 URL 不继承父页面的 query，请求退化成裸链，
> 网关返回 **403 + 3174 B「链接不完整」HTML**。手机端把下载委派给系统下载器时不继承
> 浏览器 Cookie ⇒ 必然失败：轻则「下载错误」，重则错误页/同名目录落盘，安装器读目录报
> `EISDIR`「解析软件包时出现问题」。**小米 14 与荣耀 500 Pro 同时中招，包本身无罪。**

部署完成后**必须**跑一次，全 PASS 才可发内测：

```bash
python -X utf8 D:\ai-teacher\.ai\tools\check_landing_download.py ^
  --base https://yuesheng-apk-test.app.workbuddy.host ^
  --sharecode WHHKITHUJH ^
  --apk D:\ai-teacher\yuesheng-flutter\build\app\outputs\flutter-apk\app-arm64-v8a-release.apk ^
  --full
```

判据清单（缺一不可）：

| 检查 | 必须 | 为什么 |
|:--|:--|:--|
| `[2] href 自带 sharecode` | **PASS** | 根因判据。不带就是本次事故原形 |
| `[3] HEAD 200` + `Content-Length` == 本地包字节数 | PASS | 传上去的必须是同一个文件 |
| `[3] Content-Type` 为 `application/vnd.android.package-archive` | PASS | 若是 `text/html` 说明下到的是错误页 |
| `[4] 裸链 403` | **PASS** | 证明门禁仍在 ⇒「href 带参数」是必需而非可选；哪天裸链变 200，说明门禁放开了，口径需重审 |
| `[5] og:image` 带 sharecode 且 200 | PASS | 社交平台抓预览图不执行 JS、不带 Cookie |
| `[6] --full` 的 sha256 | 与本地逐字节一致 | 传输损坏/部署错包的唯一判据 |

**部署前自查**：`--full` 之前先确认 `site\index.html` 里的 `href` 与 `og:image` 都带了 `?sharecode=`。
页面末尾有一段 JS 会从访问者 URL 里透传 sharecode（覆盖静态值），但 **og:image 只能静态写死**，
sharecode 轮换时务必同步改 `index.html` 第 14 行。

### 4.6 让内测用户重试前的三步（★ 按序，缺一步就可能白试）

> 适用：2026-11-13 下载链路修复**部署之后**，此前失败过的用户重新装。
> 线上包实测：`PASS 8 / FAIL 0`，`--full` 下载 `37,127,429 B`，
> sha256 `A2F81301D729BC87692C262040B6918DEDCC38E1F781D672BD7CF9A4EE4129E3`
> 与 `app-arm64-v8a-release.apk` **逐字节一致**。包装得起来：`minSdk 24` / `targetSdk 36` /
> `arm64-v8a` / v2 签名（aapt2 + apksigner 实dump）⇒ 「解析包时出现问题」**不是** SDK 门槛造成的。

**第 1 步 · 先删残留（最容易被跳过，也最致命）**

文件管理 → 「下载 / Download」→ 删掉 `yuesheng-v0.6.1-arm64.apk`，**以及同名的「文件夹」**。
上次故障把 3174 B 的「链接不完整」错误页存成了一个**目录**，安装器读目录才报
`read failed: EISDIR (Is a directory)`。残留不删，下面两步做得再对也没用。

**第 2 步 · 必须从带 `sharecode` 的分享链接进页面**

裸域 `https://yuesheng-apk-test.app.workbuddy.host/` 不带参数会被网关 **403**（这条是设计，
`§4.5` 判据 `[4]` 要求它保持 403）。正确入口：
`https://yuesheng-apk-test.app.workbuddy.host/?sharecode=WHHKITHUJH` → 点页面上的下载按钮。

**第 3 步 · 装之前先看文件大小**

| 看到的 | 判断 | 动作 |
|:--|:--|:--|
| **37,127,429 字节 ≈ 35.4 MiB**（文件管理器多半显示 `37.1 MB`） | 包完整 | 可以装 |
| 2–4 KB / 打不开 / 显示成「文件夹」 | 还是没下到包 | 别装，回第 1 步重来 |

**为什么第 1 步不能省（实测）**：服务端**不支持 Range** —— `Range: bytes=0-99` 返回
`200` + 全量 `Content-Length: 37127429`，无 `Accept-Ranges`、无 `206`。⇒ 断点续传不可靠，
旧残留有被续写成坏包的风险。

**若第 3 步大小正确、仍然报「解析包时出现问题」** ⇒ 已经**不是下载问题**，按这两条查
（**未验证**，属待查项，登记在 `.ai/reports/2026-11-13-APK分发故障自查.md §11.5`）：

- 荣耀 magicOS 10：设置 → 安全 → **纯净模式 / 纯净化安装**是否开启（开启时只允许应用市场安装）；
- 是否已给浏览器或文件管理器开启「允许安装未知来源应用」。
