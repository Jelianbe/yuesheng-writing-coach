> `key.properties`，批次 2 建、批次 70 修复 fail-fast 作用域）、gitignore 覆盖确认、
> 调试 keystore 流程验证出包。**以下步骤必须由舰长本人完成——密钥生成与密码填写
> 不经 AI 会话（R-029：任何密钥不入库）。**

## 1. 生成正式 keystore（本机执行，约 1 分钟）

```bash
# keytool 随 JDK 17 安装（项目要求 Java 17）。Windows 常见位置：
# "C:\Program Files\Android\Android Studio\jbr\bin\keytool"
keytool -genkey -v -keystore D:/keys/yuesheng-upload.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias yuesheng
```

- 会提示输入两个密码（keystore 密码与 key 密码，可设为同一个）——**不要用 AI
  会话生成或转达密码，自己想、自己存**。
- **keystore 目录建议放仓库之外**（如 `D:/keys/`）。`android/.gitignore` 已覆盖
  `key.properties`、`**/*.keystore`、`**/*.jks`，双保险。
- ⚠️ **丢失 keystore = 永远无法再给同一包名发更新**（用户只能卸载重装）。
  生成后立刻把 `yuesheng-upload.jks` + 两个密码备份到你信任的地方（密码管理器 /
  离线介质各一份）。这是本清单里唯一不可挽回的一步。

## 2. 填写 key.properties（不上库）

新建 `yuesheng-flutter/android/key.properties`（模板如下，值换成你的真实信息）：

```properties
storeFile=D:/keys/yuesheng-upload.jks
keyAlias=yuesheng
keyPassword=<你的 key 密码>
storePassword=<你的 keystore 密码>
```

- `storeFile` 建议用绝对路径（正斜杠）；若写相对路径，是相对 `android/app/` 目录。
- 填完执行 `git status` 确认它**没有**出现在待提交列表里（被 ignore 即正常）。

## 3. 正式出包

```bash
cd yuesheng-flutter
# versionCode 必须大于上一版（上一版 0.3.0 release = 2004，本版 0.3.2 = 2005）
# 不用 pubspec 里的 +N，因为历史 release 用了 2004 这种编号
flutter build apk --release --target-platform android-arm64 --build-number <下一版本号>
```

- 若 `key.properties` 缺失或不完整，构建会**直接报错**（fail-fast，防止误发
  debug 签名包）——这是设计行为，补齐文件重跑即可。
- 产物：`build/app/outputs/flutter-apk/app-release.apk`。

### versionCode 编号规则（2026-09-28 补）

| 版本 | versionCode | 签名 | 备注 |
|---|---|---|---|
| 0.3.0 | 2004 | **debug**（历史误发） | 当时 key.properties 未配好，回退了 debug 签名 |
| 0.3.2 | 2005 | **正式 release** | 首次正式签名，用户需卸载旧 debug 包后安装 |
| 未来 | 2006+ | 正式 release | 每次发版 +1，**不得回退** |

⚠️ 0.3.0 那个包是 debug 签名（`CN=Android Debug`），0.3.2 起切到正式签名
（`CN=Yuesheng Writing Coach`）。这是一次性切换——用户卸载旧版后，以后所有
正式包签名一致，可直接覆盖升级。

## 4. 验证签名（出包后必做一次）

> ⚠️ 不要用 `keytool -printcert -jarfile`——AGP 默认 v2 签名，jar 校验会报
> 「不是已签名的 jar 文件」（本批实测）。用 apksigner：

```bat
:: apksigner 在 Android SDK build-tools 下，版本号以本机为准
%ANDROID_HOME%\build-tools\37.0.0\apksigner.bat verify --print-certs build\app\outputs\flutter-apk\app-release.apk
```

- 输出应显示你第 1 步生成证书时填的 CN/组织信息；
- 若显示 `CN=Android Debug, O=Android, C=US`，说明签名回退到了 debug
  keystore——检查 key.properties 四个键是否齐全，重跑第 3 步。
- 顺手核版本（需 aapt2，同目录）：

```bat
%ANDROID_HOME%\build-tools\37.0.0\aapt2.exe dump badging build\app\outputs\flutter-apk\app-release.apk | findstr "package targetSdk"
```

  预期：`versionName='0.3.2'`、`versionCode='2005'`、`targetSdkVersion:'36'`。

## 5. 发给内测用户

APK 直接发文件即可安装（Android 8+ 需允许「安装未知来源应用」）。安装后核对：
设置页「关于」→ 版本应显示 `v0.3.0`、包名 `com.yuesheng.writingcoach`。

**体积说明**：默认出的是全 ABI 合并包（fat APK，本批实测 71.4MB，含
arm32/arm64/x64 三份引擎与代码）。若想减半，用单 ABI 分包：

```bash
flutter build apk --release --split-per-abi   # arm64 单包约 25MB
```

产物在 `build/app/outputs/flutter-apk/app-arm64-v8a-release.apk`，发内测时
让用户看设置 → 关于手机确认 CPU 架构（近十年手机基本都是 arm64）。
