# 月笙写作教练 v0.1.0（内测版）— 已知问题与诚实说明

> 这是内测版。下面这些是我们**知道且承认**的不足——不粉饰，也不值得吓你。
> 遇到本清单之外的问题，请用设置页「导出会话记录（JSON）」+「反馈建议」告诉我们。

## 先说承诺（不变的）

- **全部数据只存在你的设备本地**，无任何遥测、无数据上报。
- 你的作品文本只会在你主动发送诊断/对话时，发往**你自己配置的 DeepSeek API**；
  费用计入你自己的 DeepSeek 账户（设置页有「如何获取 DeepSeek Key」指引）。

## 已知问题（这是内测，这些我们知道）

### 1. 请求设定类帮助时偶发「抢诊断」

向教练请求设定类帮助（如 OC 设定）时，偶发被诊断流程抢先响应、设定求助没有得到
直接回答。经排查（2026-09 生产模型批回归），该现象**在生产模型上 0/3 复现**，
判定为特定模型（GLM 系）的特有行为而非产品缺陷；已降级为观察项持续跟踪。
如果你配了不同模型且遇到类似现象，欢迎导出会话告诉我们你的模型型号。

### 2. 长文本诊断的性能与准确度

长文分块诊断曾在推理型模型上出现「整块返回空结果却被静默当成功」的问题
（2026-09-06 已按 ADR-C80 修复：关闭该路径的推理模式 + 分级降级 + 失败块显式留痕，
不再静默吞掉）。**残留风险**，坦白两条：

- 关闭推理后，个别症候的编号可能落在语义相邻的兄弟症候上（如把 P003 愤怒/悲伤
  埋点判成相邻的 P037 心理内耗）——原文引证与严重度判断不受影响，编号可能偏一格；
- 单块分析时延仍受模型负载影响（数秒到数十秒），耐心等一等。

### 3. 换模型 = 换脾气

本应用的教练行为按 DeepSeek 生产模型校准。内测期间如果你在设置里换成其他模型
（GLM、Claude 等），会观察到行为差异：教学卡片的发射频率、建议的详略、症候判断
的倾向都可能不同——这不是 bug，是模型本身的差异。**想要与设计一致的体验，请用
DeepSeek。**

### 4. 「查看原文」找不到时会明说

角色事实的每条断言都带原文证据。当章节后来被你改写、原文已经不在时，角色详情页
会**明确显示「未定位到原文」**并灰显——我们选择诚实地说找不到，而不是假装定位
到一段不相干的文字。

### 5. 内测版本身的状态

- 教学状态机、诊断分块、角色库均已通过 2500+ 自动化用例与真机走查，但**真实
  写作场景的长尾永远比测试多**——这正是内测的意义。
- 首次对外分发，签名与包名（`com.yuesheng.writingcoach`）自此固定；之后的更新
  都会以覆盖安装的方式升级。

## 反馈怎么做

设置页 →「导出会话记录（JSON）」（文件含你的作品原文，发之前自行决定脱敏）→
连同问题描述发到反馈邮箱（设置页 →「反馈建议」可一键复制）。
