# ADR：知识注入驱动模型（Knowledge Injection Driver Model）

- **状态**：提案（待舰长确认）
- **日期**：2026-08-28
- **前置**：`docs/ADR-skill-orthogonal-model.md`（三正交维度模型）
- **相关**：`docs/designs/2026-08-28-skill-orthogonal-refactor-plan.md` §5 / §7
- **性质**：**补充性 ADR，不推翻前置 ADR。** 前置 ADR 回答「知识怎么切分」，本 ADR 回答「切完之后运行时怎么选中」。二者是同一件事的两半，缺了后一半，前一半的收益无法兑现。

## 1. 上下文与问题

### 1.1 先纠正一个口径：风险早被预见，但缓解措施瞄错了靶子

Phase 3 侦察的结论容易被表述成「方案漏掉了触发源」。这个说法不准确，予以纠正：

| 来源 | 原文 | 已预见 |
|:--|:--|:--|
| 方案 §5 风险栏 | 「知识被拆到 L3 后，若检索不触发则 AI 失去知识 → 检索触发条件的完整度是验收重点」 | 是，标为**高** |
| 方案 §5 回滚栏 | 「revert 后恢复整块注入，知识无丢失（git 历史完整）」 | 是，默认拆了可能丢 |
| ADR §3.3 风险表 | 「索引化后 L3 检索命中率不足 / 中 / 复用 syndrome/technique 已验证的检索链路」 | 是，标为**中** |

三处都看见了。**但缓解措施瞄的是「链路可靠性」，真正的缺口是「信号源缺失」**——这两件事不在同一个层面。链路回答「信号来了能不能取到知识」，信号源回答「信号会不会来」。复用一条已验证的链路，无法凭空生产出链路的输入。

### 1.2 事实核查：全仓只有一个触发信号，且它是症候专属的

以下均为 2026-08-28 实测，非推断：

| 核查项 | 结果 | 依据 |
|:--|:--|:--|
| `injectL3` 的生产调用点 | **零** | 定义于 `contracts/teaching_capability.dart:94/101`，由 `skill_dispatcher.dart:144/175` 返回；全仓无 `.injectL3(...)` 调用（仅锚点测试取字段） |
| 生产侧 L3 注入唯一入口 | `chat_service.dart:1441/1451` | `getTrainingContent([focusSyndromeId])`、`getTrainingFewShot([focusSyndromeId])` |
| 输入信号 | **仅 `focusSyndromeId`** | 由症候 detector 扫描产出 |
| 六块是否有对应信号 | **无** | 情节 / 世界观 / 大纲没有 detector，症候探测器不产出这些信号 |
| 关键词扫描补信号的可行性 | **已否决** | X-043 评估记录在 `chat_context_builder.dart` 注释：用户不会说症候名、命中率低易误命中、违反「AI 自主判断 > 刻板规则」 |
| 意图分类器维度 | compose / revise / ask / smalltalk | **无话题维度**，无法区分「问情节」和「问大纲」 |

**结论**：L3 从来就不是通用按需检索层，它是**症候知识库**。方案 §5 把它当通用检索层复用，是把一个专用设施当公共设施用。

于是方案 §5 标注的「高」风险，在当前架构下不是概率性的，是**结构性必然**：六块拆到 L3 之后，没有任何信号会去取它们 → 拆到 L3 等于删知识。

### 1.3 连续三次量化目标失准的共同根因

| Phase | 方案预期 | 实测 | 根因 |
|:--|:--|:--|
| 0 | token 估值 | 8 处事实错误已修正 | 按「全量注入」模型估算 |
| 2 | L2 注入降 30%+ | **+0.09% ~ +0.41%**（反向） | 分类学改进，运行时一字未动；contextHint 是净新增文本 |
| 3 | 大块降至索引级 <800 tokens | A 组实测 -4.8% ~ -7.8%，30% 不可达 | 无触发源，索引化范围被迫收窄 |

三次都在改「**知识怎么组织**」，没有一次定义「**知识怎么被选中**」。这是同一个缺口的三种表现。

### 1.4 里层：三正交维度，运行时只装了两维

```
        分类学（已定义）          运行时装配
知识  ×  动作  ×  态度      →    知识：无选择器（L2 全量灌入）
                                动作：intent_classifier 驱动  ✅
                                态度：ctx.attitude 三档      ✅
```

注：dispatcher **确实在生产主链路上**，已核实——`chat_page` 等 5 处 widget → `chatServiceProvider` → `session_providers.dart:123` → `capability_providers.dart:49` → `skill_dispatcher.dart:34`。因此本次改动生效，不存在「改了死代码」的问题。

⚠️ 附带发现：`capability_providers.dart:8-11` 注释称四个能力「已落地但**尚无调用方**」，该注释**整块过时**（四个 provider 均已被 `session_providers` 消费）。判断「有没有接线」必须追到 widget 层，不能信注释。

## 2. 决策

### 2.1 核心决策：知识的默认状态是「注入」

**采用「默认注入 + 按信号裁剪」，不采用「默认不注入 + 按检索命中」。**

两种策略的差别不在收益，在**失败模式**：

| 策略 | 正常情况 | 信号失效时 | 适用于 |
|:--|:--|:--|:--|
| 默认注入 + 裁剪 | 按需减少注入量 | **退化回全量**——token 不降，功能不丢 | 教学产品的默认策略 |
| 默认不注入 + 检索 | 大幅降低注入量 | **知识永久丢失**——token 降了，功能坏了 | 仅限信号可靠处 |

对一个教学产品，功能坏掉远比 token 高严重。**这是本 ADR 的第一条原则，也是唯一不可妥协的一条。**

推论：索引化（默认不注入）不是默认手段，是需要单独论证的例外。

### 2.2 裁剪准入三问

任何「按信号裁剪知识」的改动，必须书面回答三问，缺一不可：

1. **信号从哪来？** 必须有确定性来源（状态机、DB 字段、已落库的诊断结果），不接受文本猜测与关键词扫描（X-043 已否决）。
2. **信号缺失或不可信时退化成什么？** 必须能退回全量注入，不得退化为空。
3. **裁掉的段落，在该信号取值下是否确定不会被使用？**
   「确定不会」需要论证，不能凭直觉。论证方式：该段落所述行为的入口，在当前信号下不存在。

第 3 问是三问中最容易含混的一问。以已落地的 advanced-phases 为例：

| 裁剪项 | 是否满足第 3 问 | 论证 |
|:--|:--|:--|
| P5 段（远期规划） | 满足 | `TeachingPhase` 无 P5 枚举值，该段在任何 prompt 中都不可达 |
| P4 档裁掉 P3 段 | 满足 | 教学状态机单态运行，P4 档下不存在 P3 行为入口 |
| 通用迁移约束段 | **不满足** | 与 phase 无关，任何阶段都可能被引用 → **保留** |

### 2.3 驱动信号清单（现状盘点）

| 信号 | 来源 | 现状 | 可驱动的裁剪 |
|:--|:--|:--|:--|
| `ctx.phase` | 教学状态机 | **已用**（advanced-phases，2026-08-28 落地） | advanced-phases / coaching-rhythm |
| `work.genre` | DB `manuscripts.genre` | 已写入上下文（`chat_context_builder.dart:729`「类型：xxx」）但**未用于选知识** | genre-guide |
| `focusSyndromeId` | 症候 detector | 已驱动 L3 | 症候 / 技法 / 训练模板 |
| `ctx.attitude` | 用户输入 | 已驱动 L1 | —（态度是参数，非知识信号） |
| `intent` | intent_classifier | 未接入选知识 | 候选（需先补话题维度） |
| 会话历史 | 未建模 | 未用 | 候选 |

**准入规则**：新增一个驱动信号，等价于新增一条裁剪依据，必须过 §2.2 三问并回写本表。

### 2.4 量化口径改为实测

方案的 token 目标一律标注「**待实测**」，不再写死百分比。验收只认改造后实测值，改造前的估算不得作为验收依据。

已在 `docs/designs/skill-split-inventory.md` §9.2（Phase 2）与 §10（Phase 3）各修正一次，本条使该做法成为惯例。

## 3. 后果

### 3.1 收益

- Phase 3 有了可判定的完成标准：能过三问的裁剪就做，过不了的不做，不再靠「索引化」这个含混目标推进。
- Phase 4（知识 / 动作拆分）提前获得判据——拆完的知识放在哪一层，取决于它有没有驱动信号，而不是取决于它大不大。
- 失败模式从「知识静默丢失」变为「token 未下降」，后者可见、可回滚、可接受。

### 3.2 成本（诚实声明）

- **本 ADR 不产生 token 收益**。它是约束条件，不是优化手段。A 组的实测降幅（advanced -5.1%/-6.9%、诊断 -7.8%、新手 -4.8%）来自具体裁剪实现，不是来自本 ADR。
- 「默认注入」意味着 token 上限仍是全量。若要大幅下降，仍需先造出可靠的驱动信号——那是一个独立议题，不在本 ADR 范围内。
- 三问增加了每次裁剪的设计成本。这是有意的：它把「顺手裁一刀」变成需要论证的动作。

### 3.3 风险与缓解

| 风险 | 等级 | 缓解 |
|:--|:--|:--|
| 第 3 问论证含混，「当前不需要」被当成「确定不可达」 | **高** | 逐段列出裁剪项与论证（§2.2 表格为样板）；锚点测试冻结非裁剪档位的字节级输出 |
| 信号后来变得不可靠（如 genre 字段未填） | 中 | 第 2 问强制要求退化回全量；`?? skill.content` 已在 dispatcher 落地 |
| 长期只做裁剪不做检索，知识层永远无法真正按需化 | 中 | §2.3 表中 `intent` / 会话历史列为候选，待信号可靠后单独立项 |
| 本 ADR 变成「不许优化」的挡箭牌 | 中 | 例外通道明确：能过三问即可做，不设总量限制 |

## 4. 备选方案

### 4.1 维持方案 §5 原样（L2 索引 + L3 检索）

否决。当前架构下无触发源，等于删除六块知识。方案 §5 自身已将该风险标为「高」。

### 4.2 补一个「声明式检索」：让 AI 自己声明需要哪块知识

**不否决，但不在本 ADR 范围内。** 这是唯一能在不新增信号源的前提下实现按需检索的路径（AI 先输出所需知识块 ID，系统再注入）。代价是增加一轮交互、且依赖 AI 的声明准确性。若要做，应单独立项并做命中率实测，不应搭在 Phase 3 里做。

### 4.3 关键词扫描补信号（重启 X-043）

否决。X-043 的三条否决理由（用户不会说症候名、命中率低易误命中、违反「AI 自主判断 > 刻板规则」）依然成立，且关键词扫描违反 §2.2 第 1 问。

### 4.4 什么都不做，维持全量注入

可行但非最优。全量注入在功能上正确，在 token 上不可持续。本 ADR 选择的是「在全量注入的安全基线上做可论证的裁剪」。
