### B-1｜scenario-rules DP-F（`skills_l1_core_p4.dart:18-26`）

原：
```
## DP-F: 平台立场（防御点 F）
**触发词**：发平台、发番茄、发起点、上架、签约
**标准话术**：
> 平台明确公告：AI 润色的内容会拉黑账号，以后怎么写都不给流量。
> 你在月笙练完后，出月笙去平台发，必须用"AI 味浓度低"的版本。
> 月笙的 AI 检测器会告诉你：你这稿能不能发。
```

改为：
```
## DP-F: 平台立场（防御点 F）
**触发词**：发平台、发番茄、发起点、上架、签约

**必须让学员知道的意思**（说法由你组织，不照念）：
1. 各平台对 AI 生成/AI 润色内容有各自的审核规则，且规则会变——风险由学员自己承担，
   我不能替他判断"这稿能不能发"。
2. 在月笙练出来的东西，是学员自己写出来的版本；这一点是他能对平台负责的前提。
3. 因此：不代笔、不润色、不续写。

**不要说**：
- 不要引用任何具体平台的"公告"内容（我没有可靠的实时信源，说了就是编）
- 不要说"月笙有 AI 检测器/会告诉你能不能发"（没有这个功能）
```

> 依据：`AI 检测器` 在 `lib/` 全库零实现；代码中存在的 5 个检测器是
> `conflict_detector / dialogue_tag_detector / event_causality_detector /
> grammar_lexical_detector / subplot_closure_detector`（`chat_context_builder.dart:16-20`），
> 全部是**写作文本规则扫描**，与 AI 味检测无关。
> 「平台明确公告…拉黑账号…不给流量」在 `lib/` 全库无任何二次来源。

### D-1｜coaching-rhythm 的"训练节奏"规则，训练阶段根本不加载【存疑】

`coaching-rhythm` 只在 `L2Mode.beginner` 和 `L2Mode.diagnosis` 两组挂载

含义有两种可能：
- (a) 设计意图如此——训练前的桥接在 DIAGNOSIS 子阶段发出，进入 PRACTICE 后不再需要；
- (b) 漏挂——训练过程里的节奏约束实际上没进 prompt。

我倾向 (a)：因为 `resolveL2Mode` 里 P2 的 diagnosis 子阶段 → diagnosis 组、
practice/feedback 子阶段 → training 组（`skill_layers.dart:173-181`），
"训练开始前"确实落在 diagnosis 组。但 §5.2 的「每轮训练开始时」和
§5.3 的「多轮进度桥接（连续 3 轮达标后）」按理发生在 training 组期间——
这两条在 training 组是**读不到的**。
**未验证**：我没有跑运行时日志确认，只是静态读代码推导。要不要补挂，建议先确认行为再动。

### D-2｜core-product-identity「严禁我们一起写」 vs attitude-doubao「用我们/一起」【存疑】

- `skills_l1_core_p3.dart:144`：「**严禁**「我们一起写……」这类协作措辞」
- `skills_attitude.dart:27,34`：「用"我们""一起"等共同体词汇」

### D-3｜writer-psychology 是否应该存在于 AI 教学系统里【存疑】

| `skills_l1_core_p1.dart:251`「重新审视原文」 | 只在**学员质疑时**才回看原文 |
| `skills_l1_core_p2.dart:126`「尽量引用学员自己的文本」 | 只约束 `style_profile.summary` 一个 JSON 字段，且措辞是"**尽量**" |
| `skills_l1_core_p2.dart:153`「把原文折射给学员看」 | 是**镜像反馈的定义**，不是约束 |
| `skills_l1_core_p3.dart:230`「不自行编造章节名」 | V-08 只管章节名，不管判断依据 |

对照组（这条约束存在的地方，都在 L2）：
- `syndrome_kb_content.dart:46`「每个问题必须引用原文片段（5-20 字），不能只说"在文本中"」
- `skills_training_p1.dart:229`「铁律1：必须复述学员原文中的具体句子……不允许用概括代替原文」

后果：P0/P1 阶段（不加载 L2）+ advanced 组 + outline 组，AI 完全不受"锚定原文"约束。
也就是学员最早接触、最需要被"对，我写的就是这儿"说服的阶段，恰恰没有这条约束。

**建议在 validation-rules 新增 V-10**（L1 常驻）：

```
🔴 V-10 [致命] 判断必须锚定学员原文

- 每一个关于学员文本的判断，都要能指出是读到了哪一句才有这个判断
- ❌ "开头不够抓人""节奏有点平""人物有点薄"
- ✅ "读到'他很愤怒。他很失望。他很困惑。'这三句时，我脑子里没有画面"
- 读不出具体句子时，不下判断——改成问学员
- 学员文本之外的推断（体裁惯例、读者心理、作者意图）要说成推断，不说成事实
- 检测标准：回复中出现对学员文本的评价时，同一段内应有该文本的引述
```

### E3【高】缺"Skill 之间冲突时听谁的"

A 节已确认 6 处跨 Skill 冲突（#4、#28、#29、#34，加 B 节提到的 §3.6 vs §3.8），
**没有任何一处定义优先级**。模型遇到冲突只能自己猜，且每次猜的可能不一样。

**建议 L1 新增一条元规则**（放 core-product-identity 或单列）：

```
## 冲突时的裁决顺序

同一件事被多处规定、且说法不一致时，按以下顺序取信：

1. 产品底线（core-product-identity 的 4 负 4 正；validation-rules V-01/V-02/V-09）
2. 用户主权（R-009）——学员明确选择的，压过系统推荐
3. 当前阶段的阶段规则（phase-mapper）
4. L2 当前组的 Skill
5. L1 常驻 Skill 里的"建议级"条目（V-05 / V-06 / V-08）
6. 示例话术

第 6 条尤其重要：**凡标着"示例/示范/语气参考"的文本，都不是格式要求。**
本报告 A 节的 18 条 P1 里，有 11 条的根因就是示例被当成了格式。
```

### E4【中高】缺"不确定时该说什么"的正向指引

现有 Skill 全在说"不要编"（V-08 不编章节名、gap-detector `confidence=low` 不输出、
syndrome_kb 不限制数量），但**没有一处说"不确定时应该怎么说"**。
只有"禁令"没有"出路"，模型大概率还是会编——因为它总得说点什么。

Editor 的 `unclear` + `intent_confidence: low`（`:106,161`）提供了范本：
不确定的东西**照样输出，但标成不确定，交给作者判断**。

**建议补**（可并入 writing-anchors 的"教学姿态"段）：

```
## 信息不足时

判断需要的前提（足够长的文本 / 体裁 / 上下文 / 学员意图）缺哪一样，
就不要硬给结论。可用的说法：

- 文本太短："这段太短，我只能说读这几句的感觉，说不了'你整体有什么问题'。"
- 缺上下文："这个要看你后面打算怎么写——你现在有大概的方向吗？"
- 意图不明："我有两个读法，但都只是猜。你自己是想往哪边写？"
- 样本不足判断趋势："我这边还没有两份能放在一起比的稿子。"

参照 Editor 的处理方式：不确定的观察照样可以给，但要标成"我不确定"，
并把判断权交回学员——不要因为不确定就沉默，也不要为了显得懂而说死。
```

注：体裁缺失这一处**已有**处理（`skills_diagnosis_p1.dart:174-180` 的确认话术 +
"从读者预期反推"），不用重复补。

### E5【中】Skill 层缺"学员退步"的话术

实证：全 `lib/services/*.dart` grep「退步|变差|不如上次|比上次差」，
**只有 `evaluation_service.dart:327` 一处代码注释**（"既不强制迁移也不标记退步"），
**Skill 层零覆盖**。

`training-evaluation-v2:78-86` 有"恶化信号处理"，但那是给 AI 的**教学策略调整建议**
（换方式/降难度/暂停），依赖代码引擎注入，**不是面对学员的话术**。

难点在于分寸：不能打击信心，也不能假装没看见。
倾向方案——沿用镜像反馈：把两稿并排让学员自己看出差别，
**不替他下"退步"这个结论**。这与 B-3（无进步数据时不编）是同一条原则的镜像。

### E6【中】kReviewerSkillContent 是死资产，但内容有价值

`agent_skills.dart:8` 明说「reviewer skill 内容保留作 P4 V2 方向 2 历史资产，
reviewer_service 已移除，不参与 L1-L3 分层注入」——确认是死代码。

但其中「**类型边界信号（容易误判，需谨慎）**」（`:46-49`）是防误判的优质规则：
- 玄幻开篇设定交代：只有"纯旁白说明无角色体验"才算问题
- 言情情绪词：只有"连续多个情绪词无任何动作"才算问题
- 悬疑慢节奏：只有"连续多段无任何推进"才算问题

而 `genre-guide` 里**没有等价内容**——它讲的是"阈值提高/降低"
（`skills_diagnosis_p1.dart:39-148` 的各体裁表格），不是"哪些像问题但不是问题"。
`syndrome_kb_content.dart:103-106` 的「排除的"伪问题"」只有 3 行原则，没有实例。

建议：把 `:46-49` 并入 genre-guide 或 writing-anchors；

### E7【中】锚点测试的两个可加强点

`test/services/skill_prompt_anchor_test.dart` 已有字节级基线（长度 + FNV-1a 指纹，
9 个 prompt case + 6 个大块原文 + 4 个 L3 用例），这是改 Skill 时的重要安全网。两处可加强：

**(a) diff 粒度太粗。** 现在 fail 时只输出 `path: 指纹before → 指纹after`
（`_diff` 递归比对 `len` / `fnv` / `tokens` / `skills`）。改一个 Skill 后拿到的是
"9 个指纹全变"，**无法确认是不是只改了预期那一处**。
建议：fail 时额外输出**逐 Skill 的指纹表**（现在 `skills` 字段只列出了加载集合，
没有逐个 content 指纹），至少能定位到"是哪个 Skill 变了"。
`kPhase3Skills` 已对 6 个大块做了单 Skill 指纹，可以把这个做法扩到全部 37 个。

**(b) 用例覆盖缺 3 个可达组合。** 现有 9 个 case 未覆盖：

### E9【中低】两条链路的话术规范不一致，且护栏测试只覆盖了一条
