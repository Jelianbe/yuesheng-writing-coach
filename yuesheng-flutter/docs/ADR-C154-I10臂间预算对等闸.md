## 1. 为什么立这个闸

臂阶梯 `A0–A4` 里 **`A3 = A2 + 关系声明`**。若实测得 `A3 − A2 ≈ 0`，有两种解释：

| # | 解释 | 处置 |
|:--|:--|:--|
| ① | 关系层确实没有增量 | 不做关系层 |
| ② | 关系层的**输入被削了**，所以它施展不开 | 补预算/改注入面 |

**两种解释给出同一个建议**（「别做关系层」）。这是实验设计里最难拆的一对 —— 结论一致，
没人会去分辨。没有本闸，② 会一直藏在 ① 后面。

机制上这个风险是实在的：`planMergeBudget` 超预算时逐级降级，而级序 **a 裁的
`structureProfile` 正是 `A3` 关系声明的载体** ⇒ `A3` 比 `A2` 更容易被降级。
**被削掉的恰是它要测的能力。**

## 2. 为什么进 `I` 不进 `G`

`G` 判「好不好」，`I` 判「能不能比」。这里的问题不是「降级了所以差」，
是「**降级了就不该拿来比**」—— 它是可比性前提，不是效果读数。

## 3. 判据（★ 按对比对写，不按臂写）

> 对**每一个被引用的对比对** `(X, Y)`，同一 `sample_id` 上 `X` 与 `Y` 的
> `budget_report.droppedStages` **须相等且都为空**。

- 任一非空、或两臂不等 ⇒ 该 sample 标 `不可比·预算降级`，**从主对比剔除**，计入 `n_excluded_budget`；
- 任一侧 `ProgressiveMergeOverBudget` ⇒ 标 `不可比·拒发`，同样计入；
- **`n_excluded_budget` 必须与 `n` 并列报出**；占比 > 5% ⇒ 主对比结论**一律标「受限」**
  （不是「结果不可用」，是「必须写清剔了多少、剔掉的是哪一类章」）。

本轮生效的是 `(A2, A3)`；`A4` 排期时**自动**是 `(A0, A4)`，**不需要改判据**。

### 3.1 ★ 为什么必须按对比对表述

这是**同一种病的第二次**。修 `I4` 时踩过一模一样的坑 —— `I4` 原来按「全表」表述，
正确写法是「每一个被引用的对比对只许差一层」。

**判据的对象是「关系」，不是「具体的那两个东西」**：写死对象，判据就只修这一次的洞；
`A4` 一排期，同一个洞会原地重新长出来，而没人会想起来扩判据。

测试 `#I-15` 锁住这条：若有人把 `pair` 写死成 `A2,A3`，该条会红。

### 3.2 ★ 最易漏的一格：两臂**齐降**仍不可比

判据写「须相等」而不写「须相等**且都为空**」，两臂齐降会静默通过 ——
而「相等」在这里恰恰是**坏消息**：两臂输入同样被削，对比依然不成立。

测试 `#I-5` 锁住这一格。

## 4. 与 `I4` 的分工

`kb-map` 的一句收口（采纳）：

> 「`I4` 查的是**定义时**的同构，`I10` 查的是**运行时**的同构 —— 同构得查两次，
> 一次在纸上，一次在跑的时候。」

⇒ 两者不重叠也不冗余。**「定义同构而输入不同构」是本轮唯一一个真实的混淆源。**

## 5. 实现

`lib/services/p0_verify/arm_parity.dart`，纯函数无 IO（同 `p0_verify` 其余两件套的纪律）。

| 符号 | 职责 |
|:--|:--|
| `judgeArmParity` | 判一对臂在一个样本上是否可比（按 §3 四条） |
| `summarizeArmParity` | 批量判定 + 汇总，产出 `n_excluded_budget` 与受限标记 |
| `armRunFromSnapshot` | 从 merge prompt 快照载荷还原一条臂运行 |
| `ArmParitySummary.toJson` | 报出用（`n` 与 `n_excluded` 并列） |

### 三条实现纪律

1. **配对缺失抛 `ArgumentError`，不静默配错** —— 「配错对」与「预算降级」是两个不同的病，
   混在一起剔除理由会失真，而剔除理由是报告里「剔掉的是哪一类章」的唯一来源（`#I-9`）。
2. **拒发不推断**。拒发时**不发送** ⇒ 不产生快照 ⇒ `rejectedOverBudget` 只能由调用方
   从 `ProgressiveMergeOverBudget` 的捕获处传入（`#I-14`）。
3. **未测 ≠ 全合格**：空输入 ⇒ `excludedRate = 0`、不标受限（`#I-10`）。

### 前置条件已核实（非假设）

`budget_report` **早就在落**：`buildMergePromptSnapshotPayload` 把它写进 merge prompt
快照载荷，缺省落 `error_logs`（info 级 / api 类，`emitMergePromptSnapshot`）。
⇒ 本闸**不需要新增采集**，只需一个消费方。

这是「存在、不叫失败、一次没真跑」的**第四例**（前三例：`100%` 报红的巡检、长期 `SKIP`、
`G5` 对某形态恒红）：字段齐全、每天都在产，**可观测而没人拿它当判据** —— 能看见不等于在看。

## 8. 失效条件

若 `planMergeBudget` 的降级级序变更（新增/移除级），`droppedStages` 的取值域随之变；
本闸的判据本身**不需要改**（它只比「是否为空」与「是否相等」），
但 `armRunFromSnapshot` 的还原依赖载荷里 `budget_report.levels[].stage` 这个键名 —— 键名若变，需同步改。
