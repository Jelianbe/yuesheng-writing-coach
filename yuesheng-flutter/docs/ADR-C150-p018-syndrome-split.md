## §0 一句话结论

**P018 当前合并了「语言层重复瑕疵」「基础文法失稳」「内容稀碎」三个异质维度，其中「内容稀碎」与前两者在诊断信号、修复路径、严重度模型上完全不同，应拆出为独立症候；但「语言层重复」与「基础文法失稳」共享同一规则检测器与修复动作，不拆。** 建议拆分为：

- **P018 重复用词/基础语病**（保留）：子情形 A（重复/标点/起头/高频词）+ 基础文法瑕疵
- **P0xx 信息密度缺失症**（新建）：子情形 B 独立成症（信息密度 ≈0、无信息增量链）

## §1 背景与溯源

### 1.1 E-7 命题的对象纠偏

E-7 台账原文针对「P022」。经 `syndrome_retirement.dart` 溯源：

| 时点 | P022 含义 |
|:--|:--|
| 旧编号 | 重复用词/基础语病 |
| renumber 后（现行） | **节奏比例失衡症**（旧 P030 → P022） |
| 旧 P022 去向 | **renumber 到 P018**（`migration_v46.dart:110` 迁移映射 `'P022': 'P018'`） |

**故 E-7 的实际对象 = 现行 P018「重复用词/基础语病」。** 若按字面拆现行 P022（节奏比例失衡），将误伤一个内容自洽的症候。

### 1.2 P018 现行定义（事实）

`syndrome_registry.dart:583-601`：`type=expressiveDeficit`、`level=l1`、`position=local`、techniques `T019/T003`、actions `A016/A011`。

KB 手册（`syndrome_kb_content_manual_3.dart:227-276`）自身已显式分两个子情形：

- **子情形 A·基础语病**：用词/标点层重复 + 基础文法瑕疵，有**规则检测器**支撑（`grammar_lexical_detector.dart`，4 类：`dupChar`/`dupPunct`/`sentenceStartRepeat`/`frequentWord`）
- **子情形 B·内容稀碎**：信息密度≈0，**无任何规则检测器**，纯靠 AI 语义判断；且手册为此单列了与 P017/P010 的划界段（L245-248）

两子情形的严重度模型也分别定义（L264-272），进一步印证它们是两个被合并的症候。

## §3 候选方案

### 3.1 方案甲：只拆出「内容稀碎」（**推荐**）

- 新建 `P0xx 信息密度缺失症`（expressiveDeficit / **l2** / position=local→chapter，techniques/actions 待配）
- P018 定义收敛为「语言层重复瑕疵 + 基础文法失稳」
- 手册子情形 B 整段（含 P017/P010 划界、严重度模型）迁入新症候
- **优点**：拆分边界与手册已有的子情形划分完全一致；规则检测器无需动；「内容稀碎」获得独立的训练动作与教学状态跟踪
- **代价**：新增症候走全套注册（KB/训练库/prompt/学员解读），约 17 文件；子情形 B 无规则检测器，诊断召回依赖 AI 语义判断，需 prompt 注入示例守护

### 3.2 方案乙：三拆（重复用词 / 基础语病 / 内容稀碎）

- 台账原意的完整版
- **否决理由**：「重复用词」与「基础语病」共享同一检测器（`grammar_lexical_detector` 4 类规则混合输出）、同一技法（T019/T003）、同一动作（A016/A011）；拆开会产生两个信号源完全相同、修复路径完全相同的症候，违反「症候 = 可区分的根因」原则，属于为拆而拆

### 3.3 方案丙：不拆，仅在 KB 中强化子情形指引

- **否决理由**：现状即如此，而 E-7 指出的问题仍在——「内容稀碎」被挂在 `position=local`、严重度与修复动作跟语言瑕疵混用，教学状态机无法区分「这个学员是用词粗糙还是信息密度低」，训练建议卡给出的是同一条训练线

## §4 实施计划（方案甲，分 4 步）

1. **数据与注册层**：新症候 ID 分配（顺延注册表最大编号）；`syndrome_registry.dart` 新增条目；P018 的 oneLine/trainingLine 收敛；`syndrome_skill_levels.dart` / `syndrome_learner_notes.dart` 同步
2. **知识层**：手册 3 的子情形 B 整段迁移为独立条目；手册 1/4/6 的共诊与优先级关系补登新 ID；训练库为子情形 B 配训练动作（现 P018 的 A016/A011 偏向语言层，稀碎需新动作或复用结构层动作）
3. **Prompt 层（R-027 人工确认点）**：`skills_l1_core_p1.dart:300` 的语言表达类列表、`skill_registry.dart`、`skills_beginner_p5.dart` 相关表述更新——**此步执行前需你逐处过目**
4. **兼容与测试**：存量 P018 记录**不迁移**（理由见 §2 末）；`syndrome_technique_knowledge_test.dart` 锚点更新；新症候补注册表完整性测试断言

**不做**：不动 `grammar_lexical_detector`（它服务的正是保留在 P018 的部分）；不动 v46 迁移映射（历史沿革只追加不改写）。

## §5 风险与回退

| 风险 | 缓解 |
|:--|:--|
| 新症候无规则检测器，诊断召回率未知 | prompt 注入补 2 个 few-shot（手册已有判断原则可改写）；上线后观察 `active_problem` 中新 ID 的命中率 |
| 拆分后 P018 与新症候共诊时的优先级冲突 | 手册 1 的优先级表补一行：同段命中时，内容稀碎（信息层）优先于重复用词（语言层） |
| prompt 改动改变诊断行为 | R-027 停线：§4 第 3 步前逐处人工确认；前后各跑一次诊断回放锚点测试 |

**回退路径**：全部改动为新增条目 + P018 定义收窄，无存量数据迁移；回退 = 删除新症候条目并还原 P018 文本（单 commit revert）。
