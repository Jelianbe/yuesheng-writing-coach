## 一、编辑器定位与页面结构

月笙的写作入口是「章节级」写作页（`writing_page.dart`），4 层结构（百灵极简 + 月色竹青配色）：

```
1. AppBar (48dp)：返回 | 章节标题(可编辑,输入即存) | 撤销/重做 | 字数 | ⋮ 更多菜单
2. Editor (Expanded, 单 TextField, 米纸底 #F7F8F6, 文字 墨色)
   ├── 离线横幅（断网时置顶提示，本地草稿自动保存）
   ├── 划词浮动菜单「诊断这段文字」（选中 ≥20 字时右上角出现）
   └── 正文（maxLines: null 全文滚动）
3. SaveStatusBar（保存中… / 已保存 HH:MM / 保存失败）
4. PunctuationBar（36dp，15 个中文标点/控制符横滑条；AI 面板打开时隐藏）
5. FAB（AI 面板关闭时显示，点击打开教练面板）
```

> 注：写作页内**没有**章节目录/大纲/素材/角色等左侧面板——章节管理在稿件详情页（`manuscript_detail_page`）完成（章节列表/增删/重排），写作页一次只写一章。

## 二、功能盘点

### 2.1 已实现并接线（真实可用）

| 模块 | 能力 | 真源 |
|---|---|---|
| 正文编辑 | 单 TextField 纯文本、即时自动保存（无防抖，每次 onChanged 落库）、离线草稿 + 断网恢复自动同步、草稿恢复弹窗 | writing_page.dart `_onContentChanged` / WritingStore |
| 标题 | AppBar 内可编辑，输入即保存 | `_onTitleChanged` |
| 撤销/重做 | AppBar 图标，基于 store 提交点快照（非系统级） | `_handleUndo/_handleRedo` |
| 字数统计 | AppBar 右侧，≥1 万字显示「x.x万字」，否则千位分隔 | `_formatWordCount` |
| 保存状态条 | 保存中/已保存时间/失败提示（失败仅提示一次防刷屏） | `_buildSaveStatusBar` |
| 标点栏 | 15 个常用中文标点/「缩进」「换行」横滑插入（光标位置插入） | punctuation_bar.dart |
| 划词诊断 | 选中文本浮动菜单 → AI 面板自动对该选段诊断（≥20 字拦截，一次性消费防重触发） | `_handleDiagnoseSelection` |
| 教练面板 | 半屏 bottom sheet：快速观察 / 诊断本章 / 关闭 + 消息列表 + 输入栏；与写作页同章隔离会话 | writing_coach_panel.dart |
| 建议采纳 | 教练面板 AI 建议可采纳/撤销 → 回写章节内容并刷新编辑器 | `onAdopt` → suggestion_adoption_service |
| 更多菜单 | 保存状态行 + 「打开教练面板」（E3 已移除 4 个 WIP 死项） | writing_menu_sheet.dart |

### 2.2 数据层已存在、编辑器内无 UI（可扩展但暂不可达）

| 能力 | 数据层现状 | 编辑器现状 |
|---|---|---|
| 大纲 | outline 表 + outline_parser/service（批次72），对话内「大纲记忆确认卡」（批次73） | 无大纲查看/编辑入口 |
| 角色/世界观/事件设定 | character_fact / event_fact / subplot_fact 表 + 各 detector | 无设定管理界面（素材 Tab 空态文案批次77 已指路「作品详情文件」，无真实设定页） |
| 风格画像 | style_fingerprint / style_profile（批次53） | 无「当前文风」可视化 |
| 排版设置 | WritingState 有 `fontSize`/`lineSpacing` 字段 + `setFontSize/setLineSpacing` | 无任何 UI 入口（批次 E3 把「排版设置」菜单项作为 WIP 移除） |
| 字数/进度 | wordCount 即时计算 | 仅 AppBar 静态显示，无目标/曲线 |

### 2.3 明确的空缺（市面软件标配、我们完全没有）

- 写作目标（单日/单章目标字数、番茄钟/强制专注）
- 全文查找替换 / 章节内检索
- 错别字校对 / 敏感词检测 / 一键排版
- 导出（写作页无导出；对话页有「保存到文件」单条消息）
- 灵感随笔 / 素材库 / 起名助手
- 章节列表侧栏 / 卷-章两级目录导航
- 版本回溯（时光机式多版本）
- 拼字/专注排行榜类社交（低优先）

## 三、用户体感问题（从代码观察到的「AI 味」与「不灵光」）

1. **编辑器是单 TextField**：无段落感、无章节内定位，长文本编辑时难以感知结构（对照 Scrivener/云上写作的文档树）。
2. **AI 面板是半屏覆盖层**：打开即遮住编辑器，边写边看建议需要来回切换（对照起点作家助手的侧栏/浮层不遮挡正文）。
3. **划词诊断隐藏深**：需选中 ≥20 字 → 右上角浮动菜单，再开面板；真机选中文本触发浮层本身不可靠（TextField 无 onSelectionChanged，靠 controller listener 兜底）。
4. **排版设置无入口**：字号/行距字段已建却无 UI，与「百灵极简」定位冲突——真人创作者通常第一步就调字号行距护眼。
5. **无目录上下文**：写作时看不到本卷其他章节、无法快速跳转，长篇小说体感差。
6. **更多菜单只剩 1 项**：功能收敛到只剩「打开教练面板」，入口极空，反而暴露可扩展空间。

## 四、市面小说写作软件写作部分横向参考（2026-08-12 检索摘要）

> 完整调研由委托 AI 执行（见配套调查提示词），此处仅作本次快速检索基线：

| 软件 | 写作部分核心功能 | 可借鉴点 |
|---|---|---|
| 起点作家助手 | 章节管理、字数统计、敏感词检测、灵感库、世界观设定模板、多端同步 | 章节树 + 编辑器同屏；写作数据（码字速度/日字数） |
| 橙瓜码字 | 大纲助手（文字/空白大纲）、灵感随笔、素材库、时光机（每 100 字版本快照）、文字校对、起名助手、拼字、强制锁定、全文检索替换 | 时光机防丢稿；大纲助手边写边看；灵感随笔随手记 |
| 云上写作 / Scrivener | 软木塞卡片、文档树分卷分章、可视化大纲、元素管理、专业排版导出 | 结构化管理（文档树是核心）；卡片式大纲 |
| 纯纯写作 | 永不丢稿（本地+云端双备份）、Markdown、极简专注 | 防丢稿感知（数据安全感） |
| Ulysses / iA Writer | 写作目标、专注模式、Markdown、跨设备 | 目标驱动 + 沉浸式无干扰 |
| 云庐 | 章节预览与大纲管理、实时数据统计、番茄钟、多格式导出 | 目标字数 + 番茄钟专注时间管理 |

**共性提炼（真人创作者的「写作部分」核心诉求）**：① 结构感（章节树/大纲边写边看）；② 数据安全感（自动保存/版本回溯/多端同步）；③ 目标与节奏（目标字数/番茄钟/统计曲线）；④ 随手记录（灵感随笔/素材库）；⑤ 排版与护眼（字号行距/皮肤/背景）；⑥ 防错（校对/敏感词/全文检索）。

## 五、扩展点取舍与优先级（定稿版，2026-08-12）

> 依据：本盘点 + 15 款软件调查（editor-survey-report.md 第七/九/十/十一章）+ 产品定位（写作教学、移动优先、无账号体系）。P0 为建议优先。

### 5.1 取舍结论：砍掉 / 暂缓（不进路线图）

| 功能 | 判定 | 理由 |
|---|---|---|
| 拼字 / 拼字星球 / 游戏化任务 | **砍** | 消费产品社交属性，与写作教学定位不符 |
| 起名助手 | **砍** | 规则生成对教学无意义（番茄作者实测亦反馈「AI 起名鸡肋」） |
| 敏感词检测 | **砍** | 无发布场景，价值低 |
| 多端云同步 / 账号体系 | **暂缓** | 无账号体系成本高；本地即时保存已满足 MVP |
| 稿费预测 / 收益数据 / 平台发布 | **砍** | 无平台生态 |
| 语音朗读 / 语音输入 | **暂缓** | 非核心（语音输入已被起点下线，交给系统输入法） |
| 多格式导出（pdf/epub/docx） | **暂缓** | 已有「保存到文件」txt 通道，够 MVP |
| 番茄钟 / 强制锁定（小黑屋） | **暂缓** | 教学产品不刚需，观察后续 |

### 5.2 最终优先级清单

| 优先级 | 扩展点 | 说明 | 成本 |
|---|---|---|---|
| **P0** | **AI 入口重构**（右侧可收起教练侧栏 + 划词选区 AI 菜单） | 直接回应「AI 味重」：正文永不被覆盖；选区触发、生成结果可择选（番茄范式） | 中 |
| P0 | 排版设置 UI（字号/行距/背景） | 数据层已有字段，只缺入口；真人第一刚需 | 低 |
| P0 | 写作目标（单章/单日字数目标 + 进度条） | wordCount 已有，加目标字段 + AppBar 进度 | 低 |
| P0 | 保存数据安全感（即时保存 + 每 200 字本地版本快照） | SaveStatusBar 已有基础；版本快照兼顾教学留痕 | 低-中 |
| P1 | 章节树侧栏（卷-章列表 + 快速跳转 + 新建章） | 长篇小说结构感核心 | 中 |
| P1 | 大纲边写边看（抽屉/浮层，数据层 outline 已有） | 复用批次72-73 数据 | 中 |
| P1 | 灵感随笔 / 随手记 | 对标橙瓜灵感随笔，不跳出写作上下文 | 中 |
| P1 | 全文查找替换 | 长文修订刚需 | 中 |
| P2 | 行段聚焦模式 | 淡化当前行/段以外内容，低成本高价值 | 低 |
| P2 | 智能标点（自动补全 / 句末标点） | 写作天下范式，移动端减机械操作 | 中 |
| P2 | 快捷短语 / 常用语 + 文本模板 | 起点/笔落/灯果标配，提升码字效率 | 中 |
| P2 | 写作统计（码字速度 / 日字数 / 连续天数） | 数据已有雏形，兼顾教学留痕 | 中 |
| P2 | 章节完成度 / 字数徽标 | 让学员看到自己产出（教学特色增补） | 低 |
| P2 | 当前文风轻量展示 | 风格画像数据层已有（教学特色增补） | 低 |
| P3 | 正文角色 / 设定高亮 | 起点范式，依赖素材库先行 | 中-高 |
| P3 | 自定义工具栏 | 标点栏固定 15 项可改为可隐藏/排序 | 中 |

### 5.3 立项顺序（建议 4 批）

1. **第一批次（P0 四件套）**：AI 入口重构 + 排版设置 + 写作目标进度条 + 保存数据安全感
2. **第二批次（P0-P1）**：章节树侧栏 + 大纲边写边看 + 划词选区 AI 菜单（替代/并存「诊断这段文字」）
3. **第三批次（P1 工具组）**：灵感随笔 + 全文查找替换 + 轻量版本回溯
4. **第四批次（P2 效率与教学组）**：行段聚焦 + 智能标点 + 快捷短语 + 写作统计 + 完成度徽标 + 当前文风

## 六、结论

- 编辑器骨架健康（即时保存/离线草稿/撤销重做/字数/标点栏/划词诊断均真实可用），但**功能密度集中在「AI 对话」一侧，真人创作侧的「结构、目标、数据安全感、随手工具」几乎空白**，这正是「AI 味重、操作不灵光」的结构性根因。
- 定稿路线：以「**AI 入口重构 + 真人创作四件套**」开局（第一批次 P0），再补结构（章节树/大纲）与工具（随笔/查找/回溯），最后做效率与教学留痕（第二~四批次）。每批沿用四闸 + 独立 commit 惯例。
