## 一、三大核心命题补充论证

### 核心命题 1：增量代写 vs 能力教学 —— 补充证据

**原报告状态**：已覆盖，结论明确。补充如下一线证据：

| 证据来源 | 类型 | 核心发现 |
|---------|------|---------|
| Reddit r/ClaudeAI (2026.03) | 用户自述 | AI写作"让差劲的作者变得过得去，但会让优秀作者变差"，AI磨掉个人声音的棱角 |
| Reddit 社区讨论 | 元现象 | 用户发帖讨论"AI抹杀个性"，帖子本身由AI生成——形成元讽刺。社区公认AI把所有声音磨平为"均质化的无聊中庸" |
| 百度经验 (2024.12) | 中文用户反馈 | "经常用AI写作，再自己动笔时大脑一片空白……不要完全依赖AI去写文，写作过程就是训练思维" |
| 腾讯网 (2026.03) | 行业观察 | 高中生因作文写得太好被怀疑AI生成，被迫故意写差——AI正在让人类表达变得更糟 |
| Bloglingo (2025) | 博客分析 | 提出"AI写作依赖度3问题测试"：能否不看AI自己写出同等质量？能否识别AI建议的错误？上次独立完成全篇文章是什么时候？ |

> **结论强化**：代写工具的长期副作用不再是猜测，而是来自多平台的一线用户自述。写作能力的"用进废退"在AI代写场景下被加速验证。教学系统的反代写立场不仅是差异化，而是对用户长期利益的保护。

### 核心命题 2：结构化功能溯源 —— 补充论证

**原报告状态**：已提出"技术补丁"假说。补充更详尽的逐功能论证：

#### 人物库 / 角色卡

| 维度 | 论证 | 来源 |
|------|------|------|
| 设计初衷 | 让AI在长文本中记住角色属性，避免OOC | Sudowrite / NovelAI 产品文档 |

| AI真正需要的信息 | AI从不"读"角色卡——角色卡在后台被切碎为RAG片段。人物"成长弧"字段对AI而言是无意义字符串，因为它无法追踪跨章节的性格渐变 | 技术原理推断 + Claude context rot 社区报告 |
| 教学场景价值 | 极低。教会用户"填表" ≠ 教会用户"塑造角色" | — |

| 维度 | 论证 | 来源 |
|------|------|------|

| RPG vs 小说 | Campfire的成功用户群体主要是TTRPG Gamemaster，而非小说家。RPG需要固定规则参考，小说需要流动性 | Campfire 产品定位分析 |
| 教学场景价值 | 世界观库教的是"文档管理"而非"世界观构建"——两个完全不同的能力 | — |

#### Timeline 时间线

| 维度 | 论证 | 来源 |
|------|------|------|

## 二、B类 & C类产品深度补充

### B类：小说结构化管理工具

原报告已覆盖 Scrivener / Novelcrafter / Plottr / Campfire 概览。以下为查漏后的深度补充：

#### Scrivener 深度

- **学习曲线是公认痛点**：Scrivener 官方网站承认"许多购买者因沮丧而将其搁置不用"。市面上甚至存在专门的 Scrivener 付费课程（来源：scrivener.app）
- **世界构建能力**：支持 Binder 文件夹体系管理角色/地点/研究资料；分屏视图对比；自定义元数据。但这些功能全部是"组织工具"，不是"AI理解工具"（来源：Literature & Latte 官方教程）
- **核心悖论**："使用越多越有价值，但入门阶段效率被时间成本抵消"——这与写作教学系统"零门槛上手"的目标直接冲突

#### Campfire 深度

- **双重身份**：核心模块（Characters / Relationships / Timeline / Character Arcs / World / Encyclopedia）面向写作者；World Builder's Pack（Species / Cultures / Languages / Religions / Philosophies / Systems / Magic / Items）明显面向 RPG GM（来源：Mythic Scribes 评测）
- **UI简洁但不够直观**：评测者提到"微小的学习曲线和偶尔的'天哪我真的刚才那么操作了吗？'"——功能虽强但交互设计不是新手友好
- **核心优势**：高度可定制的模板系统。但这对于"不想填表"的创作者恰恰是另一重负担
- **关键洞察**：Campfire 在 RPG 策划场景下成功、在小说写作场景下小众——这恰好验证了"结构化知识库 ≠ 写作能力提升"的命题（来源：Mythic Scribes + 社区交叉讨论）

#### Plottr 深度

- **用户画像分化**：正面评价几乎全部来自 Planner 型用户；Pantser 型用户在使用中存在明显不适配（来源：Trustpilot 评价 + Reddit 讨论）
- **一个未被满足的细分需求**：Plottr 用户主动提出"希望有角色关系树，能查看父母/子女/朋友/老板等关系"——这恰恰是结构化工具的边界：它们擅长"存储关系"，不擅长"动态理解关系变化"

### C类：大模型知识库辅助创作平台

#### Claude Projects 深度补充

- **上下文腐烂**：社区报告显示，深度对话到 90 条消息后，"Claude 会尝试已被拒绝的方案、询问已提供的信息、解决方案越来越随机而非理性"。用户以为 AI 能"看到"滚动历史，实际上当线程上下文占用 70% 后它"像透过磨砂玻璃阅读"（来源：aiqnahub.com + TurboAI Dev Blog）
- **"信任线程"是最大陷阱**：用户滚动看到原始指令仍在，技术上 AI 确实能访问——但实际表现已严重退化。这是静默故障，无系统报错，对创作者极具欺骗性
- **应对方案**：每章/每个重要节拍开启新对话，在开头粘贴 Story Bible。但这意味着用户回到"手动管理上下文"的原始模式
- **教学场景启示**：Claude Projects 证明了"即使是大上下文窗口，也不能替代有结构的记忆系统"。这正是方案C（渐进式记忆生长）存在的根本理由

## 三、三方案深度对比论证（任务书第六章补充）

原报告已提出方案A/B/C，以下为核心查漏——三方案的逐维度系统对比：

### 方案对比总表

| 对比维度 | 方案A：前置全量配置 | 方案B：后置解析复盘 | 方案C：渐进式记忆生长 |
|---------|-------------------|-------------------|---------------------|
| **用户初始门槛** | 极高（先填表才能开始） | 零（直接创作） | 零（直接创作） |
| **首次价值感知时延** | 即时（输入即有结构） | 延迟（写完才有反馈） | 渐进（写一点感知一点） |
| **创作心流影响** | 打断（Plan-then-Write割裂） | 不打断（Write-then-Review） | 不打断（Write + 后台生长） |
| **教学介入时机** | 事前（规划阶段） | 事后（复盘阶段） | Just-in-time（创作中实时） |
| **用户维护负担** | 极高（持续手动同步） | 低（自动解析） | 零（自动生长） |
| **对Pantser友好度** | 不友好（强制结构化） | 友好 | 最友好 |
| **对Planner友好度** | 高 | 中 | 中（可选前置+自动合并） |
| **写作能力成长路径** | 间接（学会规划工具≠学会写作） | 直接（具体问题具体反馈） | 最直接（问题发生即纠正） |
| **技术复杂度** | 低 | 中 | 高 |
| **差异化竞争力** | 无（与Scrivener/Plottr重复） | 中（独特但非首创） | 极高（颠覆性方案） |

### 方案B专属分析："无Prompt反馈"模式验证

Tom's Guide (2025) 报告了一个关键发现：用户将草稿上传给ChatGPT/Claude/Gemini而不提供任何Prompt时，AI会自动给出最精准的写作反馈——指出节奏拖沓之处、对话闪光之处、读者可能困惑的地方。原因为"文档本身成为Prompt"，模型自动推断用户需要的是反馈而非改写。

**对方案B的启示**：
- 后置解析复盘模式在技术上是可行的，且已有一线用户验证有效
- 但方案B的短板在于"事后反馈"的时间滞后性——用户在写作过程中犯的错误要到整章完成后才知道
- 方案B可作为方案C的互补模式（长期复盘 + 实时干预），而非独立方案

### 方案C三层架构详细设计

```
┌─────────────────────────────────────────────┐
│         Layer 3: 个人写作风格模型             │
│  - 句式偏好（长短句比例、主动/被动语态倾向）    │
│  - 用词指纹（高频词汇、修辞偏好）              │
│  - 节奏特征（场景/对话/描写的段落比例）         │
│  - 成长轨迹（跨时间维度的风格变化检测）         │
│  ★ 作用：声线保护 + 个性化教学基准             │
├─────────────────────────────────────────────┤
│         Layer 2: 长期作品知识库                │
│  - 人物图谱（姓名/关系/目标/性格/成长弧）       │
│  - 事件链路（时间/地点/人物/因果链/剧情影响）    │
│  - 世界观规则（设定条目 + 冲突检测）            │
│  - 伏笔追踪（埋设/回收状态）                   │
│  ★ 作用：设定一致性 + 长篇记忆                  │
├─────────────────────────────────────────────┤
│         Layer 1: 短期工作记忆                  │
│  - 当前写作会话的活跃上下文                    │
│  - 最近N章的关键信息摘要                       │
│  - 用户当前提问/操作的意图追踪                  │
│  ★ 作用：实时响应 + 上下文感知                  │
└─────────────────────────────────────────────┘
```

**三层之间的信息流动**：

- **L1→L2**：每次会话结束，将新创作内容的结构化信息写入长期知识库
- **L2→L1**：每次会话开始，根据当前章节自动加载相关人物/事件/伏笔
- **L2→L3**：跨作品周期分析，提取稳定的个人风格模式
- **L3→L1**：实时写作时，以个人风格基准进行比对教学
- **全部自动**：用户零手动操作，三层全部AI自主维护

## 四、功能级失败案例详细拆解（任务书第五章补充）

原报告已覆盖根因分析。以下为逐功能定位的失败推演表：

### 逐功能失败推演

| 行业标配功能 | 设计假设（错的） | 实际情况 | 失败用户画像 | 对教学系统的教训 |
|-------------|---------------|---------|------------|---------------|
| **人物库** | 用户愿意为每个角色填写完整档案 | 用户在Ch.1~3认真填，之后停止维护；8万字后已有角色档案与实际剧情严重脱节 | 所有类型创作者均不同程度弃用 | 不做强制填写，AI从文本中自动提取+动态更新 |
| **世界观库** | 世界观是静态规则集，可提前定义 | 世界观在写作过程中涌现演化；预设规则反而限制创作自由 | Pantser和混合型创作者几乎不用 | 世界观规则应由AI从文中推理，支持用户review确认而非预填 |
| **Lorebook/Timeline** | 故事是线性时间序列 | 倒叙、插叙、多时间线、非线性叙事是常见技法；线性Timeline无法准确表达 | 高级创作者认为太机械 | Timeline必须支持多线、交叉、因果而非纯时间排序 |
| **Agent编排** | 多个AI角色分工=更专业 | 多Agent开销>价值；普通用户不理解如何分配角色；协作失败后用户失去信心 | 几乎所有非技术用户 | 绝对禁止Agent编排暴露给用户——这是技术实现细节，不是产品功能 |
| **点数/Token计费** | 用户愿意按使用量付费 | 点数焦虑导致用户不敢自由尝试，创作心流被"每次Generate花多少钱"打断 | 高频用户、长篇创作者最受影响 | 月费/年费制，不限量生成。创作需要安全感 |
| **复杂预设/模板** | 提供更多选择=更好体验 | 选择过载导致用户在"选什么模板最合适"上消耗精力，延迟创作启动 | 新手用户放弃率最高 | 零选择启动——系统使用唯一最优方案，高级选项作为隐藏可选功能 |

## 五、行业绝对避坑清单（任务书第九章第3条 + 第十章第6条交付物）

基于全行业研究交叉验证，以下为自研「月笙AI写作教练」的刚性禁区：

### 禁止复用设计清单

| 编号 | 禁区 | 证据来源 | 后果 |
|-----|------|---------|------|
| AVOID-01 | 点数/Token计费模式 | Sudowrite全用户群痛点 | 创造焦虑，扼杀创作自由 |
| AVOID-02 | 要求用户前置填写角色卡/世界观/Lorebook | 全行业用户弃用数据 | 填表与创作割裂，新手放弃 |
| AVOID-03 | 多Agent编排暴露给用户 | Sudowrite/Agent实验系统 | 复杂度过高，用户不理解 |
| AVOID-04 | 纯段落级/场景级工作流 | Sudowrite Discord反馈 | 不适合连载长篇，声线漂移 |
| AVOID-05 | 把结构化工具（B类产品范式）包装成AI功能 | 行业路线混淆 | 用户预期落差（以为AI在理解，实际只是存储） |
| AVOID-06 | 封闭生态/锁定导出 | 用户自由迁移需求 | 用户拒绝绑定，工具切换成本高则不用 |
| AVOID-07 | ChatGPT套壳式聊天界面 | Claude/OpenAI用户批评 | 缺乏写作专用交互设计，无法建立产品壁垒 |
| AVOID-08 | 预设/模板选择强制 | Plottr/Scrivener反思 | 选择过载=启动障碍 |
| AVOID-09 | 声线漂移无保护措施 | Sudowrite 8万字以上长篇报告 | 长文本核心体验崩溃 |
| AVOID-10 | 把"工具学会使用"等同于"写作能力提升" | 全行业痛点4（学习困难未解决） | 用户花时间学习工具≠学会了写作 |
| AVOID-11 | 仅做代写/续写，不做反馈 | 行业空白验证 | 只会让用户依赖加重，长期写作能力退化 |
| AVOID-12 | Timeline只支持单线性时间轴 | Plottr/Campfire功能局限 | 非线性叙事是现代小说常态 |

## 七、对下一步研究的建议（任务书第十章第7条细化）
