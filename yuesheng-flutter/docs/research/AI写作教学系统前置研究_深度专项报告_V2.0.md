# 第一篇：学术前沿深度拆解

## 1.1 Agents' Room (Google DeepMind, ICLR 2025)

### 核心架构

Google DeepMind 将长篇写作概念化为 **多Agent协作问题**，提出 Agents' Room 框架。

```
┌──────────────────────────────────────┐
│          Orchestrator（编排器）        │
│   负责按任务需求调度Agent、合并输出      │
├──────────────┬───────────────────────┤
│ Planning Agents │  Writing Agents      │
│ （规划Agent）   │  （写作Agent）        │
│                 │                      │
│ · 角色描述Agent  │ · 开头写作Agent       │
│ · 情节/冲突Agent │ · 结尾写作Agent       │
│ · 世界观Agent    │ · 过渡段Agent         │
├──────────────┴───────────────────────┤
│          Scratchpad（共享便签）         │
│   Planning Agent的输出在此共享给        │
│   Writing Agent使用                   │
└──────────────────────────────────────┘
```

**优势**：① LLM可被微调为专业角色；② 任务分解后可并行执行；③ 通过Scratchpad机制管理信息流。

### 对教学系统的关键启示

| 维度 | Agents' Room | 教学系统应注意 | 理由 |
|------|-------------|-------------|------|
| Agent暴露 | Plan/Write双层显式 | **禁止暴露** | 用户不理解Agent分工，暴露=困惑 |
| Scalability | 需要多个微调模型 | 极高成本 | 教学系统需要的是快速迭代，不是学术验证 |
| Orchestrator | 显式调度器 | **可作为后台引擎** | 调度逻辑对用户不可见，但技术上有借鉴价值 |
| Scratchpad | 静态信息共享 | 需升级为**动态生长知识库** | 静态便签不适合持续创作 |

**核心判断**：Agents' Room 验证了"多Agent协作=更好的一致性和连贯性"的学术命题，但其架构复杂度远超出教学产品的需要。教学系统的后台可以采用Agent编排引擎，但 **严禁将其暴露为用户可感知的功能**。

**来源**：Lee et al., "Agents' Room: Multi-Step Collaboration for Long-Form Story Generation", ICLR 2025. GitHub: google-deepmind/tell_me_a_story

## 1.2 DOME：动态层级大纲 + 时序知识图谱记忆 (NAACL 2025)

### 核心突破

华南理工 & 香港理工的 DOME 系统解决了一个关键问题：**如何在长篇生成中同时保证情节连贯性和上下文一致性**。

**两大组件**：

#### DHO：动态层级大纲机制
- 将小说写作理论（如三幕结构、Save the Cat! 节拍表）融入大纲规划
- **核心创新**：规划阶段和写作阶段不是串行的，而是**融合**的——大纲在写作过程中动态调整
- 保证了情节完整性的同时，**允许写作过程中的不确定性**（即允许灵感偏离原计划）

#### MEM：时序知识图谱记忆增强模块
- 将已生成内容存储为**时序知识图谱**（Temporal Knowledge Graph）
- 实体（人物/地点/物品）→ 关系 → 时间戳三层结构
- 自动检测上下文冲突（谁在什么时候做了什么，前后是否矛盾）

**实验结果**：在流畅性、连贯性、整体质量上显著优于基线方法。

### 对教学系统的启示

DOME 的核心贡献直接验证了方案C的可行性：

| DOME组件 | 对应方案C层级 | 教学价值 |
|----------|-------------|---------|
| DHO动态大纲 | L1 短期工作记忆 → L2 长期知识库 | AI应理解大纲是活的，创作中会偏离预设，偏离不代表错误 |
| MEM时序KG | L2 长期作品知识库 | 结构化知识库的核心数据结构应为**时序知识图谱**而非简单KV对 |
| Temporal Conflict Analyzer | L2→L1 信息流 | 自动检测矛盾是写作教练的基础能力——"第3章说他是独生子，第15章出现了妹妹" |

**DOME为教学系统提供了技术路线的学术背书**：时序知识图谱不是补丁式设计，而是解决长篇一致性的最优路径。

**来源**：Wang et al., "Generating Long-form Story Using Dynamic Hierarchical Outlining with Memory-Enhancement (DOME)", NAACL 2025.

## 1.3 LongWriter (清华 THUDM, 2024)

### 核心发现

当前长上下文LLM能处理10万token输入，但输出通常不超过2000字。**根因不是窗口限制，而是SFT训练数据中缺乏长输出样本**。

**AgentWrite 方案**：通过将超长生成任务分解为子任务（Planning → Chunk Writing → Alignment），使现有LLM能生成超过20,000字的连贯输出。基于此构建了LongWriter-6k数据集（2000-32000字样本），训练后的9B模型在长文本生成基准上超越更大模型。

### 对教学系统的启示

| 发现 | 教学系统意义 |
|------|------------|
| 输出长度瓶颈是训练数据问题，非架构问题 | 微调特定写作模型时，必须加入长篇训练样本 |
| AgentWrite的"先规划后写作"流水线 | 教学系统可以将"先写大纲再填充"作为教学路径，但**不应强制**——Pantser需要不同的流水线 |
| 分块生成+对齐机制 | 长篇训练可以拆分为节拍级教学，每次只关注一个写作技能 |

## 1.4 TombWriter：节拍级交互的设计启示 (CHI 2025)

### 关键发现回顾

TombWriter 的核心结论已在原报告中涉及，此处强调一个被低估的发现：

> "将AI写作工具定位为**发现工具**，而非**生产工具**"

以及另一个关键发现：

> "允许角色复杂性的空间：解决AI生成角色行为时过于字面化和刻板印象的倾向，允许角色发展中的细微差别"

### 对教学系统的直接映射

| TombWriter发现 | 教学系统产品决策 |
|---------------|---------------|
| AI应定位为"工具"而非"合作者" | 永远用"月笙分析发现……"而非"我们一起写……"的措辞 |
| Beat级交互优于散文级 | 教学反馈粒度应在"段落/节拍"级，而非"整章"级 |
| 声线保护是独立设计目标 | L3个人写作风格模型是必要组件，不能依赖通用模型自我约束 |
| 保留角色细微差别 | 检测"刻板角色"应是反馈维度之一 |

# 第二篇：教学法基础

## 2.1 Progressive Mastery through Deliberate Practice（逐步精熟法）

### 五要素框架

Panero & Scharff (2016) 在一项美国高中写作教学研究中，发现了一种极其有效的教学方法——被称为"通过刻意练习实现逐步精熟"。五个要素如下：

| 要素 | 说明 | 映射到AI写作教练 |
|------|------|----------------|
| ① 理解最终产品 | 学生先看到一篇好文章长什么样 | AI"示范"模式：展示一个场景的优化版本，标注改进点 |
| ② 分解关键元素 | 将写作拆分为可独立训练的子技能 | 12种反馈类型分别对应12个子技能 |
| ③ 建立技能层级 | 确定技能的先后学习顺序 | **"Just-in-time教学触发"的依据**：只提示当前水平层级的技能 |
| ④ 分层递进 | 掌握前一层才进入下一层 | 教学系统不应一次性指出所有问题，应优先暴露"当前最需要改进的一项" |
| ⑤ 逐步撤除脚手架 | 从示范→引导→独立 | "I do → We do → You do"的完整映射 |

### 技能层级设计

基于写作教学研究（Janice Hardy, 2011）和网文写作实践，建立以下教学层级：

```
Level 1: 基础表达
├── Show Don't Tell（展示而非讲述）
├── 对话标签控制（他说/她低语 vs 过于花哨的替代词）
└── 基础语法与句式多样性

Level 2: 叙事节奏
├── 场景长度控制（一句话总结 vs 三段描写）
├── 紧张-释放交替节奏
└── 信息释放速度（一次性交代 vs 逐步揭示）

Level 3: 角色塑造
├── 角色行为一致性（OOC检测）
├── 对话目的性（每句对话推动剧情/揭示性格）
└── 角色关系动态变化

Level 4: 情节结构
├── 因果链完整性（事件有因有果）
├── 伏笔埋设与回收
├── 高潮设置与情绪曲线
└── 多线交织处理

Level 5: 风格与声线
├── 个人风格稳定性
├── 文体适配（古风/现代/幽默/严肃）
└── 修辞手法使用
```

**关键教学原则**：AI教练只提示"当前层级+1"的问题——即用户刚好能理解和改进的问题，不越级提示高阶问题。

## 2.2 Gradual Release of Responsibility（责任逐步释放模型）

### 经典教学三部曲

```
I DO（我做）    →  WE DO（我们一起做）  →  YOU DO（你做）
教师示范         教师引导互动            学生独立完成

AI写作教练中的映射：
┌──────────────┬──────────────────┬─────────────────────┐
│    I DO      │     WE DO        │      YOU DO         │
├──────────────┼──────────────────┼─────────────────────┤
│ AI展示优化版  │ AI标注问题+建议   │ AI仅标注问题，       │
│ 本，逐句标注  │ 用户选择是否采纳  │ 不提供修改建议        │
│ 改进理由      │                  │                     │
├──────────────┼──────────────────┼─────────────────────┤
│ 适用于：      │ 适用于：          │ 适用于：             │
│ 新手入门阶段  │ 进阶成长阶段      │ 成熟独立阶段          │
│ 新技能首次接触 │ 技能反复练习期   │ 已内化的技能          │
└──────────────┴──────────────────┴─────────────────────┘
```

**产品实现**：用户在Profile中可设定每个反馈类型的介入级别（I/We/You），也可让AI根据用户在该技能上的表现动态调整。

# 第三篇：产品架构深度设计

## 3.1 NovelCrafter vs Sudowrite：结构化路线的内战

Sudowrite 和 NovelCrafter 都面向小说作者，但选择了截然不同的结构化路线。这场"内战"的结果直接决定了方案C的设计边界。

### 对比表

| 维度 | Sudowrite Story Bible | NovelCrafter Codex |
|------|----------------------|-------------------|
| **信息组织** | 自由形式的笔记集合 | 结构化数据库（角色/地点/派系/物品等实体类型） |
| **与AI的接口** | AI"参考"Stroy Bible，被动触发 | 写作场景时**主动链接**Codex条目，精确控制上下文窗口 |
| **大纲系统** | 有Brainstorm功能但不强制 | Story Beats 强制（支持 Save the Cat! 等结构模板） |
| **AI模型** | 内置封闭Muse 1.5 | BYOK（自带API密钥），开放多个模型 |
| **目标用户** | Pantser友好（低结构要求） | Planner友好（高结构要求） |
| **先决条件** | 基本上可以直接开始写 | 必须先填Codex、先排Beats才能有效写作 |

**来源**：Sudowrite 官方对比博客、Intellectualead NovelCrafter深度评测

### 对方案C的核心启示

两种路线各有受众，但**教学系统的目标用户包含两种创作风格**。方案C必须做到：

1. **Pantser友好**：零前置配置，AI从文本中自动提取结构化信息
2. **Planner可用**：提供可选的结构化工具（大纲/角色卡）但绝不强制
3. **统一信息层**：无论用户是Pantser还是Planner，后台都是同一个时序知识图谱——只是前端交互不同

**关键判断**：Sudowrite 的"自由式+Brainstorm"模式更适合初学者（低门槛），NovelCrafter 的"Codex+Beats"模式更适合有经验的Planner。**教学系统应在第一阶段使用 Sudowrite 式的自由模式作为默认，在第二阶段让Codex自动生长，用户永远不知道Codex存在**。

## 3.2 三层架构技术详细规格

基于 DOME（NAACL 2025）的时序知识图谱方法论 + Agents' Room 的编排思想 + Progressive Mastery 的教学框架，以下是方案C的完整技术规格：

### Layer 1：短期工作记忆

```
┌─────────────────────────────────────────┐
│  L1: 短期工作记忆（Session级，生命周期=会话）│
├─────────────────────────────────────────┤
│  数据模型：                               │
│  · 当前会话的完整对话历史（最近N轮）         │
│  · 当前写作章节的文本缓冲区（最近3000字）    │
│  · 用户最近3次操作/提问的意图向量            │
│  · 已触发的教学反馈点列表（避免重复提示）     │
│                                          │
│  技术实现：                               │
│  · 滑动窗口上下文管理                      │
│  · 意图识别分类器（创作/修改/询问/闲聊）     │
│  · 教学触发去重逻辑                       │
│                                          │
│  更新频率：实时                           │
└─────────────────────────────────────────┘
```

### Layer 2：长期作品知识库

```
┌──────────────────────────────────────────┐
│  L2: 长期作品知识库（作品级，生命周期=整本书）│
├──────────────────────────────────────────┤
│  数据模型（时序知识图谱 TKG）：             │
│                                          │
│  节点类型：                                │
│  · 人物节点 {姓名, 首次出现章节, 核心目标,   │
│     性格标签, 关系列表, 成长弧向量,         │
│     最近一次更新时间}                       │
│  · 事件节点 {时间/章节, 地点, 参与人物列表,   │
│     事件类型, 因果链前驱/后继, 剧情影响等级}  │
│  · 地点节点 {名称, 首次出现, 关联人物,       │
│     地点特征, 历史事件列表}                  │
│  · 伏笔节点 {埋设位置, 回收位置, 伏笔类型,   │
│     涉及人物, 状态(未回收/已回收/废弃)}      │
│  · 规则节点 {世界观规则, 魔法/科技体系,       │
│     社会结构, 文化习俗}                     │
│                                          │
│  边类型（关系）：                           │
│  · 人物-人物：亲属/恋人/敌对/师生/君臣...    │
│  · 人物-事件：参与/见证/主导/受害            │
│  · 事件-事件：因果→/并行∥/时间先于          │
│  · 人物-地点：居住/到访/所属                │
│                                          │
│  技术实现：                                │
│  · 从L1文本中自动抽取节点和边（信息抽取模型）  │
│  · 冲突检测引擎（基于时序逻辑规则）          │
│  · 图数据库存储（Neo4j或等效方案）          │
│  · 增量更新（只更新变更部分）                │
│                                          │
│  更新频率：每章/每会话结束时执行完整更新       │
└──────────────────────────────────────────┘
```

### Layer 3：个人写作风格模型

```
┌──────────────────────────────────────────┐
│  L3: 个人写作风格模型（用户级，生命周期=永久）│
├──────────────────────────────────────────┤
│  数据模型：                                │
│                                          │
│  定量指标（自动从文本提取）：                │

│  · 对话占比（对话行数/总行数）               │

│  · 句式结构偏好（简单句/复合句/并列句比例）   │
│  · 修辞手法使用频率（比喻/排比/反问...）      │
│  · 标点特征（省略号使用频率、感叹号密度等）   │
│                                          │
│  定性指标（需人机协作标注）：                │
│  · 叙事人称偏好（第一/第三/多视角）           │
│  · 时态偏好                                │
│  · 叙事距离（近距离/中距离/远距离）           │
│  · 幽默风格（冷/热/黑色/无厘头）             │
│                                          │
│  技术实现：                                │
│  · 统计NLP特征提取                         │
│  · 跨作品风格一致性检测                     │
│  · 声线漂移实时监控                        │
│  · 风格演化轨迹追踪（随时间的变化曲线）      │
│                                          │
│  更新频率：每章更新统计特征，跨作品触发      │
│           风格漂移告警                      │
└──────────────────────────────────────────┘
```

### 信息流动规则

```
L1 → L2（短期记忆写入长期知识库）：
  · 触发条件：用户显式保存 / 会话结束 / 每满3000新字
  · 动作：文本 → 信息抽取 → 比对现有知识库 → 增量更新
  · 防污染：用户标记"废弃草稿"不被写入

L2 → L1（长期知识库加载到短期记忆）：
  · 触发条件：用户打开某章节 / 提及某人物 / 开始新会话
  · 动作：从知识库查询相关节点 → 组装为简洁上下文 → 注入L1
  · 优先级：当前章节相关 > 近期未出现的伏笔 > 全局背景

L2 → L3（作品特征沉淀为个人风格）：
  · 触发条件：完成至少3章稳定创作后
  · 动作：提取当前作品的风格特征 → 与历史风格模型比对 → 补充新特征

L3 → L1（风格模型用于实时教学）：
  · 触发条件：AI检测到当前写作偏离用户风格基线超过阈值
  · 动作：触发声线保护反馈（如"这段的句子长度明显短于你的常规风格"）
```

| F01 | Show-Don't-Tell优化 | 情感形容词/副词密度检测 | Lv1 | "你说她很生气→可以改成她摔了杯子吗？" |
| F02 | 对话标签过度 | 对话行/非"说"类标签比例 | Lv1 | "这章用了12个'低声'，试试只用动作描写代替？" |

### 教学触发的"Just-in-Time"逻辑

```
写作中 → AI检测到可反馈点 → 判断：

1. 该反馈类型的教学层级是否 ≤ 用户当前层级+1？
   NO → 不触发（用户还没准备好接受这个层级的反馈）
   YES → 继续

2. 本次会话中该类型的反馈是否已触发过？
   YES（且上次是5分钟内）→ 不触发（避免骚扰）
   YES（但已过30分钟+用户未采纳）→ 不触发（用户选择忽略）
   NO → 继续

3. 当前是否在"心流模式"（用户持续快速输入中）？
   YES → 延迟触发（等用户停下来再提示）
   NO → 立即触发
```
