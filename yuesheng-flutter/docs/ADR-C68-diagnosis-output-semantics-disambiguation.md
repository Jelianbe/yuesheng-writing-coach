## 3. 两条缺陷的事实链

### 3.1 N35 · 体裁未确认时 severity 该按哪个基准标定

**冲突三处**：

| 位置 | 措辞 | 方向 |
|:--|:--|:--|
| `skills_diagnosis_p1.dart:177`（`genre-guide` §四） | 「教练在**第一次诊断前**需要确认学员的作品体裁」 | 体裁是诊断前置 |
| `skills_l1_core_p2.dart` §3.9 | 诊断块**必附加** | 识别到症候就得给 |
| `skills_diagnosis_p1.dart:48/94/114` 等 | 「**提高**触发阈值」「**降低**触发阈值」 | 阈值随体裁浮动 |

学员第一句话就贴了文本、且没说体裁时，模型面临两难：先问体裁 → 违反 §3.9；直接诊断 → 不知道按哪个阈值。gp-13 原话是「体裁未定就填 severity = **在阈值未定的情况下填严重度**」。

**决定性查证：阈值并非未定。**
`skills_diagnosis_p1.dart:31-34` 的容忍度矩阵已经定义了基准：

```
- **高容忍**: 该体裁读者对此特征有较高接受度，正常水平不触发诊断
- **低容忍**: 该体裁对此特征要求更严格，**阈值高于通用标准**
```

「**通用标准**」这个词本身就在 prompt 里，各体裁的调整（提高/降低）都是相对它而言的。
所以**基准早已存在**，缺的只是一条接线——把「体裁未确认」接到「按通用标准走」。

这让 N35 的性质从「需要新增一个概念」降级为「补一句裁决」。

**修法**（`skills_diagnosis_p1.dart:177` 之后补一段，纯补充说明，不改任何既有规则）：

```
> **体裁未确认 ≠ 不能诊断**：学员一上来就贴文本、还没说体裁时，诊断块按 §3.9
> 照常附加，severity 先按**通用标准**标定（见 §一 容忍度矩阵——各体裁的"提高/降低"
> 都是相对这个基准而言），同时在自然说明里顺带确认体裁。
> 体裁确认后若该体裁阈值与通用标准不同，**从下一轮起按体裁调整**即可；不要为了
> 等体裁而推迟本轮诊断，也不要因为体裁未定就降低置信度或省略诊断块。
```

**为什么不选另外两个方案**：

- **方案 B（先问体裁、本轮不附加块）**：直接违反 §3.9 必附加，且学员贴了文本却得不到任何诊断，体验上是「问了半天还没开始」。
- **方案 C（按推断体裁标定）**：把推断伪装成已知，体裁猜错时 severity 会静默偏移，比按通用标准更糟——**通用标准是所有体裁调整的中点，猜错的期望损失最小**。

### 3.2 N36 · 输出格式段缺少就近分工指引

**N36 的完整观察**（台账 :2146-2149）：

> gp-13 补充观察：L1068「先输出自然语言 + 再输出 JSON」把两者**缝在同一轮**里，
> 字面可自洽（前者管 JSON、后者管自然语言），但 prompt 从未明说 → 模型只能猜。

L1068 定位到源码是 `syndrome_kb_content.dart:53`（经 prompt 转储 `docs/audits/_prompt_dump/after_b6/diagnosis_yuesheng.txt:1068` 反查确认）。

**ADR-C67 已经解决了「从未明说」的一半**，但说明落在 `syndrome_kb_content.dart:44-45`（「## 诊断输出规范」章节规则 4 下），而模型**实际生成时逐段遵循**的是下方 6 行处的「## 输出格式」：

```
## 输出格式

先输出一段自然的诊断说明（给作者看的），然后输出 [YS_DIAGNOSIS] 标记包裹的 JSON 数据。

### 自然说明部分
[用自然的语言向作者说明你识别到的主要问题，这是给作者看的对话内容]

### JSON 数据部分
```

残留缺口有两处：

1. 「自然说明部分」的占位描述只说「**主要问题**」，没说它受教学层「聚焦 1-2 个」约束；
2. 「### JSON 数据部分」**完全没有**提示它不受聚焦约束——模型读完「聚焦 1-2 个」再往下生成 JSON，最容易发生的正是把 `syndromes` 数组也收敛到 1-2 条，而这恰恰是 N28 要防的失败模式。

**修法**（两处各补一句，均为就近指引，不新增规则）：

```
### 自然说明部分
[用自然的语言向作者说明本轮聚焦的 1-2 个主要问题（"聚焦"由教学层规则另定），这是给作者看的对话内容]

### JSON 数据部分
（**不受上面"聚焦 1-2 个"的限制**——两段管的是不同事：自然说明按教学层聚焦讲，
syndromes 数组则按上文"不限制数量"全量识别）
```

### 5.3 护栏

新增 `test/services/diagnosis_output_semantics_test.dart`，断言：

1. **存在性**：① 的裁决段落存在，且含「通用标准」字样（与 §一 容忍度矩阵的基准同词，可被交叉检索）；
2. **生效性**（V4.9）：三段说明必须分别落在**会被注入的常量 / skill 区间内**——
   - ②③ 必须落在 `kSyndromeIndexContent` 区间内，**不得**落在 `kSyndromeManualContent` 区间；
   - ① 必须落在 `genre-guide` 的 `content` 区间内；
3. **就近性**：② 与 ③ 必须分别位于 `### 自然说明部分` 与 `### JSON 数据部分` 标题**之后**、下一个 `###` 或 `##` 标题**之前**——防止说明被挪到别处后「存在但不再就近」；
4. **反向断言**：原文「教练在第一次诊断前需要确认学员的作品体裁」「不限制问题数量——识别到多少就报多少」**不得被改写**（只补不删）；
5. **逐处断言**（V4.8）：②③ 各自独立断言，**不求和**。

实现：`test/services/diagnosis_output_semantics_test.dart`，**15 个用例全绿**。

### 5.3.1 变异验证（7 个变异，全部拦截、无漏网）

脚本 `tool/_c68_mutation.py`：逐个注入变异 → 跑护栏 → **try/finally 恢复**。

| # | 变异 | 命中 |
|:--|:--|:--|
| A | 删掉 N35 裁决段落 | ① ×2、② ×1 |
| B | 把 N35 段落挪到 `_genreGuide` 声明之前 | ② ×1（① 是存在性判定，本就通过——分工符合设计） |
| C | 删掉 ③（JSON 段说明） | ② ×1、③ ×1、⑤ ×2 |
| D | 把 ② 挪到 index 内容最末端（脱离小节，但仍在可注入范围内） | ③ ×1、⑤ ×1 |
| E | 把 ③ 挪到「### JSON 数据部分」标题之前 | ③ ×1、⑤ ×1 |
| F | 改掉「不限制问题数量」原文 | ④ ×1 |
| H | 把 ② 挪到「## 输出格式」标题之前 | ② ×1、③ ×1、⑤ ×1 |

两点值得记下：

- **C 的意义**：⑤ 采用「②③ 各自独立计数」而非「两段合计 ≥ 2」，
  正是为了防「删掉一段、另一段重复一次也能蒙混」。C 实测命中 ⑤，

  正确通过、由 ③「就近性」兜住；H 挪到「## 输出格式」之前才由 ② 拦下。
  即 **② 管「会不会被注入」，③ 管「是不是在生成位」**，两者职责不重叠。

### 5.3.2 判据加强：「## 输出格式」下界

首版 ② 只判「在 index 声明之后、manual 声明之前」。D 变异暴露了一个盲点：
把说明插在两常量声明之间也能通过（位置仍 `< idxManual`），但那里既不在
输出格式段内、也不在模型逐段遵循的路径上——这次是靠 ③ 兜住的。

已收紧：② 增加下界 `iNatural / iJson > indexOf('## 输出格式')`，
并补变异 H 验证该下界确实生效（实测命中 ②）。

### 5.3.3 本批新踩的三个坑

1. **变异脚本崩溃 → 源码被留在「已变异」状态（最严重）**。
   首版脚本没有 `try/finally`，`run_test()` 抛 `FileNotFoundError`
   （python 子进程找不到 `flutter`，见坑 2）后直接退出，**恢复逻辑从未执行**，
   把 N35 段落永久留在了删除状态。而脚本下一轮 `main()` 开头的备份
   又把「已损坏」的文件当成了基线 → 后续四个变异的结果**全部被污染**
   （表现为「C 删 JSON 段说明」却报 ① N35 相关断言失败）。
   **教训：任何「改源码 → 跑验证」的脚本必须 try/finally 恢复，
   且备份要校验锚点存在**（本批是人工比对 `git diff` 才发现的）。
2. **python 子进程找不到 `flutter`**：Git Bash 里 `which flutter` 有值，
   但 Windows 原生 python 的 subprocess 没有 shell PATH。
   需 `shutil.which('flutter.bat')` 或绝对路径。
3. **Dart RegExp 两处方言差异**：不支持 `(?m)` 内联修饰符（须用
   `multiLine: true` 构造参数）；`\#` 被判为非法转义（用字符类 `[#]{2,3}`，
   同时避开 Dart 把 `#{2,3}` 当字符串插值的问题）。
