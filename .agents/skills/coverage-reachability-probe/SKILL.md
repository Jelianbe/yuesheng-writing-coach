# 覆盖可达性查询操作法

> 来源：`.ai/team/skill-gaps.md` #5（舰长 2026-11-26「批，建」）。本仓特有形态：
> 消费侧间接覆盖 + 同名外测试 ⇒ 公共库没有现成 skill 可装。

## Purpose

回答一个覆盖率数字回答不了的问题：**某个文件的某个行为，到底有没有被任何一条测试真正断言过？**
`coverage` 只说明执行到了哪些行，不说明断言了什么；而 `guardrail-coverage-audit` 只给
"要不要覆盖"的判据，`dart-mutation-test-pilot` 只给变异体定性——两者都不给**怎么查**。

## When to use

- 要给一批 `lib/` 文件标"已覆盖 / 零覆盖"，作为补测试或加门禁的依据。
- 覆盖率已达标，但怀疑某些行为其实没断言。
- 任何单入口检索（grep 文件名 / grep 类名）给出"零覆盖"结论 ⇒ **必须复核**，不许直接采信。

## 四步操作法（顺序不可换）

### ① 取真实公开符号名——读源码，不许从文件名推

打开目标文件，把真正暴露出去的函数 / 类 / 常量逐个抄下来。
**实例**：`editor_parser.dart` 里没有 `EditorParser`；真符号是
`parseEditorObservation` / `EditorParseResult` / `kEditorStart`。按文件名搜 `EditorParser`
会命中 0 条，得出"零覆盖"的假结论。

产物：一份符号清单，每条注明签名与所在文件行号。

### ② 逐符号检索直接引用

对每个符号全仓检索（含 `test/`），记下直接调用点。

### ③ 手工追消费链路

对每个直接调用点继续追：
**消费方 import → 消费方的测试 → 断言了哪条分支**。
覆盖常常不在被测文件自己的同名测试里，而在上游消费方的测试里——这就是"消费侧间接覆盖"。

### ④ 落到断言分支

对每个找到的测试，写明它断言的是哪个行为。只有"跑到了"不算覆盖，必须有断言。
输出时把"执行到但未断言"单列一类，不要混进"已覆盖"。

## 实证：为什么步骤不能省

上一批按**文件名**检索判定覆盖；本批改按**符号 + 消费链路**判定。同一批 16 条里，
步骤②单独做（等价于按文件名检索）把 **5 条误报成"零覆盖"** —— 差一步就把 5 条重复劳动
判成该测。**单入口检索的结论会反向，不是"精度差一点"。**

## 配套纪律：新口径自身要被反例证伪过

换一个更准的检索口径时，**新口径必须先在一个已知反例上被证伪过**，
否则只是把一种系统性误差换成另一种。已知反例就是上面那 5 条：
若你的新口径仍把它们报成零覆盖，说明口径没换对。

## 输出格式

| 文件 | 真实公开符号 | 直接引用 | 消费链路 | 断言分支 | 结论 |
|:--|:--|:--|:--|:--|:--|
| `lib/x.dart` | `foo` / `kBar` | `a.dart:12` | `a_test.dart:40` | 返回 nil 时分支 | 已覆盖 |

结尾必须写三项计数：已覆盖 / 执行但未断言 / 零覆盖，以及**本轮用的检索口径**与**反例复核结果**。

## 失败形态（命中即重做）

- 从文件名推符号名 ⇒ 重做①。
- 只做②就下结论 ⇒ 重做③④，并在报告里标注"此前结论作废"。
- 把"测试跑到了"当"断言了" ⇒ 重做④。
- 新口径没有在已知反例上验证过 ⇒ 结论不可采信。
