# 自写判据的哨兵变异自证三段式

> 来源：`.ai/team/skill-gaps.md` #8（舰长 2026-11-26「批，建」）。
> `analysis-probe-selfcheck` 只给纪律（"自证必须含能让错误实现变红的分支"），不给骨架；
> `gate-run-evidence-integrity` 管跑门禁时的树一致性，不管给自写检查器做负向自证；
> `dart-mutation-test-pilot` 是 Dart 产品源码变异，不覆盖 Python 检查器。

## Purpose

证明"这条判据真的会拦"。**校验器 rc=0 不等于我写的东西被看见了**——
格式不对、变异串过期、注入点自带豁免，都会让自证恒绿。恒绿的自证比没有自证更危险：
它把"没牙齿"伪装成"有纪律"。

## When to use

- 新写一个检查器，或给已有检查器加了一条判据。
- 改了判据的常量 / 阈值 / 版本 / 格式。
- 基线型门禁（"只卡新增"）想知道豁免基线本身会不会误挡。
- 任何 `--selfcheck` 从绿变红、或从红变绿之后（必须确认是真变，不是字符串漂移）。

## 五条硬规则

### ① 注入只在临时副本上做

```python
import shutil, tempfile
tmp = tempfile.mkdtemp()
shutil.copytree(repo, tmp, ignore=shutil.ignore_patterns('.git'))
```

真仓零污染。**禁止用 `git restore` 代替备份恢复**——它救不了未提交的新文件和副本。
测试结束删临时目录，并断言已删。

### ② 注入点必须语义上真的会红

避开判据自身的关键词，否则哨兵自带"缺省"出口 ⇒ 守卫漏过 ⇒ 假绿。
注入前先确认：这个形态在一份**已知正确**的样本上是通过的，在变异样本上必须被判错。

### ③ 断言双向 + 逐字节复原

```python
assert run(checker, tmp).returncode != 0, "注入后必须红"
restore(tmp)
assert run(checker, tmp).returncode == 0, "还原后必须绿"
assert bytes_identical(tmp, repo), "副本须逐字节复原"
```

只断言"注入后红"不够——还原失败、顺便改坏别的文件，同样能通过。

### ④ 基线豁免要有单独的摘除臂

加一条"摘掉一条基线豁免 ⇒ 必须复红"，证明基线本身不是万能挡箭牌。
否则基线一放宽，所有自证臂都跟着绿。

### ⑤ 变异未生效必须 fail-closed

**注入前后若字节相同（源码形态与预期不符），直接抛错退出，不许静默跳过这一臂。**
最危险的不是变异后没红，而是**变异根本没发生**、臂自己报"通过"。

## 活案例：硬编码变异串的静默失效（本仓实证）

`check_review_discipline.py` 的 K3 版本承载臂曾把变异串硬编码成
`"当前版本 **1.11.0**" → "当前版本 **1.10.0**"`。版本升到 1.12.0 后，
README 里已无这个串 ⇒ 注入是空操作 ⇒ 自证**照样报绿**。

修法必须从真值变量派生，而不是再抄一遍新版本号：

```python
_parts = EXPECT_VERSION.split(".")
_prev = "%d.%d.%d" % (int(_parts[0]), int(_parts[1]) - 1, int(_parts[2]))
mutate(README, f"当前版本 **{EXPECT_VERSION}**", f"当前版本 **{_prev}**")
```

**第二次踩坑**：最初写的是 `max(0, patch - 1)`；当前版本 patch=0 ⇒ `max(0,-1)=0`
⇒ `_prev` 仍等于 `EXPECT_VERSION`，空操作重现。改为降 minor 位才真正变红。

> 结论：**自证的变异串必须从真值变量派生，且升级后必须实跑自证。**
> "自证通过"若没有"变异确实生效"的证据，就是假绿。

## 输出格式

每个自证臂打印三行：`臂名 / 注入后 rc / 还原后 rc`，末尾打印
`N 臂全红且逐字节复原`。**任一臂未生效按失败处理**，不允许"跳过"字样出现在成功路径。

## 失败形态（命中即判自证无效）

- 在真仓上直接注入。
- 变异串是硬编码字面量，且没和当前真值变量比对过。
- 只断言注入后红，没断言还原后绿 / 逐字节一致。
- 用 `git restore` 当恢复手段。
- 变异前后字节相同却仍计为通过。
- 基线型检查器没有"摘除豁免"臂。
